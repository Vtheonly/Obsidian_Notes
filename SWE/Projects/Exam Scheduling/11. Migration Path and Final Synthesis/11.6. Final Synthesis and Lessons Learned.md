# 11.6. Final Synthesis and Lessons Learned

> [!abstract] What this note teaches you
> The final note of the vault. This is the mindset shift from V1 to V2, the 20 biggest V1 mistakes reconciled with their V2 fixes, and the conflict-resolution log between the source documents. Read this last.

## The mindset shift

V1 was built with a "looking done" mindset — fake buttons, empty test files, empty docs, a README that claimed 45s scheduling with no evidence. The goal was to *appear* professional.

V2 is built with a "being done" mindset — real auth, real tests, real benchmarks, real audit logs. The goal is to *be* professional, even when nobody is looking.

> [!important] The single most important lesson
> You shipped a working demo. That's not nothing — most people don't even ship. But you also shipped fake buttons, empty test files, and empty docs that *look* like real deliverables. That's a pattern I see in juniors who are optimizing for *looking done* instead of *being done*. Fix that mindset first. — The V1 review's closing advice to the author

## The lessons you should take to your next project

1. **The brief is a constraint satisfaction problem, not a feature checklist.** Model it globally, not feature-by-feature.
2. **Pick the right algorithm before writing code.** Greedy on NP-hard is wrong from day 1.
3. **The database is your friend.** Use RLS, EXCLUDE, partitioning, materialized views. Don't reinvent them in the app layer.
4. **Defense in depth.** RLS + RBAC + token scopes + PII redaction + audit. No single layer is enough.
5. **Async by default.** Anything that takes > 1 second should be a queued job.
6. **Soft delete everything.** Hard deletes are irreversible.
7. **Observability is not optional.** If you can't see it, you can't fix it.
8. **Tests are documentation that runs.** Empty test files are worse than no test files.
9. **The README is not a benchmark.** Back performance claims with executable evidence.
10. **Looking done ≠ being done.** Ship real things, not theater.
