# 11.2. What to Keep, Delete, and Rewrite from V1

> [!abstract] What this note teaches you
> V1 wasn't all bad — it had a few genuinely good ideas worth preserving. This note is the audit: what V2 keeps (with attribution to V1), what V2 deletes entirely, and what V2 rewrites from scratch.

## What V2 keeps from V1

V1 had good instincts in a few places. V2 preserves these patterns:

### 1. Partial indexes

V1's `idx_inscriptions_active ... WHERE statut IN ('inscrit', 'rattrapage')` and `idx_lieu_disponible ON lieu_examen (capacite DESC) WHERE disponible = TRUE` were textbook partial indexes. V2 extends this pattern to every table — see [[3.3. Index Strategy B-Tree Partial GIN BRIN GIST]].

### 2. RPC delegation

V1 pushed computation to the DB via stored functions (`get_global_stats`, `get_department_stats`). This is the right instinct — why fetch rows to Python and aggregate there when Postgres can do it in one query? V2 keeps this with `get_dashboard_data` — see [[3.2. Schema Design Principles for SaaS]].

### 3. Batched inserts

V1's seeder used 500-row batches for `etudiants` and 1000-row batches for `inscriptions`. This is correct for the Supabase REST API (which has payload limits). V2 keeps batched inserts for bulk imports.

### 4. Largest-enrollment-first greedy ordering

V1's `ORDER BY nb_inscrits DESC` is the standard bin-packing heuristic. V2 keeps this as a tiebreaker in the CP-SAT model (after fairness and conflict-degree).

### 5. Best-fit room selection

V1's `ORDER BY capacite ASC LIMIT 1` (smallest-fitting-room-first) maximizes utilization. V2 keeps this as soft constraint W6 (weight 1) — see [[4.5. The 7 Soft Constraints and Objective]].

### 6. Pre-materialized conflict graph

V1's `temp_module_conflicts` (modules sharing ≥1 student) is the right data structure. V2 makes it a permanent materialized view (`mv_module_conflicts`) — see [[3.6. Materialized Views and Refresh Strategies]].

### 7. Incremental per-student daily counter

V1's `temp_student_daily_counts` with `ON CONFLICT DO UPDATE` is an atomic upsert pattern. V2 keeps the pattern in the CP-SAT model (constraint 3 uses incremental counting).

### 8. Session-scoped scheduling

V1's `sessions_examen` + `creneaux(session_id)` correctly separates "January session" from "rattrapage". V2 preserves this — see [[3.2. Schema Design Principles for SaaS]].

### 9. Status enums via CHECK constraints

V1's `statut CHECK (...)` on every status column was good. V2 keeps CHECK constraints and adds state-machine enforcement — see [[7.5. State Machines for Session and Validation]].

### 10. `schedule_logs` audit table

V1 had the right idea — log every scheduling run with JSONB details. V2 generalizes it to `audit_log` partitioned by year, with hash chaining — see [[6.6. Audit Logging and Hash Chaining]].

## What V2 deletes entirely

### 1. The entire `univ_exam_optimizer/` codebase

17 of its files were zero-byte placeholders. The rest was a partial skeleton with a different schema, different driver, and a broken greedy algorithm. Delete it. Keep only `bda_test_univ_exam/` as a V1 reference snapshot.

### 2. Streamlit pages' direct Supabase access

`db.supabase.table(...).select("*")` from a Streamlit page is gone. All access goes through the Laravel API — see [[2.2. Streamlit to Database Coupling]].

### 3. The fake "Valider le planning" buttons

The `# TODO: Update session status in DB` theater is gone. Real `POST /sessions/{id}/validate` calls replace it — see [[8.5. Validation State Machines in the UI]].

### 4. `st.balloons()` in production

Cute in a demo. Unprofessional in production. Gone.

### 5. The broken CSS

V1's `background: linear-gradient(135deg, color: white; }` (missing color stops) is replaced with valid CSS in a shared `render_header` component.

### 6. Empty test files

V1's `tests/test_db_constraints.py` (0 bytes) and `tests/test_optimization_logic.py` (0 bytes) are gone. V2 has real tests — see [[11.5. Testing Strategy Unit Integration E2E Property-Based]].

### 7. Empty docs

V1's `benchmarks_performances.md` and `rapport_technique.md` (both 0 bytes) are gone. V2 has executable benchmarks and this vault as documentation.

### 8. The `EXTRACT(MILLISECONDS)` bug

The wrong execution-time logging is replaced with `EXTRACT(EPOCH) * 1000` — see [[2.5. PL-pgSQL Anti-Patterns]].

### 9. `SET LOCAL statement_timeout = 0`

The unbounded timeout footgun is replaced with explicit `max_time_in_seconds` on the CP-SAT solver and `timeout = 600` on the Laravel job.

### 10. Hardcoded `DB_PASSWORD = "password"`

Gone. Secrets in AWS Secrets Manager / HashiCorp Vault — see [[6.3. OAuth2 with Sanctum Fortify Socialite]].

## What V2 rewrites completely

### 1. The schema

V1's `UNIQUE(module_id, creneau_id)` is replaced with `exams` + `exam_allocations` (split rooms) — see [[2.6. The Fatal UNIQUE Constraint]]. V1's `TEXT[]` for equipment is replaced with a normalized `equipment` + `room_equipment` junction. V1's `lieu_examen.disponible BOOLEAN` is replaced with `statut + lieu_indisponibilites`.

### 2. The scheduler

V1's greedy PL/pgSQL loop is replaced with CP-SAT — see Chapter 4.

### 3. The frontend

V1's Streamlit-only frontend is replaced with:
- Streamlit admin portal (decoupled, OAuth2) — see [[8.3. The Decoupled Streamlit Admin Portal]].
- Blade + Livewire student/professor portal — see [[8.4. Laravel Blade and Livewire 3 for Student Professor Portal]].

### 4. Authentication

V1 had none. V2 has Sanctum + Fortify + Socialite + RBAC — see Chapter 6.

### 5. Multi-tenancy

V1 had none. V2 has `university_id` + RLS + partitioning — see Chapter 6.

### 6. Observability

V1 had `st.error(str(e))`. V2 has structured JSON logs, Pulse, Horizon, Sentry, Prometheus, OpenTelemetry — see Chapter 9.

### 7. Testing

V1 had empty test files. V2 has Pest + pgTAP + Hypothesis + Locust + k6 + Playwright — see [[11.5. Testing Strategy Unit Integration E2E Property-Based]].

### 8. CI/CD

V1 had `render.yaml` (manual deploys). V2 has GitHub Actions with lint → test → security → build → deploy, blue-green, canary — see [[9.6. CI-CD with GitHub Actions Blue-Green Canary]].

## The migration decision matrix

| V1 component | V2 action | Reason |
|---|---|---|
| `bda_test_univ_exam/` schema | Rewrite | Fatal UNIQUE, no RLS, no partitioning |
| `bda_test_univ_exam/` scheduler | Rewrite | Greedy, no backtracking, no fairness |
| `bda_test_univ_exam/` Streamlit pages | Rewrite | Direct DB access, no auth, fake buttons |
| `bda_test_univ_exam/` services | Delete | Anemic, no logic |
| `bda_test_univ_exam/` db_manager | Delete | Replaced by Laravel Eloquent |
| `bda_test_univ_exam/` seed_data | Keep (adapted) | Batched inserts, but fix the random.choice pattern |
| `bda_test_univ_exam/` partial indexes | Keep | Good pattern, extend to all tables |
| `univ_exam_optimizer/` | Delete entirely | 17 empty files, different schema, broken |
| V1 PL/pgSQL `generate_schedule` | Delete | Replaced by Python CP-SAT |
| V1 PL/pgSQL KPI functions | Keep (adapted) | Move to `get_dashboard_data` single function |
| V1 triggers | Delete most | Replace with EXCLUDE constraints + Boolean functions |
| V1 `schedule_logs` | Migrate to `audit_log` | Add `user_id`, partition, hash chaining |

## Common junior developer mistakes

- **"Throw it all away and start fresh."** No. V1 has good ideas. Preserve them with attribution.
- **"Keep it all, just patch the bugs."** No. V1's architecture is fundamentally broken. Rewrite the architecture, keep the patterns.
- **No decision matrix.** Without explicit "keep/delete/rewrite" decisions, the migration drifts. Make the matrix and stick to it.
- **Forgetting to migrate audit logs.** Compliance requires historical audit data. Plan for it.
