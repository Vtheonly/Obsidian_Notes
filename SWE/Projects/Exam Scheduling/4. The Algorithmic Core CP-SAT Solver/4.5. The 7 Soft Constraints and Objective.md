# 4.5. The 7 Soft Constraints and Objective

> [!abstract] What this note teaches you
> Hard constraints (see [[4.4. The 16 Hard Constraints]]) define feasibility. Soft constraints define **quality** — what makes one feasible schedule better than another. V2 has 7 weighted soft constraints, summed into a single objective the solver minimizes. This note explains each weight and the trade-offs between them.

## The objective function

V2's CP-SAT model minimizes:

$$\text{Minimize: } W_1 \cdot \text{unscheduled} + W_2 \cdot \text{unfairness} + W_3 \cdot \text{cross\_dept} + W_4 \cdot \text{consecutive} + W_5 \cdot \text{weekend} + W_6 \cdot \text{room\_mismatch} + W_7 \cdot \text{daily\_overload}$$

| Weight | Value | Term | What it penalizes |
|---|---|---|---|
| W1 | 1000 | unscheduled | Modules that couldn't be placed |
| W2 | 100 | unfairness | Professor workload variance |
| W3 | 10 | cross_dept | Cross-department proctoring |
| W4 | 5 | consecutive | Consecutive-day exams for students |
| W5 | 3 | weekend | Exams on Saturday/Sunday |
| W6 | 1 | room_mismatch | Small exam in big room |
| W7 | 50 | daily_overload | Students exceeding max_exams_per_day (when relaxed) |

The weights are **deliberately hierarchical**: W1 is 10× W2, which is 10× W3, etc. This means the solver will sacrifice any amount of fairness (W2) to schedule one more module (W1), and sacrifice any amount of cross-dept proctoring (W3) to improve fairness (W2).

## W1: Unscheduled penalty (weight 1000)

```python
unscheduled = []
for m in self.data.modules:
    terms = [self.x[m.id, c.id]
             for c in self.data.creneaux_for_module(m)
             if (m.id, c.id) in self.x]
    if terms:
        unscheduled.append(1 - sum(terms))
    else:
        unscheduled.append(1)  # no feasible creneau at all
```

This is the heaviest weight by design. An unscheduled module means a student cannot take that exam — a critical failure. The solver will trade any amount of fairness, spread, or room utilization to schedule one more module.

## W2: Professor workload fairness (weight 100)

```python
# Variance of professor workloads across the session
workloads = []
for p in self.data.professors:
    w = sum(self.z[m.id, p.id, c.id]
            for m in self.data.modules
            for c in self.data.creneaux
            if (m.id, p.id, c.id) in self.z)
    workloads.append(w)

# Minimize sum of (workload - avg)^2
# CP-SAT needs this expressed linearly; use a piecewise linear approximation
# or compute via auxiliary variables
```

This is the V2 fix for V1's missing fairness constraint — see [[1.3. Hard Constraints and Business Rules]] constraint 5. The brief explicitly required "Tous les enseignants doivent avoir le même nombre de surveillances." V1's greedy "least-loaded today" heuristic actively harmed session-level fairness.

The variance formulation `(workload - avg)^2` is **non-linear** (it squares the deviation). CP-SAT supports this via:
- Auxiliary variables for the deviation.
- Piecewise linear approximation.
- Or `AddMultiplicationEquality` for exact quadratic modeling (slower).

V2 uses the piecewise linear approximation for performance.

## W3: Department proctoring priority (weight 10)

```python
cross_dept_terms = []
for m in self.data.modules:
    for p in self.data.professors:
        if p.departement_id != m.departement_id:
            for c in self.data.creneaux:
                if (m.id, p.id, c.id) in self.z:
                    cross_dept_terms.append(self.z[m.id, p.id, c.id])
```

The brief requires that exams of a department are proctored by professors of the same department "en priorité" — see [[1.3. Hard Constraints and Business Rules]] constraint 4. V2 models this as a soft constraint (not hard) so the solver can use cross-dept professors when infeasible otherwise.

## W4: Student spread (weight 5)

```python
consecutive_terms = []
for student, modules in self.data.student_modules.items():
    for i, c1 in enumerate(self.data.creneaux_sorted):
        for c2 in self.data.creneaux_sorted[i+1:]:
            # If student has exams on consecutive creneaux, penalize
            if are_consecutive(c1, c2):
                for m1 in modules:
                    for m2 in modules:
                        if m1 < m2:
                            if (m1, c1.id) in self.x and (m2, c2.id) in self.x:
                                consecutive_terms.append(
                                    self.x[m1, c1.id] * self.x[m2, c2.id]
                                )
```

Penalizes students having exams on consecutive creneaux (e.g. Monday 10:00 and Monday 14:00). The product `x * x` is non-linear; CP-SAT handles it via `AddMultiplicationEquality` or by introducing an auxiliary AND variable.

V1 had no spread optimization at all — a student could end up with 6 exams in 3 days.

## W5: Weekend avoidance (weight 3)

```python
weekend_terms = []
for c in self.data.creneaux:
    if c.jour in (6, 7):  # Saturday, Sunday (from generated column)
        for m in self.data.modules:
            if (m.id, c.id) in self.x:
                weekend_terms.append(self.x[m.id, c.id])
```

Penalizes exams scheduled on weekends. Lower weight than W4 (consecutive) because weekend exams are inconvenient but not pedagogically harmful.

## W6: Room size match (weight 1)

```python
room_mismatch_terms = []
for m in self.data.modules:
    for c in self.data.creneaux_for_module(m):
        for r in self.data.rooms_for_module(m):
            if (m.id, r.id, c.id) in self.y:
                # Penalize using a much larger room than needed
                waste = r.capacity - m.enrollment
                if waste > 0:
                    room_mismatch_terms.append(waste * self.y[m.id, r.id, c.id])
```

Discourages putting a 20-student exam in a 350-seat amphi. This is V1's Best-Fit heuristic (`ORDER BY capacite ASC`) elevated to a soft constraint — the solver will prefer small rooms for small exams but can use big rooms if necessary.

## W7: Daily overload (weight 50, only when relaxed)

```python
daily_overload_terms = []
if self.data.max_exams_per_day > 1:  # only when fallback relaxes this
    for student, modules in self.data.student_modules.items():
        for day, day_creneaux in self.data.creneaux_by_day.items():
            terms = [self.x[m_id, c.id]
                     for m_id in modules
                     for c in day_creneaux
                     if (m_id, c.id) in self.x]
            if terms:
                # Excess over the original 1-exam/day rule
                excess = sum(terms) - 1
                daily_overload_terms.append(max(0, excess))
```

Only active when the fallback strategy (see [[4.8. The Fallback Strategy]]) relaxes the 1-exam/day rule. The weight (50) is high enough that the solver prefers keeping 1/day but accepts 2/day when infeasible otherwise.

## The full objective

```python
def add_objective(self):
    self.model.Minimize(
        1000 * sum(self._unscheduled_terms()) +
        100 * self._fairness_term() +
        10 * sum(self._cross_dept_terms()) +
        5 * sum(self._consecutive_terms()) +
        3 * sum(self._weekend_terms()) +
        1 * sum(self._room_mismatch_terms()) +
        50 * sum(self._daily_overload_terms())
    )
```

## Trade-offs between weights

The weights encode policy choices:

- **W1 (unscheduled) > W2 (fairness)**: Schedule completeness is more important than fairness. A schedule with 100% scheduled but unfair proctoring is better than 95% scheduled with perfect fairness.
- **W2 (fairness) > W3 (cross-dept)**: Fairness matters more than department priority. The brief lists department priority as constraint 4 and fairness as constraint 5, but V2 inverts the weight order because fairness is a global invariant while cross-dept is a per-exam preference.
- **W4 (consecutive) > W5 (weekend)**: Pedagogical harm (consecutive exams fatigue students) outweighs convenience (weekend exams inconvenience them).
- **W6 (room match) is low**: Room utilization is a nice-to-have, not a must-have.

These weights are tunable. V2 exposes them as `parameters.json` in the `GenerateScheduleRequest` so admins can experiment.

## Common junior developer mistakes

- **Setting all weights equal.** This makes the solver trade off indiscriminately. Use a hierarchical weighting scheme.
- **Forgetting the unscheduled penalty.** Without W1, the solver will leave modules unscheduled to avoid any soft-constraint penalty.
- **Modeling preferences as hard constraints.** "No weekend exams" as a hard constraint is too strict — the solver will declare infeasibility when scheduling on weekends is the only option. Use W5 instead.
- **Not testing weight changes.** A 10% change in W2 can shift the schedule significantly. Always run the test suite after changing weights.
- **Using squared terms without proper modeling.** `(workload - avg)^2` is non-linear. Use CP-SAT's `AddMultiplicationEquality` or piecewise linear approximation.
