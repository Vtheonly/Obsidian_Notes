# IDENTITY Columns

## What it is

An **IDENTITY column** is a column that the database auto-populates with a unique integer on insert. You don't specify a value for it; Oracle does. It's the SQL-standard (SQL:2003) way to do surrogate keys, available in Oracle since 12c (so XE 18c and 21c have it).

```sql
CREATE TABLE intern (
    intern_id NUMBER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name      VARCHAR2(100) NOT NULL,
    ...
);

INSERT INTO intern(name) VALUES ('Alice');   -- intern_id auto-populated
```

The `GENERATED ALWAYS` form forbids you from supplying a value. The `GENERATED BY DEFAULT` form lets you supply one (useful for data loads), and `GENERATED BY DEFAULT ON NULL` does the same but auto-generates when you supply NULL.

## What IDENTITY does under the hood

Oracle creates an implicit sequence (`ISEQ$$<n>`) and uses it to populate the column. You don't see or manage the sequence - it's internal. You can customize it:

```sql
CREATE TABLE intern (
    intern_id NUMBER GENERATED ALWAYS AS IDENTITY
        (START WITH 1000 INCREMENT BY 1 CACHE 100) PRIMARY KEY,
    ...
);
```

The same `CACHE`, `CYCLE`, `ORDER` options as a regular sequence - see [[12 - Advanced Database Features/13 - Sequences]].

## IDENTITY vs sequence + trigger (pre-12c pattern)

Before 12c, Oracle devs used a sequence + a `BEFORE INSERT` trigger:

```sql
CREATE SEQUENCE intern_seq;

CREATE OR REPLACE TRIGGER intern_bir
BEFORE INSERT ON intern
FOR EACH ROW
BEGIN
    IF :NEW.intern_id IS NULL THEN
        :NEW.intern_id := intern_seq.NEXTVAL;
    END IF;
END;
/
```

This works but has overhead: every insert fires the trigger, which context-switches from SQL to PL/SQL and back. IDENTITY columns avoid this - the generation is inlined into the SQL layer.

IDENTITY also makes the schema **self-documenting**. `GENERATED ALWAYS AS IDENTITY` declares "this column is the surrogate key" right on the table; the sequence+trigger pattern hides it in two objects.

## Retrieving the generated key

```sql
INSERT INTO intern(name) VALUES ('Alice')
RETURNING intern_id INTO :id;
```

In JDBC, use `getGeneratedKeys`:

```java
String sql = "INSERT INTO intern(name) VALUES (?)";
try (PreparedStatement ps = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
    ps.setString(1, "Alice");
    ps.executeUpdate();
    try (ResultSet keys = ps.getGeneratedKeys()) {
        if (keys.next()) {
            long id = keys.getLong(1);
        }
    }
}
```

See [[13 - JDBC and Data Access/16 - getGeneratedKeys]].

## Why it matters

IDENTITY is the modern, declarative, race-free way to generate surrogate keys. It removes the `MAX(id)+1` race, the trigger overhead, and the manual sequence management.

## Project Connection

The project uses neither IDENTITY nor a sequence nor a trigger - it does `MAX(id)+1` in Java. The redesign proposes IDENTITY on every table:

```sql
CREATE TABLE intern (
    intern_id NUMBER GENERATED ALWAYS AS IDENTITY (CACHE 100) PRIMARY KEY,
    name      VARCHAR2(100 CHAR) NOT NULL,
    is_accepted VARCHAR2(10) DEFAULT 'Pending'
        CHECK (is_accepted IN ('Accepted','Rejected','Pending')),
    ...
);
```

This eliminates the race condition at the source.

## Common pitfalls

- Forgetting `CACHE` - the default cache is 20, which serializes high-throughput inserts. Set `CACHE 100` or higher for write-heavy tables.
- Trying to insert a value into a `GENERATED ALWAYS` column - `ORA-32795: cannot insert into a generated always identity column`. Use `GENERATED BY DEFAULT` if you need to.
- Using `GENERATED BY DEFAULT` and then forgetting to set a sequence start value past any existing rows - you'll get PK violations.
- Expecting IDENTITY values to be gap-free - they aren't, same as sequences.

## Trade-offs

- **IDENTITY vs sequence**: IDENTITY is more declarative and slightly faster (no trigger). A standalone sequence is more flexible (you can use the same sequence across tables - though you usually shouldn't).
- **GENERATED ALWAYS vs BY DEFAULT**: ALWAYS is safer (no app can supply a duplicate); BY DEFAULT is more flexible (data loads).
