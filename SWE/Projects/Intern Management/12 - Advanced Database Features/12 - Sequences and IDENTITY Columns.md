# Sequences and IDENTITY Columns

## The problem with MAX(id)+1

The project generates IDs with:
```java
int newId = oracleConnector.getMaxId("intern", "intern_id") + 1;
```

This is a **race condition**: two concurrent inserts both read MAX=100, both compute 101, both insert → PK violation. One fails.

It's also slow: `SELECT MAX(intern_id) FROM intern` is O(log n) with a PK index, O(n) without.

## Sequences (Oracle 6+)

A **sequence** is a database object that generates unique numbers. Thread-safe, no race conditions.

```sql
CREATE SEQUENCE intern_seq START WITH 1 INCREMENT BY 1 NOCACHE NOCYCLE;

-- Get next value
SELECT intern_seq.NEXTVAL FROM DUAL;

-- Use in INSERT
INSERT INTO interns (intern_id, name) VALUES (intern_seq.NEXTVAL, 'Alice');
```

`CACHE 20` (default) pre-allocates 20 values in memory for speed. `NOCACHE` is slower but loses no values on crash.

## IDENTITY columns (Oracle 12c+)

An **IDENTITY column** is a column that auto-generates values. The DB creates and manages the sequence internally.

```sql
CREATE TABLE interns (
    intern_id NUMBER(10) GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR2(100),
    ...
);

-- INSERT without the ID
INSERT INTO interns (name) VALUES ('Alice');
-- intern_id is auto-generated.
```

### GENERATED ALWAYS vs BY DEFAULT
- `GENERATED ALWAYS` — you cannot specify the ID in INSERT. The DB always generates it.
- `GENERATED BY DEFAULT` — you can specify the ID (uses your value); if you don't, the DB generates.

Use `GENERATED ALWAYS` unless you need to import data with specific IDs.

## Retrieving generated keys (JDBC)

```java
String sql = "INSERT INTO interns (name, age) VALUES (?, ?)";
try (PreparedStatement ps = conn.prepareStatement(sql, Statement.RETURN_GENERATED_KEYS)) {
    ps.setString(1, "Alice");
    ps.setInt(2, 22);
    ps.executeUpdate();
    try (ResultSet keys = ps.getGeneratedKeys()) {
        if (keys.next()) {
            long id = keys.getLong(1);
            System.out.println("Generated ID: " + id);
        }
    }
}
```

## Why this is better

- **No race condition** — sequences are atomic.
- **No extra query** — the INSERT returns the generated key.
- **No O(n) scan** — sequences are O(1) (with caching).
- **No application logic** — the DB handles it.

## Project Connection

The project's `MAX(id)+1` is the textbook race condition. The fix:
```sql
-- Migration
ALTER TABLE interns MODIFY (intern_id GENERATED ALWAYS AS IDENTITY);
-- Or in a new table:
CREATE TABLE interns (
    intern_id NUMBER(10) GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    ...
);
```

Then remove `getMaxId` from `oracleConnector` and use `RETURN_GENERATED_KEYS` in the INSERT.
