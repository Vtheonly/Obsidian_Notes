# 02.01 — The Need for Standardization

> [!abstract] Why Standards Exist
> In the 1970s, every computer vendor shipped a proprietary networking stack. IBM had SNA, DEC had DECnet, Xerox had XNS. None of them could talk to each other. The OSI model and the TCP/IP protocol suite emerged as **open standards** that broke vendor lock-in and made the internet possible.

---

##  The Pre-Standardization Era

Before the 1980s, if you bought computers from three different vendors, you got three incompatible networks:

| Vendor | Stack | Reach |
| :--- | :--- | :--- |
| IBM | SNA (Systems Network Architecture) | IBM mainframes and terminals |
| Digital Equipment Corp. | DECnet | PDP-11, VAX |
| Xerox | XNS (Xerox Network Systems) | Xerox workstations; inspired IP |
| Honeywell | DSA | Honeywell minicomputers |
| Hewlett-Packard | DS/1000 | HP 1000 minicomputers |

The defining trait of every proprietary stack: **you could only buy hardware and software from the same vendor**. Switching vendors meant rewiring your building and retraining your staff. This was *wonderful* for vendors and *terrible* for everyone else.

---

##  The Concept of Open Systems

The pushback was the concept of **open systems** — protocols published as public specifications, with multiple interoperable implementations from competing vendors. Two standards bodies drove this:

### ISO / OSI Reference Model (1984)

The **International Organization for Standardization** (ISO) published the **Open Systems Interconnection (OSI) reference model** in 1984 as ISO/IEC 7498-1. The model defined 7 layers and a parallel suite of protocols (X.25, FTAM, MOTIS, etc.). The model became universally adopted as a *teaching framework*; the protocols mostly failed in the marketplace (X.25 survived in telecom networks for a while, but the rest died).

### IETF / TCP/IP Suite (1981)

The **Internet Engineering Task Force** (IETF) developed the **TCP/IP protocol suite** in the late 1970s and early 1980s, driven by ARPA-funded research. RFC 791 (IP) and RFC 793 (TCP) were published in September 1981. TCP/IP was less academically pure than OSI but **shipped working code** — most notably in 4.2BSD Unix in 1983 — and so won the market.

> [!info] Why TCP/IP Won
> Academic debate raged for a decade, but the deciding factor was simple: TCP/IP was free, shipped with Unix, and connected to the growing ARPANET/NSFNET backbone. OSI was complex, slow to standardize, and required expensive licenses. By 1995 the debate was over — TCP/IP ran the internet, and OSI survived only as a teaching model and in a few niche telecom protocols (SS7, X.400 email).

##  Standardization Bodies You Should Know

| Body | Full Name | Domain | Notable Standards |
| :--- | :--- | :--- | :--- |
| **ISO** | International Organization for Standardization | Reference models, generic standards | OSI model (ISO/IEC 7498), country codes, OSI protocols |
| **IEC** | International Electrotechnical Commission | Electrical / electronic standards | Co-publishes ISO/IEC standards |
| **ITU-T** | Int'l Telecommunication Union — Telecom sector | Telecom (carrier-grade) | X.509, H.323, SS7, G.711 (voice), SDH/SONET |
| **IEEE** | Institute of Electrical and Electronics Engineers | L1/L2 wired & wireless | 802.3 Ethernet, 802.11 Wi-Fi, 802.1Q VLANs, 802.1X |
| **IETF** | Internet Engineering Task Force | Internet protocols (L3–L7) | IP, TCP, UDP, HTTP, TLS, BGP, OSPF (RFC series) |
| **IANA** | Internet Assigned Numbers Authority | Registries | Port numbers, protocol numbers, IP address allocations |
| **ICANN** | Internet Corporation for Assigned Names and Numbers | DNS root, TLDs | Domain name delegation, root zone signing |
| **W3C** | World Wide Web Consortium | Web technologies | HTML, CSS, XML, SOAP, WebRTC (parts) |
| **RFC Editor** | (under IAB) | RFC publication | The RFC series itself |

> [!note] National mirrors
> Most countries have a national body that mirrors ISO work (e.g., **AFNOR** in France, **BSI** in the UK, **DIN** in Germany, **ANSI** in the US, **IANOR** in Algeria). The roadmap mentions **IANOR** (Institut Algérien de Normalisation) explicitly — national bodies adopt ISO standards, sometimes with local amendments.

##  The RFC Process

Internet standards are published as **Requests for Comments (RFCs)** — a tradition dating to 1969. The process is roughly:

1. **Internet-Draft (I-D)** — anyone can submit. Expires after 6 months unless renewed.
2. **RFC publication** — after IETF consensus and IESG review, the I-D becomes an RFC with a permanent number.
3. **Standardization track** — Proposed Standard → Draft Standard (rare today) → Internet Standard.

Notable RFCs referenced throughout this vault:

| RFC | Title | Year | What it defines |
| :--- | :--- | :-: | :--- |
| 768 | User Datagram Protocol | 1980 | UDP |
| 791 | Internet Protocol | 1981 | IPv4 |
| 792 | Internet Control Message Protocol | 1981 | ICMP |
| 793 | Transmission Control Protocol | 1981 | TCP |
| 826 | Ethernet Address Resolution Protocol | 1982 | ARP |
| 1918 | Private Address Allocation | 1996 | RFC 1918 private IP ranges |
| 2131 | Dynamic Host Configuration Protocol | 1997 | DHCP |
| 2328 | OSPF Version 2 | 1998 | OSPFv2 |
| 4271 | BGP-4 | 2006 | BGPv4 |

> [!tip] Searching RFCs
