# 05.03 — Practical Walkthroughs

> [!abstract] Learn by Doing
> Three worked fragmentation scenarios. Cover them, then try to re-derive them without looking. If you can do all three from memory, you've mastered fragmentation.

---

##  Walkthrough 1 — 2000-byte Datagram, 512-byte MTU

(Same as in [[05 - IP Datagram & Fragmentation/05.02 Fragmentation Mathematics|05.02]], repeated for self-containment.)

**Given:**
- Datagram size: 2000 bytes
- Header: 20 bytes
- MTU: 512 bytes
- Identification: 10

**Computations:**
- $D_{\text{data}} = 2000 - 20 = 1980$
- $P_{\text{max}} = \lfloor (512 - 20) / 8 \rfloor \times 8 = \lfloor 61.5 \rfloor \times 8 = 61 \times 8 = 488$
- $N = \lceil 1980 / 488 \rceil = \lceil 4.057 \rceil = 5$

**Fragment table:**

| # | ID | Length | Payload | Offset (bytes) | Offset (value) | MF |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 1 | 10 | 508 | 488 | 0 | 0 | 1 |
| 2 | 10 | 508 | 488 | 488 | 61 | 1 |
| 3 | 10 | 508 | 488 | 976 | 122 | 1 |
| 4 | 10 | 508 | 488 | 1464 | 183 | 1 |
| 5 | 10 | 64 | 44 | 1952 | 244 | 0 |

##  Walkthrough 2 — 5000-byte Datagram, 1500-byte MTU

**Given:**
- Datagram size: 5000 bytes
- Header: 20 bytes
- MTU: 1500 bytes (standard Ethernet)
- Identification: 42

**Computations:**
- $D_{\text{data}} = 5000 - 20 = 4980$
- $P_{\text{max}} = \lfloor (1500 - 20) / 8 \rfloor \times 8 = \lfloor 185 \rfloor \times 8 = 185 \times 8 = 1480$
- $N = \lceil 4980 / 1480 \rceil = \lceil 3.365 \rceil = 4$

**Fragment table:**

| # | ID | Length | Payload | Offset (bytes) | Offset (value) | MF |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 1 | 42 | 1500 | 1480 | 0 | 0 | 1 |
| 2 | 42 | 1500 | 1480 | 1480 | 185 | 1 |
| 3 | 42 | 1500 | 1480 | 2960 | 370 | 1 |
| 4 | 42 | 560 | 540 | 4440 | 555 | 0 |

**Verification:** Payloads sum to $1480 \times 3 + 540 = 4440 + 540 = 4980$ .

**Note:** Offset increment is $1480 / 8 = 185$. So offsets are 0, 185, 370, 555 — easy to compute mentally.

##  Walkthrough 3 — 1500-byte Datagram, 700-byte MTU

**Given:**
- Datagram size: 1500 bytes
- Header: 20 bytes
- MTU: 700 bytes
- Identification: 7

**Computations:**
- $D_{\text{data}} = 1500 - 20 = 1480$
- $P_{\text{max}} = \lfloor (700 - 20) / 8 \rfloor \times 8 = \lfloor 85 \rfloor \times 8 = 85 \times 8 = 680$
  - Note: $680 / 8 = 85$ exactly — no rounding needed here.
- $N = \lceil 1480 / 680 \rceil = \lceil 2.176 \rceil = 3$

**Fragment table:**

| # | ID | Length | Payload | Offset (bytes) | Offset (value) | MF |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| 1 | 7 | 700 | 680 | 0 | 0 | 1 |
| 2 | 7 | 700 | 680 | 680 | 85 | 1 |
| 3 | 7 | 160 | 120 | 1360 | 170 | 0 |

**Verification:** Payloads sum to $680 + 680 + 120 = 1480$ .

##  Edge Cases to Watch For

### Edge case A: Datagram exactly equals MTU

A 1500-byte IP packet on a 1500-byte MTU link → **no fragmentation**. The packet just fits. This is the ideal case.

### Edge case B: Datagram exceeds MTU by 1 byte

A 1501-byte IP packet on a 1500-byte MTU → payload = 1481, max payload = 1480, so the last fragment carries 1 byte. Total: 2 fragments — one with 1480 bytes payload, one with 1 byte payload + 20 byte header = 21-byte packet on the wire.

### Edge case C: DF flag is set and packet exceeds MTU

Router drops the packet and sends **ICMP Type 3 Code 4 (Fragmentation Needed, DF Set)** back to the source. The source should then reduce its packet size (this is PMTUD, see [[05 - IP Datagram & Fragmentation/05.04 Path MTU Discovery|05.04]]).

> [!warning] PMTUD black holes
> Some firewalls block ICMP Type 3 Code 4 entirely (overzealous "security"). The source never learns that its packets are too big, keeps sending them, and they keep getting dropped. The connection hangs. This is a "PMTUD black hole" — the most common cause of mysterious "MTU problems" with VPN tunnels. The fix is either to allow ICMP 3/4 through the firewall or enable TCP MSS clamping on the router.

### Edge case D: Nested tunnels and MTU shrinkage

A GRE tunnel carrying IPsec inside another GRE tunnel can shrink the effective MTU to ~1400 bytes or less. Each layer adds its own header. Without PMTUD or MSS clamping, large packets will be dropped silently.

##  Quick Mental Algorithm for Exam Day

When the exam gives you a fragmentation question:

1. **Circle the three numbers**: datagram size, header size, MTU.
2. Compute $D_{\text{data}} = \text{datagram} - \text{header}$.
3. Compute $P_{\text{max}} = \lfloor (\text{MTU} - \text{header}) / 8 \rfloor \times 8$.
4. Compute $N = \lceil D_{\text{data}} / P_{\text{max}} \rceil$.
5. The first $N-1$ fragments are all $P_{\text{max}}$ bytes of payload, MF=1.
6. The last fragment is whatever's left, MF=0.
7. Offsets: $0, P_{\text{max}}/8, 2P_{\text{max}}/8, \ldots$

That's it. The whole chapter in seven steps.
