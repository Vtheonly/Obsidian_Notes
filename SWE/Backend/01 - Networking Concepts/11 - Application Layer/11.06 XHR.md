# 11.06 — XHR (XMLHttpRequest)

> [!abstract> The Original AJAX API
> **XMLHttpRequest (XHR)** is the browser API that enabled **AJAX** (Asynchronous JavaScript and XML) — the technique of making HTTP requests from JavaScript without reloading the page. Before XHR, every user interaction required a full page reload. XHR made web apps feel like desktop apps. It's now largely superseded by `fetch()`, but still widely deployed.

---

##  A Brief History

- **1999** — Microsoft invents XHR as an ActiveX object for Outlook Web Access.
- **2004-2005** — Google Maps and Gmail popularize AJAX patterns.
- **2006** — W3C standardizes XHR.
- **2015** — `fetch()` introduced as the modern replacement.
- **Today** — both coexist; `fetch()` is preferred for new code, XHR remains in legacy code and libraries (jQuery's `$.ajax` wraps XHR).

---

##  Basic XHR Usage

```javascript
// Classic XHR pattern
const xhr = new XMLHttpRequest();
xhr.open('GET', 'https://api.example.com/users', true);
xhr.onload = function() {
  if (xhr.status === 200) {
    const data = JSON.parse(xhr.responseText);
    console.log(data);
  } else {
    console.error('Error:', xhr.status);
  }
};
xhr.onerror = function() {
  console.error('Network error');
};
xhr.send();
```

### POST with JSON
```javascript
const xhr = new XMLHttpRequest();
xhr.open('POST', 'https://api.example.com/users', true);
xhr.setRequestHeader('Content-Type', 'application/json');
xhr.onload = function() {
  if (xhr.status === 201) {
    console.log('Created:', JSON.parse(xhr.responseText));
  }
};
xhr.send(JSON.stringify({name: 'Alice', email: 'alice@example.com'}));
```

### Uploading a file
```javascript
const formData = new FormData();
formData.append('file', fileInput.files[0]);

const xhr = new XMLHttpRequest();
xhr.open('POST', '/upload', true);
xhr.upload.onprogress = function(e) {
  if (e.lengthComputable) {
    console.log(`${(e.loaded / e.total * 100).toFixed(1)}% uploaded`);
  }
};
xhr.onload = () => console.log('Upload complete');
xhr.send(formData);
```

##  XHR vs fetch()

| Feature | XHR | fetch() |
| :--- | :-: | :-: |
| API style | Callbacks | Promises (and async/await) |
| Stream support | Limited | Full streaming (response body) |
| Request cancellation | `xhr.abort()` | `AbortController` |
| Progress events | Yes (`onprogress`) | Limited (response body only; upload progress via `ReadableStream`) |
| Timeout | `xhr.timeout` | Manual via `AbortController` + `setTimeout` |
| CORS | Built-in | Built-in |
| Browser support | Universal | Modern browsers (no IE) |
| Status code | 0 on network error | Resolves with `ok: false` |

### Equivalent fetch() examples
```javascript
// GET
const response = await fetch('https://api.example.com/users');
if (response.ok) {
  const data = await response.json();
  console.log(data);
}

// POST with JSON
const response = await fetch('https://api.example.com/users', {
  method: 'POST',
  headers: {'Content-Type': 'application/json'},
  body: JSON.stringify({name: 'Alice', email: 'alice@example.com'})
});

// With timeout
const controller = new AbortController();
const timeout = setTimeout(() => controller.abort(), 5000);
try {
  const response = await fetch('/api', {signal: controller.signal});
} catch (e) {
  if (e.name === 'AbortError') console.log('Timed out');
} finally {
  clearTimeout(timeout);
}
```

##  Same-Origin Policy and CORS

XHR and `fetch()` enforce the **Same-Origin Policy**: by default, JavaScript can only make requests to the same origin (protocol + host + port) as the page that loaded it.

### Same-origin example
- Page at `https://example.com/page.html` → can fetch `https://example.com/api/users`  (same origin)
- Page at `https://example.com` → cannot fetch `https://api.example.com/data`  (different host)

### CORS (Cross-Origin Resource Sharing)
CORS relaxes same-origin policy for cross-origin requests, with the server's permission:

1. **Simple requests** (GET, POST with simple headers): browser sends the request directly, with an `Origin` header. Server responds with `Access-Control-Allow-Origin: https://example.com` (or `*`) to permit.
2. **Preflighted requests** (PUT, DELETE, custom headers, non-simple content types): browser first sends an `OPTIONS` request asking "am I allowed?". Server responds with the allowed methods, headers, and origin. Then the actual request is sent.

Common CORS response headers:
- `Access-Control-Allow-Origin: https://example.com` — which origins may use the response.
- `Access-Control-Allow-Methods: GET, POST, PUT, DELETE` — which methods are allowed.
- `Access-Control-Allow-Headers: Content-Type, Authorization` — which request headers are allowed.
- `Access-Control-Allow-Credentials: true` — allow cookies to be sent cross-origin.

> [!warning] Common CORS pitfalls
> - Sending `Access-Control-Allow-Origin: *` together with `Access-Control-Allow-Credentials: true` is **not allowed**. You must echo the specific origin.
> - CORS is enforced by the **browser**, not the server. The server just sends headers; the browser decides whether to expose the response to JavaScript.
> - CORS does **not** protect against CSRF — for that, use CSRF tokens.

##  Why XHR Still Matters

Even though `fetch()` is the modern API:
- **Libraries like jQuery, Axios, and older code** still use XHR.
- **Upload progress events** are better in XHR than in `fetch()` (though `fetch()` is improving).
- **Sync requests** are technically possible with XHR (set the third arg of `open()` to `false`). **Don't do this** — it freezes the UI. But it exists.
- **IE 11 and other old browsers** only support XHR (use `fetch()` with a polyfill if needed).

For new code, use `fetch()` or a library like Axios. For maintaining old code, understand XHR.
