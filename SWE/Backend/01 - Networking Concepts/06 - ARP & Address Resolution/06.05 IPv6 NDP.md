# 06.05 — IPv6 Neighbor Discovery Protocol (NDP)

> [!abstract] ARP, Reimagined for IPv6
> IPv6 doesn't use ARP. Instead, it uses the **Neighbor Discovery Protocol (NDP, RFC 4861)**, which runs over ICMPv6 and uses multicast instead of broadcast. NDP does everything ARP did, plus duplicate address detection, router discovery, and prefix discovery — all in one protocol family.

---

##  ARP vs NDP at a Glance

| Feature | ARP (IPv4) | NDP (IPv6) |
| :--- | :--- | :--- |
| Carrier protocol | Directly inside Ethernet frames (EtherType 0x0806) | ICMPv6 (next-header 58) inside IPv6 packets |
| Resolution request | Broadcast (`FF:FF:FF:FF:FF:FF`) | Multicast to `solicited-node` group (`FF02::1:FFxx:xxxx`) |
| Resolution reply | Unicast | Unicast |
| Address conflict detection | ARP probe (sender IP = 0.0.0.0) | Neighbor Solicitation with unspecified source |
| Router discovery | DHCP or static config | Router Solicitation / Router Advertisement (built-in) |
| Prefix discovery | DHCP or static config | Router Advertisements carry prefixes |
| Security | None (separate DAI mitigation) | SEND (RFC 3971, rarely deployed); IPsec possible |

---

##  Multicast Instead of Broadcast

In IPv4, ARP broadcasts to every host on the subnet, wasting every non-target host's CPU. In IPv6, NDP uses **solicited-node multicast** — a special multicast group derived from the target's IPv6 address.

For an IPv6 address `FE80::1234:5678:ABCD:EF01`, the solicited-node multicast address is:
```
FF02::1:FFCD:EF01
```
The last 24 bits of the IPv6 address are appended to the prefix `FF02::1:FF00:0/104`. The corresponding multicast MAC is `33:33:FF:CD:EF:01` (prefix `33:33:FF` for IPv6 multicast + last 24 bits).

**Benefit:** only hosts whose last 24 bits collide with the target are interrupted. Most hosts don't even receive the multicast at L2 because the switch (with IGMP snooping) only forwards it to subscribed ports.

---

##  NDP Message Types

| ICMPv6 Type | Name | Purpose |
| :-: | :--- | :--- |
| 133 | **Router Solicitation (RS)** | Host asks routers to send an RA immediately (don't wait for next periodic) |
| 134 | **Router Advertisement (RA)** | Router announces its presence + network prefixes + MTU + flags for autoconfiguration |
| 135 | **Neighbor Solicitation (NS)** | "Who has this IPv6 address?" — equivalent to ARP Request |
| 136 | **Neighbor Advertisement (NA)** | "I have that address" — equivalent to ARP Reply |
| 137 | **Redirect** | Router tells host "use this other router for that destination" |

These five ICMPv6 types do everything ARP did, plus router discovery and prefix discovery.

---

##  Neighbor Solicitation — The ARP Replacement

When Host A wants to find Host B's MAC for IPv6 address `FE80::B`:

1. **A sends a Neighbor Solicitation** (ICMPv6 type 135) to the solicited-node multicast address derived from B's address.
   - Source IPv6: A's address (or `::` if A is doing DAD — see below)
   - Destination IPv6: `FF02::1:FFxx:xxxx` (B's solicited-node multicast)
   - Source MAC: A's MAC
   - Destination MAC: `33:33:FF:xx:xx:xx` (multicast MAC for the solicited-node group)
   - Payload: "What's the MAC for FE80::B?"

2. **B receives the NS** (because B is subscribed to its own solicited-node multicast group), checks that the target IPv6 is its own, and replies with a **Neighbor Advertisement** (type 136).
   - Source IPv6: B's address
   - Destination IPv6: A's address (unicast)
   - Payload: "My MAC is 00:11:22:33:44:55"

3. **A caches** the IPv6→MAC mapping in its **Neighbor Cache** (the IPv6 equivalent of the ARP cache).

---

##  Duplicate Address Detection (DAD)

Before a host claims an IPv6 address, it sends a Neighbor Solicitation with:
- Source IPv6: `::` (unspecified)
- Destination IPv6: solicited-node multicast for the candidate address
- Target IPv6: the candidate address

If no Neighbor Advertisement is received within a timeout, the address is considered unique and the host claims it. If a reply arrives, another host is already using the address — the host logs an error and tries a different address.

DAD is mandatory for all IPv6 addresses (link-local and global). It's the IPv6 equivalent of the IPv4 ARP probe.

---

##  Router & Prefix Discovery

A host can boot with no configuration and learn everything it needs via NDP:

1. **Host sends Router Solicitation (RS)** to `FF02::2` (all-routers multicast).
2. **Router replies with Router Advertisement (RA)** containing:
   - The router's link-layer address
   - One or more **prefixes** (with prefix length and lifetime) — used for SLAAC
   - The link's MTU
   - Flags: whether to use DHCPv6 for additional info, router lifetime, etc.
3. **Host uses SLAAC (StateLess Address AutoConfiguration)** to construct its own global IPv6 address from one of the advertised prefixes + its MAC (via the Modified EUI-64 format).
4. Host runs DAD on the new address. If unique, it's now reachable from anywhere on the internet (assuming the prefix is globally routable).

No DHCP server needed — though DHCPv6 is still used for stateful assignments (DNS, domain search list, etc.).

---

##  NDP Security

Like ARP, NDP is **unauthenticated**. An attacker can:
- Send forged Neighbor Advertisements to redirect traffic.
- Send forged Router Advertisements to set themselves as the default gateway.
- Reply to DAD for any address, blocking legitimate hosts from claiming addresses.

Defenses:
- **SEND (Secure Neighbor Discovery, RFC 3971)** — cryptographically signs NDP messages using X.509 certs. Almost never deployed due to PKI complexity.
- **RA Guard** — switch feature that blocks Router Advertisements from non-router ports. Equivalent to DHCP snooping for IPv6.
- **IPsec** — can be used for NDP authentication, but key management is painful.
- **Static neighbor entries** — manual, doesn't scale.

In practice, IPv6 networks rely on RA Guard + switch-level mitigations, similar to how IPv4 networks rely on DHCP snooping + DAI.
