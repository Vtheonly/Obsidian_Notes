# 14.02 — IP Fragmentation Memory Tricks

> [!abstract> The Shipping Company Analogy
> Imagine an IP packet as a giant package being shipped. The IPv4 header is the shipping label — every field answers one question. When the package is too big for the truck, you split it into smaller pieces (fragments), each with its own label pointing back to the original.

---

##  The Header as a Shipping Label

| Field | Question it answers |
| :--- | :--- |
| Version | Which shipping system are we using? |
| IHL | How big is the shipping label? |
| Total Length | How big is the entire package? |
| Identification | Which package family does this piece belong to? |
| Flags | Are we allowed to cut it apart? |
| Fragment Offset | Where does this piece belong? |
| TTL | How many cities can it pass through before being destroyed? |
| Protocol | Which department receives it? |
| Checksum | Is the label damaged? |
| Source IP | Who sent it? |
| Destination IP | Who receives it? |

##  The Fragmentation Formula Chain — "D M N T"

The entire fragmentation exercise is always the same 4-step recipe:

> "**Don't Make Networking Terrifying**"
>
> → **D**ata → **M**ax → **N**umber → **T**able

### Step 1: Find Data
$$D_{data} = D_{original} - H$$

Memory: "Remove the wrapper first."

### Step 2: Find Max Payload per Fragment
$$P_{max} = \left\lfloor \frac{MTU - H}{8} \right\rfloor \times 8$$

Memory: "MTU minus header, then round DOWN to a multiple of 8."

> [!warning] The Rule Students Forget Most
> "MULTIPLE OF 8. MULTIPLE OF 8. MULTIPLE OF 8."
>
> Because offsets count in 8-byte blocks.

### Step 3: Find Number of Fragments
$$N = \left\lceil \frac{D_{data}}{P_{max}} \right\rceil$$

Memory: "Data ÷ Capacity, round UP."
> Even 1 remaining byte needs another fragment.

### Step 4: Build the Table
For each fragment:
> **P L O M** → "**Plum**"
>
> **P**ayload, **L**ength, **O**ffset, **M**F.

---

##  The Offset Trick

Don't calculate offsets individually. Count how many payload chunks came before:

$$\text{Offset} = \frac{\text{Bytes Before Me}}{8}$$

### Pattern Example

If payload size = 488:

| Fragment | Bytes before | Offset = bytes / 8 |
| :---: | :-: | :-: |
| 1 | 0 | 0 |
| 2 | 488 | 61 |
| 3 | 976 | 122 |
| 4 | 1464 | 183 |
| 5 | 1952 | 244 |

Just **add 61 each time** (because $488 / 8 = 61$).

---

##  The MF Flag Trick

Imagine a movie series:

| MF | Meaning |
| :-: | :--- |
| 1 | "**To be continued...**" — more fragments coming |
| 0 | "**The End**" — final fragment |

> "MF = 1 → More coming. MF = 0 → Last fragment."

---

##  Three Numbers to Circle Immediately

When the exam gives you a fragmentation question, circle these three numbers:
1. **Total Datagram Size** (e.g., 2000)
2. **Header Size** (e.g., 20)
3. **MTU** (e.g., 512)

Everything else comes from these three.

---

##  Ultra-Short Exam Memory

```text
1. Data = Original − Header

2. MaxPayload = floor((MTU − Header) / 8) × 8
   (MUST be multiple of 8 for offset alignment)

3. Fragments = ceil(Data / MaxPayload)
   (round up — even 1 byte needs another fragment)

4. For each fragment:
   Payload: P_max (or remainder for last)
   Length: Payload + Header
   Offset: Bytes_before / 8
   MF: 1 except last fragment (which is 0)
```

The entire chapter in 5 lines.

---

##  The Whole Chapter in One Sentence

> "Remove the header, fit payload into MTU-sized chunks rounded to multiples of 8, count fragments, divide previous bytes by 8 for offsets, and set MF=1 until the last piece."
