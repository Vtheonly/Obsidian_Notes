# 14.04 — General Networking Mnemonics

> [!abstract> Universal Memory Aids
> The mnemonics every network engineer should have memorized: OSI layers, PDU chain, TCP flags, well-known ports, and the TCP/IP vs OSI layer mapping.

---

##  OSI 7-Layer Model

### Bottom-Up
> "**Please Do Not Throw Sausage Pizza Away**"

| Letter | Layer | Example |
| :-: | :--- | :--- |
| **P** | Physical | Cables, fiber, radio |
| **D** | Data Link | Ethernet, Wi-Fi |
| **N** | Network | IP, ICMP |
| **T** | Transport | TCP, UDP |
| **S** | Session | RPC, NetBIOS |
| **P** | Presentation | TLS, JPEG |
| **A** | Application | HTTP, DNS |

### Top-Down
> "**All People Seem To Need Data Processing**"

A → P → S → T → N → D → P

---

##  PDU Chain — Encapsulation Order

> "**Data Segments Produce Frames Bit by bit**"

| Layer | PDU |
| :-: | :--- |
| Application | Data |
| Transport | Segment (TCP) / Datagram (UDP) |
| Network | Packet |
| Data Link | Frame |
| Physical | Bit |

### Reverse (Decapsulation)
> "**Bits Form Packets' Substance Downward**"

---

##  TCP Control Flags

> "**UAPRSF**" → "**U Are Prepared, Restart Server Fast**"

| Flag | Letter | Meaning |
| :-: | :-: | :--- |
| Urgent | U | Urgent pointer valid |
| Acknowledgment | A | Ack field valid |
| Push | P | Push to app immediately |
| Reset | R | Reset connection |
| Synchronize | S | SYN — start handshake |
| Finish | F | FIN — close connection |

### Common Combinations
- **SYN** — connection request
- **SYN-ACK** — connection accepted
- **ACK** — handshake complete + data segments
- **FIN-ACK** — close request
- **RST-ACK** — connection reset (port closed)
- **PSH-ACK** — data with immediate push

##  Well-Known Ports — Mnemonics

| Port | Service | Mnemonic |
| :-: | :--- | :--- |
| 22 | SSH | "SSH = 22" |
| 23 | Telnet | "Telnet is one less than SSH (legacy, came first)" |
| 25 | SMTP | "Sends Mail To People" |
| 53 | DNS | "Domain has 3 letters; 5+3=8" (or just memorize) |
| 80 | HTTP | "HTTP has 4 letters; 8×10=80" (forced) |
| 110 | POP3 | "Picks up mail: 1+1+0=2, just like the O in pOp" (forced) |
| 143 | IMAP | "Interacts Mail And ... 1+4+3=8" |
| 443 | HTTPS | "HTTPS = HTTP (80) + TLS (4×80+something, just memorize)" |
| 161 | SNMP | "161 = Simple Network Management Protocol" |

**The five you must memorize cold:** 22 (SSH), 53 (DNS), 80 (HTTP), 443 (HTTPS), 25 (SMTP). The rest follow patterns.

##  OSI vs TCP/IP Mapping

> "**OSI splits 7; TCP/IP squashes 4.**"

| OSI | TCP/IP |
| :-: | :-: |
| 7 Application | Application (merges 5+6+7) |
| 6 Presentation | ↑ |
| 5 Session | ↑ |
| 4 Transport | Transport |
| 3 Network | Internet |
| 2 Data Link | Network Access (merges 1+2) |
| 1 Physical | ↑ |

##  Loop Prevention Across Layers

| Layer | Mechanism |
| :-: | :--- |
| L2 (STP) | Block redundant ports |
| L3 (IP) | TTL decrement |
| L3 (RIP) | Split Horizon, Poison Reverse, Hold-Down, max hop |
| L3 (OSPF) | SPF algorithm computes loop-free tree |
| L3 (BGP) | AS_PATH — discard if own ASN is in the path |

> "**At every layer, something kills loops.**"

##  Routing Source Codes (Cisco `show ip route`)

> "**C S R O B**" → "**Cats Sometimes Run Over Bears**"

| Code | Source |
| :-: | :--- |
| C | Connected |
| S | Static |
| R | RIP |
| O | OSPF |
| B | BGP |
| D | EIGRP |
| i | IS-IS |

Plus:
- `*` = candidate default
- `L` = local (router's own interface IP as /32)

##  The "Two Questions" Trick

When stuck on a layer question, ask:

1. **Host-to-host or process-to-process?**
   - L3 (Network) = host-to-host.
   - L4 (Transport) = process-to-process.
2. **Single link or end-to-end?**
   - L2 = single link (MAC changes at every hop).
   - L3 = end-to-end (IP stays the same, modulo NAT).

---

##  The Diagnostics Workflow

> "**Bottom up**" — when something's broken, start at L1 and work up:

1. **L1:** Cable plugged in? Interface up? (`show ip interface brief`)
2. **L2:** MAC learned? CAM table populated? ARP cache populated? (`show mac-address-table`, `show arp`)
3. **L3:** Can you ping the gateway? Can you ping the destination? (`ping`)
4. **L4:** Is the destination port open? (`telnet <ip> <port>`)
5. **L7:** Does the application respond? (`curl`, `dig`, `ssh`)

If a lower layer fails, upper layers won't work — fix L1 before debugging DNS.

```text
OSI:    Please Do Not Throw Sausage Pizza Away
PDU:    Data → Segment → Packet → Frame → Bit
TCP flags: UAPRSF
Ports:  22 SSH, 25 SMTP, 53 DNS, 80 HTTP, 443 HTTPS
AD:     0 connected, 1 static, 90 EIGRP, 110 OSPF, 120 RIP
OSPF cost: Reference BW / Interface BW

```
