# 08.06 — OSPF Cost & the Gigabit Bottleneck

> [!abstract] The Default That Bit Everyone
> OSPF's cost formula was standardized in 1998 when 100 Mbps Fast Ethernet was the high end. The default reference bandwidth of 100 Mbps means any link ≥ 100 Mbps gets cost 1 — including 1 Gbps, 10 Gbps, and 100 Gbps. This breaks OSPF's ability to distinguish fast from slow links above 100 Mbps. The fix is the `auto-cost reference-bandwidth` command.

---

##  The Cost Formula

$$\text{Cost} = \left\lfloor \frac{\text{Reference Bandwidth (bps)}}{\text{Interface Bandwidth (bps)}} \right\rfloor$$

The minimum cost is 1 (you can't have a fractional cost).

### Default Behavior (Reference BW = 100 Mbps = $10^8$ bps)

| Interface | Bandwidth | OSPF Cost |
| :--- | :-: | :-: |
| 56 Kbps dial-up | 56 Kbps | 1785 |
| 1.544 Mbps T1 | 1.544 Mbps | 64 |
| 10 Mbps Ethernet | 10 Mbps | 10 |
| 100 Mbps Fast Ethernet | 100 Mbps | **1** |
| 1 Gbps Gigabit Ethernet | 1 Gbps | **1** ← problem |
| 10 Gbps | 10 Gbps | **1** ← problem |
| 100 Gbps | 100 Gbps | **1** ← problem |

Notice: every interface ≥ 100 Mbps has the same cost. So OSPF will see a path through three 100 Mbps links as having cost 3, and a path through three 10 Gbps links as also having cost 3 — and may pick either one. That's wrong — the 10 Gbps path is 100× faster.

---

##  The Fix — Raise the Reference Bandwidth

```cisco
R1(config-router)# auto-cost reference-bandwidth 10000
```

This sets the reference bandwidth to 10 Gbps = $10^{10}$ bps. Resulting costs:

| Interface | Cost (with 10G ref) |
| :--- | :-: |
| 10 Mbps | 1000 |
| 100 Mbps | 100 |
| 1 Gbps | 10 |
| 10 Gbps | 1 |
| 100 Gbps | 1 (still tied!) |

Better — now 1 Gbps (cost 10) is preferred over 100 Mbps (cost 100). But 10 Gbps and 100 Gbps are still tied.

For modern datacenter networks with 25G/40G/100G links, set the reference to 100 Gbps or higher:
```cisco
R1(config-router)# auto-cost reference-bandwidth 100000
```

This gives 100 Gbps cost 1, 10 Gbps cost 10, 1 Gbps cost 100, etc.

> [!warning] Must be set consistently
> The reference bandwidth must be set to the **same value on every router in the OSPF domain**. If R1 uses 100 Mbps ref and R2 uses 10 Gbps ref, they'll compute different costs for the same link, leading to asymmetric routing and confusion.

---

##  Operational Recommendations

1. **Always set `auto-cost reference-bandwidth`** explicitly on every OSPF router. Don't rely on the default.
2. **Pick a value larger than your fastest link.** For modern networks, 100 Gbps is a safe default.
3. **Document the choice.** Put it in your OSPF design doc.
4. **Apply consistently** — use a config management tool (Ansible, Terraform) to ensure every router has the same setting.

---

##  Overriding Cost Manually

Sometimes you want to override the calculated cost — for example, to prefer a backup path that has lower priority:

```cisco
R1(config-if)# ip ospf cost 50
```

This sets the cost of the interface to 50 regardless of its bandwidth. Use sparingly — manual overrides don't auto-adjust when you upgrade link speeds.

Common use cases:
- Pin traffic to a specific path for traffic engineering.
- Make a high-bandwidth backup path less preferred than a primary low-bandwidth path.
- Equalize costs for ECMP across unequal-bandwidth links.

##  Cost Across Routing Protocols

For comparison:

| Protocol | Metric | Range | Notes |
| :--- | :--- | :-: | :--- |
| RIP | Hop count | 0–15 | Doesn't consider bandwidth |
| OSPF | Cost (ref BW / link BW) | 1–65535 | Considers bandwidth (with proper ref) |
| EIGRP | Composite (BW + delay) | 1–4,294,967,295 | Considers BW + delay + load + reliability |
| IS-IS | Cost (default 10/hop) | 1–1023 | Defaults to hop-count-like; can be tuned |
| BGP | Multi-attribute | N/A | Path attributes, not a single metric |

---

##  Memory Aid

> "OSPF Cost = Reference ÷ Real"
>
> Reference defaults to 100 Mbps. Real is interface bandwidth. Result is the cost.
>
> If Real ≥ Reference, cost = 1. If Real < Reference, cost = Reference ÷ Real (rounded down).
