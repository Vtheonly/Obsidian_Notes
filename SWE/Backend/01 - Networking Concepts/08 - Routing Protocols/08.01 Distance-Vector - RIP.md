# 08.01 — Distance-Vector & RIP

> [!abstract] Routing by Rumor
> **Distance-vector** protocols use the Bellman-Ford algorithm. Each router periodically sends its entire routing table to its neighbors. A router doesn't see the full network topology — it trusts what its neighbors tell it ("routing by rumor"). The canonical distance-vector protocol is **RIP** (Routing Information Protocol).

```mermaid
graph LR
    R1["Router 1"] <-->|"Periodic full table exchange"| R2["Router 2"]
    R2 <-->|"Periodic full table exchange"| R3["Router 3"]
```

---

##  Distance-Vector Mechanics

Each router maintains:
- A routing table with `(destination, metric, next-hop)`.
- A periodic timer (RIP: 30 seconds) to send the entire table to neighbors.

When a router receives a neighbor's table:
1. Increment each entry's metric by 1 (one more hop to reach the destination via this neighbor).
2. For each entry, decide whether to install/replace/discard based on the rules in [[08 - Routing Protocols/08.03 RIP Update Logic|08.03]].

The router never knows *why* a route has a given metric — it just trusts the number.

---

##  RIP — Routing Information Protocol

| Property | Value |
| :--- | :--- |
| Algorithm | Bellman-Ford (distance-vector) |
| Metric | Hop count |
| Max hop count | 15 (16 = unreachable / infinity) |
| Update interval | 30 seconds |
| Transport | UDP port 520 |
| AD (Cisco) | 120 |

### RIP Versions

| Version | Classful/Classless | Update destination | Mask in update? | Auth? | VLSM? |
| :-: | :--- | :--- | :-: | :-: | :-: |
| RIPv1 | Classful | Broadcast `255.255.255.255` | No | No | No |
| RIPv2 | Classless | Multicast `224.0.0.9` | Yes | Yes (MD5) | Yes |
| RIPng | Classless | Multicast `FF02::9` | Yes | IPsec | Yes (IPv6) |

### RIPv2 Configuration (Cisco)

```cisco
R1(config)# router rip
R1(config-router)# version 2
R1(config-router)# no auto-summary
R1(config-router)# network 192.168.1.0
R1(config-router)# network 10.0.0.0
R1(config-router)# passive-interface fastethernet 0/0
```

- `version 2` — required for VLSM and classless support.
- `no auto-summary` — prevents automatic classful summarization at network boundaries (which would break VLSM).
- `network X.X.X.X` — classful network spec; RIP runs on all interfaces whose IP is in that classful network. The mask is auto-derived.
- `passive-interface` — suppresses outgoing RIP updates on the interface (used on access ports where there are no other routers), but RIP still advertises the interface's subnet to other neighbors.

### Timers

| Timer | Default | Purpose |
| :--- | :-: | :--- |
| **Update** | 30s | Periodic full-table advertisement |
| **Invalid** | 180s | Mark route as unreachable (metric 16) if no updates received |
| **Hold-down** | 180s | After invalid, ignore worse-metric updates for this route |
| **Flush** | 240s | Permanently remove the route from the table |

##  RIP Packet Format

A RIPv2 packet (UDP payload, port 520):

| Field | Size | Purpose |
| :--- | :-: | :--- |
| Command | 1 byte | `1` = Request, `2` = Response |
| Version | 1 byte | `1` or `2` |
| Reserved | 2 bytes | Zero |
| **Route Entry** (1–25 per packet) | 20 bytes each | AFI + Route Tag + IP + Mask + Next Hop + Metric |

Each Route Entry:
- **Address Family Identifier (AFI):** `2` for IPv4.
- **Route Tag:** for external route tagging (e.g., routes imported from BGP).
- **IP Address:** the destination network.
- **Subnet Mask:** the network's mask (RIPv2 only; RIPv1 has this set to 0).
- **Next Hop:** explicit next-hop IP (often 0.0.0.0 = "use me as next hop").
- **Metric:** 1–15 (16 = unreachable).

A single RIP packet can carry up to 25 route entries. Larger tables use multiple packets.

---

##  Why RIP Is Mostly Obsolete

1. **Hop count is a poor metric.** A 2-hop path over 100 Mbps fiber loses to a 1-hop path over 1 Mbps dial-up in RIP. Real networks care about bandwidth, latency, and reliability.
2. **Slow convergence.** 30-second update intervals + 180-second invalid timer = up to 4 minutes before a failure is detected.
3. **Limited scale.** 15-hop max kills RIP for any network bigger than a small office.
4. **Broadcasts (RIPv1) waste bandwidth.** Even RIPv2's multicast adds overhead.

RIP survives in:
- Small lab networks.
- Some embedded / IoT routers with limited CPU.
- Teaching environments (it's a great first protocol to learn).

Modern networks use OSPF (link-state) or EIGRP (advanced distance-vector) for IGP and BGP for EGP.
