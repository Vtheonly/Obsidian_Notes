# 10.11 — TCP vs UDP Comparison

> [!abstract> When to Use Which
> TCP and UDP solve different problems. TCP is for **reliable, ordered delivery** (web pages, files, email). UDP is for **low-latency, best-effort delivery** (DNS, VoIP, gaming). Modern protocols like QUIC blur the line — they run on UDP but add TCP-like reliability in user space.

---

##  Side-by-Side

| Property | TCP | UDP |
| :--- | :--- | :--- |
| Connection | Connection-oriented (3-way handshake) | Connectionless |
| Reliability | Reliable (ACKs + retransmit) | Best-effort |
| Ordering | Ordered (sequence numbers) | Unordered |
| Header size | 20–60 bytes | 8 bytes |
| Flow control | Sliding window | None |
| Congestion control | Slow start, AIMD | None |
| State on sender/receiver | Yes (connection state) | No |
| Multicast/broadcast | No | Yes |
| Use cases | HTTP/1, HTTP/2, SSH, SMTP, FTP, IMAP | DNS, DHCP, VoIP, video, gaming, SNMP |
| Throughput | Slower (overhead) | Faster (no overhead) |
| Latency | Variable (retransmit delays) | Consistent |

---

##  When to Use TCP

Use TCP when:
1. **Data must arrive intact** — file transfers, web pages, email. A single dropped byte corrupts a file.
2. **Order matters** — a database replication stream, a configuration file. Out-of-order bytes break things.
3. **You don't want to implement reliability** — TCP does it for you. Reinventing ACK/retransmit in your app is harder than it looks.
4. **The application is request-response** — HTTP, SSH, IMAP. The 3-way handshake is amortized over a long session.

##  When to Use UDP

Use UDP when:
1. **Latency is critical** — VoIP, video conferencing, gaming. A retransmitted packet arriving 200ms late is worse than no packet.
2. **Loss is tolerable** — streaming media. The codec can interpolate missing frames.
3. **Small query-response** — DNS, NTP. The TCP handshake would be 3× the data exchange.
4. **Multicast/broadcast is needed** — UDP is the only transport that supports it.
5. **You're building a custom protocol on top** — QUIC, WebRTC, DTLS all run on UDP because they implement their own reliability/congestion control.

---

##  Modern Hybrids

The TCP/UDP dichotomy is blurring:

### QUIC (HTTP/3)
Runs on UDP but implements:
- TCP-like reliability (ACKs, retransmit)
- TLS encryption (built-in, not an afterthought)
- Multiplexed streams (no head-of-line blocking)
- 0-RTT connection resumption

Why UDP? Because middleboxes (NATs, firewalls) drop unknown L4 protocols. UDP is universally allowed, so QUIC builds a modern transport inside it.

### WebRTC
Real-time media over UDP. Uses SRTP (Secure RTP) for media, SCTP over DTLS for data channels.

### HTTP/3
Runs over QUIC, which runs over UDP. So HTTP/3 traffic in Wireshark looks like UDP packets to port 443.

---

##  Decision Heuristic

```
Need multicast/broadcast?           → UDP
Latency-critical?                   → UDP
Tiny query/response?                → UDP
Need guaranteed delivery?           → TCP
Need ordered bytes?                 → TCP
Reinventing reliability badly?      → TCP (just use it)
Building a new transport protocol?  → UDP (then build reliability on top, or use QUIC)
```

##  Concrete Examples

| Application | Transport | Why |
| :--- | :-: | :--- |
| Web browsing (HTTP/1, HTTP/2) | TCP | Reliable page delivery, ordered |
| Web browsing (HTTP/3) | UDP (via QUIC) | Multiplexing, 0-RTT, faster handshakes |
| DNS lookup | UDP | Tiny query/response; TCP handshake would be 3× the data |
| DNS zone transfer | TCP | Large transfers need reliability |
| Email (SMTP, IMAP, POP3) | TCP | Mail must arrive intact and ordered |
| File transfer (FTP, SFTP) | TCP | Files must be byte-perfect |
| VoIP (Skype, Zoom) | UDP | Latency trumps reliability |
| Online gaming | UDP | Same — late packets are useless |
| DHCP | UDP | Needs broadcast; client doesn't have an IP yet |
| SNMP monitoring | UDP | Small queries, occasional drops OK |
| Streaming video (Netflix, YouTube) | TCP (mostly) | Modern adaptive streaming uses TCP because reliability > latency; the player buffers |
| Live streaming (Twitch) | TCP or UDP | Latency-sensitive; some use UDP-based protocols |
