# 07.04 — Static Routing

> [!abstract] Manual Configuration
> **Static routes** are manually-configured forwarding paths. They don't adapt to network changes — if a link fails, traffic stops until an administrator intervenes. But they're free, simple, secure, and consume no bandwidth. Use them for small networks, default routes, and as backups (floating static routes).

---

##  Command Syntax

```cisco
Router(config)# ip route [destination_network] [subnet_mask] [next_hop_ip | exit_interface] [administrative_distance]
```

Three flavors depending on what you specify as the "where to send":

### 1. Next-Hop Static Route

```cisco
R1(config)# ip route 192.168.2.0 255.255.255.0 10.10.10.2
```

The router forwards packets for `192.168.2.0/24` to next-hop `10.10.10.2`. The router must then ARP-resolve `10.10.10.2` (recursive lookup if `10.10.10.2` isn't on a directly-connected subnet).

### 2. Directly Attached Static Route (Exit Interface)

```cisco
R1(config)# ip route 192.168.2.0 255.255.255.0 serial 0/0/0
```

The router forwards packets out `Serial0/0/0` directly. No next-hop IP needed. The router treats the destination as if it were directly connected on that interface — it ARP-resolves the destination IP itself (for multi-access media like Ethernet) or just encapsulates and sends (for point-to-point like Serial).

> [!warning] Don't use exit interface on multi-access networks
> Specifying `ip route 192.168.2.0 255.255.255.0 FastEthernet0/0` works, but it forces the router to ARP-resolve every destination IP in that subnet (proxy ARP hack). This pollutes the ARP cache and breaks if the next-hop router doesn't run proxy ARP. **Always specify next-hop IP for Ethernet.** Exit-interface is fine for point-to-point (Serial, GRE tunnels).

### 3. Fully Specified Static Route (Both)

```cisco
R1(config)# ip route 192.168.2.0 255.255.255.0 FastEthernet0/0 10.10.10.2
```

Specifies both the exit interface AND the next-hop IP. The router knows exactly where to send without recursive lookup. Most efficient for high-throughput scenarios.

### 4. Default Static Route

```cisco
R1(config)# ip route 0.0.0.0 0.0.0.0 209.165.202.129
```

Matches all destinations (LPM picks it only as a last resort). Used for stub networks with a single path to the internet.

---

##  Removing Static Routes

Prefix the command with `no`:

```cisco
R1(config)# no ip route 192.168.2.0 255.255.255.0 10.10.10.2
```

Or just `no ip route 192.168.2.0 255.255.255.0` — anything that matches uniquely enough.

---

##  Floating Static Routes

A floating static route is a static route with a high AD, used as a backup when the primary (dynamic) route fails:

```cisco
! Primary: OSPF route to 192.168.2.0/24 (AD 110)
! Backup: static route with AD 250 (only used if OSPF route disappears)
R1(config)# ip route 192.168.2.0 255.255.255.0 10.10.20.2 250
```

When OSPF has the route, the static (AD 250) is ignored — OSPF has lower AD (110). When OSPF loses the route, the static kicks in.

Use case: a primary WAN link with OSPF and a backup dial-up/4G link. The backup is only used when the primary is down.

---

##  Verifying Static Routes

```cisco
R1# show ip route static
      192.168.2.0/24 is directly connected, Serial0/0/0
S    192.168.3.0/24 [1/0] via 10.10.10.2
S*   0.0.0.0/0 [1/0] via 209.165.202.129
```

- `S` = static
- `S*` = candidate default
- `[1/0]` = AD 1 / metric 0 (static routes have no metric by definition)

##  Static vs Other Route Sources

| Property | Static | Connected | OSPF | RIP |
| :--- | :--- | :--- | :--- | :--- |
| Source | Manual | Automatic (interface up) | Dynamic | Dynamic |
| AD | 1 | 0 | 110 | 120 |
| Adapts to failures | No | Yes (interface down) | Yes | Yes |
| Bandwidth cost | None | None | Some (hellos + LSAs) | Some (periodic updates) |
| CPU cost | None | None | Moderate (SPF calc) | Low |
| Scales to | Small networks | Any | Any | Small (≤15 hops) |

See [[07 - IP Routing/07.07 Static vs Dynamic Routing|07.07 Static vs Dynamic]] for the full comparison.

##  Operational Tips

1. **Document every static route.** Use comments (`!` lines in your config) or a separate spreadsheet. Undocumented static routes are the #1 source of "ghost" routing problems.
2. **Prefer next-hop IP over exit interface** for Ethernet. Avoids proxy-ARP surprises.
3. **Use floating statics for backup paths** rather than a second dynamic protocol — simpler and clearer.
4. **Avoid more than ~20 static routes in a single router.** If you need more, you probably need a dynamic protocol.
5. **Always configure a default route last.** Set up specific routes first; only add `0.0.0.0/0` once you've decided what should *not* match the default.
