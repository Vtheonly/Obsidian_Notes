# 12.02 — Ngrok

> [!abstract> Instant Public URL for Localhost
> **Ngrok** is a developer tool that creates a public URL tunneled to a port on your local machine. It's the fastest way to share a local dev server with a remote colleague, test a webhook from a third-party service, or demo a project without deploying it. One command, one URL, done.

```bash
$ ngrok http 8080
Session Status                online
Account                       Alice (Plan: Free)
Version                       3.0.0
Region                        United States (us)
Latency                       45ms
Web Interface                 http://127.0.0.1:4040
Forwarding                    http://abc123.ngrok.app -> http://localhost:8080
Forwarding                    https://abc123.ngrok.app -> http://localhost:8080

Connections                   TTL     Method     Path
1c1c0d0a0e0f                  2023-06-01 14:32:11 UTC   GET  /
```

Anyone can now visit `https://abc123.ngrok.app` and reach your local server on port 8080.

---

##  Installation and Setup

### Install
```bash
# macOS
brew install ngrok/ngrok/ngrok

# Linux (snap)
snap install ngrok

# Or download the binary from https://ngrok.com/download
```

### Authenticate
Sign up at ngrok.com, get your auth token, then:
```bash
ngrok config add-authtoken YOUR_TOKEN
```

This stores the token in `~/.config/ngrok/ngrok.yml` and unlocks features reserved for authenticated users (custom subdomains, more simultaneous tunnels, etc.).

##  Common Commands

### HTTP tunnel (auto HTTPS)
```bash
ngrok http 8080
# Provides both http:// and https:// URLs
```

### HTTP tunnel to a specific host:port
```bash
ngrok http localhost:3000
ngrok http 192.168.1.50:80        # another host on your LAN
```

### TCP tunnel (for non-HTTP protocols)
```bash
ngrok tcp 22                      # SSH
ngrok tcp 3306                    # MySQL
ngrok tcp 5432                    # PostgreSQL
```

### Custom subdomain (paid feature)
```bash
ngrok http --subdomain=myapp 8080
# → https://myapp.ngrok.app
```

### Custom domain (paid feature)
```bash
ngrok http --domain=dev.example.com 8080
```

### Inspect traffic
Open `http://127.0.0.1:4040` in your browser while ngrok is running. You'll see every request and response, with the ability to replay requests.

##  Use Cases

1. **Webhook testing** — point Stripe, GitHub, or Slack webhooks at your ngrok URL. They hit your local dev server instantly; you can debug live.
2. **Demoing local work** — share the URL with a colleague or recruiter; no deployment needed.
3. **Mobile app development** — your mobile app can hit a local backend during dev.
4. **Browser testing on real devices** — BrowserStack, Sauce Labs, or a physical phone can load your local site.
5. **OAuth callback testing** — many OAuth providers require HTTPS callbacks; ngrok provides one for free.
6. **Quick file sharing** — `ngrok http 8000` while running `python -m http.server 8000` in a directory.

---

##  Security Considerations

Ngrok tunnels are **publicly accessible by default**. Anyone with the URL can reach your local service. Mitigations:

### HTTP Basic Auth
```bash
ngrok http --basic-auth="user:password" 8080
```

### OAuth (paid)
```bash
ngrok http --oauth=google 8080      # require Google login
ngrok http --oauth=github 8080      # require GitHub login
```

### Restrict by IP
```bash
ngrok http --cidr-allow=203.0.113.0/24 8080
```

### Use a random subdomain (default behavior)
The default `abc123.ngrok.app` URL is unguessable. Don't share it publicly; share it only with the intended viewer.

### Be careful with sensitive data
Ngrok's free tier logs all traffic through their relay. Don't tunnel production credentials, real customer data, or proprietary source code through a free Ngrok tunnel.

##  How It Works Under the Hood

1. You run `ngrok http 8080`.
2. Ngrok client opens a persistent outbound TLS connection to Ngrok's relay servers (`*.ngrok.app`).
3. Ngrok assigns your tunnel a public URL like `abc123.ngrok.app`.
4. When a visitor hits that URL, Ngrok's relay forwards the request through the persistent outbound tunnel to your client.
5. Your client forwards the request to `localhost:8080`.
6. The response goes back the same way.

The clever part: the connection from your machine to the relay is **outbound**, so it punches through NAT and firewalls without configuration. No port forwarding needed on your router.
