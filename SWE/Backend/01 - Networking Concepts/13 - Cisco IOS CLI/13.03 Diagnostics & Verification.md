# 13.03 — Diagnostics & Verification

> [!abstract> The `show` Commands
> Cisco IOS has hundreds of `show` commands. These are the ones you'll use 95% of the time. Run them from **Privileged EXEC** mode (`Router#`).

---

##  General Device Status

### `show version`
Device hardware, IOS version, uptime, interfaces, configuration register.

```cisco
R1# show version
Cisco IOS Software, ...
Technical Support: http://www.cisco.com/techsupport
...
Router uptime is 1 day, 3 hours, 27 minutes
System returned to ROM by power-on
System image file is "flash:c2900-universalk9-mz.SPA.151-4.M4.bin"
...
4 FastEthernet interfaces
2 Serial interfaces
...
Configuration register is 0x2102
```

Key things to check:
- IOS version and image filename.
- Uptime.
- Number and type of interfaces.
- Configuration register (`0x2102` = normal boot; `0x2142` = skip loading startup-config, used for password recovery).

### `show clock`
Current system time.

### `show running-config`
The current active configuration in RAM.

```cisco
R1# show running-config
Building configuration...

Current configuration : 1247 bytes
!
version 15.1
!
hostname R1
!
...
```

### `show startup-config`
The saved configuration in NVRAM.

### `show history`
Recent commands entered.

##  Interface Status

### `show ip interface brief`
The most-used interface command — shows all interfaces with their IP, status, and protocol in a compact table.

```cisco
R1# show ip interface brief
Interface              IP-Address      OK? Method Status                Protocol
FastEthernet0/0        192.168.1.254   YES manual up                    up
FastEthernet0/1        unassigned      YES unset  administratively down down
Serial0/0/0            10.0.0.1        YES manual up                    up
Serial0/0/1            unassigned      YES unset  administratively down down
```

- **Status** = L1 state (up / down / administratively down).
- **Protocol** = L2 state (up / down).
- Both up → interface is fully operational.
- Status down, protocol down → cable unplugged or remote end down.
- Status "administratively down" → `shutdown` configured.
- Status up, protocol down → L1 OK but L2 issue (e.g., encapsulation mismatch, no clock rate on serial).

### `show interfaces fa0/0`
Detailed info on one interface: bandwidth, delay, MTU, encapsulation, MAC, errors, drops.

### `show interfaces description`
Quick view of interface descriptions (useful on devices with many interfaces).

### `show interface fa0/0 status` (switches)
Status, duplex, speed, VLAN in one line:
```
Port      Name               Status       Vlan       Duplex  Speed Type
Fa0/1     Server port        connected    10         a-full  a-100  10/100BaseTX
```

##  Routing Tables

### `show ip route`
Full routing table — covered in detail in [[07 - IP Routing/07.01 Routing Table Structure|07.01]].

### `show ip route <prefix>`
Which route matches a specific destination:
```cisco
R1# show ip route 192.168.1.57
Routing entry for 192.168.1.48/28
  Known via "static", distance 1, metric 0
  Routing Descriptor Blocks:
  * 10.0.0.2
    Route metric is 0, traffic share count is 1
```

### `show ip route summary`
Counts of routes by source — useful for spotting if a protocol is over-advertising:
```
Route Source    Networks    Subnets     Replicas  Overhead    Memory (bytes)
connected       0           4           0         288         592
static          1           2           0         216         444
ospf 1          3           8           0         864         1776
Intra-area: 3 Inter-area: 5 External-1: 1 External-2: 2
internal        2                                       2268
Total           6           14          0         1368        5080
```

### `show ip protocols`
Active routing protocols, their timers, networks, and ADs.

##  ARP & MAC Tables

### `show arp` (routers and L3 switches)
ARP cache:
```cisco
R1# show arp
Protocol  Address          Age (min)  Hardware Addr   Type   Interface
Internet  192.168.1.1            -    0011.2233.4455  ARPA   FastEthernet0/0
Internet  192.168.1.10           2    0050.56ab.cdef  ARPA   FastEthernet0/0
Internet  192.168.1.20          17    001a.2b3c.4d5e  ARPA   FastEthernet0/0
```

### `show mac-address-table` (switches)
CAM table — MACs learned on each port:
```cisco
Switch# show mac-address-table
          Mac Address Table
-------------------------------------------

Vlan    Mac Address       Type        Ports
----    -----------       --------    -----
   1    0011.2233.4455    DYNAMIC     Fa0/1
   1    0050.56ab.cdef    DYNAMIC     Fa0/2
   1    001a.2b3c.4d5e    DYNAMIC     Fa0/5
  10    0090.27ab.cdef    DYNAMIC     Fa0/10
Total Mac Addresses for this criterion: 4
```

`DYNAMIC` = learned from traffic; `STATIC` = manually configured.

### `show mac-address-table interface fa0/1`
Filter by interface.

### `show mac-address-table address 0011.2233.4455`
Find which port a specific MAC is on.

##  OSPF & RIP Diagnostics

### `show ip ospf neighbor`
OSPF adjacencies:
```cisco
R1# show ip ospf neighbor

Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           1   FULL/BDR        00:00:36    10.0.0.2        Serial0/0/0
3.3.3.3           1   FULL/DR         00:00:35    10.0.0.3        FastEthernet0/0
```

`FULL` = fully adjacent. `DR`/`BDR` = designated router / backup. `INIT`, `EXSTART`, `EXCHANGE`, `LOADING` = intermediate states (indicate a problem if persistent).

### `show ip ospf interface fa0/0`
OSPF config on a specific interface: cost, area, hello/dead timers, DR/BDR.

### `show ip ospf database`
The Link-State Database. Identical on all routers in the same area.

### `show ip rip database`
RIP's view of the network.

##  Connectivity Testing

### `ping`
```cisco
R1# ping 192.168.1.10
Type escape sequence to abort.
Sending 5, 100-byte ICMP Echos to 192.168.1.10, timeout is 2 seconds:
!!!!!
Success rate is 100 percent (5/5), round-trip min/avg/max = 1/2/4 ms
```

Extended ping (more options):
```cisco
R1# ping
Protocol [ip]: 
Target IP address: 192.168.1.10
Repeat count [5]: 100
Datagram size [100]: 1400
Timeout in seconds [2]: 
Extended commands [n]: y
Source address or interface: 10.0.0.1
...
```

The extended ping lets you source from a specific interface — invaluable for testing reachability from a different subnet.

### `traceroute`
```cisco
R1# traceroute 8.8.8.8
Type escape sequence to abort.
Tracing the route to 8.8.8.8
  1 10.0.0.2 4 msec 1 msec 1 msec
  2 203.0.113.1 12 msec 8 msec 9 msec
  3 72.14.196.57 22 msec 18 msec 19 msec
  ...
```

### `telnet <ip> <port>` (TCP port test)
Not actually Telnet — just opens a TCP connection to test if a port is reachable:
```cisco
R1# telnet 192.168.1.20 80
Trying 192.168.1.20, 80 ... Open
```

##  Debug Commands

`debug` commands are powerful but generate lots of output and can crash a production router if you're not careful. Always `undebug all` when done.

```cisco
R1# debug ip icmp              # show ICMP packets
R1# debug ip rip               # show RIP updates
R1# debug ip ospf hello        # show OSPF hello packets
R1# debug arp                  # show ARP transactions
R1# terminal monitor           # send debug output to current terminal (if logged in via SSH/Telnet)
R1# undebug all                # turn off all debugs (CRITICAL)
```

> [!warning] Debug with care
> `debug ip packet detail` on a production router can generate megabytes of output per second and peg the CPU. Always filter with an ACL:
> ```cisco
> R1(config)# access-list 100 permit icmp host 192.168.1.10 host 192.168.1.20
> R1# debug ip packet detail 100
> ```
