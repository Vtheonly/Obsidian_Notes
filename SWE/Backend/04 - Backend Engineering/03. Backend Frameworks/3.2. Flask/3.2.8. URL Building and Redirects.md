# 3.2.8. URL Building and Redirects

> [!info] Orientation
> Building URLs by hand is brittle. Flask's `url_for()` reverses route definitions to generate URLs, and `redirect()` sends the client to them. This note covers `url_for`, `redirect`, `abort`, custom error pages, the difference between 301/302/307/308, and the POST-REDIRECT-GET pattern that prevents the dreaded "confirm form resubmission" dialog.

## 1. Why Reverse URL Building Matters

Hardcoding URLs in templates and view code works until you rename a route. Then every hardcoded URL breaks silently — `url_for` raises a `BuildError` at request time, but a hardcoded string just produces a 404 the user has to discover. Reverse URL building means you refer to routes by their **endpoint name** (the view function's name) and let Flask generate the URL from the current route table. Rename a route and every `url_for` call updates automatically.

```python
from flask import url_for

@app.route("/user/<username>")
def profile(username):
    return f"Hi {username}"

@app.route("/dashboard")
def dashboard():
    return redirect(url_for("profile", username=current_user.username))
```

`url_for("profile", username="alice")` returns `/user/alice`. The keyword arguments after the endpoint name fill in the URL converters; any extra arguments become query string parameters. `url_for("profile", username="alice", tab="posts")` returns `/user/alice?tab=posts`. To generate an absolute URL (with scheme and host), pass `_external=True`.

## 2. url_for in Detail

`url_for` resolves an endpoint name to a URL by consulting the Flask URL map. It works inside and outside a request context — outside a request, you must wrap the call in `app.test_request_context()` so Flask knows what host to use for `_external=True`.

```python
with app.test_request_context("/"):
    url_for("profile", username="alice")                    # "/user/alice"
    url_for("profile", username="alice", _external=True)    # "http://localhost/user/alice"
    url_for("static", filename="css/main.css")              # "/static/css/main.css"
```

Three `_`-prefixed arguments control special behavior. `_external=True` generates an absolute URL. `_scheme="https"` forces a scheme (requires `_external=True`). `_anchor="section1"` appends `#section1` to the URL. For blueprint endpoints, prefix the endpoint with the blueprint name: `url_for("auth.login")` returns the URL for the `login` view in the `auth` blueprint.

## 3. redirect()

`redirect(location, code=302)` returns a `Response` with the given status code and a `Location` header pointing to `location`. The location can be a string URL, a `Response` object, or anything `url_for` returns.

```python
from flask import redirect, url_for

@app.route("/old-home")
def old_home():
    return redirect(url_for("index"))

@app.route("/login")
def login():
    if not current_user.is_authenticated:
        return redirect(url_for("auth.login"))
    return "Welcome back"
```

The default redirect code is `302 Found`, which is correct for almost all temporary redirects. Permanent redirects (301) and the new `307`/`308` codes have specific semantics covered below.

## 4. The Redirect Status Codes

Four redirect status codes are in common use, and the differences matter for forms and SEO.

| Code | Name | Method preserved? | Typical use |
| ---- | ---- | ----------------- | ----------- |
| 301 | Moved Permanently | No (often becomes GET) | Permanent URL change, SEO migration |
| 302 | Found | No (often becomes GET) | Temporary redirect, default for `redirect()` |
| 307 | Temporary Redirect | Yes (method kept) | Temporary redirect that must preserve method |
| 308 | Permanent Redirect | Yes (method kept) | Permanent redirect that must preserve method |

The "method preserved?" column is the subtle one. By historical accident, browsers convert a `POST` that receives a `301` or `302` into a `GET` to the new URL — dropping the original body. This is what makes the POST-REDIRECT-GET pattern work, but it is also what surprises you when you expected the redirect to preserve a POST. `307` and `308` were introduced to give a strict "preserve the method" semantics. Use 307/308 when you genuinely want a redirected POST to remain a POST; use 302 (the default) for the PRG pattern.

## 5. abort()

`abort(status_code, description=None)` raises an `HTTPException` that Flask converts into the corresponding error response. It is the right way to short-circuit a view when a precondition fails.

```python
from flask import abort

@app.route("/post/<int:post_id>")
def show_post(post_id):
    post = Post.query.get(post_id)
    if post is None:
        abort(404)
    if not post.is_published and post.author != current_user:
        abort(403)
    return render_template("post.html", post=post)
```

`abort(404)` raises `werkzeug.exceptions.NotFound`, which Flask's error handling machinery catches and turns into a 404 response. Custom messages are supported: `abort(404, description="No such post")`. Inside an API view, you can also raise the exception classes directly: `raise NotFound` or `raise BadRequest("invalid email")`.

## 6. Custom Error Pages

`@app.errorhandler(code)` registers a function that handles errors of that code (or that exception class). The handler can return HTML for browser requests or JSON for API requests, depending on the `Accept` header.

```python
from flask import render_template, jsonify, request

@app.errorhandler(404)
def not_found(error):
    if request.path.startswith("/api/"):
        return jsonify(error="Not found", path=request.path), 404
    return render_template("errors/404.html"), 404

@app.errorhandler(403)
def forbidden(error):
    return render_template("errors/403.html"), 403

@app.errorhandler(500)
def server_error(error):
    app.logger.exception("Unhandled server error")
    return render_template("errors/500.html"), 500
```

The `500` handler logs the exception with `app.logger.exception`, which captures the full traceback, and returns a generic page. It deliberately does not show the user the traceback — that is debug mode's job, and debug mode must never be in production. For blueprint-scoped errors, use `@bp.errorhandler` to handle only errors raised inside that blueprint.

## 7. The POST-REDIRECT-GET Pattern

When a user submits a POST form (say, creating a new blog post) and the server responds with the rendered post page, the user can hit refresh — and the browser will re-submit the POST. The result is a duplicate post, or worse, a "Confirm Form Resubmission" dialog that confuses users.

The fix is the POST-REDIRECT-GET pattern. The POST handler does its work, then responds with a `302` redirect to a GET endpoint that shows the result. The browser follows the redirect with a GET, the URL bar now shows the result URL, and refreshing only re-runs the GET.

```python
@app.route("/post/new", methods=["GET", "POST"])
def new_post():
    form = PostForm()
    if form.validate_on_submit():
        post = Post(title=form.title.data, body=form.body.data)
        db.session.add(post)
        db.session.commit()
        # PRG: redirect to GET view of the new post
        return redirect(url_for("show_post", post_id=post.id))
    return render_template("new_post.html", form=form)
```

The browser's address bar ends up at `/post/42`, not `/post/new`. Hitting refresh re-runs `GET /post/42`, which is idempotent and safe. The same pattern applies to login (redirect to a dashboard after successful POST), cart updates, and any other state-changing action.

## 8. Common Patterns

**Trailing-slash redirects.** As covered in [[3.2.3. Routes and Views]], Flask automatically 308-redirects `/projects` to `/projects/` when the rule is registered with a trailing slash. This is correct behavior and should not be fought.

**Canonical URLs.** For SEO, pick one URL form (`/blog/post/42` vs `/posts/42`) and redirect the other to it with `301`. The handler is a single line of `redirect(url_for("..."), code=301)`.

**After-login redirect.** Store the intended destination in the session before redirecting to login, then on successful login redirect back to it:

```python
@app.route("/secret")
def secret():
    if not current_user.is_authenticated:
        session["next_url"] = url_for("secret")
        return redirect(url_for("auth.login"))
    return "Top secret"

# In auth.login after successful authentication:
next_url = session.pop("next_url", url_for("index"))
return redirect(next_url)
```

Always validate `next_url` is a relative URL before redirecting to it; an open redirect (where an attacker can craft `?next=https://evil.com`) is a real vulnerability used in phishing.

## Summary

`url_for(endpoint, **kwargs)` is the only correct way to build internal URLs. `redirect(location, code=302)` returns a redirect response; pick 302 for PRG, 307/308 when method preservation matters, and 301 only for permanent URL migrations. `abort(code)` short-circuits a view with an HTTP error, and `@app.errorhandler(code)` customizes the response. The POST-REDIRECT-GET pattern is the standard solution to the form-resubmission problem and should be the default for every state-changing POST. The next note, [[3.2.9. Flask with SQLite and SQLAlchemy]], moves from HTTP plumbing to persistence.
