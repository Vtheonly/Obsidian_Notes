# 3.2.1. Introduction to Flask

> [!info] Orientation
> Flask is the lightweight Python web framework that powers everything from quick prototypes to large production APIs. This note covers what Flask actually is, how it compares to Django and FastAPI, what its "micro" label really means, and how to write your first running application.

## 1. What Flask Is

Flask is a Python web framework originally created by Armin Ronacher in 2010 and currently maintained by the Pallets organization. It is classified as a **micro-framework** because it ships only the bare essentials needed to build a web application: request and response objects, a routing system, a templating engine, a development server, and a small set of conventions. Anything beyond that — database access, form validation, authentication, admin interfaces — is added by you through extensions. The word "micro" therefore refers to scope and philosophy, not to the size of apps you can build. Production Flask apps routinely serve millions of requests per day, especially when wrapped behind a real WSGI server like Gunicorn.

Flask is built on top of two other Pallets libraries: Werkzeug and Jinja2. Werkzeug provides the WSGI application interface, the request and response wrappers, the routing matcher, and the development server. Jinja2 supplies the templating engine that renders dynamic HTML. Two more dependencies — Click (CLI toolkit) and ItsDangerous (signed serialization) — give Flask its `flask` command and signed-cookie sessions. MarkupSafe handles HTML escaping for Jinja2. These five libraries are the entire dependency tree of a minimal Flask install, which is one reason Flask projects start so quickly and stay so easy to reason about.

## 2. The WSGI Philosophy

Flask speaks WSGI (Web Server Gateway Interface), the Python standard (PEP 3333) that defines a synchronous interface between a web server and a Python application. A WSGI application is any callable that takes an environment dict and a start_response callback, and returns an iterable of byte strings. Flask wraps that low-level contract behind a friendly API: you write view functions that return strings or `Response` objects, and Flask handles the WSGI plumbing for you. Because WSGI is synchronous by design, Flask itself is synchronous. Concurrency comes from the WSGI server in front of it — Gunicorn with workers, uWSGI, or a managed platform like Render.

This synchronous model has trade-offs. It is simple to reason about, works perfectly for the typical request-response cycle, and integrates trivially with the synchronous database drivers that most projects already use. It is not ideal for long-lived connections (WebSockets, Server-Sent Events) or for IO-heavy workloads where you would rather hold thousands of idle connections than spawn thousands of threads. Those workloads are better served by ASGI frameworks like FastAPI or Quart (an async reimplementation of Flask's API). Many teams use Flask for the bulk of an API and reach for an ASGI service only where they actually need async.

## 3. Flask vs Django vs FastAPI

The three dominant Python web frameworks differ mostly in what they pre-decide for you.

| Dimension | Flask | Django | FastAPI |
| --------- | ----- | ------ | ------- |
| Philosophy | Minimal core, plug what you need | Batteries-included | Async-first, type-driven |
| ORM | None (use SQLAlchemy) | Built-in Django ORM | None (use SQLAlchemy) |
| Templating | Jinja2 | Django Templates | None (API only by default) |
| Auth | None (use Flask-Login) | Built-in `auth` app | None |
| Admin | None (use Flask-Admin) | Built-in admin | None |
| Async | No (synchronous WSGI) | Partial since 3.1 | Yes (ASGI native) |
| Schema validation | None (use Pydantic via extensions) | Forms / serializers | Built-in via Pydantic |
| Best for | APIs, dashboards, prototypes | Full-stack apps with admin | High-throughput JSON APIs |

Django is the right pick when you want everything decided for you and your project fits Django's model of "apps" with a built-in admin and ORM. FastAPI is the right pick when your workload is dominated by JSON APIs, you benefit from async IO, and you want automatic OpenAPI documentation. Flask sits in between: you assemble the stack you want, pay only for what you use, and avoid fighting opinionated defaults.

## 4. When to Choose Flask

Choose Flask when you want fine-grained control over your architecture, when the project is an API or microservice rather than a full-stack monolith, when you already know SQLAlchemy and Jinja2 and want to reuse that knowledge, or when you are building an internal tool where startup speed matters more than long-term scaling. Flask is also an excellent teaching framework: because nothing is hidden, you learn how HTTP, cookies, sessions, and templates actually work rather than memorizing a framework's magic.

Avoid Flask when you need WebSockets or long-polling as a core feature (use FastAPI or Quart), when your team already knows Django and wants the admin and ORM batteries, or when you genuinely need the asynchronous ecosystem (asyncpg, aiohttp, aioredis) end-to-end. Flask can be made async-friendly with `flask[async]` and `async def` views, but it is still WSGI under the hood.

## 5. Installation

Flask is a single pip install. Always install into a virtual environment so the project's dependencies stay isolated from the system Python.

```bash
python3 -m venv venv
source venv/bin/activate
pip install Flask
```

To verify the install and see the versions of Flask and its dependencies:

```bash
python -m flask --version
```

```text
Python 3.12.4
Flask 3.0.3
Werkzeug 3.0.3
```

## 6. Hello World

The canonical Flask application fits in five lines:

```python
# app.py
from flask import Flask

app = Flask(__name__)

@app.route("/")
def hello():
    return "Hello, Flask!"

if __name__ == "__main__":
    app.run(debug=True)
```

Run it with `python app.py` and open `http://127.0.0.1:5000/` in a browser. The `Flask(__name__)` call creates the application instance; `__name__` tells Flask where to find the `templates/` and `static/` folders relative to the module that defines the app. The `@app.route("/")` decorator registers the URL pattern `/` with the view function `hello`. The view returns a plain string, which Flask wraps in a `200 OK` response with `Content-Type: text/html`. The `if __name__ == "__main__"` guard ensures the dev server only starts when the file is executed directly, not when it is imported.

## 7. Key Dependencies

Flask's small dependency tree is one of its quiet advantages. Werkzeug supplies routing, request/response objects, the dev server, the interactive debugger, and several utilities (security helpers, HTTP status codes, file handling). Jinja2 supplies templating with autoescaping, inheritance, filters, and macros. Click powers the `flask` CLI command group, including custom commands you register with `@app.cli.command()`. ItsDangerous provides the signed-cookie serializer that backs Flask's `session` object. MarkupSafe provides the HTML escaper used by Jinja2's autoescaping. Knowing these layers matters because you will occasionally need to read Werkzeug or Jinja2 documentation to debug a Flask problem.

## Summary

Flask is a small, synchronous, WSGI-based Python web framework that ships only the essentials and lets you assemble the rest. Its core dependencies are Werkzeug, Jinja2, Click, ItsDangerous, and MarkupSafe. Flask is the right default for APIs, prototypes, internal tools, and projects where architectural control matters more than built-in batteries. The next note, [[3.2.2. Project Structure]], takes the five-line Hello World and shows how to organize it into a maintainable application.
