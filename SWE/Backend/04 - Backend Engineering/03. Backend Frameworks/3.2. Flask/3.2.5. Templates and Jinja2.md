# 3.2.5. Templates and Jinja2

> [!info] Orientation
> Templates are how Flask produces dynamic HTML. This note covers Jinja2 syntax (`{{ }}`, `{% %}`, `{# #}`), `render_template()` and the `templates/` folder, the template inheritance pattern that keeps layouts DRY, the filter pipeline, context injection via context processors, macros for reusable snippets, `url_for('static', ...)` for asset URLs, and the autoescaping mechanism that protects you from XSS.

## 1. Why Templates Exist

Returning HTML strings from view functions works for three-line demos and nothing else. As soon as your HTML needs to include dynamic data — a username, a list of posts, a calculated total — embedding it inside Python string concatenation becomes unreadable and unsafe. A templating engine separates presentation (HTML structure) from logic (Python code). The template is a text file with placeholders and control structures; the engine takes the template plus a context dict and produces the final HTML string. Flask ships with Jinja2 as its default engine and there is no reason to swap it.

Jinja2 was designed to feel like Python. Its expression syntax (`{{ ... }}`) and statement syntax (`{% ... %}`) are intentionally familiar, and its control flow (`if`, `for`, `block`, `extends`, `macro`, `include`) mirrors Python's. The result is a templating language that is easy to read for Python developers while remaining a true DSL — not embedded Python — so designers can edit templates without learning the host language.

## 2. render_template and the templates Folder

Flask looks for templates in a directory named `templates` next to the application module (or package). The `render_template(filename, **context)` function loads the file, renders it with the supplied context, and returns a string that the view can return directly.

```python
# routes.py
from flask import render_template
from app import app

@app.route("/")
def index():
    return render_template("index.html", page_title="Home", user_count=42)
```

```html
<!-- templates/index.html -->
<!DOCTYPE html>
<html>
<head><title>{{ page_title }}</title></head>
<body>
  <p>There are {{ user_count }} users.</p>
</body>
</html>
```

Variables passed as keyword arguments to `render_template` are available inside the template as top-level names. Jinja2 resolves attribute access with `obj.attr` and item access with `obj["key"]` interchangeably — it tries `getattr`, then `__getitem__`, then falls back to undefined. This is why both `user.name` and `user["name"]` work for dicts and objects.

## 3. Jinja2 Syntax

Jinja2 has three delimiter styles.

| Delimiter | Purpose | Example |
| --------- | ------- | ------- |
| `{{ ... }}` | Expression — output the result | `{{ user.name }}` |
| `{% ... %}` | Statement — control flow | `{% if x %}...{% endif %}` |
| `{# ... #}` | Comment — stripped from output | `{# debug note #}` |

Conditionals and loops mirror Python closely:

```jinja2
{% if user.is_admin %}
  <p>Welcome, admin.</p>
{% elif user.is_moderator %}
  <p>Welcome, moderator.</p>
{% else %}
  <p>Welcome, user.</p>
{% endif %}

<ul>
{% for post in posts %}
  <li>{{ loop.index }}. {{ post.title }}</li>
{% else %}
  <li>No posts yet.</li>
{% endfor %}
</ul>
```

The `loop` variable inside a `for` exposes `loop.index` (1-based), `loop.index0` (0-based), `loop.first`, `loop.last`, `loop.length`, and `loop.revindex`. The `{% else %}` clause inside a `for` runs when the iterable is empty — a feature borrowed from Python's `for/else` but easier to read in templates.

## 4. Filters

Filters transform a value before output. They are applied with the pipe `|`, can be chained, and can take arguments.

```jinja2
{{ user.name | upper }}
{{ user.bio | default("No bio provided") }}
{{ posts | length }}
{{ tags | join(", ") }}
{{ long_text | truncate(100, true) }}
```

| Filter | Effect |
| ------ | ------ |
| `upper` / `lower` / `capitalize` / `title` | Case transforms |
| `trim` | Strip leading and trailing whitespace |
| `default("fallback")` | Use fallback if value is undefined |
| `length` / `count` | Length of a sequence or mapping |
| `join(", ")` | Concatenate a sequence |
| `truncate(n, True)` | Truncate to `n` chars with ellipsis |
| `safe` | Mark a string as safe — disables autoescaping |
| `tojson` | Serialize to JSON (also marks safe) |

The `safe` filter is the explicit way to opt out of autoescaping for a specific value. Use it only on content you generated yourself and trust — never on raw user input. The `tojson` filter is the correct way to embed JSON in a `<script>` tag for passing server data to client-side JavaScript.

## 5. Template Inheritance

Inheritance is the single most powerful Jinja2 feature. You write a base template containing the page skeleton (`<html>`, `<head>`, navigation, footer) with named `{% block %}` placeholders. Child templates `{% extends %}` the base and override only the blocks they need to change.

```html
<!-- templates/base.html -->
<!DOCTYPE html>
<html>
<head>
  <title>{% block title %}My App{% endblock %}</title>
  <link rel="stylesheet" href="{{ url_for('static', filename='css/main.css') }}">
</head>
<body>
  <nav>{% block nav %}{% endblock %}</nav>
  <main>{% block content %}{% endblock %}</main>
  <footer>&copy; 2025</footer>
</body>
</html>
```

```html
<!-- templates/index.html -->
{% extends "base.html" %}

{% block title %}Home - {{ super() }}{% endblock %}

{% block content %}
  <h1>Welcome</h1>
  <p>You have {{ notifications }} notifications.</p>
{% endblock %}
```

`{% extends %}` must be the first line of the child template. `{{ super() }}` inside a block inserts the parent's version of that block — useful for appending or prepending rather than replacing. Blocks can be nested, and a block defined in a child can itself contain `{% block %}` declarations for grandchildren to override. The result is a layout system that scales from a 3-page site to a 300-page site without losing maintainability.

## 6. Macros and Includes

Macros are Jinja2's functions. Define a reusable snippet once and call it from anywhere in the template (or import it from another template).

```jinja2
{# templates/macros/forms.html #}
{% macro field(name, label, type="text", value="") %}
  <label>{{ label }}
    <input type="{{ type }}" name="{{ name }}" value="{{ value }}">
  </label>
{% endmacro %}
```

```jinja2
{% from "macros/forms.html" import field %}

<form method="post">
  {{ field("email", "Email", "email") }}
  {{ field("password", "Password", "password") }}
  <button type="submit">Log in</button>
</form>
```

`{% include "partial.html" %}` inserts the rendered content of another template inline. Includes are best for static chunks (a sidebar, a footer variant) that do not fit the inheritance model. Macros are better when the snippet takes parameters.

## 7. Context Processors

A context processor is a function decorated with `@app.context_processor` that returns a dict of variables to inject into every template's context. It is the right place for globals like the current user, the site name, or feature flags.

```python
from flask import g

@app.context_processor
def inject_globals():
    return {
        "site_name": "MyApp",
        "current_user": getattr(g, "user", None),
        "year": 2025,
    }
```

Every template now sees `{{ site_name }}`, `{{ current_user }}`, and `{{ year }}` without the view having to pass them explicitly. Use context processors sparingly — they run on every render, so an expensive database call inside one will slow down every page.

## 8. Static Assets with url_for

Templates need to reference CSS, JavaScript, and image files. The correct way to do this is `url_for('static', filename='...')`:

```html
<link rel="stylesheet" href="{{ url_for('static', filename='css/main.css') }}">
<script src="{{ url_for('static', filename='js/app.js') }}"></script>
<img src="{{ url_for('static', filename='img/logo.png') }}" alt="Logo">
```

`url_for` generates the correct path (`/static/css/main.css` by default) and survives any future change to the static URL prefix. It also lets you switch to a CDN or a fingerprinted filename by overriding the static handler — see [[3.2.7. Static Files]] for the full treatment of static asset serving.

## 9. Autoescaping and XSS Prevention

Jinja2 autoescapes HTML in any template with a `.html`, `.htm`, `.xml`, or `.xhtml` extension. Autoescaping means the characters `<`, `>`, `&`, `"`, and `'` are converted to their HTML entity equivalents (`&lt;`, `&gt;`, `&amp;`, `&quot;`, `&#39;`) before the value is written to the output. This is what protects you from cross-site scripting (XSS): if a user's bio contains `<script>alert(1)</script>`, the rendered template outputs the script tag as visible text rather than executing it.

```python
@app.route("/bio/<username>")
def bio(username):
    return render_template("bio.html", username=username)
```

```html
<!-- User-supplied username "Bob<script>alert(1)</script>" is rendered as text -->
<h1>Bio for {{ username }}</h1>
```

Three rules govern autoescaping. First, it applies per-template based on the file extension; templates named `.txt` or `.csv` are not autoescaped. Second, it applies only to values that come from a context variable or a template expression, not to literal template text. Third, the `safe` filter and `Markup` class mark a value as already-safe, which **disables** autoescaping for that value — use them only on content you generated yourself.

A common mistake is to use `|safe` on a value that contains user input. The right pattern for embedding JSON data into a `<script>` tag is the `tojson` filter, which JSON-encodes and HTML-escapes the result:

```html
<script>
  const config = {{ config_data | tojson }};
</script>
```

## 10. Custom Filters

Register custom filters with `@app.template_filter`:

```python
@app.template_filter("money")
def money_filter(value):
    return f"${value:,.2f}"

# In templates: {{ order.total | money }}  -> "$1,234.50"
```

Custom filters are useful for domain-specific formatting (currency, dates, units). For anything more complex than a single transformation, prefer a context processor or a macro — filters should stay pure and side-effect-free.

## Summary

Jinja2 templates live in `templates/`, are rendered with `render_template()`, and use `{{ }}` for expressions, `{% %}` for statements, and `{# #}` for comments. Template inheritance with `{% extends %}` and `{% block %}` is how you keep HTML DRY. Filters transform values; the `safe` and `tojson` filters are the two you must understand for security. Autoescaping is on by default for HTML templates and is the primary XSS defense; never disable it for user content. Static assets are referenced with `url_for('static', ...)` so the URL stays decoupled from the file layout. The next note, [[3.2.6. Forms and User Input]], covers the other direction — receiving data from the browser.
