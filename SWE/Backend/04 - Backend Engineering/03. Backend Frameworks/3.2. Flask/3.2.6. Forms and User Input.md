# 3.2.6. Forms and User Input

> [!info] Orientation
> Forms are how Flask receives data from the browser. This note covers the four input sources on the `request` object (`form`, `args`, `files`, `json`), WTForms integration via Flask-WTF, automatic CSRF protection, field types and validators, rendering fields in Jinja2, secure file uploads with `secure_filename`, and the common gotchas around multipart data and upload size limits.

## 1. The Four Input Sources

The `request` object exposes four attributes that cover the full range of HTTP input. Each is a different shape because each maps to a different part of the HTTP request.

| Attribute | Source | Shape |
| --------- | ------ | ----- |
| `request.args` | URL query string (`?name=value`) | `ImmutableMultiDict` |
| `request.form` | Form-posted body (`Content-Type: application/x-www-form-urlencoded`) | `ImmutableMultiDict` |
| `request.files` | Multipart body (`Content-Type: multipart/form-data`) | `MultiDict` of `FileStorage` |
| `request.json` | JSON body (`Content-Type: application/json`) | Parsed dict / list / scalar |

```python
from flask import request

@app.route("/search")
def search():
    q = request.args.get("q", "")
    page = request.args.get("page", 1, type=int)
    return f"Searching for {q}, page {page}"

@app.route("/login", methods=["POST"])
def login():
    username = request.form.get("username")
    password = request.form.get("password")
    return f"Authenticating {username}"

@app.route("/api/echo", methods=["POST"])
def echo():
    payload = request.get_json()        # parses JSON body
    return {"you_sent": payload}
```

`request.args.get("q", "")` returns `""` if `q` is absent; without the default it would return `None`. The `type=int` argument to `get` coerces the value, returning `None` (or the default) if conversion fails. `request.get_json()` raises a `400 Bad Request` if the body is not valid JSON; pass `silent=True` to get `None` instead.

## 2. Manual Form Handling

You can handle forms entirely by hand: read `request.form`, validate, and act. For a two-field login form this is fine. For anything bigger the validation code grows linearly with the form, and you end up reimplementing what WTForms already gives you.

```python
@app.route("/contact", methods=["GET", "POST"])
def contact():
    if request.method == "POST":
        name = request.form.get("name", "").strip()
        email = request.form.get("email", "").strip()
        message = request.form.get("message", "").strip()
        errors = []
        if not name:
            errors.append("Name is required.")
        if "@" not in email:
            errors.append("Valid email is required.")
        if len(message) < 10:
            errors.append("Message must be at least 10 characters.")
        if errors:
            return render_template("contact.html", errors=errors, name=name, email=email, message=message)
        send_email(name, email, message)
        return redirect(url_for("contact_thanks"))
    return render_template("contact.html", errors=[])
```

This works and is honest about what it does. The problems arrive when the form grows to ten fields, when you need to render the same form prefilled with submitted values, and when you want consistent error display across the site. That is where WTForms earns its keep.

## 3. WTForms and Flask-WTF

WTForms is a form library that separates form definition (a Python class) from rendering (templates) and validation (the `validate_on_submit` call). Flask-WTF is a thin Flask integration that adds CSRF protection, file upload fields, and a `FlaskForm` base class.

```bash
pip install Flask-WTF
```

```python
# forms.py
from flask_wtf import FlaskForm
from wtforms import StringField, PasswordField, TextAreaField, SubmitField
from wtforms.validators import DataRequired, Email, Length

class ContactForm(FlaskForm):
    name = StringField("Name", validators=[DataRequired(), Length(max=80)])
    email = StringField("Email", validators=[DataRequired(), Email()])
    message = TextAreaField("Message", validators=[DataRequired(), Length(min=10, max=2000)])
    submit = SubmitField("Send")
```

```python
# routes.py
@app.route("/contact", methods=["GET", "POST"])
def contact():
    form = ContactForm()
    if form.validate_on_submit():
        send_email(form.name.data, form.email.data, form.message.data)
        return redirect(url_for("contact_thanks"))
    return render_template("contact.html", form=form)
```

`form.validate_on_submit()` returns `True` only when the request method is `POST` **and** all field validators pass. On a `GET` request it returns `False` and you fall through to render the empty form. On a failed `POST` you re-render the same template with the same `form` object — fields retain their submitted values and errors are attached for the template to display.

## 4. CSRF Protection

Cross-Site Request Forgery (CSRF) is the attack where a malicious site tricks the user's browser into submitting a POST to your site, riding on the user's session cookie. The defense is a per-session random token: your form includes the token as a hidden field, and your server rejects any POST whose token does not match the session.

Flask-WTF enables CSRF protection by default as soon as `WTF_CSRF_ENABLED` is `True` (the default) and `SECRET_KEY` is set. The token is rendered in templates with `{{ form.csrf_token }}` or, for non-WTF forms, with `{{ csrf_token() }}`. For JSON APIs served from the same app, you can pass the token via the `X-CSRFToken` header instead.

```html
<form method="post">
  {{ form.csrf_token }}
  {{ form.name.label }} {{ form.name }}
  {{ form.email.label }} {{ form.email }}
  {{ form.message.label }} {{ form.message }}
  {{ form.submit }}
  {% for field in form if field.errors %}
    <ul class="errors">
      {% for err in field.errors %}
        <li>{{ field.label }}: {{ err }}</li>
      {% endfor %}
    </ul>
  {% endfor %}
</form>
```

For APIs consumed by non-browser clients (mobile apps, scripts), CSRF protection is typically disabled for those blueprints and authentication is done via bearer tokens — see [[3.2.13. APIs with Flask and JSON]] and [[1.6. API Authentication Patterns]].

## 5. Field Types and Validators

WTForms ships with field types covering the common HTML inputs.

| Field | Renders as | Python value |
| ----- | ---------- | ------------ |
| `StringField` | `<input type="text">` | `str` |
| `PasswordField` | `<input type="password">` | `str` |
| `TextAreaField` | `<textarea>` | `str` |
| `BooleanField` | `<input type="checkbox">` | `bool` |
| `IntegerField` | `<input type="number">` | `int` or `None` |
| `SelectField` | `<select>` | `str` (the chosen `choices` value) |
| `DateField` | `<input type="date">` | `datetime.date` |
| `FileField` | `<input type="file">` | `FileStorage` |
| `SubmitField` | `<input type="submit">` | `str` (label) |

Validators are callables that raise `ValidationError` on failure. The built-ins cover most cases: `DataRequired`, `Email`, `Length(min, max)`, `NumberRange(min, max)`, `URL`, `Regexp(pattern)`, `EqualTo(other_field)` (for password confirmation), `Optional` (skip further validators if empty). Custom validators are simple functions:

```python
def not_banned_words(form, field):
    banned = {"spam", "casino", "viagra"}
    if any(w in field.data.lower() for w in banned):
        raise ValidationError("Disallowed content.")

class ContactForm(FlaskForm):
    message = TextAreaField("Message", validators=[DataRequired(), not_banned_words])
```

## 6. File Uploads

File uploads arrive on `request.files` as `FileStorage` objects. Each `FileStorage` has a `filename`, a `stream`, and a `save(path)` method. The single most important security rule is **never trust the client-supplied filename**. A user can submit any string as a filename, including `../../etc/passwd` or `evil.exe`. Werkzeug's `secure_filename` sanitizes the name down to a safe subset.

```python
import os
from werkzeug.utils import secure_filename
from flask import current_app

@app.route("/upload", methods=["GET", "POST"])
def upload():
    if request.method == "POST":
        f = request.files["file"]
        if not f:
            return "No file provided", 400
        filename = secure_filename(f.filename)   # "../etc/passwd" -> "etc_passwd"
        if not filename:
            return "Invalid filename", 400
        dest = os.path.join(current_app.config["UPLOAD_FOLDER"], filename)
        f.save(dest)
        return redirect(url_for("upload_done", filename=filename))
    return render_template("upload.html")
```

The upload form must use `multipart/form-data`, which WTForms/HTML handle automatically when you include a `FileField` and add `enctype="multipart/form-data"` to the `<form>` tag. Forgetting the `enctype` is the most common reason a file upload silently returns `None`.

## 7. Gotchas

**Multipart form data.** A POST with `Content-Type: multipart/form-data` populates both `request.form` (text fields) and `request.files` (file fields). A POST with `application/x-www-form-urlencoded` populates only `request.form` and `request.files` is empty. Mixing these up leads to "the field is always None" bugs.

**Size limits.** Flask itself does not limit request body size, but your WSGI server does. Werkzeug's dev server defaults to unlimited; Gunicorn defaults to unlimited unless you set `--limit-request-line` and `--limit-request-field_size`. For uploads, set `app.config["MAX_CONTENT_LENGTH"]` and Flask will reject larger bodies with a `413 Payload Too Large` before reading them:

```python
app.config["MAX_CONTENT_LENGTH"] = 16 * 1024 * 1024  # 16 MB
```

**JSON vs form.** `request.json` is `None` if the `Content-Type` is not `application/json`. `request.get_json(force=True)` parses regardless of content type, which is convenient for testing but a security smell in production — never parse a body as JSON just because the user asked you to.

**CSRF on AJAX.** JSON `POST` requests from the browser need the CSRF token in the `X-CSRFToken` header, not the body. Flask-WTF reads it from there automatically if you include the header. For non-browser clients (curl, mobile apps), disable CSRF on those routes and require a bearer token instead.

## Summary

Flask receives input through `request.args`, `request.form`, `request.files`, and `request.json`. For anything beyond a two-field form, Flask-WTF gives you a clean form-class abstraction, automatic CSRF protection, declarative validators, and consistent error rendering. File uploads require `secure_filename` to avoid path traversal and `MAX_CONTENT_LENGTH` to cap upload size. The biggest gotchas are missing `enctype="multipart/form-data"` on upload forms and forgetting the CSRF header on JSON requests. The next note, [[3.2.7. Static Files]], covers the other direction — sending assets back to the browser.
