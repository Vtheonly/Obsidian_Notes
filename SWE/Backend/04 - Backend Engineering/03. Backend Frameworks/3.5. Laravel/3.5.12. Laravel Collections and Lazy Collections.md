# 3.5.12. Laravel Collections and Lazy Collections

> [!info] Orientation
> Data manipulation is a fundamental task in backend applications. While native PHP arrays can be tedious to manage, Laravel wraps arrays in **Collections**, providing a highly readable, fluent interface for filtering, mapping, and reducing datasets. This note details standard Collections, their memory overhead limitations, and how to scale to massive datasets using **Lazy Collections** and PHP Generators.

---

## 1. Fluent Data Pipelines with Standard Collections

Laravel's `Illuminate\Support\Collection` class provides an expressive, chainable wrapper for working with arrays of data. Standard database queries via Eloquent automatically return a Collection of model instances.

Instead of writing verbose nested loops, you can chain single-purpose declarative pipeline operations:

```php
use App\Models\User;

// Retrieve all users, filter out inactive ones, extract email addresses, and group by domain
$domains = User::all()
    ->filter(fn ($user) => $user->is_active)
    ->map(fn ($user) => strtolower($user->email))
    ->groupBy(fn ($email) => substr(strrchr($email, "@"), 1));

// Output: A clean, structured Collection!
```

## 2. Common Collection Methods

Collections include hundreds of built-in methods. Some of the most frequently used are:

* **`pluck($value, $key = null)`:** Extract a specific column's values into a flat list.
* **`filter(callable $callback)`:** Filter items out of the collection using a truth-test closure.
* **`map(callable $callback)`:** Run a callback over each item, modifying values in place.
* **`reduce(callable $callback, $initial = null)`:** Reduce the collection to a single value (e.g., summing totals).
* **`groupBy($key)`:** Group items in the collection by a given key.

---

## 3. The Memory Exhaustion Bottleneck

Standard collections process datasets **entirely in memory**. If you execute:

```php
// ❌ Dangerous: Pulls 500,000 rows into PHP memory and instantiates 500,000 Eloquent model objects!
$users = User::all();
```

Your server will quickly exhaust its allocated memory, triggering a fatal PHP crash:

```text
Fatal error: Allowed memory size of 134217728 bytes exhausted (tried to allocate 4096 bytes)
```

To process massive datasets without running out of memory, you must process records iteratively in small batches or streams.

---

## 4. Lazy Collections and PHP Generators

Laravel introduced **Lazy Collections** (`Illuminate\Support\LazyCollection`) to resolve memory bottlenecks.

Lazy Collections utilize PHP's native **Generators** and the `yield` keyword under the hood. They let you execute fluent collection pipelines (like `map` and `filter`) while keeping only a **single item in memory at any given time**, keeping your memory footprint flat and constant.

```mermaid
graph TD
    DB[(Database)] -- chunk by chunk -- Stream[Cursor / Generator]
    Stream -- yields single item -- Pipeline[LazyCollection map/filter]
    Pipeline -- output record -- GC[Garbage Collector frees memory]
```

### Implementing Lazy Collections with Database Cursors
Instead of calling `all()` or `get()`, execute queries using the **`cursor()`** method to load records lazily:

```php
use App\Models\User;

//  Optimized: Uses a Lazy Collection to process 500,000 users with constant memory footprint!
User::cursor()
    ->filter(fn ($user) => $user->last_login_at < now()->subYear())
    ->each(function ($user) {
        $user->deactivate(); // Run task on each record sequentially
    });
```

## 5. Under the Hood: PHP Generators and `yield`

How do Lazy Collections achieve constant memory usage? They rely on PHP **Generators**, which are functions that can pause and resume execution on demand, yielding values one-by-one rather than returning an entire array at once.

Let's look at how to build a manual Lazy Collection using a custom generator:

```php
use Illuminate\Support\LazyCollection;

// 🛠️ Custom Generator function
function readLargeLogFile($path) {
    $handle = fopen($path, 'r');
    
    while (($line = fgets($handle)) !== false) {
        // Yield lines one-by-one. The function pauses execution here 
        // until the caller requests the next item!
        yield $line; 
    }
    
    fclose($handle);
}

// 🚀 Wrap the generator inside a LazyCollection to unlock fluent pipelines
$logCollection = LazyCollection::make(function () {
    return readLargeLogFile('/var/log/nginx/access.log');
});

// Now, process gigabytes of log lines with less than 2MB of memory usage!
$errors = $logCollection
    ->filter(fn ($line) => str_contains($line, '500 Internal Server Error'))
    ->take(10) // Stop reading the file early once we find 10 matches!
    ->all();
```

---

## Summary

Laravel Collections provide an elegant, declarative pipeline interface for data manipulation. However, standard Collections load all records into memory at once, which can trigger memory exhaustion on large datasets. By wrapping database queries in Lazy Collections with `cursor()`, developers can leverage PHP Generators to stream and process millions of records with a flat, constant memory footprint.
