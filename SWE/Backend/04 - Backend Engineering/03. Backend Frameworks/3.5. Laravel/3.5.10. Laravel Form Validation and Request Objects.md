# 3.5.10. Laravel Form Validation and Request Objects

> [!info] Orientation
> Restricting and validating incoming user input is a fundamental security requirement. Laravel provides multiple validation layers, ranging from simple inline controller validations to dedicated Form Request objects. This note details how validation works under the hood, how to implement Form Requests, and how to write custom validation rules.

---

## 1. Validation Foundations in Laravel

When an HTTP request carries query params or body parameters, Laravel parses them into a central `Request` object.

You can validate incoming data inline inside your controllers using `$request->validate()`:

```php
public function store(Request $request)
{
    // If validation fails, Laravel automatically redirects back with flash errors (web)
    // or returns a structured 422 Unprocessable Entity JSON response (API).
    $validatedData = $request->validate([
        'username' => 'required|string|min:3|max:50',
        'email' => 'required|email|unique:users,email',
        'password' => 'required|string|min:8|confirmed', // requires 'password_confirmation'
    ]);

    // Proceed safely with validated data...
}
```

While inline validation is great for simple scripts, large controllers quickly clutter with duplicate validation rules, bloating their code.

---

## 2. Type-Safe Form Request Objects

**Form Requests** are custom request classes that encapsulate their own authorization and validation logic. They completely isolate input validation from your controllers.

To generate a Form Request, execute:

```bash
php artisan make:request StoreUserRequest
```

This creates a class inside `app/Http/Requests/StoreUserRequest.php`:

```php
namespace App\Http\Requests;

use Illuminate\Foundation\Http\FormRequest;

class StoreUserRequest extends FormRequest
{
    /**
     * Determine if the user is authorized to make this request.
     * Use this method to check resource ownership or user permissions.
     */
    public function authorize(): bool
    {
        // Example: Only allow administrators to create users
        return $this->user() && $this->user()->role === 'admin';
    }

    /**
     * Get the validation rules that apply to the request.
     */
    public function rules(): array
    {
        return [
            'username' => ['required', 'string', 'min:3', 'max:50'],
            'email' => ['required', 'email', 'unique:users,email'],
            'password' => ['required', 'string', 'min:8', 'confirmed'],
            'profile_picture' => ['nullable', 'image', 'max:2048'], // limit: 2MB
        ];
    }

    /**
     * Customize the validation error messages.
     */
    public function messages(): array
    {
        return [
            'email.unique' => 'This email address is already associated with another account.',
            'password.confirmed' => 'The password confirmation field does not match.',
        ];
    }
}
```

## 3. Injecting Form Requests into Controllers

To apply your Form Request validation rules, type-hint the custom class directly in your controller's method signature. Laravel resolves the class from the service container, executes the authorization and validation checks, and only runs your controller method if all checks pass:

```php
namespace App\Http\Controllers;

use App\Http\Requests\StoreUserRequest;
use App\Models\User;

class UserController extends Controller
{
    public function store(StoreUserRequest $request)
    {
        // 🚀 This code only runs if authorization and validation pass!
        
        // Retrieve ONLY the validated and cleaned attributes
        $validated = $request->validated();

        $user = User::create([
            'name' => $validated['username'],
            'email' => $validated['email'],
            'password' => bcrypt($validated['password']),
        ]);

        return response()->json($user, 201);
    }
}
```

## 4. Writing Custom Validation Rule Classes

If Laravel's built-in validation rules are not sufficient, you can write custom, reusable validation rule classes.

Generate a custom rule class:

```bash
php artisan make:rule StrengthPassword
```

This creates a class inside `app/Rules/StrengthPassword.php`:

```php
namespace App\Rules;

use Closure;
use Illuminate\Contracts\Validation\ValidationRule;

class StrengthPassword implements ValidationRule
{
    /**
     * Run the validation rule.
     *
     * @param  \Closure(string): \Illuminate\Translation\PotentiallyTranslatedString  $fail
     */
    public function validate(string $attribute, mixed $value, Closure $fail): void
    {
        // Verify the password contains at least one uppercase letter and one number
        if (! preg_match('/[A-Z]/', $value) || ! preg_match('/[0-9]/', $value)) {
            $fail('The :attribute must contain at least one uppercase letter and one number.');
        }
    }
}
```

Now, include your custom rule inside your Form Request or inline validation checks:

```php
use App\Rules\StrengthPassword;

'password' => ['required', 'string', new StrengthPassword],
```

---

## Summary

Form validation with Request objects keeps Laravel controllers clean and focused on orchestration. By shifting authorization and validation checks to dedicated Form Request classes and encapsulating custom logic inside reusable Rule components, applications remain highly secure and maintainable.
