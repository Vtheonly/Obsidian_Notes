# 3.6.11. Booleans and Comparisons

> [!info] Comparisons evaluate to a boolean (`true` or `false`) and are the basis of every conditional in PHP. The language's loose typing means comparisons can produce surprising results — `0 == "abc"` was true in PHP 7 and is false in PHP 8. This note covers the truthy/falsy rules, the loose vs strict distinction, the spaceship operator, and the modern `match` expression that replaces `switch` for value comparisons.

## 1. Booleans — The Simplest Type

A boolean is the simplest data type, representing only two possible states: `true` or `false`. It is the language of logic in programming.

### 1.1 Echoing Booleans — A Common Source of Confusion

When you `echo` a boolean directly, it gets converted to a string first. `true` becomes the string `"1"`; `false` becomes the empty string `""`. This is why `echo false;` appears to do nothing — there is nothing to display, and beginners often interpret "nothing on screen" as "the boolean was not set" rather than "the boolean was false".

```php
<?php
echo true;   // Output: 1
echo false;  // Output: (nothing)
```

To properly see the value of a boolean for debugging, use `var_dump()`, which shows the type and value without conversion: `var_dump(true)` outputs `bool(true)`. See [[3.6.6. Echo Print and PrintR]] for the full comparison of output functions.

### 1.2 Truthy and Falsy Values

Every value in PHP can be coerced to a boolean. The following values are **falsy** — they evaluate to `false` in a boolean context:

- `false` itself
- The integer `0` and the float `0.0` and `-0.0`
- The empty string `""` and the string `"0"`
- The empty array `[]`
- `null`
- SimpleXML objects created from empty elements

Everything else is **truthy**. Note carefully that the string `"0"` is falsy but the string `"0.0"` is truthy — PHP only special-cases the exact string `"0"`. This is a recurring source of bugs when validating numeric input that arrives as a string.

## 2. Standard Comparison Operators

These operators work as you would expect from basic mathematics.

| Operator | Name | Description | Example | Result |
| -------- | ---- | ----------- | ------- | ------ |
| `>` | Greater than | Is the left value greater than the right? | `10 > 5` | `true` |
| `<` | Less than | Is the left value less than the right? | `10 < 5` | `false` |
| `>=` | Greater than or equal | Left >= right | `5 >= 5` | `true` |
| `<=` | Less than or equal | Left <= right | `5 <= 5` | `true` |
| `==` | Equal (loose) | Equal, ignoring type | `5 == '5'` | `true` |
| `!=` | Not equal (loose) | Not equal, ignoring type | `5 != '5'` | `false` |
| `===` | Identical (strict) | Equal value AND type | `5 === '5'` | `false` |
| `!==` | Not identical (strict) | Different value OR type | `5 !== '5'` | `true` |

## 3. Comparing Strings

When comparing strings with `<`, `>`, `<=`, `>=`, PHP performs a **lexicographical** (alphabetical) comparison based on ASCII/Unicode values. The comparison is case-sensitive. In the ASCII table, uppercase letters come before lowercase letters, so `'A'` is less than `'a'`.

```php
<?php
var_dump('shaun' > 'Shaun');   // true — 's' (115) > 'S' (83)
var_dump('shaun' < 'yoshi');   // true — 's' (115) < 'y' (121)
var_dump('mario' == 'Mario');  // false — case-sensitive
```

For natural or case-insensitive comparison, use `strcasecmp()` (binary safe, case-insensitive) or `strcmp()` (binary safe, case-sensitive). These return `0` for equal, a negative int if the first string is less than the second, and a positive int otherwise — the same convention as the spaceship operator.

A subtle trap: when you compare a string to a number with `==`, PHP converts the string to a number first. `"abc" == 0` was `true` in PHP 7 because `"abc"` coerced to `0`. **PHP 8 changed this**: a non-numeric string is now compared as a string, so `"abc" == 0` is `false`. This is one of the most important PHP 8 changes for security, because the old behaviour was the cause of many authentication bypass bugs.

## 4. Loose (`==`) vs Strict (`===`) Comparison

This is one of the most important concepts to master in PHP.

### 4.1 Loose Comparison (`==`)

Loose comparison compares only the *value*. If the data types are different, PHP performs **type juggling** in the background, converting one of the values to match the other's type before comparing. This can lead to unexpected results.

```php
<?php
var_dump(5 == '5');          // true — '5' converted to int 5
var_dump(true == "1");       // true — "1" converted to bool true
var_dump(false == "");       // true — "" converted to bool false
var_dump(false == 0);        // true — 0 converted to bool false
var_dump(null == false);     // true — both falsy
```

The famous PHP comparison table contains many surprises: `"abc" == 0` was true (PHP 7), `"1" == "01"` is true (numeric string comparison), and `"10" == "1e1"` is true (both are numeric strings evaluating to 10). These rules are documented but easy to forget, and they are the source of countless security vulnerabilities.

### 4.2 Strict Comparison (`===`)

Strict comparison compares both the *value* and the *data type*. No type juggling occurs. If the types are not identical, the result is immediately `false`. This is predictable, safe, and the recommended way to compare for equality.

```php
<?php
var_dump(5 === '5');          // false — int vs string
var_dump(5 === 5);            // true — same type and value
var_dump(true === "1");       // false — bool vs string
var_dump(true === true);      // true — same type and value
```

> ### The Golden Rule of Comparison
> **Always use strict comparison (`===` and `!==`) by default.** Only use loose comparison (`==` and `!=`) if you have a specific and intentional reason to allow type juggling. This single rule prevents a large class of PHP bugs.

## 5. The Spaceship Operator (`<=>`)

PHP 7 introduced the spaceship operator, a three-way comparison that returns `-1`, `0`, or `1` depending on whether the left operand is less than, equal to, or greater than the right. It works on numbers, strings, arrays, and any comparable values, and it follows the same type-juggling rules as the corresponding `<`, `==`, and `>` operators.

```php
<?php
echo 1 <=> 2;   // -1
echo 2 <=> 2;   //  0
echo 3 <=> 2;   //  1

echo 'a' <=> 'b'; // -1
echo 'b' <=> 'a'; //  1
```

The spaceship operator's main use is in `usort()` callbacks, where it replaces verbose comparison functions with a single expression:

```php
<?php
$numbers = [3, 1, 4, 1, 5, 9, 2, 6];
usort($numbers, fn($a, $b) => $a <=> $b);
print_r($numbers); // [1, 1, 2, 3, 4, 5, 6, 9]
```

## 6. The `match` Expression (PHP 8)

PHP 8 introduced `match`, a safer and more concise alternative to `switch` for value comparison. `match` is an expression (it returns a value), uses strict comparison (`===`) automatically, supports combined conditions, and throws `UnhandledMatchError` if no arm matches (instead of silently falling through).

```php
<?php
$statusCode = 404;

$message = match($statusCode) {
    200, 300    => 'Success',
    404         => 'Not found',
    500         => 'Server error',
    default     => 'Unknown status',
};

echo $message; // Not found
```

Compared to `switch`, `match` has several advantages: it uses strict comparison, it returns a value (no need to assign inside a `case` block), it does not fall through (no `break` needed), and it requires a `default` arm or throws an error if no arm matches. Use `match` for value comparisons and `switch` only when you genuinely need fall-through behaviour. See [[3.6.12. Conditions if else elseif switch]] for the full treatment of `switch` and `match`.

## 7. PHP 8 Comparison Changes Summary

PHP 8 made several comparison behaviour changes that developers must know about, because code that worked under PHP 7 can produce different results under PHP 8.

| Expression | PHP 7 | PHP 8 | Reason |
| ---------- | ----- | ----- | ------ |
| `0 == "abc"` | `true` | `false` | Non-numeric string now compared as string |
| `"abc" == 0` | `true` | `false` | Same as above |
| `"1" == "1e1"` | `true` | `true` | Still true (numeric strings) |
| `"1" == "01"` | `true` | `true` | Still true (numeric strings) |
| `0 == "0"` | `true` | `true` | Still true |
| `switch (0) { case "abc": ... }` | matches | does not match | Switch now uses `===` semantics for non-numeric strings |

These changes make comparisons more predictable but mean that upgrading from PHP 7 to 8 requires careful review of any code that uses `==` with mixed types.

## Summary

Booleans are PHP's simplest type, but `echo` of a boolean is confusing because `false` produces no output. Every value is either truthy or falsy according to documented rules, with the string `"0"` and the empty array among the surprises. Loose comparison (`==`) performs type juggling that produces security-relevant surprises, especially when comparing strings to numbers — PHP 8 fixed many of these. Strict comparison (`===`) is the modern default. The spaceship operator (`<=>`) makes `usort` callbacks concise, and the PHP 8 `match` expression is a safer alternative to `switch` for value comparisons.
