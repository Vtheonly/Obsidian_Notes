# 3.6.10. Strings and Numbers

> [!info] PHP's type system is dynamically typed with aggressive automatic coercion — "type juggling". A variable that holds `5` (int) becomes `5` (string) the moment you concatenate it with another string, and `"5"` becomes `5` when you add it. This is convenient and dangerous. Modern PHP offers `declare(strict_types=1)` to opt out of coercion at function boundaries, plus specialised functions for exact decimal math (`bcmath`) and a rich set of string functions. This note covers the essential string and number machinery every PHP developer must know.

## 1. Common String Functions

PHP ships with a rich library of built-in string functions. They allow you to inspect a string (its length, position of a substring) or create a new, modified version (uppercase, lowercase, trimmed, replaced). A critical property to remember: strings in PHP are **immutable**. String functions do not change the original string; they return a new, modified string.

### 1.1 strlen — String Length

`strlen()` returns the number of bytes in a string. Note "bytes", not "characters" — for multibyte encodings like UTF-8, use `mb_strlen()` to get the actual character count.

```php
<?php
$name = 'yoshi';
echo strlen($name); // 5

$unicode = 'café';
echo strlen($unicode);   // 5 (é is 2 bytes in UTF-8)
echo mb_strlen($unicode); // 4 (4 characters)
```

### 1.2 strtoupper and strtolower — Case Conversion

`strtoupper()` returns a new string with all alphabetic characters converted to uppercase. `strtolower()` does the opposite. For UTF-8 strings, use `mb_strtoupper()` and `mb_strtolower()`. Common use case: normalising email addresses before storing or comparing them.

```php
<?php
echo strtoupper('Hello World'); // HELLO WORLD
echo strtolower('EMAIL@EXAMPLE.COM'); // email@example.com
```

### 1.3 str_replace — Find and Replace

`str_replace()` replaces all occurrences of a search string with a replacement string. The syntax is `str_replace($search, $replace, $subject)`. All three arguments can be a single value or an array of values; if arrays, the replacements happen element-by-element. The comparison is case-sensitive; use `str_ireplace()` for case-insensitive replacement.

```php
<?php
echo str_replace('m', 'w', 'mario');  // wario

$phrase = 'hello ninja, the ninja is here.';
echo str_replace('ninja', 'wizard', $phrase);
// hello wizard, the wizard is here.
```

### 1.4 Other Essential String Functions

| Function | Purpose |
| -------- | ------- |
| `trim()`, `ltrim()`, `rtrim()` | Strip whitespace (or other characters) from both ends / left / right |
| `substr($s, $start, $length)` | Extract a substring |
| `strpos($haystack, $needle)` | Find the position of the first occurrence (returns `false` if not found) |
| `str_contains($haystack, $needle)` | PHP 8+ — returns `true`/`false`, cleaner than `strpos !== false` |
| `str_starts_with()`, `str_ends_with()` | PHP 8+ — boolean prefix/suffix tests |
| `sprintf($format, ...$args)` | Format a string with placeholders (`%s`, `%d`, `%f`) |
| `implode($glue, $array)` | Join an array into a string |
| `explode($delim, $string)` | Split a string into an array |
| `htmlspecialchars($s)` | Convert special HTML characters to entities (XSS defence) |

A common gotcha with `strpos()` is that it returns `0` when the needle is at the very beginning of the haystack. Because `0` is falsy, you must use the strict comparison `strpos(...) !== false` to distinguish "found at position 0" from "not found at all". The PHP 8 `str_contains()` function eliminates this trap entirely.

## 2. String Interpolation — Single, Double, Heredoc, Nowdoc

PHP provides four ways to write string literals, with different interpolation rules.

**Single quotes** create a literal string. No variable interpolation, no escape sequences (except `\'` and `\\`). Fastest, because PHP does not need to scan the string.

**Double quotes** enable variable interpolation. PHP scans the string for `$` variables and replaces them with their values. Escape sequences like `\n`, `\t`, `\r`, `\$`, and `\u{xxxx}` are interpreted. Curly braces `{$var}` disambiguate complex expressions: `"Hello, {$user->name}!"`.

**Heredoc** (`<<<EOT ... EOT;`) is a multi-line double-quoted string without the quotes. Useful for embedding large blocks of HTML or SQL. Variables are interpolated.

**Nowdoc** (`<<<'EOT' ... EOT;`) is the single-quoted equivalent of heredoc. No interpolation at all. Useful for embedding PHP code or SQL templates as literal text.

```php
<?php
$name = 'Alice';
$count = 5;

$single = 'Hello $name';              // Hello $name (literal)
$double = "Hello $name, count=$count"; // Hello Alice, count=5
$heredoc = <<<HTML
<p>Welcome, {$name}.</p>
<p>You have {$count} items.</p>
HTML;
$nowdoc = <<<'SQL'
    SELECT * FROM users WHERE name = :name
SQL; // No interpolation, the literal text is preserved
```

## 3. Numbers and Arithmetic

PHP handles numbers as either integers (whole numbers like `10`) or floats (decimal numbers like `3.14`). The distinction matters for division and for precision-sensitive code.

### 3.1 Arithmetic Operators

| Operator | Name | Example | Result |
| -------- | ---- | ------- | ------ |
| `+` | Addition | `5 + 3` | `8` |
| `-` | Subtraction | `5 - 3` | `2` |
| `*` | Multiplication | `5 * 3` | `15` |
| `/` | Division | `15 / 3` | `5` |
| `%` | Modulo | `10 % 3` | `1` (remainder) |
| `**` | Exponentiation | `5 ** 2` | `25` |

A common trap: `^` is **not** exponentiation in PHP — it is the bitwise XOR operator. Always use `**` for powers. Another trap: `/` always returns a float if the result is not a whole number. `7 / 2` returns `3.5`, not `3`. To get integer division, use `intdiv(7, 2)` (returns `3`) or `(int) (7 / 2)`.

### 3.2 Order of Operations

PHP follows the standard mathematical order of operations, often remembered as BIDMAS or PEMDAS: **B**rackets, **I**ndices (powers), **D**ivision and **M**ultiplication (left to right), **A**ddition and **S**ubtraction (left to right).

```php
<?php
$result = 2 * (4 + 9) / 3; // 2 * 13 / 3 = 26 / 3 ≈ 8.667
echo $result; // 8.6666666666667
```

### 3.3 Increment, Decrement, and Shorthand Operators

`++` and `--` add or subtract 1 from a variable. They come in prefix (`++$x` — increment, then return) and postfix (`$x++` — return, then increment) flavours; the difference matters when the result is used in an expression. Shorthand operators combine arithmetic with assignment: `$age += 10` is shorthand for `$age = $age + 10`, and similarly for `-=`, `*=`, `/=`, `%=`, and `**=`.

### 3.4 Useful Math Functions

PHP provides many functions for common mathematical tasks. `floor()` rounds a number down to the nearest integer. `ceil()` rounds up. `round()` rounds to the nearest integer, with an optional second argument for decimal precision. `abs()` returns the absolute value. `pi()` returns the value of π. `max()` and `min()` return the largest or smallest of a list of arguments.

```php
<?php
echo floor(4.7);          // 4
echo ceil(4.3);           // 5
echo round(4.7);          // 5
echo round(2.83749, 2);   // 2.84
echo abs(-7);             // 7
echo max(3, 9, 1);        // 9
```

## 4. Strict Types

By default, PHP performs type coercion at function boundaries: if a function declares a parameter as `int` and you pass the string `"5"`, PHP silently converts it to `5`. This is convenient but masks bugs. Since PHP 7, you can opt out by adding `declare(strict_types=1);` at the very top of the file (before any other code, including the opening `<?php` tag). With strict types enabled, the same call would throw a `TypeError`.

```php
<?php
declare(strict_types=1);

function add(int $a, int $b): int {
    return $a + $b;
}

echo add(5, 10);      // 15
// echo add('5', '10'); // TypeError: Argument #1 must be of type int, string given
```

Strict types apply **per file**, and the file that contains the *call site* is what matters — not the file that defines the function. The recommendation for modern PHP is to enable strict types in every file. It costs nothing and catches an entire class of bugs.

## 5. Float Precision and Exact Decimal Math

Floating-point numbers in PHP (and every other language that uses IEEE 754 doubles) cannot represent most decimal fractions exactly. `0.1 + 0.2` is `0.30000000000000004`, not `0.3`. This is the same behaviour as JavaScript, Python, and every other language using IEEE 754 — it is not a PHP bug.

For money or any value where exact decimal arithmetic matters, do not use floats. Use the `bcmath` extension (`bcadd`, `bcsub`, `bcmul`, `bcdiv`, `bccomp`), which operates on string representations of numbers and produces exact results.

```php
<?php
echo 0.1 + 0.2;                    // 0.30000000000000004
echo bcadd('0.1', '0.2', 2);       // 0.30

echo bccomp('1.00', '1.00', 2);    // 0 (equal)
echo bccomp('1.01', '1.00', 2);    // 1 (left > right)
echo bccomp('0.99', '1.00', 2);    // -1 (left < right)
```

The third argument to all `bc*` functions is the scale — the number of decimal places to preserve. For money, a scale of `2` is typical. `bccomp` is preferable to `==` for comparing two floats that should be equal, because of the precision issues described above.

## 6. Type Juggling Reference

PHP converts between types according to documented rules. Some are intuitive (`"5"` becomes `5` in arithmetic context), others are surprising (`"5abc"` becomes `5` with a Warning in PHP 8+, where it used to silently become `5`).

| Expression | Result | Notes |
| ---------- | ------ | ----- |
| `"5" + 3` | `8` | String converted to int |
| `"5abc" + 3` | `8` (PHP 8: with Warning) | Leading digits parsed, rest ignored |
| `"abc" + 0` | `0` (PHP 8: TypeError if strict) | No leading digits |
| `5 . "abc"` | `"5abc"` | `.` is string concatenation |
| `0 == "abc"` | `false` (PHP 8), `true` (PHP 7) | PHP 8 fixed this |
| `null == false` | `true` | Both falsy |

PHP 8 made type juggling more predictable by removing many surprising coercions. The most important change is that `0 == "foo"` is now `false` (it used to be `true` because `"foo"` was coerced to `0`).

## Summary

PHP's string functions are immutable: they return new strings rather than modifying the original. The four string literal syntaxes — single quotes, double quotes, heredoc, nowdoc — offer different interpolation behaviours for different needs. Numbers come in two flavours (int and float) and PHP's type juggling silently converts between them, which `declare(strict_types=1)` disables at function boundaries. Float arithmetic cannot represent decimal fractions exactly, so money and other precision-sensitive values require `bcmath`. PHP 8 has cleaned up many of the most surprising type-juggling behaviours, but strict types and explicit comparison are still the modern best practice.
