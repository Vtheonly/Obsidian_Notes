# 3.6.4. MariaDB vs MySQL

> [!info] MariaDB is a community-developed, commercially supported fork of MySQL. From a PHP developer's perspective the two are nearly interchangeable — `mysqli` and `PDO` work identically against either — but their licensing, feature sets, and engines have diverged enough that the choice is no longer trivial. This note covers what a PHP developer needs to know; for the deep engines-and-internals comparison see [[2.4. MariaDB vs MySQL]].

## 1. The Origin Story

The two databases share a common ancestor and a fork event. MySQL was created in the mid-1990s by the Swedish company MySQL AB and grew into the world's most popular open-source relational database. In 2008, Sun Microsystems acquired MySQL AB. In 2010, Oracle Corporation acquired Sun Microsystems, taking control of MySQL in the process. Fearing that Oracle might weaken MySQL's open-source nature or prioritise its commercial interests over the community, Michael "Monty" Widenius — the principal author of MySQL — forked the source code (specifically from MySQL 5.5) and launched MariaDB. The fork is now stewarded by the non-profit MariaDB Foundation, which exists specifically to guarantee that MariaDB remains free and open-source forever.

The fork was as much philosophical as technical. Monty and the early MariaDB contributors did not trust Oracle, as the owner of the proprietary Oracle Database, to invest seriously in an open-source competitor. Whether or not that fear was justified, MariaDB has since diverged enough that the "drop-in replacement" label is now aspirational rather than strictly true.

## 2. Licensing and Governance

The governance model is the most concrete reason teams choose one over the other. MySQL is owned by Oracle Corporation and is dual-licensed. The Community Edition is free under the GNU General Public License (GPL), but advanced features — the Thread Pool, Enterprise Backup, Audit, Firewall — are only available in paid Enterprise Editions with a commercial license. MariaDB is governed by the MariaDB Foundation and is purely open-source under the GPL. Every feature that is paywalled in MySQL, including the thread pool, is available for free in MariaDB. Its development is community-driven and transparent, with public design discussions and a published roadmap.

For a PHP developer working on a personal project or a startup, the practical difference is small. For a company building a SaaS product on top of MySQL and considering which Enterprise features to pay for, MariaDB becomes attractive precisely because those same features are free.

## 3. Performance and Optimisation

Performance is highly workload-dependent and broad generalisations are dangerous, but some patterns show up consistently. MySQL's performance is excellent and highly tuned, but several of the most advanced optimisation features — like the Thread Pool for handling thousands of concurrent connections — are locked behind the Enterprise paywall. MariaDB often shows a slight performance edge in benchmark tests, thanks to its query optimizer and various enhancements. MariaDB ships its own implementation of the thread pool, available in the free version, which is a meaningful win for high-concurrency workloads.

In practice, the PHP driver layer (`mysqli` or `PDO_MYSQL`) is identical for both databases. A `SELECT` query that runs fast against MySQL runs fast against MariaDB, and vice versa. Performance tuning at the database level — indexing, query plan analysis, buffer pool sizing — works the same way on either.

## 4. Storage Engines

A storage engine is the underlying software component that a database uses to create, read, update, and store data. The choice of engine affects performance characteristics, durability guarantees, and supported feature sets.

MySQL focuses primarily on **InnoDB** (the default) and its original **MyISAM** engine. Other engines are available but receive less development attention. MariaDB supports a wider array of storage engines out of the box, including InnoDB (its default) and MyISAM, plus several of its own: **Aria** (a crash-safe alternative to MyISAM), **MyRocks** (from Facebook, optimised for high compression and fast storage), **Spider** (a sharding engine that lets tables be split across multiple servers), and **Connect** (an engine for accessing external files or remote databases as if they were local tables).

For a typical PHP application running on Laravel or Symfony, the choice of engine is invisible — InnoDB is the default on both databases, and the framework's ORM works against InnoDB. The wider engine selection in MariaDB matters in specialised cases: a high-write log table might benefit from MyRocks' compression, and a federated query across multiple regions might use Spider.

## 5. Feature Set Comparison

The feature gap has grown wide enough that the two are no longer drop-in replacements for every workload.

| Feature | MariaDB | MySQL |
| ------- | ------- | ----- |
| JSON support | Supports JSON via alias data types and a rich function set; stores JSON as plain text | Native JSON data type that stores data in an optimised binary format — generally faster reads and more robust validation |
| Temporal data | System-Versioned Tables (Temporal Tables) — query the state of your data at any point in the past; powerful for auditing and analytics | No built-in equivalent; must be implemented at the application level |
| Security | Advanced password validation plugins and role-based access control | `validate_password` component plus a mature set of security features |
| High availability | Standard replication plus Galera Cluster (multi-master synchronous replication) | Standard replication plus Group Replication (Oracle-developed, fault-tolerant) |
| SQL syntax | CTEs, Window Functions, plus Oracle-compatibility syntax to ease migration | CTEs and Window Functions (since 8.0), plus X Protocol for client-server communication |
| Connection pooling | Free, built into the server | Enterprise-only thread pool |

## 6. Compatibility for PHP Developers

MariaDB aims to be a drop-in replacement for MySQL at the wire protocol level. The `mysqlnd` driver used by PHP's `mysqli` and `PDO_MYSQL` extensions speaks the same protocol to either server. Connection strings, DSNs, and SQL syntax are interchangeable for the vast majority of common cases. A standard LAMP stack running WordPress, for example, can switch from MySQL to MariaDB by changing the package installation and restarting PHP — no code changes required.

The compatibility is not perfect, however. As the two have diverged, full 1:1 compatibility is no longer guaranteed. Using a feature specific to MySQL 8.0 (like its native JSON binary type) will not work in MariaDB, and using a feature from MariaDB (like Temporal Tables) will not work in MySQL. If your application uses an ORM like Eloquent, the framework usually papers over these differences, but raw SQL queries that target one database's specific features will not be portable.

## 7. Which Should a PHP Developer Choose?

The decision is rarely about performance, and rarely about SQL syntax. It is about philosophy, licensing, and ecosystem fit.

Choose MariaDB if you are a strong advocate for Free and Open Source Software and want to avoid vendor lock-in. Choose it if you need features that are paywalled in MySQL (thread pooling, enterprise backup) for free. Choose it if you require a specific storage engine like MyRocks or Spider, or if you value a transparent, community-driven development process. It is also the default database provided by several major Linux distributions (Red Hat Enterprise Linux, Debian, CentOS), so if you are deploying on those systems, MariaDB is what `apt install mariadb-server` or `dnf install mariadb-server` gives you.

Choose MySQL if you require paid commercial support directly from Oracle, or if your organisation has standardised on Oracle products and requires that ecosystem. Choose it if your application relies heavily on a MySQL-specific feature like its native binary JSON type or Group Replication. Choose it if you prefer the stability and predictable release cycle of a large corporate-backed product.

For most new PHP projects, both are excellent and highly capable. The choice usually comes down to philosophy, specific feature requirements, and ecosystem preferences rather than any objective technical superiority.

## Summary

MariaDB is a community-driven fork of MySQL that has diverged enough to develop its own identity. For most PHP applications the two are interchangeable at the driver and SQL level — `mysqli` and PDO work identically against either. The differences that matter are licensing (MariaDB is fully open-source, MySQL is dual-licensed with paywalled Enterprise features), engine selection (MariaDB ships more engines), and specific features (MySQL has the native JSON binary type, MariaDB has Temporal Tables and Galera). For the deep internals comparison — InnoDB page layout, buffer pool behaviour, replication internals — see [[2.4. MariaDB vs MySQL]].
