# 3.6.20. Variable Scope

> [!info] Variable scope is the context in which a variable is defined and accessible. PHP has three main scopes: local (inside a function), global (outside any function), and static (local but persistent across calls). On top of these, closures have their own rules for capturing outer variables, and arrow functions capture automatically by value. Understanding scope is essential to avoid "where did this variable come from?" bugs and to design functions that are independent and testable.

## 1. Local Scope (Function Scope)

Variables declared *inside* a function have **local scope**. They are only accessible from within that function. They are created when the function starts executing and are destroyed once the function finishes. Variables with the same name declared outside the function are completely separate entities — PHP does not link them in any way.

```php
<?php
$price = 50;  // Global scope

function myFunc(): void {
    $price = 10;  // A NEW, LOCAL variable named $price
    echo "Inside myFunc, \$price is: $price<br>";
}

myFunc();
echo "Outside myFunc, \$price is: $price<br>";
// Output:
// Inside myFunc, $price is: 10
// Outside myFunc, $price is: 50
```

The local `$price` inside `myFunc` does not affect the global `$price`. The function correctly accesses its own local copy; the outer `echo` correctly sees the unchanged global value.

### 1.1 Parameters as Local Variables

When you pass arguments to a function, those arguments become **local variables** within the function's scope. Even if a global variable has the same name as a function parameter, the parameter takes precedence and is treated as a distinct local variable. Modifying the parameter inside the function has no effect on the global variable of the same name (unless you pass by reference with `&`).

```php
<?php
$name = 'mario';  // Global

function sayBye(string $name): void {
    $name = 'wario';  // Modifies the LOCAL parameter, not the global
    echo "Inside sayBye, \$name is: $name<br>";
}

sayBye('luigi');
echo "Outside sayBye, \$name is: $name<br>";
// Output:
// Inside sayBye, $name is: wario
// Outside sayBye, $name is: mario
```

## 2. Global Scope

Variables declared outside of any function are in the **global scope**. They are accessible anywhere in the top-level script, but *not directly inside functions* by default. This is one of PHP's quirks compared to languages like JavaScript — global variables do not automatically leak into function scope.

```php
<?php
$globalName = 'Peach';

function displayGlobalName(): void {
    // echo $globalName;  // Notice (PHP 7) / Warning (PHP 8): Undefined variable
    echo "Inside displayGlobalName, \$globalName is NOT directly accessible.<br>";
}

displayGlobalName();
```

The `echo $globalName;` line inside `displayGlobalName()` would generate a Notice or Warning because `$globalName` is outside the function's local scope. PHP treats function scope as a sealed bubble by default, which is a deliberate design choice to prevent the spaghetti-code problem of globals silently modifying each other.

## 3. The `global` Keyword

If you specifically need to access or modify a global variable from inside a function, you must explicitly declare it using the `global` keyword within the function. The `global` keyword tells PHP to link the local variable name to the corresponding global variable.

```php
<?php
$globalMessage = "wow";

function changeGlobalMessage(): void {
    global $globalMessage;  // Now refers to the GLOBAL $globalMessage
    $globalMessage = "changed";
}

echo "Before: $globalMessage<br>";  // wow
changeGlobalMessage();
echo "After: $globalMessage<br>";   // changed
```

### 3.1 The `$GLOBALS` Superglobal

PHP also provides the `$GLOBALS` superglobal array. This is an associative array that contains references to all variables available in the global scope. You can access and modify global variables using this array from anywhere, including inside functions, without the `global` keyword.

```php
<?php
$websiteName = "My Awesome Site";

function updateWebsiteName(): void {
    $GLOBALS['websiteName'] = "My NEW Awesome Site";
}

updateWebsiteName();
echo $websiteName;  // My NEW Awesome Site
```

While `$GLOBALS` works, the `global` keyword is generally preferred for clarity when you only need to access a few specific global variables. Better still is to avoid globals entirely — see the Best Practices section.

### 3.2 Why `global` Is Discouraged

Using `global` creates **tight coupling** between a function and the global state. The function is no longer self-contained: its behaviour depends on whatever value the global happens to have when it is called, which makes the function harder to test (you must set up the global before each test) and harder to reason about (the same call can produce different results depending on global state). The `global` keyword is a code smell in modern PHP. The clean alternatives are to pass data through parameters, use dependency injection (in classes), or use constants for truly global, unchanging values.

## 4. Static Variables

A `static` variable inside a function retains its value between function calls, but is still only accessible within that function. It combines the persistence of a global with the encapsulation of a local. Use cases include counters, memoization caches, and one-time initialisation flags.

```php
<?php
function callCounter(): int {
    static $count = 0;  // Initialised only on the first call
    $count++;
    return $count;
}

echo callCounter();  // 1
echo callCounter();  // 2
echo callCounter();  // 3
```

The `static $count = 0;` line runs only once — on the first call. On subsequent calls, `$count` retains its previous value. This is useful but should be used sparingly; a static variable is still hidden state that makes a function harder to test. For memoization, prefer a cache object that can be injected and reset.

## 5. Closures and the `use` Keyword

Anonymous functions (closures) have their own scope and do **not** automatically capture outer variables. To use an outer variable inside a closure, you must list it in a `use` clause. By default, the variable is captured **by value** — the closure gets a copy of its value at the time the closure is created. To capture by reference, prefix with `&`.

```php
<?php
$multiplier = 3;

$multiply = function ($n) use ($multiplier) {
    return $n * $multiplier;
};

echo $multiply(5);  // 15

$multiplier = 10;  // Does NOT affect $multiply — captured by value
echo $multiply(5);  // Still 15
```

To capture by reference (so changes to the outer variable affect the closure):

```php
<?php
$factor = 2;
$multiply = function ($n) use (&$factor) {
    return $n * $factor;
};

$factor = 10;
echo $multiply(5);  // 50 — captured by reference
```

Capture-by-reference is rarely what you want; it usually indicates a design that would be clearer with a class.

## 6. Arrow Functions and Automatic Capture

Arrow functions (PHP 7.4+) automatically capture outer variables **by value** — no `use` keyword needed. This makes them much cleaner than traditional closures for short callbacks. They cannot capture by reference.

```php
<?php
$factor = 10;

$scaled = array_map(fn($n) => $n * $factor, [1, 2, 3]);
// $scaled is [10, 20, 30] — $factor auto-captured by value

$factor = 100;
$scaled2 = array_map(fn($n) => $n * $factor, [1, 2, 3]);
// $scaled2 is [100, 200, 300] — captured the NEW value because the arrow
// function is created fresh inside array_map
```

The automatic capture makes arrow functions the natural choice for short, single-expression callbacks. See [[3.6.19. Functions]] for the full treatment of arrow functions and the modern function-related features.

## 7. Best Practices

Design your functions to operate on parameters passed to them and return values. This makes functions independent, easier to test, and less prone to side effects (unintended changes to other parts of your code). Minimise `global` keyword usage — relying on `global` creates tight coupling between your functions and the global state, making the code harder to understand, debug, and reuse. Use constants for truly global, unchanging values — for configuration settings, use `define()` or `const` (see [[3.6.9. Constants and Define]]) rather than global variables. Constants are globally accessible by default without needing `global`. Pass data via parameters — the cleanest way for a function to receive data is through its parameters. For complex dependencies (database connections, mailers, loggers), use dependency injection in classes rather than globals or singletons.

## Summary

PHP has three main scopes: local (inside a function, destroyed when the function exits), global (outside any function, not directly visible inside functions), and static (local but persistent across calls). The `global` keyword and `$GLOBALS` superglobal let functions access globals but are discouraged because they create tight coupling. Closures must explicitly capture outer variables with `use`, by value by default and by reference with `&`. Arrow functions (PHP 7.4+) automatically capture outer variables by value. The modern best practice is to design functions that receive data via parameters and return results, avoiding shared mutable state entirely.
