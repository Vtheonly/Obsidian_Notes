# 3.6.12. Conditions if else elseif switch

> [!info] Conditional statements are the decision-making building blocks of a program. PHP provides the classic `if`/`elseif`/`else` chain, the `switch` statement for multi-way value dispatch, the ternary operator for inline branches, the null coalescing operator `??` for default values, the nullsafe operator `?->` for chained method calls, and the PHP 8 `match` expression as a safer alternative to `switch`. Each has its place; choosing the wrong one leads to verbose, fragile code.

## 1. The if / elseif / else Structure

This structure allows you to test a series of conditions in order. The `if` is the first condition to be checked. `elseif` lets you check another condition if the previous `if` was false, and you can have multiple `elseif` statements. `else` is the fallback block that runs only if all preceding `if` and `elseif` conditions were false.

PHP checks the conditions from top to bottom. As soon as it finds a condition that is `true`, it executes that block of code and then exits the entire `if`/`elseif`/`else` chain.

```php
<?php
$price = 20;

if ($price < 10) {
    echo 'cheap';
} elseif ($price < 30) {
    echo 'moderate';  // This block will be executed
} else {
    echo 'expensive';
}
```

The execution walkthrough: `if ($price < 10)` — is `20 < 10`? False, so PHP skips this block. `elseif ($price < 30)` — is `20 < 30`? True, so PHP executes this block, printing "moderate". Because a condition was met, PHP now skips the final `else` block and continues with the code after the chain.

## 2. Combining Conditions with Logical Operators

Often, you need to check more than one thing within a single `if` statement. Logical operators combine conditions.

| Operator | Name | Rule |
| -------- | ---- | ---- |
| `&&` | AND | Both conditions must be `true` |
| `\|\|` | OR | At least one of the conditions must be `true` |
| `!` | NOT | Inverts a boolean (`!true` becomes `false`) |

`&&` and `||` short-circuit: as soon as the result is determined, the remaining conditions are not evaluated. This is useful for guard clauses like `if ($user !== null && $user->isActive())`.

```php
<?php
$products = [
    ['name' => 'shiny star',     'price' => 20],
    ['name' => 'green shell',    'price' => 10],
    ['name' => 'red shell',      'price' => 15],
    ['name' => 'gold coin',      'price' =>  5],
];

foreach ($products as $product) {
    // Products MORE than 2 AND LESS than 15
    if ($product['price'] > 2 && $product['price'] < 15) {
        echo htmlspecialchars($product['name']) . '<br>';
    }

    // Products that are very cheap OR very expensive
    if ($product['price'] < 10 || $product['price'] > 18) {
        echo htmlspecialchars($product['name']) . '<br>';
    }
}

// NOTE: if ($product['price'] > 20 && $product['price'] < 10)
// can NEVER be true. A number cannot be both greater than 20
// AND less than 10 at the same time. Check your logic!
```

## 3. The Ternary Operator

The ternary operator `? :` is a one-line shorthand for a simple `if/else`. It takes the form `condition ? value_if_true : value_if_false`. It is an expression, so it returns a value rather than executing a block.

```php
<?php
$age = 20;
$status = ($age >= 18) ? 'adult' : 'minor';
echo $status; // adult
```

A common pitfall is nesting ternaries, which produces unreadable code due to PHP's left-associative parsing: `a ? b : c ? d : e` parses as `(a ? b : c) ? d : e`, not `a ? b : (c ? d : e)`. Always use parentheses when nesting, or just use a regular `if/else`. PHP 8 deprecates nesting without parentheses to make this trap explicit.

## 4. The Null Coalescing Operator `??`

PHP 7 introduced `??`, the null coalescing operator. It returns its left operand if it is set and not `null`; otherwise, it returns its right operand. It is the clean way to provide a default value for a possibly-missing array key or variable.

```php
<?php
$user = ['name' => 'Alice', 'email' => null];

$name  = $user['name']  ?? 'Anonymous';   // 'Alice'
$email = $user['email'] ?? 'No email';    // 'No email' — null triggers fallback
$phone = $user['phone'] ?? 'No phone';    // 'No phone' — missing key triggers fallback
```

The `??` operator does not produce a Notice for missing array keys or undefined variables, which is its key advantage over the older `isset($x) ? $x : $default` pattern. It can also be chained: `$a ?? $b ?? $c` returns the first non-null value.

The null coalescing assignment operator `??=`, introduced in PHP 7.4, combines the check and the assignment: `$config['timeout'] ??= 30;` sets `timeout` to `30` only if it is currently null or unset.

## 5. The Nullsafe Operator `?->` (PHP 8)

PHP 8 introduced `?->`, the nullsafe method call operator. When you chain method or property accesses, `?->` short-circuits the entire chain if the left-hand side is `null`, returning `null` immediately instead of throwing an "attempt to read property on null" error.

```php
<?php
// PHP 7 — verbose null checks needed
$country = null;
if ($user !== null) {
    $address = $user->getAddress();
    if ($address !== null) {
        $country = $address->getCountry();
    }
}

// PHP 8 — nullsafe operator
$country = $user?->getAddress()?->getCountry();
```

The entire chain evaluates to `null` if any link is `null`. This is a substantial readability win for object traversal code.

## 6. The switch Statement

The `switch` statement is an alternative to a chain of `if/elseif` when you are comparing one variable against many possible values. It is cleaner than a long `elseif` chain for equality checks.

```php
<?php
$userRole = 'admin';

switch ($userRole) {
    case 'admin':
        echo 'Admin access granted.';
        break;  // CRITICAL — stops the switch from falling through
    case 'editor':
        echo 'Editor access granted.';
        break;
    default:
        echo 'Guest access.';
}
```

The most important rule of `switch` is the `break` statement. Without it, PHP "falls through" to the next case, executing its code regardless of whether the case matched. This is occasionally useful (multiple cases sharing the same body) but more often a bug. A `switch` statement uses **loose comparison** (`==`), not strict, which is one of its dangers — `switch ("0") { case 0: ... }` matches.

## 7. The `match` Expression (PHP 8)

PHP 8 introduced `match`, a safer and more concise alternative to `switch`. `match` is an expression (it returns a value), uses **strict comparison** (`===`) automatically, supports combined conditions, does not fall through, and throws `UnhandledMatchError` if no arm matches.

```php
<?php
$statusCode = 404;

$message = match($statusCode) {
    200, 300    => 'Success',
    404         => 'Not found',
    500         => 'Server error',
    default     => 'Unknown status',
};

echo $message; // Not found
```

The advantages over `switch` are substantial: strict comparison prevents type-juggling bugs, the absence of fall-through eliminates the forgotten-`break` bug, returning a value is more concise than assigning inside a `case`, and the unhandled-match error forces you to think about all cases. Use `match` for value comparisons; reserve `switch` for the rare cases where fall-through is intentional.

## 8. Alternative Syntax for Templates

When you need to use conditional statements inside an HTML file, repeatedly using `<?php ... ?>` for `{` and `}` is messy. PHP provides a cleaner alternative syntax for templates: replace the opening brace `{` with a colon `:`, and the closing brace `}` with `endif;`.

The messy way:

```php
<ul>
  <?php foreach ($products as $product) { ?>
    <?php if ($product['price'] > 15) { ?>
      <li><?php echo htmlspecialchars($product['name']); ?></li>
    <?php } ?>
  <?php } ?>
</ul>
```

The clean way (recommended):

```php
<ul>
  <?php foreach ($products as $product): ?>
    <?php if ($product['price'] > 15): ?>
      <li><?= htmlspecialchars($product['name']) ?></li>
    <?php endif; ?>
  <?php endforeach; ?>
</ul>
```

See [[3.6.7. Mixing PHP and HTML]] for the full set of alternative control-flow syntaxes.

## Summary

PHP's conditional toolbox has grown over the years: `if`/`elseif`/`else` for sequential checks, `switch` for multi-way value dispatch (with fall-through and loose comparison), the ternary operator for inline branches, `??` for null-safe defaults, `?->` for null-safe method chains (PHP 8), and `match` for strict, fall-through-immune value comparison (PHP 8). The modern best practice is to prefer `match` over `switch` for value comparisons, use `??` and `?->` to avoid verbose null checks, and use the alternative syntax (`if (...) endif`) inside HTML templates.
