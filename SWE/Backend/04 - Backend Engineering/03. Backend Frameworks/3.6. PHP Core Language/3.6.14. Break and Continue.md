# 3.6.14. Break and Continue

> [!info] Loops are designed to repeat a block of code until a condition is no longer met, but sometimes you need to alter that flow from inside the body. The `break` and `continue` statements give you that precise control. `break` terminates the loop entirely; `continue` skips the rest of the current iteration. Both accept an optional numeric argument that controls how many enclosing loops they affect. This note also covers the famous `continue`-inside-`switch` gotcha.

## 1. The break Statement

The `break` statement immediately terminates the execution of the current loop. No further iterations will run, and execution continues on the first line *after* the loop's closing brace `}`. A useful analogy: `break` is the emergency stop button on an assembly line — everything stops instantly.

### 1.1 When to Use break

Use `break` when you have found what you were looking for and there is no need to continue looping. This saves processing time and makes the code's intent explicit. A linear search through a list, for example, should break as soon as the target is found rather than iterating through the remaining elements.

### 1.2 Example — Finding the First Expensive Product

```php
<?php
$products = [
    ['name' => 'green shell',     'price' => 10],
    ['name' => 'red shell',       'price' => 15],
    ['name' => 'lightning bolt',  'price' => 40], // The loop will stop here
    ['name' => 'shiny star',      'price' => 20], // Never checked
    ['name' => 'gold coin',       'price' =>  5], // Never checked
];

echo "Searching for the first expensive item...<br>";

foreach ($products as $product) {
    echo "Checking " . htmlspecialchars($product['name']) . "...<br>";

    if ($product['price'] > 30) {
        echo "FOUND IT! It's the " . htmlspecialchars($product['name']) . ".<br>";
        break;  // Exit the foreach loop immediately
    }
}

echo "Loop finished. Search complete.";
```

Output:

```text
Searching for the first expensive item...
Checking green shell...
Checking red shell...
Checking lightning bolt...
FOUND IT! It's the lightning bolt.
Loop finished. Search complete.
```

Notice how 'shiny star' and 'gold coin' were never checked. The `break` saved us from iterating through the rest of the array unnecessarily.

## 2. The continue Statement

The `continue` statement skips the rest of the current iteration and immediately jumps to the start of the next iteration. The loop itself does not terminate. The analogy: `continue` is telling a worker on an assembly line to skip this one item and move on to the next.

### 2.1 When to Use continue

Use `continue` when you encounter an element that you do not want to process, but you still need to check the remaining elements in the loop. A common pattern is filtering at the top of the loop body — check a precondition, `continue` if it fails, and put the actual processing logic below.

### 2.2 Example — Displaying Only High-Priced Products

```php
<?php
$products = [
    ['name' => 'green shell',     'price' => 10], // Skipped
    ['name' => 'red shell',       'price' => 15], // Skipped
    ['name' => 'lightning bolt',  'price' => 40],
    ['name' => 'shiny star',      'price' => 20],
    ['name' => 'gold coin',       'price' =>  5], // Skipped
];

echo "<h3>Expensive Products:</h3>";
echo "<ul>";

foreach ($products as $product) {
    if ($product['price'] <= 15) {
        continue;  // Skip the rest of this iteration
    }
    echo "<li>" . htmlspecialchars($product['name']) . "</li>";
}

echo "</ul>";
```

Output:

```html
<h3>Expensive Products:</h3>
<ul>
  <li>lightning bolt</li>
  <li>shiny star</li>
</ul>
```

The `continue` effectively filtered the list, allowing the code to ignore the cheaper items and only execute the `echo` statement for the ones above the threshold.

## 3. The Optional Numeric Argument — `break N` and `continue N`

Both `break` and `continue` accept an optional integer argument that specifies how many enclosing nested structures to affect. `break 1` is the same as `break` — it exits the innermost loop. `break 2` exits the innermost loop *and* the next-outer loop, and so on. This is most often used to break out of nested loops from inside the inner loop.

```php
<?php
$matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 99],  // Looking for 99
];

foreach ($matrix as $rowIndex => $row) {
    foreach ($row as $colIndex => $value) {
        if ($value === 99) {
            echo "Found 99 at row $rowIndex, col $colIndex.<br>";
            break 2;  // Break out of BOTH loops
        }
    }
}
echo "Search done.";
```

Without `break 2`, the inner `break` would only exit the inner `foreach`, and the outer loop would continue iterating the remaining rows. The same syntax applies to `continue`: `continue 2` skips to the next iteration of the outer loop.

While `break N` is occasionally the cleanest solution to a nested-search problem, an alternative is to refactor the search into a function and use `return` — this is often more readable than `break 2`.

## 4. The `continue` Inside `switch` Gotcha

This is one of the most surprising behaviours in PHP. Inside a `switch` statement, `continue` acts like `break` — it exits the current `case`. This is because `switch` is, historically, considered a loop-like structure for the purposes of `continue`. The result is that `continue` and `break` are interchangeable inside a `switch`, which is almost never what you want.

```php
<?php
$values = [1, 2, 3, 'skip', 5];

foreach ($values as $v) {
    switch (true) {
        case is_int($v) && $v < 3:
            echo "Small int: $v<br>";
            break;
        case $v === 'skip':
            continue;  // INTENDED: skip to next iteration of foreach
                       // ACTUAL: same as break — falls out of switch only
            // The rest of the foreach body still runs!
            break;
        default:
            echo "Other: $v<br>";
    }
    echo "Bottom of loop body for $v<br>";
}
```

If you want `continue` to skip the rest of the *foreach* iteration (not just the `switch`), you must use `continue 2`:

```php
case $v === 'skip':
    continue 2;  // Skip to the next iteration of the foreach loop
```

This gotcha is the source of many subtle bugs. PHP 7.3+ emits a warning when `continue` is used inside a `switch` for exactly this reason. The safest rule is: never use `continue` inside a `switch`; always use `break`, and use `continue 2` if you genuinely need to skip the enclosing loop iteration.

## 5. Summary Table

| Keyword | Action | Affects | Analogy | Primary Use Case |
| ------- | ------ | ------- | ------- | ---------------- |
| `break` | Terminates the loop entirely | The whole loop block | Emergency stop button | Stop looping once a goal is achieved |
| `break N` | Terminates N enclosing loops | N nested loops | Pulling the plug on a section | Exit nested search loops from inside |
| `continue` | Skips the rest of the current iteration | The current iteration | Skip-this-item button | Filter elements and proceed with the rest |
| `continue N` | Skips to the next iteration of the Nth outer loop | N nested loops | Skip-this-outer-item | Skip remaining inner loop too |
| `break` in `switch` | Exits the current `case` | The `switch` block | — | Standard switch fall-through prevention |
| `continue` in `switch` | Same as `break` (gotcha!) | The `switch` block | — | Almost never intentional — use `continue 2` |

## 6. When to Avoid break and continue

While `break` and `continue` are legitimate control-flow tools, they can make loops harder to reason about when overused. A loop with three `continue` statements and two `break` statements has many exit points, which makes it difficult to verify by reading. In these cases, refactoring the loop into a function with explicit `return` statements is often clearer. For the specific case of "find the first element matching a condition," PHP 8's `array_find` (from the new array functions RFC) or a manual `foreach` with `break` is fine; deeply nested loops with `break 3` are a code smell.

## Summary

`break` terminates the loop entirely; `continue` skips the rest of the current iteration only. Both accept an optional numeric argument (`break 2`, `continue 2`) that controls how many enclosing nested loops they affect. The famous gotcha is that `continue` inside a `switch` behaves like `break` — to skip the enclosing loop iteration, use `continue 2`. Use these statements judiciously; prefer extracting complex loop logic into a function with explicit `return` statements when there are multiple exit conditions.
