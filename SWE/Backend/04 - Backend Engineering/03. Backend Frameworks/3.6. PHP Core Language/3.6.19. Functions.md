# 3.6.19. Functions

> [!info] Functions are self-contained blocks of code that perform a specific task. They are the most fundamental tool for organising PHP code into reusable, testable, and maintainable units. Modern PHP (7.4, 8.0, 8.1) has added a stream of function-related features: return type declarations, nullable and union types, named arguments, variadic parameters, the spread operator, arrow functions, and first-class callable syntax. This note covers the basics and the modern additions.

## 1. Why Use Functions

Imagine you need to perform the same calculation or display the same formatted data multiple times throughout an application. Without functions, you would have to copy and paste the same lines of code repeatedly. Functions solve this problem with five concrete benefits: **reusability** (write code once, use it many times), **modularity** (break complex problems into smaller, manageable chunks where each function handles one task), **readability** (code becomes easier to understand when logic is grouped into named functions), **maintainability** (a change in one place propagates everywhere), and **reduced bugs** (less copied code means fewer places for errors to hide).

## 2. Defining and Calling a Function

Functions are defined using the `function` keyword, followed by the function name, a pair of parentheses `()`, and a block of code enclosed in curly braces `{}`.

```php
<?php
function sayHello(): void {
    echo "Hello, PHP Learner!<br>";
}

sayHello();  // Hello, PHP Learner!
sayHello();  // Hello, PHP Learner!
```

Function names should be descriptive and reflect what the function does. They typically use `camelCase` (e.g., `calculateTotal`, `getUserData`). Names must start with a letter or underscore, followed by letters, numbers, or underscores. Function names are not case-sensitive in PHP, but it is *highly* recommended to always call them with the same casing as defined.

## 3. Function Parameters

Functions can accept input values, called **parameters** (or arguments), that influence their behaviour.

### 3.1 Required and Default Parameters

Required parameters must be provided when the function is called. Default parameters can be omitted — the default value is used instead. Default parameters *must* come after any non-default (required) parameters.

```php
<?php
function greetUser(string $name = 'Guest', string $greeting = 'Hello'): void {
    echo htmlspecialchars($greeting) . ", " . htmlspecialchars($name) . "!<br>";
}

greetUser('Yoshi');             // Hello, Yoshi!
greetUser();                    // Hello, Guest!
greetUser('Shaun', 'Welcome');  // Welcome, Shaun!
```

### 3.2 Type Declarations (PHP 7+)

You can specify the expected data type for parameters and return values. This makes your code more robust and readable, helping catch errors early. With `declare(strict_types=1)` at the top of the file, PHP enforces types strictly rather than coercing.

```php
<?php
declare(strict_types=1);

function addNumbers(int $num1, int $num2): int {
    return $num1 + $num2;
}

echo addNumbers(10, 20);  // 30
// echo addNumbers('5', '10');  // TypeError with strict_types
```

### 3.3 Nullable Types (`?int`)

A nullable type is prefixed with `?` and accepts either the specified type or `null`. Useful for optional arguments where `null` is a meaningful "not provided" signal distinct from a default value.

```php
<?php
function findUser(?int $id): ?string {
    if ($id === null) return null;
    return "User #$id";
}
```

### 3.4 Union Types (PHP 8.0)

Union types let a parameter or return value be one of several types, written as `int|float|string`. The previous workaround was PHPDoc annotations; PHP 8 made them native and verifiable at runtime.

```php
<?php
function formatPrice(int|float $price): string {
    return '$' . number_format($price, 2);
}
```

There is also the special `mixed` type (PHP 8.0+) which means "any type" — useful when a function truly accepts anything, but a sign that the design might benefit from being more specific.

### 3.5 Variadic Parameters with `...`

A function can accept any number of arguments using the `...` token. The variadic parameter becomes an array inside the function.

```php
<?php
function sum(int ...$numbers): int {
    return array_sum($numbers);
}

echo sum(1, 2, 3);        // 6
echo sum(1, 2, 3, 4, 5);  // 15
```

### 3.6 The Spread Operator for Arguments

Conversely, the `...` token unpacks an array into function arguments. This is the inverse of variadic parameters.

```php
<?php
$nums = [1, 2, 3];
echo sum(...$nums);  // 6 — same as sum(1, 2, 3)
```

### 3.7 Named Arguments (PHP 8.0)

Named arguments let you pass arguments to a function by name rather than position. This is especially useful for functions with many optional parameters where you want to set only one.

```php
<?php
function makeCoffee(string $type = 'latte', string $size = 'medium', bool $decaf = false): string {
    return "A $size " . ($decaf ? 'decaf ' : '') . $type;
}

echo makeCoffee(size: 'large', type: 'espresso');  // A large espresso
echo makeCoffee(decaf: true);                       // A medium decaf latte
```

Named arguments make code self-documenting and resistant to parameter-order changes. They are particularly valuable with framework functions that have many configuration flags.

## 4. Return Values

Functions send a value back to the caller using the `return` statement. `return` immediately exits the function — any code after `return` is unreachable. A function can return any data type, and since PHP 7 you can declare the return type after a colon.

```php
<?php
function calculateArea(int $width, int $height): int {
    return $width * $height;
    echo "This line will never be reached.";
}

$roomArea = calculateArea(5, 8);
echo "The room's area is $roomArea square meters.<br>";
```

### 4.1 Returning Multiple Values

PHP functions can only return a single value, but you can package multiple values into an array (or, since PHP 8.1, use a named tuple-like structure via a readonly class). Array destructuring on the call site makes the multi-return pattern readable.

```php
<?php
function getUserInfo(string $id): array {
    if ($id === 'user123') {
        return ['name' => 'Alice', 'age' => 30, 'email' => 'alice@example.com'];
    }
    return ['name' => 'Unknown', 'age' => 0, 'email' => ''];
}

['name' => $userName, 'age' => $userAge] = getUserInfo('user123');
echo "Name: $userName, Age: $userAge";
```

### 4.2 Never Return Type (PHP 8.1)

The `never` return type indicates that a function never returns — it either calls `exit`, throws an exception, or runs forever. This is useful for redirect helpers, exception-throwing helpers, and event loops, and it tells static analysers that code after the call is unreachable.

```php
<?php
function redirect(string $url): never {
    header("Location: $url");
    exit;
}

redirect('/login');
echo "This will never execute.";
```

## 5. Variable Scope — A Brief Mention

Variables declared *inside* a function are **local** to that function — they cannot be accessed from outside, and they disappear when the function finishes. Variables declared outside the function (in the global scope) are *not* directly accessible inside the function unless you use the `global` keyword (which is discouraged). The clean way to give a function access to external data is to pass it as an argument. See [[3.6.20. Variable Scope]] for the full treatment.

## 6. Anonymous Functions (Closures)

Anonymous functions are functions without a name. They are often used as arguments to other functions (callbacks) or assigned to variables. They create their own scope and must explicitly import external variables using the `use` keyword.

```php
<?php
$sayGoodbye = function (string $name): void {
    echo "Goodbye, " . htmlspecialchars($name) . "!<br>";
};

$sayGoodbye('Luigi');  // Goodbye, Luigi!

$numbers = [1, 2, 3];
$doubled = array_map(function ($n) { return $n * 2; }, $numbers);
// $doubled is [2, 4, 6]
```

## 7. Arrow Functions (PHP 7.4+)

Arrow functions are a concise syntax for simple anonymous functions, especially one-liners. They automatically capture external variables **by value** — no `use` keyword needed — which makes them cleaner than traditional closures for short callbacks.

```php
<?php
$multiply = fn($a, $b) => $a * $b;
echo $multiply(5, 3);  // 15

$factor = 10;
$scaled = array_map(fn($n) => $n * $factor, [1, 2, 3]);
// $scaled is [10, 20, 30] — $factor auto-captured by value
```

Arrow functions are expressions, so they can be used anywhere an expression is valid: as array elements, as arguments, in ternaries. They cannot have multi-line bodies — for that, use a traditional closure.

## 8. First-Class Callable Syntax (PHP 8.1)

PHP 8.1 introduced a clean way to create a closure from any callable: append `(...)` to the callable name. This replaces the older `Closure::fromCallable('functionName')` syntax.

```php
<?php
function square(int $n): int { return $n * $n; }

// Old way:
$fn = Closure::fromCallable('square');

// New way (PHP 8.1+):
$fn = square(...);

echo $fn(5);  // 25

// Works with methods too:
$logger = new Logger();
$handler = $logger->log(...);
```

This makes higher-order functions cleaner — passing a function reference is now `func(...)` rather than a string `'func'` (which has no static analysis guarantees).

## 9. Best Practices

Each function should do one thing and do it well (Single Responsibility Principle). Function names should clearly describe their purpose. If a function takes too many parameters, it is probably doing too much, or the parameters should be grouped into an object. Avoid side effects: a function should ideally only affect its own scope and return a value, rather than modifying global state or printing directly. Use type declarations on parameters and return values — they cost nothing and catch bugs early. And keep functions short — a function that fits on one screen is easier to reason about than one that scrolls.

## Summary

Functions are the primary unit of code organisation in PHP. Modern PHP has added many features on top of the basic syntax: typed parameters and return values, nullable (`?int`) and union (`int|float`) types, variadic parameters with `...`, the spread operator for unpacking, named arguments (`size: 'large'`), arrow functions (`fn($x) => $x * 2`) for concise closures, and first-class callable syntax (`func(...)`) for creating closures from any callable. The Single Responsibility Principle and explicit type declarations are the foundations of maintainable PHP code.
