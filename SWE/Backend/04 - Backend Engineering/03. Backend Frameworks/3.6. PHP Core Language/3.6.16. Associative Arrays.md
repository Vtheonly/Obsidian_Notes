# 3.6.16. Associative Arrays

> [!info] An associative array uses meaningful string keys to identify values, making it PHP's dictionary or map type. It is the workhorse structure for records, configuration, request payloads, and any data where the key describes the value. This note covers creation, CRUD operations, the `foreach` iteration that preserves insertion order, the subtle key-type coercion rules, the `isset` vs `array_key_exists` distinction, and the spread operator for unpacking.

## 1. The Anatomy of a Key-Value Pair

At the heart of an associative array is the **key-value pair**: `'key' => 'value'`. The key is the unique identifier for the value. It must be either an *integer* or a *string* — in associative arrays, we almost always use descriptive strings like `'name'`, `'email'`, `'age'`. The value can be any data type: a string, a number, a boolean, another array, or an object.

For `$ninjas = ['shaun' => 'black', 'mario' => 'orange', 'luigi' => 'brown'];`:

| Key | `=>` | Value | Description |
| --- | ---- | ----- | ----------- |
| `'shaun'` | Arrow | `'black'` | The key `'shaun'` points to the value `'black'` |
| `'mario'` | Arrow | `'orange'` | The key `'mario'` points to the value `'orange'` |
| `'luigi'` | Arrow | `'brown'` | The key `'luigi'` points to the value `'brown'` |

## 2. CRUD Operations

CRUD stands for Create, Read, Update, Delete — a helpful framework for thinking about data manipulation.

### 2.1 Create

You create an array by declaring it, and you can add new key-value pairs at any time.

```php
<?php
$ninjas = ['mario' => 'orange', 'luigi' => 'brown'];
$ninjas['peach'] = 'pink';
// print_r($ninjas) now shows 'peach' => 'pink' as the third element.
```

### 2.2 Read

You read a value by referencing its key in square brackets `[]`.

```php
<?php
echo $ninjas['mario']; // orange

// Accessing a key that doesn't exist?
echo $ninjas['bowser']; // Warning (PHP 8): Undefined array key "bowser"
```

### 2.3 Update

You update a value by assigning a new value to an existing key.

```php
<?php
$ninjas['mario'] = 'red';
echo $ninjas['mario']; // red
```

### 2.4 Delete

To completely remove a key-value pair from an array, use the `unset()` language construct.

```php
<?php
$ninjas = ['mario' => 'red', 'luigi' => 'brown', 'peach' => 'pink'];
unset($ninjas['luigi']);
// print_r($ninjas) now shows only 'mario' and 'peach'.
```

## 3. Iteration Order and the `foreach` Loop

Because associative array keys are not predictable numbers, a standard `for` loop is not suitable. The `foreach` loop is designed specifically for arrays. A crucial property of PHP arrays is that **iteration order is guaranteed to match insertion order** — the first key you added is the first one you see when iterating. This is a deliberate design choice; in many other languages (Python before 3.7, JavaScript's `Object` keys before ES2015) hash map iteration order is unspecified.

### 3.1 Looping Through Values Only

```php
<?php
$ninjas = ['shaun' => 'black', 'mario' => 'orange', 'luigi' => 'brown'];

echo "<h3>Ninja Belt Colors:</h3><ul>";
foreach ($ninjas as $color) {
    echo "<li>A ninja has a $color belt.</li>";
}
echo "</ul>";
```

### 3.2 Looping Through Both Keys and Values

This is the most common iteration form, as you often need both.

```php
<?php
$ninjas = ['shaun' => 'black', 'mario' => 'orange', 'luigi' => 'brown'];

echo "<h3>Ninja Roster:</h3><ul>";
foreach ($ninjas as $name => $beltColor) {
    echo "<li><strong>$name</strong> has a $beltColor belt.</li>";
}
echo "</ul>";
```

Output:
- **shaun** has a black belt.
- **mario** has a orange belt.
- **luigi** has a brown belt.

See [[3.6.13. Loops for while foreach do-while]] for the full treatment of `foreach`, including by-reference iteration with `&$value`.

## 4. Key Type Coercion — A Subtle Trap

PHP arrays accept both integer and string keys, but the engine performs a quiet coercion that surprises developers. **Numeric strings are silently cast to integers** when used as array keys. The string `'5'` becomes the integer `5`. The string `'+5'` also becomes `5`. The string `'5.0'` does not — it stays a string, because it is not a "canonical integer string." Floats are truncated to integers when used as keys: `8.7` becomes `8`. Booleans become integers: `true` becomes `1`, `false` becomes `0`. `null` becomes the empty string `''`.

```php
<?php
$arr = [
    '1'   => 'one',     // stored as int key 1
    1     => 'ONE',     // overwrites the previous entry — same key
    '1.0' => 'one point zero',  // stays as string key '1.0'
    true  => 'true',    // stored as int key 1 — overwrites again
];

print_r($arr);
// Array ( [1] => true [1.0] => one point zero )
```

This coercion means that mixing numeric-string keys with integer keys can lead to surprising overwrites. The practical advice is: pick a key type and stick with it. Use string keys like `'user_5'` if you need to avoid the coercion.

## 5. Checking If a Key Exists — `isset` vs `array_key_exists`

Directly accessing a key that might not exist produces a Warning. To avoid this, you should check for the key's existence first. There are two main ways, and they differ in a subtle but important way.

| Function | `isset($array['key'])` | `array_key_exists('key', $array)` |
| -------- | ---------------------- | --------------------------------- |
| Returns `true` when | The key exists **and** its value is not `null` | The key exists, **regardless of its value** |
| Performance | Marginally faster (language construct) | Marginally slower (function call) |
| When to use | 95% of the time — you usually care if the key has a real value | Only when you explicitly need to know if a key is set, even if its value is `null` |

```php
<?php
$userProfile = ['name' => 'Yoshi', 'email' => null];

var_dump(isset($userProfile['name']));             // bool(true)
var_dump(array_key_exists('name', $userProfile));  // bool(true)

var_dump(isset($userProfile['email']));            // bool(false) — null!
var_dump(array_key_exists('email', $userProfile)); // bool(true)

var_dump(isset($userProfile['missing']));          // bool(false)
var_dump(array_key_exists('missing', $userProfile)); // bool(false)
```

The distinction matters when an API returns `null` to mean "this field is explicitly set to no value" versus "this field is absent." In most application code, you want `isset` — a null value is treated as missing.

## 6. Useful Functions for Associative Arrays

### 6.1 `array_keys()` and `array_values()`

`array_keys($array)` returns a new indexed array containing all the keys. `array_values($array)` returns a new indexed array containing all the values, discarding the keys. The latter is useful when you want to convert an associative array into a list (for example, after a `foreach` filter or after `array_unique`).

```php
<?php
$ninjas = ['shaun' => 'black', 'mario' => 'orange'];
$allKeys   = array_keys($ninjas);   // ['shaun', 'mario']
$allValues = array_values($ninjas); // ['black', 'orange']
```

### 6.2 `array_merge()`

`array_merge($a, $b)` merges two or more arrays into a new one. When merging associative arrays, the behaviour depends on the keys. If the arrays have different string keys, the keys are simply added to the new array. If the arrays have the **same string key**, the value from the **last array** in the sequence **overwrites** the previous ones.

```php
<?php
$ninjasOne = ['shaun' => 'black', 'mario' => 'orange', 'peach' => 'brown'];
$ninjasTwo = ['bowser' => 'green', 'peach' => 'yellow'];

$merged = array_merge($ninjasOne, $ninjasTwo);
print_r($merged);
// Array (
//   [shaun]  => black
//   [mario]  => orange
//   [peach]  => yellow   // 'brown' overwritten by 'yellow'
//   [bowser] => green
// )
```

For the same operation with integer keys, `array_merge` reindexes everything rather than overwriting. Use the `+` operator if you want first-key-wins behaviour instead — `$a + $b` keeps the value from `$a` for duplicate keys.

### 6.3 `array_map`, `array_filter`, `array_reduce`

These three higher-order functions are the functional-programming core for arrays. `array_map($callback, $array)` applies a function to each value and returns a new array with the results, preserving keys. `array_filter($array, $callback)` keeps only the elements for which the callback returns `true` (use `ARRAY_FILTER_USE_KEY` or `ARRAY_FILTER_USE_BOTH` to access keys). `array_reduce($array, $callback, $initial)` folds the array into a single value.

```php
<?php
$scores = ['alice' => 88, 'bob' => 42, 'carol' => 95, 'dave' => 33];

// Double every score
$doubled = array_map(fn($s) => $s * 2, $scores);

// Keep only passing scores (>= 60)
$passing = array_filter($scores, fn($s) => $s >= 60);

// Average score
$avg = array_sum($scores) / count($scores);
```

A common gotcha: `array_filter` preserves keys, so the result is no longer a list. Wrap with `array_values()` if you need a list.

## 7. Array Unpacking with the Spread Operator

PHP 7.4 introduced the spread operator (`...`) for unpacking arrays in function arguments, and PHP 8.1 extended it to work with string-keyed (associative) arrays in array literals.

```php
<?php
// Unpacking in function calls (PHP 5.6+)
function greet(string $greeting, string $name): void {
    echo "$greeting, $name!";
}
$args = ['Hello', 'Alice'];
greet(...$args);  // Hello, Alice!

// Unpacking in array literals (PHP 7.4 for indexed, 8.1 for string keys)
$defaults = ['host' => 'localhost', 'port' => 3306, 'timeout' => 30];
$override = ['port' => 5432, 'ssl'  => true];
$config   = [...$defaults, ...$override];
// ['host' => 'localhost', 'port' => 5432, 'timeout' => 30, 'ssl' => true]
```

The spread operator is a clean alternative to `array_merge` for combining arrays, with one key difference: duplicate string keys in spread unpacking cause the later value to overwrite the earlier one, just like `array_merge`. The spread operator is faster than `array_merge` because it is a language construct, not a function call.

## 8. When to Use Associative vs Indexed Arrays

Use **indexed arrays** for ordered lists of items where the index is just a position. Examples: a shopping list, a list of players in a game, a queue of tasks. The order matters; the names of the slots (0, 1, 2) do not.

Use **associative arrays** for records or descriptive data where the key names describe the value. Examples: a user profile (`'name'`, `'email'`, `'id'`), configuration settings (`'db_host'`, `'db_user'`), a dictionary entry. The order usually does not matter; the description (the key) is essential.

In modern PHP, you might also reach for a class with typed properties when the structure is fixed and known at design time. A `User` class with `public readonly string $name` is safer than `['name' => 'Alice']` because the type system enforces the shape. Use associative arrays for ad-hoc structures and DTOs that cross module boundaries; use classes for the domain model. See [[3.6.19. Functions]] and the Laravel/Symfony notes for the framework patterns.

## Summary

Associative arrays are PHP's dictionary type, using string keys to identify values. Iteration order is guaranteed to match insertion order. The `foreach` loop is the natural way to iterate. PHP silently coerces numeric-string keys to integers, which can cause surprising overwrites — pick a key type and stick with it. Use `isset` for "key exists and is not null"; use `array_key_exists` only when you need to detect null values. `array_keys`, `array_values`, `array_merge`, `array_map`, `array_filter`, and `array_reduce` are the essential functions. The spread operator `...` (extended to string-keyed arrays in PHP 8.1) provides a cleaner alternative to `array_merge` for combining arrays.
