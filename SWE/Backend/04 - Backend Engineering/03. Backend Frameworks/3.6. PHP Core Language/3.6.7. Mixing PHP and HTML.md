# 3.6.7. Mixing PHP and HTML

> [!info] PHP was designed from the start as a templating language that lives inside HTML. The `<?php ?>` tag is the canonical escape into PHP, the `<?= ?>` short echo tag is its concise output cousin, and the alternative syntax (`if (...): ... endif;`, `foreach (...): ... endforeach;`) makes control flow readable inside HTML. This note covers the three mechanisms and the modern best practices for keeping template files clean.

## 1. PHP Tags — The Escape Hatches

PHP code is embedded in HTML using special tags. The web server (or PHP-FPM) recognises these tags, hands the contents to the PHP interpreter, and substitutes the tag with whatever the interpreter outputs. Everything outside the tags is sent to the browser verbatim.

### 1.1 The Canonical Tag: `<?php ?>`

The `<?php ?>` tag is the only PHP tag guaranteed to be enabled on every server, regardless of configuration. It opens with `<?php` and closes with `?>`. Inside the tag, the normal rules of PHP syntax apply: statements end with semicolons, variables start with `$`, and so on.

```php
<?php
  $username = 'CodeNinja';
  $age = 28;
  $location = 'Tokyo';
?>

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title><?php echo htmlspecialchars($username); ?>'s Profile</title>
</head>
<body>
  <h1><?php echo 'User: ' . htmlspecialchars($username); ?></h1>
  <p><?php echo "Age: $age years old"; ?></p>
  <p><?php echo "Location: $location"; ?></p>
</body>
</html>
```

A subtle but important rule: if a file is *pure* PHP (no trailing HTML), you should omit the closing `?>` tag. The reason is that any whitespace or newline after a closing `?>` gets sent to the browser as output, which can break HTTP headers ("headers already sent" errors) when a later `header()` call tries to set a cookie or redirect. Omitting the close tag is the universal convention in PHP library files.

### 1.2 The Short Echo Tag: `<?= ?>`

The `<?= ?>` tag is shorthand for `<?php echo ?>`. It is always available since PHP 5.4, regardless of the `short_open_tag` setting. It is the idiomatic way to output a single expression inside HTML and is the foundation of every PHP template.

```php
<title><?= htmlspecialchars($pageTitle) ?></title>
<h1><?= htmlspecialchars($heading) ?></h1>
<p>Price: $<?= number_format($price, 2) ?></p>
```

Note that `<?= ?>` does not require a trailing semicolon — it takes a single expression, evaluates it, and prints the result. This is the cleanest way to interpolate a PHP value into HTML, and modern PHP frameworks all use it in their raw template files.

### 1.3 The Legacy Short Open Tag: `<? ?>` (Avoid)

The `<? ?>` tag (without the `php` or `=`) is a legacy short open tag that is disabled by default since PHP 5.4 and conflicts with XML declarations (`<?xml ?>`). Never use it. It is mentioned here only so that you recognise it in old code and know to rewrite it.

## 2. Single Quotes vs Double Quotes in Templates

The type of quote you use to wrap a string changes how PHP interprets it. This is one of the most important concepts to grasp early, because template code is full of strings.

Single quotes create a **literal string**. PHP does not process or interpret almost anything inside them. Variables are not parsed — `$name` inside single quotes is printed as the literal text `$name`. Most escape sequences like `\n` or `\t` are not parsed either; they are printed literally. The only escape sequences that work inside single quotes are `\'` (escaped single quote) and `\\` (escaped backslash).

Double quotes create an **interpreted string**. PHP scans the string for variables and certain escape sequences and replaces them with their actual values. This is called **variable interpolation**. Variables starting with `$` are replaced by their value, and escape sequences like `\n`, `\t`, `\r`, and `\$` are interpreted.

```php
<?php
$framework = 'Laravel';

echo 'I am learning $framework.\nNew line.';
// Browser output: I am learning $framework.\nNew line.

echo "I am learning $framework.\nNew line.";
// Browser output: I am learning Laravel.
//                 New line.  (newline visible in page source)
```

| Feature | Single quotes `' '` | Double quotes `" "` |
| ------- | ------------------- | -------------------- |
| Variable parsing | No — `$name` printed literally | Yes — replaced with the value |
| Escape sequences | Only `\'` and `\\` | `\n`, `\t`, `\r`, `\$`, `\\`, `\u{...}` |
| Performance | Marginally faster | Marginally slower (parsing overhead) |
| Best use | Literal strings, regex, code | Interpolation of variables |

For complex interpolation, PHP supports `{$variable}` (curly braces around the variable name) which works inside double-quoted strings and disambiguates complex expressions: `"Hello, {$user->name}!"` or `"Items: {$cart['count']}"`.

## 3. The Alternative Syntax for Control Structures

When you need to use `if`, `foreach`, `while`, or `for` inside an HTML file, repeatedly opening `<?php ... ?>` for `{` and `}` produces unreadable code. PHP provides a cleaner alternative syntax specifically for templates: replace the opening brace `{` with a colon `:`, and replace the closing brace `}` with a keyword like `endif;`, `endforeach;`, `endwhile;`, or `endfor;`.

The messy way:

```php
<ul>
  <?php foreach ($products as $product) { ?>
    <?php if ($product['price'] > 15) { ?>
      <li><?php echo htmlspecialchars($product['name']); ?></li>
    <?php } ?>
  <?php } ?>
</ul>
```

The clean way (recommended):

```php
<ul>
  <?php foreach ($products as $product): ?>
    <?php if ($product['price'] > 15): ?>
      <li><?= htmlspecialchars($product['name']) ?></li>
    <?php endif; ?>
  <?php endforeach; ?>
</ul>
```

The alternative syntax clearly shows where each block starts and ends within the HTML structure, without a confusing jumble of curly braces. Every control structure has an alternative form: `if`/`elseif`/`else` use `endif;`, `foreach` uses `endforeach;`, `while` uses `endwhile;`, `for` uses `endfor;`, and `switch` uses `endswitch;`.

## 4. A Worked Example

A common pattern is to define variables at the top of a file (the controller logic) and then render them in the HTML below (the view). This pattern is the foundation of every more advanced PHP architecture — see [[3.6.5. PHP Architectures]] for the full evolution.

```php
<?php
$products = [
  ['name' => 'Mechanical Keyboard', 'price' => 129.99, 'stock' => 15],
  ['name' => 'Wireless Mouse',      'price' =>  29.50, 'stock' =>  0],
  ['name' => 'USB-C Hub',           'price' =>  44.00, 'stock' =>  7],
];
?>

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Product Listing</title>
</head>
<body>
  <h1>Today's Products</h1>
  <table>
    <thead>
      <tr><th>Name</th><th>Price</th><th>Stock</th></tr>
    </thead>
    <tbody>
      <?php foreach ($products as $p): ?>
        <tr>
          <td><?= htmlspecialchars($p['name']) ?></td>
          <td>$<?= number_format($p['price'], 2) ?></td>
          <td>
            <?php if ($p['stock'] === 0): ?>
              <em>Out of stock</em>
            <?php elseif ($p['stock'] < 5): ?>
              <strong>Low stock (<?= $p['stock'] ?> left)</strong>
            <?php else: ?>
              <?= $p['stock'] ?> available
            <?php endif; ?>
          </td>
        </tr>
      <?php endforeach; ?>
    </tbody>
  </table>
</body>
</html>
```

Notice how every value coming from the `$products` array is wrapped in `htmlspecialchars()` before being printed. This is the **golden rule of output**: never trust data, escape it on the way out. See [[3.6.18. htmlspecialchars and Output Escaping]] for the full explanation.

## 5. Modern Best Practices

The naive mixing of PHP and HTML works for small pages but does not scale. As a project grows, the best practice is to separate logic from presentation as strictly as possible. Three concrete rules help.

First, push logic to the top of the file or into separate controller files. The template section should contain only simple variable echoes, loops, and conditionals — no database queries, no business decisions. Second, use the alternative syntax religiously in templates. The visual clarity of `endif;` and `endforeach;` over scattered `}` is dramatic in any non-trivial template. Third, escape every output value with `htmlspecialchars()` unless you have a specific reason not to.

For larger projects, graduate to a templating engine like Twig (Symfony) or Blade (Laravel). These engines provide auto-escaping (so you do not have to remember `htmlspecialchars` on every line), template inheritance (so a layout can define a header and footer that child templates fill in), and helpers for common tasks like formatting dates and numbers. They also restrict the subset of PHP available in templates, which prevents the temptation to put logic in the view. See [[3.5.1. Laravel Overview and Installation]] for how Blade fits into a Laravel project.

## Summary

PHP's three templating mechanisms — `<?php ?>` for arbitrary PHP, `<?= ?>` for short output, and the alternative control-flow syntax (`if:`, `foreach:`, `endif;`, `endforeach;`) — are enough to write clean, maintainable templates. The rule of thumb is to put logic at the top of the file, use short echo tags for output, use the alternative syntax for control flow, and escape every value with `htmlspecialchars()`. For larger projects, a real templating engine like Twig or Blade replaces these primitives with auto-escaping, inheritance, and a safer subset of PHP.
