## 2. Topic Outline & Atomic Notes

This module is designed to take you from a blank directory to a production-ready, test-driven Express application:

### [[3.1.1. Installing Express.js|1. Environment, Modules & Package Management]]
*Setting up a deterministic, standardized development sandbox.*
* **Module Systems:** CommonJS (`require`) vs modern ECMAScript Modules (`import`/`export`), ESM interop.
* **Lockfiles & Verifying Builds:** Manifest setups, SemVer constraints, and why you must run `npm ci` rather than `npm install` in your deployment pipelines.

### [[3.1.2. First App and Project Structure|2. Bootstrapping Your First Application]]
*The foundation blocks of an Express instance.*
* **App Factory:** Invoking `express()` and configuring basic application settings via `app.set()` and `app.get()`.
* **Basic Structure:** Registering a simple test route, mapping port bindings, and spinning up a local dev server with `nodemon` or the native Node `--watch` tool.

### [[3.1.3. GET Routes and Routing|3. Express Routing Engine]]
*Building robust URL routing rules.*
* **Request Mapping:** Standard routes (`app.get()`, `app.post()`, etc.), verb grouping with `app.route()`, and routing setups with nested prefixes using `express.Router()`.
* **Path Parameters:** Capturing route variables (e.g., `:id`), setting up optional params, wildcard fallback endpoints, and handling common routing fallthrough issues (the shadow route bug).

### [[3.1.4. CURL and API Testing|4. API Testing with cURL]]
*Interacting with running web applications from the CLI.*
* **CLI Testing:** Formulating valid GET, POST, PUT, and DELETE HTTP requests.
* **Inspecting Payloads:** Querying with headers, passing formatted JSON, and reading response logs directly inside your terminal.

### [[3.1.5. Query Parameters and Request Object|5. Query Strings and Request Inspection]]
*How web apps parse client parameters and inspect headers.*
* **Query Parsing:** Query string formats and parsing engines (`qs` bracket/array notation vs native `URLSearchParams`).
* **Request Inspection:** Parsing IP addresses, protocols, user agents, cookies, and custom headers.

### [[3.1.6. Express Middleware Architecture|6. Chain of Responsibility Pattern]]
*Understanding the core engine pipeline pattern behind Express.*
* **Signature Rules:** The `(req, res, next) => { ... }` middleware blueprint.
* **Pipeline Lifecycles:** App-level, Router-level, Built-in, and 4-argument Exception handlers.
* **The Hanging Request Pitfall:** Debugging pipelines where execution hangs due to omitted terminations or missing `next()` triggers.

### [[3.1.7. Express Request and Response Objects|7. Deep Dive: req & res APIs]]
*Mastering the rich surface area of HTTP messages inside the framework.*
* **Request API:** Under-the-hood properties (`req.headers`, `req.cookies`, `req.secure`).
* **Response API:** Controlling status codes, content-type headers, static file responses, and redirects via `res.json()`, `res.status()`, and `res.sendFile()`.

### [[3.1.8. Custom Middleware and Chaining|8. Building & Chaining Custom Middlewares]]
*Writing tailored handlers to implement cross-cutting concerns.*
* **Custom Code:** Logging parameters, auth guards, tracking request IDs across services, and injecting request-context properties.
* **Chaining Sequences:** Mounting arrays of custom middleware to target specific endpoints or routers.

### [[3.1.9. Input Validation with Zod|9. Defensive Coding & Validation]]
*Protecting your database from bad query payloads or untrusted client inputs.*
* **Validation Lifecycles:** Defining strict schemas, type-coercion, and safe parsing via **Zod**.
* **Formatted Errors:** Intercepting validation schema errors and formatting them into clean, standardized HTTP 400 JSON payloads.

### [[3.1.10. Express.js Layered Architecture and MVC|10. Layered MVC & Decoupled Architecture]]
*Scaling your project codebase past a single file using production blueprints.*
* **Separation of Concerns:** Dividing files into Routing, Controllers, Services, Repository/Models, and Configurations.
* **Decoupling Application:** Splitting Express initialization (`app.js`) from port binding (`index.js`) to allow decoupled server runs and mock testing environments.

### [[3.1.11. Integration Testing with Supertest and Vitest|11. Writing Pipeline Tests]]
*Testing routes and middleware pipelines reliably without binding ports.*
* **Integration Frameworks:** Running endpoint assertions via `supertest` and Vitest or Jest.
* **Mock Testing:** Simulating database transactions, testing authentication scenarios, and tracking test coverage.

### [[3.1.12. Graceful Shutdown and WebSocket Upgrades|12. High-Availability Operational Concerns]]
*Deploying highly resilient, modern full-duplex systems.*
* **Graceful Exit:** Binding listeners to POSIX OS signals (`SIGTERM`, `SIGINT`) to finish running request buffers and terminate database pools safely.
* **WebSockets:** Extracting the raw HTTP server wrapper, hijacking connection pipelines, and upgrading HTTP sockets to WebSocket structures (`ws`, `socket.io`).
