# 3.4.11. Spring Boot Integration Testing with SpringBootTest

> [!info] Orientation
> A robust test suite is key to maintaining clean, production-ready software. Spring Boot provides excellent support for integration testing by instantiating the Spring application context directly. This note details how to write high-performance integration tests using `@SpringBootTest`, mock web layers using `MockMvc`, and isolate database tests using `@DataJpaTest`.

---

## 1. Testing Modes in Spring Boot

Spring Boot classifies testing into three core paradigms depending on how much of the application context is loaded:

1. **Unit Tests (No Spring Context):** Testing pure Java classes with mock dependencies (using JUnit 5 and Mockito). These are extremely fast and decoupled from Spring.
2. **Sliced Context Tests (Partial Context):** Loading only the specific Spring beans required to test a single layer (such as `@WebMvcTest` for controller routing, or `@DataJpaTest` for database persistence).
3. **Full Integration Tests (`@SpringBootTest`):** Bootstrapping the entire application context, loading all configuration classes, auto-configurations, database connections, and active profiles.

```mermaid
graph TD
    Test[Spring Test Runner] --> Sliced[Sliced Context Tests]
    Test --> Full[Full Integration Tests]
    
    Sliced --> WebMvc[@WebMvcTest: Only controllers & routing]
    Sliced --> DataJpa[@DataJpaTest: Only JPA repositories & SQL]
    
    Full --> SBTest[@SpringBootTest: Entire Bean Container & AutoConfig]
```

## 2. Bootstrapping Full Context Tests with `@SpringBootTest`

To test the end-to-end integration of controllers, business services, and database layers, use `@SpringBootTest`:

```java
@SpringBootTest(webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT)
@ActiveProfiles("test") // Loads application-test.properties configuration overrides
class UserIntegrationTest {

    @LocalServerPort
    private int port; // Capture the random port bound by Tomcat

    @Autowired
    private TestRestTemplate restTemplate; // Standard client helper for HTTP queries

    @Autowired
    private UserRepository userRepository;

    @BeforeEach
    void cleanUp() {
        userRepository.deleteAll(); // Clean state before each test
    }

    @Test
    void shouldRegisterUserAndPersistToDatabase() {
        // Arrange
        UserRegistrationRequest request = new UserRegistrationRequest("tester", "test@example.com", "pw123");

        // Act
        ResponseEntity<UserDto> response = restTemplate.postForEntity(
            "http://localhost:" + port + "/api/users", request, UserDto.class
        );

        // Assert
        expect(response.getStatusCode()).toBe(HttpStatus.CREATED);
        expect(response.getBody().getEmail()).toBe("test@example.com");
        
        // Verify database persistence
        Optional<User> persistedUser = userRepository.findByEmail("test@example.com");
        expect(persistedUser.isPresent()).toBe(true);
    }
}
```

## 3. Sliced MVC Testing with `MockMvc` and `@MockBean`

If you want to test controller routing, status code mappings, validation constraints, and serialization without starting the embedded servlet container (Tomcat) or connecting to a database, use `@WebMvcTest`:

```java
@WebMvcTest(UserController.class) // Load only the web layer for UserController
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc; // Emulates HTTP requests directly in memory

    @MockBean
    private UserService userService; // Mock the business logic service dependency

    @Test
    void shouldReturnUserById() throws Exception {
        // Arrange
        UserDto mockUser = new UserDto(1L, "tester", "test@example.com");
        Mockito.when(userService.getUserById(1L)).thenReturn(mockUser);

        // Act & Assert
        mockMvc.perform(MockMvcRequestBuilders.get("/api/users/1")
                .accept(MediaType.APPLICATION_JSON))
                .andExpect(MockMvcResultMatchers.status().isOk())
                .andExpect(MockMvcResultMatchers.jsonPath("$.username").value("tester"))
                .andExpect(MockMvcResultMatchers.jsonPath("$.email").value("test@example.com"));
    }
}
```

## 4. Database Sliced Testing with `@DataJpaTest`

To verify database custom queries, triggers, or Hibernate mappings quickly, use `@DataJpaTest`.
* `@DataJpaTest` disables standard autoconfiguration and loads *only* JPA repository beans and transaction managers.
* By default, it configures an in-memory database (such as H2) automatically, bypassing your production database connection details.
* It wraps every test inside a transaction and automatically rolls it back at the end of the test, keeping the database in-memory cleanly isolated.

```java
@DataJpaTest
class UserRepositoryTest {

    @Autowired
    private UserRepository userRepository;

    @Test
    void shouldFindUserByEmail() {
        // Arrange
        User user = new User("tester", "test@example.com", "pw");
        userRepository.save(user);

        // Act
        Optional<User> found = userRepository.findByEmail("test@example.com");

        // Assert
        expect(found.isPresent()).toBe(true);
        expect(found.get().getUsername()).toBe("tester");
    }
}
```

## Summary

Spring Boot provides a highly complete testing framework. By selecting `@SpringBootTest` for full end-to-end flow verifications, `@WebMvcTest` with `MockMvc` for fast HTTP routing and validation tests, and `@DataJpaTest` for transactional database queries, developers can maintain a fast, highly reliable deployment suite.
