# 19. Gray Code

## 1. Problem Description

A Gray code of length `n` is a list of all `2^n` bit strings of length `n`, where any two successive strings differ in exactly one bit (Hamming distance `1`).

Create a Gray code for a given length `n`.

## 2. Expected Input

A single integer `n`.

## 3. Expected Output

Print `2^n` lines, each containing an `n`-bit string. Any valid Gray code is accepted.

## 4. Constraints

- `1 <= n <= 16`
- Time limit: 1.00 s
- Memory limit: 512 MB

## 5. Examples

| Input | Output |
|---|---|
| `2` | `00`<br>`01`<br>`11`<br>`10` |

## 6. Intuition

The standard **reflected Gray code** is built recursively:
- Gray code for `n = 1` is `["0", "1"]`.
- Gray code for `n = k` is: prepend `"0"` to each string in Gray(k-1), then prepend `"1"` to each string in the reverse of Gray(k-1).

Equivalently, the `i`-th Gray code (0-indexed) is `i ^ (i >> 1)`.

```mermaid
flowchart LR
```

## 8. Brute-Force Approach

Generate all `2^n` bit strings, then try all `2^n!` orderings to find one where consecutive strings differ in one bit. Completely infeasible.

## 9. Optimized Solution

```python
def solve(n: int) -> list[str]:
    """Return the reflected Gray code of length n."""
    result = []
    for i in range(1 << n):
        gray = i ^ (i >> 1)
        result.append(format(gray, f"0{n}b"))
    return result


if __name__ == "__main__":
    n = int(input())
    for code in solve(n):
        print(code)
```

## 10. Why the Optimized Solution Works

**The formula `gray(i) = i ^ (i >> 1)`** produces the reflected Gray code. Here's why:

Consider the binary representations of `i` and `i >> 1`:
- `i` in binary: `b_{n-1} b_{n-2} ... b_1 b_0`.
- `i >> 1` in binary: `0 b_{n-1} b_{n-2} ... b_1`.

XOR them bit by bit:
- Bit `j` of `gray(i)` = `b_j XOR b_{j+1}` (with `b_n = 0`).

Now consider `gray(i)` and `gray(i + 1)`:
- The binary representations of `i` and `i + 1` differ in some bits. Specifically, if `i` ends in `011...1` (with `k` trailing 1s), then `i + 1` ends in `100...0` (with `k` trailing 0s). All higher bits are the same.
- The Gray code changes only at the position where `i` and `i+1` differ in their `b_{j+1}` bit. Specifically, the trailing 1s in `i` mean that `gray(i)` has alternating bits at the end, and `gray(i+1)` flips exactly one bit.

A more concrete proof: the Gray code sequence has the property that `gray(i) XOR gray(i+1)` has exactly one bit set. This is a known result; see Knuth's TAOCP or any digital logic textbook.

**Recursive construction** (equivalent):
- `Gray(1) = ["0", "1"]`.
- `Gray(k) = ["0" + s for s in Gray(k-1)] + ["1" + s for s in reversed(Gray(k-1))]`.

The recursive construction "reflects" the previous code and prepends 0/1, which is why it's called the **reflected** Gray code.

## 11. Algorithm Used

Closed-form formula `gray(i) = i ^ (i >> 1)`.

## 12. Data Structures Used

- A list `result` to collect the codes.
- Integers and string formatting.

## 13. Time Complexity Analysis

**`O(2^n * n)`** — we generate `2^n` codes, each requiring `O(n)` work to format as a binary string.

For `n = 16`, this is `65536 * 16 = ~10^6` operations. Fast.

## 14. Space Complexity Analysis

**`O(2^n * n)`** to store all the codes as strings.

## 15. Step-by-Step Code Walkthrough

1. Loop `i` from `0` to `2^n - 1`.
2. Compute `gray = i ^ (i >> 1)`.
3. Format `gray` as a binary string with `n` digits, zero-padded: `format(gray, f"0{n}b")`.
4. Append to `result`.
5. Print each code.

## 16. Dry Run with Example

Input: `n = 2`.

| i | i (binary) | i >> 1 | gray = i ^ (i>>1) | gray (binary, 2 digits) |
|---|---|---|---|---|
| 0 | 00 | 00 | 00 | `00` |
| 1 | 01 | 00 | 01 | `01` |
| 2 | 10 | 01 | 11 | `11` |
| 3 | 11 | 01 | 10 | `10` |

Output: `00, 01, 11, 10`. Matches expected.

**Check the Gray property**: consecutive codes differ in exactly one bit.
- `00` vs `01`: differ in bit 0. OK.
- `01` vs `11`: differ in bit 1. OK.
- `11` vs `10`: differ in bit 0. OK.

## 17. Common Pitfalls

- **Forgetting to zero-pad.** `format(2, "b")` gives `"10"`, but for `n = 4` we want `"0010"`. Use `format(gray, f"0{n}b")` to ensure `n` digits.
- **Using the wrong formula.** Some students try `i ^ (i << 1)` or `(i << 1) ^ i`, which are different and don't produce a valid Gray code.
- **Off-by-one in the range.** `range(1 << n)` produces `0, 1, ..., 2^n - 1`, which is correct.

## 18. Edge Cases

| Case | Expected Behavior |
|---|---|
| `n = 1` | `0`, `1` (two codes) |
| `n = 16` | `65536` codes, each 16 bits |
| `n = 0` (out of constraints) | `0` (single empty code) |

## 19. Alternative Approaches

- **Recursive construction**: Build Gray(k) from Gray(k-1) by reflection. Same complexity.
- **Iterative reflection**: Start with `["0", "1"]`, then for each additional bit, reflect and prepend. Same complexity.

```python
def solve_recursive(n: int) -> list[str]:
    if n == 1:
        return ["0", "1"]
    smaller = solve_recursive(n - 1)
    return ["0" + s for s in smaller] + ["1" + s for s in reversed(smaller)]
```

## 21. Key Takeaways

- **Gray code formula `i ^ (i >> 1)`** is a fundamental bit-manipulation identity. Memorize it.
- **The reflected construction** (prepend 0 to original, prepend 1 to reversed) is the recursive way to think about Gray codes.
- **Hamming distance 1** between consecutive codes is the defining property. This is useful in error-correcting codes and digital logic.
- The formula `i ^ (i >> 1)` is `O(1)` per code, making it the fastest way to generate Gray codes.
