# 6. Missing Number

## 1. Problem Description

You are given all numbers between `1` and `n` except one. Find the missing number.

## 2. Expected Input

- First line: integer `n`.
- Second line: `n - 1` distinct integers between `1` and `n` (inclusive).

## 3. Expected Output

The missing number.

## 4. Constraints

- `2 <= n <= 2 * 10^5`
- Time limit: 1.00 s
- Memory limit: 512 MB

## 5. Examples

| Input | Output |
|---|---|
| `5`<br>`2 3 1 5` | `4` |

## 6. Intuition

The sum of integers from `1` to `n` is `n * (n + 1) / 2`. The sum of the given `n - 1` numbers is the same sum minus the missing number. So:

```
missing = n*(n+1)/2 - sum(given)
```

This is `O(n)` time and `O(1)` extra space.

## 7. Thought Process

```mermaid
flowchart LR
    A["Read n"] --> B["expected = n*(n+1)//2"]
    B --> C["Read n-1 numbers"]
    C --> D["actual = sum of those"]
    D --> E["missing = expected - actual"]
    E --> F["Print missing"]
```

## 8. Brute-Force Approach

Sort the array, then scan for the gap. `O(n log n)` time, `O(n)` space. Works but is slower than the sum formula.

Alternative: use a boolean array of size `n + 1` to mark which numbers are present. `O(n)` time, `O(n)` space. Also works but uses more memory.

## 9. Optimized Solution

```python
def solve(n: int, nums: list[int]) -> int:
    """Return the missing number from 1..n."""
    expected = n * (n + 1) // 2
    actual = sum(nums)
    return expected - actual


if __name__ == "__main__":
    n = int(input())
    nums = list(map(int, input().split()))
    print(solve(n, nums))
```

## 10. Why the Optimized Solution Works

The set of integers from `1` to `n` has sum `S = 1 + 2 + ... + n = n*(n+1)/2`. The input contains every integer in `[1, n]` except the missing one `m`. Therefore the sum of the input is `S - m`, and `m = S - sum(input)`.

The arithmetic is exact: `n*(n+1)` is always even (one of `n`, `n+1` is even), so integer division by `2` is exact. There is no rounding error.

For `n = 2 * 10^5`, `S = 2*10^5 * 200001 / 2 = 2*10^10`, which fits comfortably in a 64-bit integer (and Python's `int` is arbitrary precision anyway).

## 11. Algorithm Used

Gauss's sum formula.

## 12. Data Structures Used

- The list `nums` (required because we have to read the input).
- Scalar integers for the sums.

## 13. Time Complexity Analysis

**`O(n)`** — one pass to sum the input.

## 14. Space Complexity Analysis

**`O(1)`** extra space (we only need the running sum). In Python, `sum()` is lazy in the sense that it doesn't build intermediate structures.

## 15. Step-by-Step Code Walkthrough

1. `expected = n * (n + 1) // 2` — Gauss's formula. Use `//` for integer division.
2. `actual = sum(nums)` — built-in sum is implemented in C and is fast.
3. `return expected - actual` — the missing number.

## 16. Dry Run with Example

Input: `n = 5`, `nums = [2, 3, 1, 5]`.

- `expected = 5 * 6 / 2 = 15`.
- `actual = 2 + 3 + 1 + 5 = 11`.
- `missing = 15 - 11 = 4`. Correct.

## 17. Common Pitfalls

- **Overflow in other languages.** In C++ with `int`, `n*(n+1)` for `n = 2*10^5` is `4*10^10`, which overflows 32-bit `int`. Use `long long`. In Python this is a non-issue.
- **Floating-point division.** Using `/` instead of `//` in Python gives a float, which can introduce precision errors for very large `n`. Always use `//`.
- **Reading the input.** The second line may have trailing whitespace or newlines; `input().split()` handles this gracefully.

## 18. Edge Cases

| Case | Expected Behavior |
|---|---|
| `n = 2`, missing is `1` | `nums = [2]`, `expected = 3`, `actual = 2`, answer `1` |
| `n = 2`, missing is `2` | `nums = [1]`, `expected = 3`, `actual = 1`, answer `2` |
| `n = 2*10^5` (max) | Works; sum fits in 64-bit |

## 19. Alternative Approaches

- **XOR approach**: XOR all numbers from `1` to `n`, then XOR with all input numbers. The result is the missing number. `O(n)` time, `O(1)` space. Avoids potential overflow in languages without big integers.
- **Sorting**: `O(n log n)` time, `O(n)` space (or `O(1)` if in-place). Slower but works.
- **Boolean array**: `O(n)` time, `O(n)` space. Simple but uses extra memory.

```python
def solve_xor(n: int, nums: list[int]) -> int:
    result = 0
    for i in range(1, n + 1):
        result ^= i
    for x in nums:
        result ^= x
    return result
```

## 21. Key Takeaways

- **Gauss's sum formula `n*(n+1)/2`** is a fundamental identity. Memorize it.
- **Sum-based "find the missing element" problems** are common in interviews. The same trick works for finding a missing number in an arithmetic progression.
- **XOR is a useful alternative** when overflow is a concern, because XOR is associative, commutative, and `a ^ a = 0`.
- Always prefer `O(1)` space over `O(n)` space when the problem allows it.
