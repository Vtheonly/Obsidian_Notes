# 9. Bit Strings

## 1. Problem Description

Calculate the number of bit strings of length `n`. A bit string is a string of `0`s and `1`s. For `n = 3`, the answer is `8` because the possible strings are `000, 001, 010, 011, 100, 101, 110, 111`.

Output the result modulo `10^9 + 7`.

## 2. Expected Input

A single integer `n`.

## 3. Expected Output

The number of bit strings of length `n`, modulo `10^9 + 7`.

## 4. Constraints

- `1 <= n <= 10^6`
- Time limit: 1.00 s
- Memory limit: 512 MB

## 5. Examples

| Input | Output |
|---|---|
| `3` | `8` |

## 6. Intuition

Each of the `n` positions can be either `0` or `1`, independently. So the total count is `2^n`. Compute this modulo `10^9 + 7` using fast exponentiation.

## 8. Brute-Force Approach

Compute `2^n` by multiplying `2` by itself `n` times. `O(n)` time. For `n = 10^6`, this is acceptable but slower than necessary. Also, without modular reduction at each step, the intermediate value becomes astronomically large (`10^301030` digits).

## 9. Optimized Solution

```python
def solve(n: int) -> int:
    """Return 2^n mod (10^9 + 7)."""
    MOD = 10**9 + 7
    return pow(2, n, MOD)


if __name__ == "__main__":
    n = int(input())
    print(solve(n))
```

## 10. Why the Optimized Solution Works

The number of bit strings of length `n` is `2^n` because each of the `n` positions has 2 independent choices. By the multiplication principle, the total is `2 * 2 * ... * 2 = 2^n`.

Python's built-in `pow(base, exp, mod)` uses **modular exponentiation by squaring**, which is `O(log n)`. It computes `(base^exp) mod mod` without ever materializing the enormous intermediate value `2^n`.

The modular reduction is consistent because `(a * b) mod m = ((a mod m) * (b mod m)) mod m`. So we can reduce at each multiplication step without changing the final answer.

## 11. Algorithm Used

Modular exponentiation by squaring (built-in `pow` with three arguments).

- Scalar integers only.

## 17. Common Pitfalls

- **Using `2 ** n % MOD` instead of `pow(2, n, MOD)`.** The first form computes `2^n` as a huge integer first, then takes the modulus. For `n = 10^6`, `2^n` has ~300,000 digits; computing it is slow and memory-intensive. Always use the three-argument `pow`.
- **Forgetting the modulus.** The problem requires the answer modulo `10^9 + 7`.
- **Wrong modulus value.** It's `10**9 + 7 = 1000000007`, not `10**9` or `10**9 + 9`.

## 18. Edge Cases

| Case | Expected Behavior |
|---|---|

| Very large `n` (out of constraints) | Still fast in Python |

## 19. Alternative Approaches

- **Manual binary exponentiation**: implement `pow_mod` yourself using the square-and-multiply algorithm. Same complexity, but more code.
- **Iterative multiplication with modular reduction**: `O(n)`. Slower but works for `n = 10^6`.

```python
def pow_mod_iterative(base: int, exp: int, mod: int) -> int:
    result = 1
    for _ in range(exp):
        result = result * base % mod
    return result
```

## 21. Key Takeaways

- **`pow(base, exp, mod)`** is the correct way to compute modular exponentiation in Python. It is `O(log exp)` and never produces huge intermediate values.
- **Modular arithmetic identities** (`(a*b) mod m = ((a mod m) * (b mod m)) mod m`) let us reduce at each step.
- **`10^9 + 7`** is the standard modulus in competitive programming because it is prime (which makes modular inverses exist for all non-zero residues) and large enough to distinguish most answers.
- Counting problems often reduce to computing `k^n mod p` for some base `k` — always use fast exponentiation.
