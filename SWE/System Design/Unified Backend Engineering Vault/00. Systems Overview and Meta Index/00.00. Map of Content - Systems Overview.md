# 00.00. Map of Content: Systems Overview

## Overview

This section is the **roof of the vault** — the meta layer that every later section hangs from. It does not teach any single operating-system primitive, framework feature, or persistence mechanism. Instead it installs four pieces of conceptual scaffolding that the rest of the vault assumes you already hold in your head: (1) the **Universal Request-Response Pipeline** that turns an Ethernet frame on a NIC into a JSON response back out the same NIC; (2) the **anchor-and-delta learning protocol** that tells you to learn every concept deeply once in Spring Boot and then translate it as deltas to Express, Django, Flask, and Laravel; (3) a **terminology dictionary** that pins down what words like "idempotent", "WAL", "MVCC", and "exactly-once" actually mean so that downstream notes can use them without re-defining them; and (4) a **cross-ecosystem equivalence graph** that maps the same idea (say, "middleware") across all five ecosystems so that a delta translation is a lookup, not a research project.

Everything in sections 01 through 12 — operating systems, networking, runtime concurrency, framework abstractions, persistence, messaging, distributed systems, architecture, infrastructure, observability, serverless — is a zoomed-in view of one slice of the pipeline described in [[00.01. Master Architectural Mental Model]]. When you finish a section and want to remember where it fits, you come back here. When you are about to start a new section and want to know what mental model to carry in, you also come back here. This is the only section in the vault that is read out-of-order intentionally: jump in, jump out, jump back.

## Section Map

### Top Level Notes

- [[00.01. Master Architectural Mental Model]] — The single most important note in the vault. Teaches the **Universal Request-Response Pipeline** (NIC → DMA ring buffer → kernel TCP stack → `sk_buff` queue → `recv()` syscall → framework HTTP parser → router → middleware chain → controller method → serializer → `send()` syscall → socket write buffer → TCP segments → NIC egress) with real latencies, buffer sizes, and syscall names. Also defines the **layered abstraction hierarchy** (Silicon → Kernel → Syscalls → Runtimes → Frameworks), the **compute/network/storage plane decomposition**, and the principle of **Systems Invariance** — why `accept()`, `epoll_wait()`, `read()`, `write()`, `fsync()`, and `mmap()` are the same calls under every framework. Read this first; every other note in the vault assumes you have.

- [[00.02. The Anchor-and-Delta Learning Protocol]] — Explains the *learning method* the entire vault is built around: pick one strict, opinionated, multi-threaded, explicitly-typed stack (Java/Spring Boot + PostgreSQL) and learn every concept to production depth inside it. Then do a rapid **Δ-translation pass** into TypeScript/Express (the secondary concurrency anchor — event-loop, libuv, single-threaded async I/O), Python/Django, Python/Flask, and PHP/Laravel, recording only the deltas — what is automatic vs. manual, what is hidden vs. exposed, what is named differently. Includes the cognitive-science rationale (why anchoring beats parallel study), the explicit anti-patterns (context thrashing, tutorial loops, syntax memorization), and the per-ecosystem delta checklist.

- [[00.03. Unified Backend Engineering Terminology Dictionary]] — A real glossary, not a one-liner list. Each term — `socket`, `file descriptor`, `page cache`, `fsync`, `WAL`, `MVCC`, `ACID`, `CAP`, `consensus`, `idempotency`, `backpressure`, `circuit breaker`, `bulkhead`, `retry`, `jitter`, `exactly-once`, `at-least-once`, `at-most-once`, `outbox`, `CDC`, `saga`, `CQRS`, `event sourcing` — gets a paragraph that defines the mechanism, names the layer it lives on, and points at the failure mode it exists to prevent. Read this when a downstream note uses a word you cannot instantly define.

- [[00.04. Cross-Ecosystem Equivalence Graph]] — A lookup matrix that lets you find the equivalent concept across the five target ecosystems in O(1). Each row is a concept (routing, middleware, DI, validation, error handling, ORM, migrations, connection pooling, background jobs, auth, caching), each column is an ecosystem, each cell names the specific implementation (`@RequestMapping` + `DispatcherServlet` for Spring Boot routing, `Router().get()` + Express middleware pipeline for Express, `urlpatterns` + `URLResolver` for Django, `@app.route` + `Werkzeug`'s `Map` for Flask, `Route::get()` + `Router` for Laravel). Use it during the Δ-translation pass when you know the Spring Boot name and need the equivalent in another ecosystem.

## Conceptual Roadmap

The four child notes are not parallel — they form a strict dependency chain:

```
   ┌────────────────────────────────────────────────────────────────┐
   │  00.01. Master Architectural Mental Model                      │
   │  (The pipeline + the layered model + Systems Invariance)       │
   │  → installs the *map* of where everything in the vault lives   │
   └───────────────────────────┬────────────────────────────────────┘
                               │ depends on
                               ▼
   ┌────────────────────────────────────────────────────────────────┐
   │  00.02. The Anchor-and-Delta Learning Protocol                 │
   │  (Why anchor in Spring Boot; how to Δ-translate out)           │
   │  → installs the *method* you will use to traverse the map      │
   └───────────────────────────┬────────────────────────────────────┘
                               │ requires shared vocabulary
                               ▼
   ┌────────────────────────────────────────────────────────────────┐
   │  00.03. Unified Backend Engineering Terminology Dictionary     │
   │  (The fixed lexicon every downstream note uses)                │
   │  → installs the *words* the method operates on                 │
   └───────────────────────────┬────────────────────────────────────┘
                               │ consumed by the delta pass
                               ▼
   ┌────────────────────────────────────────────────────────────────┐
   │  00.04. Cross-Ecosystem Equivalence Graph                      │
   │  (The lookup table used during every Δ-translation)            │
   │  → the *tool* the method uses when the anchor's name for a     │
   │    concept must be translated into another ecosystem's name    │
   └────────────────────────────────────────────────────────────────┘
```

Read in numeric order on first pass: 00.01 builds the spatial mental model, 00.02 tells you how to learn inside it, 00.03 hands you the vocabulary, and 00.04 hands you the lookup table you will use during every delta pass. After the first pass you should be able to traverse them in any order — they cross-reference each other freely. If you find yourself reading a later section (say, section 06 on persistence) and you cannot remember what MVCC is, jump back to 00.03. If you cannot remember whether a `Repository` in Spring Boot corresponds to a `Manager` in Django or a `Model` in Laravel, jump back to 00.04. If you cannot remember which layer of the stack a syscall belongs to, jump back to 00.01.

## How to Read This Section

1. **Read 00.01 first, in full.** Do not skim. The four H3 sub-sections — the Universal Request-Response Pipeline, the compute/network/storage plane decomposition, Systems Invariance, and the layered abstraction hierarchy — are the load-bearing structure of the entire vault. Every later note assumes you can recite the pipeline from memory and name which layer a given syscall or framework feature belongs to.
2. **Read 00.02 next.** It explains *why* the vault is organized the way it is: one deep anchor implementation in Spring Boot, then rapid delta translations. Without this you will be tempted to learn each ecosystem in parallel — which is the explicit anti-pattern the protocol exists to prevent.
3. **Skim 00.03.** You do not need to memorize the dictionary on first pass. You need to know that *when a downstream note uses a term you cannot instantly define, the definition is in 00.03*. Bookmark it.
4. **Skim 00.04.** Same principle — it is a lookup table, not a textbook. You will return to it during every Δ-translation note in sections 05 onward.

> [!tip] Reading order
> First pass: 00.01 → 00.02 → 00.03 → 00.04, in strict numeric order. Revision pass: jump directly to whichever of the four you need. The four notes are designed to be re-entered randomly — each H3 is self-contained enough to be useful in isolation.

## Prerequisites

This is the entry point. No prerequisites. If you have written any HTTP backend in any language you have enough context. If you have not, read [[00.01. Master Architectural Mental Model]] first and treat every system call and framework name as a term to look up in [[00.03. Unified Backend Engineering Terminology Dictionary]].
