# 02.04.03. The POSIX Socket Lifecycle

## What This Is

**The POSIX Socket Lifecycle** is the sequence of syscalls that takes a network endpoint from non-existence to a connected, data-carrying file descriptor and back again: `socket()` to create the FD, `bind()` to assign a local address, `listen()` to mark the socket as passive, `accept()` to materialise a new connected FD per client, `connect()` on the client side to drive the TCP 3-way handshake, `send()` / `recv()` to exchange bytes, and `close()` to send `FIN` and tear down the connection. Every backend listener in the world — PostgreSQL's postmaster, Nginx's worker, Node's `net.Server`, Java's `ServerSocketChannel`, Python's `socketserver`, PHP-FPM's master — runs this exact eight-call dance on every connection. The reason this note sits in section 02 is that the lifecycle is kernel-enforced: the state machine (`UNBOUND → BOUND → LISTENING → CONNECTED → CLOSING`) is the kernel's `struct sock->sk_state`, and the transitions between states are syscall boundaries that the kernel validates. No runtime can skip a step; every runtime that wants to accept TCP connections must call `socket` + `bind` + `listen` + `accept` in that order, and every client must call `socket` + `connect`.

The mental model is: a listening socket is *one* FD that produces *many* child FDs. The `accept` syscall is the only kernel primitive that creates a new FD from an existing FD without re-opening the underlying resource — every other FD-creating syscall (`open`, `socket`, `pipe`, `eventfd`) takes a path or a fresh resource, but `accept` synthesises a new connected socket from the listening socket's accept queue. This is why a long-lived server can open the listening socket once and accept millions of connections over its lifetime — the listening FD is stable, the connected FDs are ephemeral. The kernel distinguishes the two via `struct sock->sk_state`: a listening socket is in `TCP_LISTEN` (state 10), a connected socket is in `TCP_ESTABLISHED` (state 1). Each accepted connection is a fresh `struct sock` allocated by `tcp_v4_rcv` during the 3-way handshake, queued in the listener's accept queue (`struct sock->ack_backlog`), and handed out by `accept`. Every metric you will ever see on a server (`ss -tan`, `netstat -an`, `Recv-Q`, `Send-Q`) reads these per-socket states directly from `/proc/net/tcp`.

The reason every backend engineer must internalise this lifecycle is that every production TCP incident maps onto one of its stages. "Connection refused" is a `connect` to an address where no socket is `LISTEN`ing. "Connection timed out" is a `connect` to an address where the SYN was dropped (firewall, full SYN queue, dead host). "Connection reset" is a `recv` returning `ECONNRESET` because the peer sent RST. "Address already in use" is a `bind` to an address where a previous socket is in `TIME_WAIT` (or still `LISTENING`). "Too many open files" is an `accept` failing with `EMFILE` because the process's FD table is full. The kernel exposes every one of these states through `/proc/net/tcp`, `ss -tan`, and the `tcpdump` of the wire traffic; once you can map a TCP error to a lifecycle stage, you can localise the bug in minutes.

## The Details

### Creating a network endpoint via `socket(AF_INET, SOCK_STREAM, 0)`

The `socket()` syscall is the entry point to the entire BSD sockets API. Its signature is `int socket(int domain, int type, int protocol)`, and it returns a non-negative integer (the new FD) or `-1` with `errno` on failure. The three arguments select which kernel code path will service the FD: `domain` picks the address family (`AF_INET` for IPv4, `AF_INET6` for IPv6, `AF_UNIX` for UNIX domain sockets, `AF_NETLINK` for kernel-to-userspace notifications, `AF_PACKET` for raw link-layer frames), `type` picks the semantic class (`SOCK_STREAM` for connection-oriented reliable byte streams — TCP for `AF_INET`, UDS-stream for `AF_UNIX`; `SOCK_DGRAM` for unordered unreliable datagrams — UDP; `SOCK_RAW` for direct IP-level access; `SOCK_SEQPACKET` for connection-oriented message-preserving streams), and `protocol` picks the specific protocol within the family+type (almost always `0` for "the default", which is `IPPROTO_TCP` for `AF_INET`+`SOCK_STREAM` and `IPPROTO_UDP` for `AF_INET`+`SOCK_DGRAM`). On success, the kernel allocates a fresh `struct socket` (VFS-level, in `include/linux/net.h`), a fresh `struct sock` (network-level, in `include/net/sock.h`), and a fresh `struct file` (FD-level), wires them together, picks the lowest available FD number, and returns it.

The `type` argument on Linux accepts two flag bits OR'd in: `SOCK_CLOEXEC` (set `FD_CLOEXEC` on the new FD atomically, so it does not leak across `fork`+`execve` — without this flag there is a race between `socket()` returning and a `fcntl(F_SETFD, FD_CLOEXEC)` call, during which a concurrent `fork`+`exec` in another thread would inherit the FD) and `SOCK_NONBLOCK` (set `O_NONBLOCK` on the new FD atomically, so the first `connect` or `accept` does not block). Both flags are Linux 2.6.27 additions and have POSIX equivalents in `socket()`'s `SOCK_CLOEXEC`/`SOCK_NONBLOCK` since POSIX.1-2008. Modern production code should always use `SOCK_CLOEXEC` — the alternative (`socket()` then `fcntl(F_SETFD, FD_CLOEXEC)`) is a race that has caused real security bugs (a forked SUID binary inheriting an open raw socket FD, for example). The pattern `socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC, 0)` is the canonical idiom for any non-blocking server.

The kernel data structures allocated by `socket()` are worth knowing because every subsequent syscall operates on them. `struct socket` (VFS) has fields `state` (the socket state machine: `SS_UNCONNECTED`, `SS_CONNECTING`, `SS_CONNECTED`, `SS_DISCONNECTING`), `type` (the `SOCK_*` type), `flags` (`SOCK_ASYNC_NOSPACE`, etc.), `ops` (a pointer to `const struct proto_ops`, the dispatch table — for `AF_INET`+`SOCK_STREAM` this is `inet_stream_ops`), and `sk` (a pointer to the underlying `struct sock`). `struct sock` (network) has hundreds of fields, but the load-bearing ones for backend engineering are: `sk_state` (`TCP_ESTABLISHED`, `TCP_LISTEN`, `TCP_TIME_WAIT`, etc.), `sk_receive_queue` (the `sk_buff` list of bytes that `recv` will return), `sk_write_queue` (the `sk_buff` list of bytes queued for transmission), `sk_sndbuf` and `sk_rcvbuf` (the send/receive buffer sizes, defaults 16 KB / 16 KB, configurable via `SO_SNDBUF`/`SO_RCVBUF` or via `/proc/sys/net/ipv4/tcp_{r,w}mem`), `sk_socket` (back-pointer to the VFS `struct socket`), and `sk_peercred` (for UDS, the PID/UID/GID of the peer). The lifetime of these structs is reference-counted: `sock_hold` increments, `sock_put` decrements, and when the count hits zero the struct is freed.

```c
/* The three-argument socket() call and the modern atomic-flags form. */
#include <sys/socket.h>
#include <netinet/in.h>
#include <unistd.h>
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main(void) {
    /* Legacy form — leaks the FD across fork+exec if not closed. */
    int fd_legacy = socket(AF_INET, SOCK_STREAM, 0);
    if (fd_legacy < 0) { perror("socket"); return 1; }

    /* Modern form — atomic cloexec + nonblock. */
    int fd_modern = socket(AF_INET,
                           SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC,
                           IPPROTO_TCP);
    if (fd_modern < 0) { perror("socket (modern)"); return 1; }

    /* Inspect what the kernel gave us. */
    int buf; socklen_t len = sizeof(buf);
    getsockopt(fd_modern, SOL_SOCKET, SO_TYPE, &buf, &len);
    printf("SO_TYPE = %d (SOCK_STREAM = %d)\n", buf, SOCK_STREAM);

    /* Inspect the FD flags — should have O_NONBLOCK and FD_CLOEXEC. */
    int fl = fcntl(fd_modern, F_GETFL);
    printf("O_NONBLOCK = %s\n", (fl & O_NONBLOCK) ? "yes" : "no");
    int fd_flags = fcntl(fd_modern, F_GETFD);
    printf("FD_CLOEXEC = %s\n", (fd_flags & FD_CLOEXEC) ? "yes" : "no");

    close(fd_legacy);
    close(fd_modern);
    return 0;
}

The connection to the layered mental model is the FD abstraction from [[02.03.01. The File Descriptor Abstraction]] — `socket()` returns an integer that you can `read`, `write`, `poll`, `epoll_wait`, `dup`, `close`, and pass to `fork`+`exec` (with `FD_CLOEXEC`). The socket FD is a `struct file*` pointing to a `struct socket` pointing to a `struct sock` — the same three-level indirection as a regular file, just with different leaf types. The production failure mode is forgetting `SOCK_CLOEXEC`: a multi-threaded server that opens a raw socket in one thread while another thread forks and execs a child process leaks the socket into the child, which then has the privilege to send arbitrary IP packets — a security bug. The fix is to always use `SOCK_CLOEXEC | SOCK_NONBLOCK` in new code, and to verify with `ls -la /proc/<pid>/fdinfo/<n>` (look at the `flags:` line — bit `02000000` is `FD_CLOEXEC`).

### Binding to interfaces: `bind()` with `sockaddr_in` structs, network byte order vs. host byte order (`htons()`, `htonl()`)...

The `bind()` syscall assigns a local address (an IP and a port) to a socket. Its signature is `int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen)`, where `addr` is a pointer to a generic `struct sockaddr` (the type-erased view; the real struct is `struct sockaddr_in` for IPv4, `struct sockaddr_in6` for IPv6, `struct sockaddr_un` for UDS) and `addrlen` is the real struct's size. The kernel validates that `addr->sa_family` matches the `domain` passed to `socket()`, then calls `inet_bind()` (for `AF_INET`) which checks port-range permissions (ports below 1024 require `CAP_NET_BIND_SERVICE`), checks for address conflicts against the existing sockets in the same namespace, and on success sets `sk->sport` and `sk->rcv_saddr`. The two most common error codes are `EADDRINUSE` (an existing socket is already bound to this IP:port, and `SO_REUSEADDR` was not set on the new socket) and `EACCES` (the port is below 1024 and the process lacks `CAP_NET_BIND_SERVICE`).

The byte-order issue is the classic sockets-API footgun. The IP protocol specifies that all multi-byte fields in headers (source/destination port, source/destination IP, packet length, etc.) are in **network byte order**, which is **big-endian** (most-significant byte first — RFC 791, 1981). Most modern CPUs (x86, x86_64, ARM in the default little-endian mode) use **host byte order** = **little-endian** (least-significant byte first). If you write `addr.sin_port = 8080;` directly, the kernel will read the bytes in network order, interpret `8080 = 0x01F90` (host) as `0xF901 = 63745` (network), and you will silently bind to port 63745 instead of 8080 — and `ss -tlnp` will show the wrong port with no error indication. The fix is the byte-swap functions: `htons()` (host-to-network-short, 16-bit) for ports, `htonl()` (host-to-network-long, 32-bit) for IP addresses, and their inverses `ntohs()`/`ntohl()` for parsing fields you read out of the kernel. The standard idiom is `addr.sin_port = htons(8080);` and `addr.sin_addr.s_addr = htonl(INADDR_ANY);`.

The address you bind to determines which network interface the socket will accept connections on. `INADDR_ANY` (0.0.0.0) means "all interfaces" — the socket accepts connections on every IP the host has, including loopback, ethernet, and any VPN tunnels. `INADDR_LOOPBACK` (127.0.0.1) means "loopback only" — the socket accepts connections only from the same host, which is the secure default for administrative ports (Postgres's `listen_addresses = 'localhost'`, Redis's `bind 127.0.0.1`). A specific IP like `10.0.0.5` means "only this interface" — useful for multi-homed hosts where you want a service to be reachable only on the internal network. The IPv6 equivalents are `in6addr_any` (`::`) and `in6addr_loopback` (`::1`). The `SO_REUSEADDR` flag (set via `setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt))` before `bind`) allows a new socket to bind to a port that an old socket is still in `TIME_WAIT` on — without it, restarting a server that has just been killed typically fails with `EADDRINUSE` for 60 seconds (the `TIME_WAIT` duration is `2 * MSL = 2 * 60s = 120s` on Linux, but `tcp_fin_timeout` and other sysctls trim this). `SO_REUSEADDR` does NOT allow two sockets to bind to the same IP:port simultaneously — for that, you need `SO_REUSEPORT` (covered in the next H3).

```c
/* bind() with correct byte-order handling and SO_REUSEADDR. */
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>
#include <unistd.h>
#include <stdio.h>
#include <string.h>
#include <errno.h>

int make_listener(uint16_t port, uint32_t addr_net) {
    int fd = socket(AF_INET, SOCK_STREAM | SOCK_CLOEXEC, 0);

    /* SO_REUSEADDR must be set BEFORE bind() — otherwise the bind will fail
       if a previous incarnation of this socket is in TIME_WAIT. */
    int opt = 1;
    setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));

    struct sockaddr_in sa;
    memset(&sa, 0, sizeof(sa));
    sa.sin_family      = AF_INET;
    sa.sin_port        = htons(port);          /* host → network byte order */
    sa.sin_addr.s_addr = addr_net;             /* already in network order */

    if (bind(fd, (struct sockaddr*)&sa, sizeof(sa)) < 0) {
        /* EADDRINUSE  — port already in use (and not reusable).
           EACCES      — port < 1024 and no CAP_NET_BIND_SERVICE.
           EADDRNOTAVAIL — addr_net is not configured on any interface. */
        fprintf(stderr, "bind(%u): %s\n", port, strerror(errno));
        close(fd);
        return -1;
    }
    return fd;
}

int main(void) {
    /* Bind to all interfaces, port 8080. */
    int fd1 = make_listener(8080, htonl(INADDR_ANY));

    /* Bind to loopback only, port 9090. */
    int fd2 = make_listener(9090, htonl(INADDR_LOOPBACK));

    /* Bind to a specific IP, port 443 (requires CAP_NET_BIND_SERVICE). */
    int fd3 = make_listener(443, inet_addr("10.0.0.5"));
    /* inet_addr() returns the IP already in network byte order — do NOT
       wrap it in htonl().  This is a common bug. */

    return 0;
}

/* The classic byte-order bug — what happens if you forget htons(). */
struct sockaddr_in bad;
bad.sin_family = AF_INET;
bad.sin_port   = 8080;               /* BUG: should be htons(8080) */
bad.sin_addr.s_addr = htonl(INADDR_ANY);
bind(fd, (struct sockaddr*)&bad, sizeof(bad));
/* On a little-endian host (x86), the kernel reads 8080 = 0x91 0x1F as
   0x1F91 = 8081... no, wait: 8080 in host bytes is 0x90 0x1F, which the
   kernel reads in network order as 0x90 0x1F = 0x1F90 = 8080... no.
   Actually: 8080 decimal = 0x1F90 hex.  In host (little-endian) memory,
   this is stored as bytes [0x90, 0x1F].  The kernel reads these bytes
   in network (big-endian) order as 0x90 0x1F = 0x901F = 36895 decimal.
   So the socket binds to port 36895 instead of 8080, silently. */
```

The connection to the layered mental model is that the same `bind()` syscall serves every runtime's "listen on a port" feature — Java's `ServerSocket(port)`, Node's `net.Server().listen(port)`, Python's `socket.bind(('', port))`, PHP's `stream_socket_server('tcp://0.0.0.0:80')` all descend into the same `inet_bind` kernel function. The production failure modes are (1) the silent wrong-port bug from a missing `htons()` (diagnosed by `ss -tlnp` showing the wrong port), (2) the `EADDRINUSE`-after-restart bug from a missing `SO_REUSEADDR` (diagnosed by `ss -tan | grep TIME-WAIT` showing lingering TIME_WAIT entries on the port), and (3) the unintended exposure bug from binding to `0.0.0.0` when you meant `127.0.0.1` (diagnosed by `nmap` from an external host showing the port open). The fix for (3) is to default to `127.0.0.1` and only switch to `0.0.0.0` when you have explicitly configured a firewall.

### Activating passive listening: `listen(fd, backlog)` and managing SYN/Accept queues

The `listen()` syscall marks a bound socket as passive — willing to accept incoming connections. Its signature is `int listen(int sockfd, int backlog)`, and the only argument of substance is `backlog`, which sets the maximum length of the **accept queue** (the queue of connections that have completed the TCP 3-way handshake but have not yet been returned by `accept()`). The kernel also internally maintains a separate **SYN queue** (connections that have received a SYN but not yet completed the handshake — the SYN_RCVD state), whose size is controlled by `/proc/sys/net/ipv4/tcp_max_syn_backlog` (default 1024 on most distros, often raised to 8192 or higher on production servers). The `backlog` argument is silently capped by `/proc/sys/net/core/somaxconn` (default 128 on older kernels, raised to 4096 on Linux 5.4+), so a server that calls `listen(fd, 65535)` on a default kernel actually gets a backlog of `min(65535, 128) = 128` — a common source of "why are my connections being dropped under load" production incidents.

When a SYN arrives, the kernel checks the SYN queue. If the SYN queue is full, the SYN is silently dropped (or, if `tcp_syncookies` is enabled, a SYN cookie is sent instead — this is the SYN-flood defence mechanism from RFC 4987, where the kernel encodes state into the SYN-ACK's ISN and discards the local state, so it does not need to allocate a SYN-queue entry until the final ACK arrives). When the third ACK of the handshake arrives, the kernel moves the connection from the SYN queue to the accept queue (incrementing `sk->ack_backlog`). If the accept queue is full, the kernel's behaviour depends on `/proc/sys/net/ipv4/tcp_abort_on_overflow`: if 0 (the default), the kernel silently drops the ACK, forcing the client to retransmit it (the client sees a delayed connection); if 1, the kernel sends a RST (the client sees `ECONNRESET` immediately). Either way, the connection does not complete until the application calls `accept()` and drains the queue.

The `SO_REUSEPORT` socket option (Linux 3.9+) allows multiple sockets to bind to the same IP:port simultaneously, and the kernel load-balances incoming connections across them in a round-robin fashion (with the hash-based variant added in Linux 4.6 for better cache locality). This is what enables Nginx's multi-worker model: each worker has its own listening socket on port 80, and the kernel hands each new connection to exactly one worker — eliminating the "thundering herd" problem where all workers are woken up on every new connection (the pre-SO_REUSEPORT behaviour, where all workers `epoll_wait` on the same listening FD and the kernel wakes them all but only one gets to `accept`). The `EPOLLEXCLUSIVE` flag (Linux 4.5+) is a related mechanism for non-`SO_REUSEPORT` cases: it tells `epoll` to wake only one waiter per event, eliminating the thundering herd without requiring `SO_REUSEPORT`. For a multi-process listener that does not use `SO_REUSEPORT`, the production fix for thundering-herd is `epoll_ctl(EPOLL_CTL_ADD, fd, &ev)` with `ev.events = EPOLLIN | EPOLLEXCLUSIVE`.

```c
/* listen() with a sane backlog — and SO_REUSEPORT for multi-process. */
#include <sys/socket.h>
#include <netinet/in.h>
#include <unistd.h>
#include <stdio.h>

int make_listener_reuseport(uint16_t port, int workers) {
    for (int i = 0; i < workers; i++) {
        pid_t pid = fork();
        if (pid == 0) {
            int fd = socket(AF_INET, SOCK_STREAM | SOCK_CLOEXEC, 0);
            int opt = 1;
            setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));
            setsockopt(fd, SOL_SOCKET, SO_REUSEPORT, &opt, sizeof(opt));

            struct sockaddr_in sa = {
                .sin_family = AF_INET,
                .sin_port   = htons(port),
                .sin_addr.s_addr = htonl(INADDR_ANY),
            };
            bind(fd, (struct sockaddr*)&sa, sizeof(sa));

            /* The actual backlog is min(8192, somaxconn).  On Linux 5.4+
               somaxconn defaults to 4096 — check /proc/sys/net/core/somaxconn. */
            listen(fd, 8192);

            /* Each worker now has its own listening socket on the same port;
               the kernel load-balances incoming connections across them. */
            worker_loop(fd);
            _exit(0);
        }
    }
    return 0;
}

/* Diagnose: am I really getting the backlog I asked for? */
int print_actual_backlog(int fd) {
    int backlog; socklen_t len = sizeof(backlog);
    /* There is no portable way to read the backlog, but on Linux: */
    FILE *f = fopen("/proc/sys/net/core/somaxconn", "r");
    int smax; fscanf(f, "%d", &smax); fclose(f);
    printf("somaxconn = %d\n", smax);
    return smax;

### Accepting active connections: `accept()` / `accept4()`, generating dedicated connected socket des...

The `accept()` syscall is the listener's primary work loop. Its signature is `int accept(int sockfd, struct sockaddr *addr, socklen_t *addrlen)`, where `sockfd` is the listening FD and `addr`/`addrlen` (if non-NULL) receive the peer's address. On success it returns a **new** FD — the listening FD stays open and ready to produce more accepts. The new FD is a fully-connected socket in `TCP_ESTABLISHED` state, with its own `struct sock` containing the four-tuple (local IP, local port, peer IP, peer port) that uniquely identifies this connection. The new FD inherits many properties from the listening socket (`SO_REUSEADDR`, `SO_KEEPALIVE` if set on the listener, etc.) but not all — for example, `O_NONBLOCK` is NOT inherited (which is a common bug: the listener is non-blocking but accepted sockets are blocking, so the first `recv` blocks the entire event loop). The fix is to use `accept4()` (Linux 2.6.28+), which takes a `flags` argument that can include `SOCK_NONBLOCK` and `SOCK_CLOEXEC` — set atomically on the new FD, eliminating the race between `accept` and `fcntl`.

The race that `accept4` eliminates is the same one that `socket(... | SOCK_CLOEXEC, ...)` eliminates: between `accept()` returning the new FD and the application calling `fcntl(F_SETFD, FD_CLOEXEC)` on it, another thread in the same process could `fork` + `execve` a child, and the child would inherit the new FD. For a server that accepts thousands of connections per second, the probability of the race is non-trivial, and the consequence — a child process inheriting an accepted socket FD — is a real security bug (the child can read or write the connection's data). The same race exists for `O_NONBLOCK`: between `accept()` returning and `fcntl(F_SETFL, O_NONBLOCK)`, the application might call `recv` on the new FD and block, freezing the event loop. Modern servers should always use `accept4(fd, NULL, NULL, SOCK_NONBLOCK | SOCK_CLOEXEC)`.

The `accept` syscall returns `EAGAIN` (or `EWOULDBLOCK`, which is the same value on Linux) when the listening socket is non-blocking and the accept queue is empty — this is the event-loop pattern where `epoll_wait` reports the listener as readable, the application calls `accept` in a loop until `EAGAIN`, then goes back to `epoll_wait`. The `accept` syscall returns `EMFILE` when the per-process FD limit is hit — at this point the listener cannot accept any more connections, and the kernel will keep the connection in the accept queue (which will eventually overflow). The production fix for the `EMFILE` case is the "EMFILE dance": keep a placeholder FD open (an "emergency FD" opened at startup), and when `accept` returns `EMFILE`, `close` the emergency FD (which frees one slot), `accept` the new connection (which now succeeds), `close` the new connection immediately (sending RST to the peer), then `open` a new emergency FD. This breaks the accept-queue-fill loop and lets the server recover gracefully.

The lifecycle of an accepted connection is: `accept` returns FD N → application calls `recv`/`send` on N → application calls `close(N)` → kernel sends `FIN`, transitions through `FIN_WAIT_1` → `FIN_WAIT_2` → `TIME_WAIT` (lasting `2 * MSL` = 60 seconds by default) → socket is freed. The `TIME_WAIT` state exists to catch any stray packets from the peer that arrive after the close — without it, a new connection that reuses the same four-tuple could receive old packets from the previous connection. The `TIME_WAIT` state is owned by the side that initiated the close (sent the first `FIN`), which is why servers should usually let the client close first (so the client owns the `TIME_WAIT`, not the server). For a long-lived server that initiates closes, `TIME_WAIT` accumulation is a real concern — each entry is ~250 bytes of kernel memory, and 100,000 entries is 25 MB plus a hash-table load on every socket lookup. The `SO_LINGER` socket option with `l_onoff=1` and `l_linger=0` causes `close` to send RST instead of FIN, aborting the connection and skipping `TIME_WAIT` entirely — this is a valid optimisation for short-lived request/response connections where the application is sure all data has been acknowledged, but it leaves the peer with `ECONNRESET` (which looks like an error in the peer's logs) instead of `EOF` (which does not). Use with care.

```c
/* A complete accept loop with accept4, the EMFILE dance, and non-blocking
   reads.  This is the kernel-level pattern every event-loop runtime uses. */
#include <sys/socket.h>
#include <netinet/in.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <sys/epoll.h>

static int g_emergency_fd = -1;   /* opened once at startup */

void accept_loop(int listen_fd, int epfd) {
    for (;;) {
        int cli = accept4(listen_fd, NULL, NULL,
                          SOCK_NONBLOCK | SOCK_CLOEXEC);
        if (cli < 0) {
            if (errno == EAGAIN || errno == EWOULDBLOCK) {
                return;   /* accept queue drained; back to epoll_wait */
            }
            if (errno == EMFILE) {
                /* Per-process FD limit hit — do the EMFILE dance. */
                close(g_emergency_fd);                  /* free one slot */
                int victim = accept(listen_fd, NULL, NULL);  /* now succeeds */
                if (victim >= 0) {
                    close(victim);   /* send RST, refuse the connection */
                }
                g_emergency_fd = open("/dev/null", O_RDONLY | O_CLOEXEC);
                return;
            }
            if (errno == EINTR) continue;
            perror("accept4");
            return;
        }

        /* Register the new FD with epoll for read-readiness. */
        struct epoll_event ev = {
            .events  = EPOLLIN | EPOLLRDHUP | EPOLLET,  /* edge-triggered */
            .data.fd = cli,
        };
        epoll_ctl(epfd, EPOLL_CTL_ADD, cli, &ev);
    }
}

/* At startup: open the emergency FD. */
void init_emergency_fd(void) {
    g_emergency_fd = open("/dev/null", O_RDONLY | O_CLOEXEC);
}

/* On connection close: send FIN, enter TIME_WAIT on this side. */
void close_connection(int fd) {
    /* Default: close → FIN → TIME_WAIT (60s on Linux).
       For request/response patterns where you are sure all data is acked,
       SO_LINGER with l_linger=0 sends RST instead, skipping TIME_WAIT. */
    close(fd);
}

/* Set TCP_NODELAY on an accepted connection (disable Nagle's algorithm —
   see the next H3 for why this matters for latency). */
void set_tcp_nodelay(int fd) {
    int opt = 1;
    setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));
}

/* Set SO_KEEPALIVE on an accepted connection (detect dead peers). */
void set_keepalive(int fd) {
    int opt = 1;
    setsockopt(fd, SOL_SOCKET, SO_KEEPALIVE, &opt, sizeof(opt));
    /* The default keepalive idle is 7200s — too long for production.
       Tune via the per-socket TCP_KEEPIDLE/TCP_KEEPINTVL/TCP_KEEPCNT
       options (Linux 2.4+). */
    int idle = 60;       /* start probing after 60s of idle */
    int intvl = 10;      /* probe every 10s after that */
    int cnt = 3;         /* give up after 3 unacked probes */
    setsockopt(fd, IPPROTO_TCP, TCP_KEEPIDLE,  &idle,  sizeof(idle));
    setsockopt(fd, IPPROTO_TCP, TCP_KEEPINTVL, &intvl, sizeof(intvl));
    setsockopt(fd, IPPROTO_TCP, TCP_KEEPCNT,   &cnt,   sizeof(cnt));
}

### Client-side lifecycle: `connect()`, non-blocking connection polling, `send()`, and `recv()`

The `connect()` syscall is the client's counterpart to the server's `listen` + `accept`. Its signature is `int connect(int sockfd, const struct sockaddr *addr, socklen_t addrlen)`, and for a TCP socket it drives the 3-way handshake: the kernel sends a SYN to `addr`, waits for the SYN-ACK from the peer, sends the final ACK, and returns 0 (success) or -1 with `errno`. The failure modes are differentiated by `errno`: `ECONNREFUSED` means the peer actively rejected the SYN (RST received — usually because no socket is listening on the target port, or the port is firewalled with `--reject-with tcp-reset`), `ETIMEDOUT` means no response was received within the connection timeout (default 75 seconds on Linux, controlled by the per-socket `TCP_SYNCNT` or the system-wide `tcp_syn_retries`), `ENETUNREACH` means no route to the destination network (routing table has no entry), `EHOSTUNREACH` means the route exists but the next-hop host is not responding (ARP failed), `EACCES` means a firewall rule blocked the SYN silently (the application cannot distinguish this from `ETIMEDOUT`). Each of these maps to a different production failure mode, and the on-call engineer's job is to `tcpdump` the wire to see which one is happening.

For a non-blocking socket (`O_NONBLOCK` set), `connect` returns -1 with `errno = EINPROGRESS` immediately, and the handshake proceeds in the background. The application then uses `poll`/`select`/`epoll` to wait for the FD to become writable (which signals that the handshake completed) or to encounter an error (which signals that it failed). The error is retrieved with `getsockopt(fd, SOL_SOCKET, SO_ERROR, &err, &len)` — this is the canonical way to distinguish "connected successfully" from "connection failed" on a non-blocking socket, because `epoll` reports both as `EPOLLOUT`. The non-blocking connect is what enables event-loop clients to initiate thousands of concurrent connections without blocking any thread — Node's `net.connect(port, host).on('connect', ...)`, Python's `asyncio.open_connection(host, port)`, Java's NIO `SocketChannel.connect()` followed by `SelectionKey.OP_CONNECT`.

Once connected, `send(fd, buf, len, flags)` and `recv(fd, buf, len, flags)` move bytes. The `flags` argument supports `MSG_DONTWAIT` (this one call is non-blocking even on a blocking socket — useful for occasional probes), `MSG_NOSIGNAL` (do not send `SIGPIPE` if the peer has closed — instead return `-1` with `EPIPE`; this is essential on any program that does not set `signal(SIGPIPE, SIG_IGN)` globally, because the default `SIGPIPE` action is to terminate the process), `MSG_PEEK` (read data without consuming it from the receive queue — useful for protocol sniffing), `MSG_WAITALL` (block until `len` bytes are read or EOF — useful for fixed-length protocols), `MSG_MORE` (coalesce small sends into one packet — the inverse of `TCP_NODELAY`). For most applications, `flags = 0` is correct, and `MSG_NOSIGNAL` should be added if the program has not disabled `SIGPIPE` globally.

The `TCP_NODELAY` socket option disables **Nagle's algorithm** (RFC 896, 1984), which by default coalesces small writes into larger packets to amortise the 40-byte TCP/IP header overhead. Without `TCP_NODELAY`, a `send(fd, "G", 1)` followed by a `send(fd, "E", 1)` followed by a `send(fd, "T", 1)` would be coalesced into one packet containing `"GET"` (good for bandwidth, bad for latency, because the kernel waits up to 40 ms for more data before sending). With `TCP_NODELAY`, each `send` produces a packet immediately (good for latency, bad for bandwidth — three packets with 40 bytes of header each to deliver 3 bytes of payload). The 40 ms coalescing delay interacts badly with **delayed ACK** (RFC 1122), where the receiver waits up to 40 ms before ACKing a small packet, in the hope of piggybacking the ACK on response data — the combination can produce a "TCP_NODELAY + delayed ACK deadlock" where small request/response workloads see a 40 ms latency floor that disappears when either `TCP_NODELAY` is set on the sender or `TCP_QUICKACK` is set on the receiver. Production-grade services that speak request/response over TCP (HTTP, Redis, PostgreSQL, MySQL, gRPC) should always set `TCP_NODELAY` on both sides — the bandwidth cost is negligible and the latency win is large.

`SO_KEEPALIVE` enables TCP keepalive probes: when a connection has been idle for `tcp_keepalive_time` (default 7200 seconds = 2 hours, far too long for production), the kernel sends a keepalive probe (an empty TCP segment); if no ACK arrives, it retries every `tcp_keepalive_intvl` (default 75 seconds) for `tcp_keepalive_probes` (default 9) times, after which it returns `ETIMEDOUT` on the next `send`/`recv`. The default 2-hour idle is useless for production — a service whose peer has died will hold the FD open for 2 hours + 9 * 75 seconds = 2 hours 11 minutes before noticing. The fix is to tune the per-socket values via `TCP_KEEPIDLE` (set to 60 seconds for an aggressive probe), `TCP_KEEPINTVL` (10 seconds), and `TCP_KEEPCNT` (3 probes — total 60 + 3 * 10 = 90 seconds to detect a dead peer). The alternative is application-level heartbeats (which every protocol that runs over TCP — HTTP/2 PING frames, Redis CLIENT NO-EVICT, PostgreSQL `tcp_keepalives_idle` — implements precisely because TCP keepalive defaults are inadequate).

```c
/* End-to-end client: non-blocking connect with timeout, send/recv with
   TCP_NODELAY and SO_KEEPALIVE, and clean close. */
#include <sys/socket.h>
#include <netinet/in.h>
#include <netinet/tcp.h>
#include <arpa/inet.h>
#include <unistd.h>
#include <fcntl.h>
#include <errno.h>
#include <poll.h>
#include <stdio.h>
#include <string.h>

int connect_with_timeout(const char *ip, uint16_t port, int timeout_ms) {
    int fd = socket(AF_INET, SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC, 0);

    struct sockaddr_in sa = {
        .sin_family = AF_INET,
        .sin_port   = htons(port),
        .sin_addr.s_addr = inet_addr(ip),
    };

    int r = connect(fd, (struct sockaddr*)&sa, sizeof(sa));
    if (r < 0 && errno != EINPROGRESS) {
        /* ECONNREFUSED, ENETUNREACH, EHOSTUNREACH — fail immediately. */
        fprintf(stderr, "connect: %s\n", strerror(errno));
        close(fd); return -1;
    }
    if (r == 0) {
        /* Synchronous success (rare — only on localhost). */
        return fd;
    }

    /* Wait for the connection to complete or fail. */
    struct pollfd pfd = { .fd = fd, .events = POLLOUT };
    r = poll(&pfd, 1, timeout_ms);
    if (r <= 0) {
        fprintf(stderr, "connect timeout\n");
        close(fd); return -1;
    }

    /* Check the result.  On non-blocking connect, both success and failure
       show up as POLLOUT — retrieve the actual error with SO_ERROR. */
    int err; socklen_t len = sizeof(err);
    getsockopt(fd, SOL_SOCKET, SO_ERROR, &err, &len);
    if (err != 0) {
        fprintf(stderr, "connect failed: %s\n", strerror(err));
        close(fd); return -1;
    }

    /* Tune the connection for production request/response traffic. */
    int opt = 1;
    setsockopt(fd, IPPROTO_TCP, TCP_NODELAY, &opt, sizeof(opt));   /* no Nagle */

    opt = 1;
    setsockopt(fd, SOL_SOCKET, SO_KEEPALIVE, &opt, sizeof(opt));   /* detect dead peers */
    int idle = 60, intvl = 10, cnt = 3;
    setsockopt(fd, IPPROTO_TCP, TCP_KEEPIDLE,  &idle,  sizeof(idle));
    setsockopt(fd, IPPROTO_TCP, TCP_KEEPINTVL, &intvl, sizeof(intvl));
    setsockopt(fd, IPPROTO_TCP, TCP_KEEPCNT,   &cnt,   sizeof(cnt));

    return fd;
}

/* Send-all and recv-all — handle partial sends and recvs correctly. */
ssize_t send_all(int fd, const void *buf, size_t len) {
    const char *p = buf;
    size_t total = 0;
    while (total < len) {
        ssize_t n = send(fd, p + total, len - total, MSG_NOSIGNAL);
        if (n < 0) {
            if (errno == EINTR) continue;
            if (errno == EAGAIN || errno == EWOULDBLOCK) {
                /* Non-blocking: caller should poll and retry. */
                return total;   /* return partial so far */
            }
            return -1;   /* EPIPE (peer closed) or ECONNRESET (peer RST'd) */
        }
        if (n == 0) return -1;   /* should not happen for send */
        total += n;
    }
    return total;
}

/* Recv returns:
   > 0 : got n bytes
   = 0 : peer closed (EOF)
   < 0 : error (EAGAIN, ECONNRESET, EPIPE) */
ssize_t recv_all(int fd, void *buf, size_t len) {
    for (;;) {
        ssize_t n = recv(fd, buf, len, 0);
        if (n < 0) {
            if (errno == EINTR) continue;
            if (errno == EAGAIN || errno == EWOULDBLOCK) return -1;  /* no data right now */
            return -2;   /* ECONNRESET, EPIPE, etc. */
        }
        return n;   /* 0 = EOF, > 0 = data */
    }
}

int main(void) {
    int fd = connect_with_timeout("93.184.216.34", 80, 5000);  /* example.com */
    if (fd < 0) return 1;

    const char *req = "GET / HTTP/1.0\r\nHost: example.com\r\n\r\n";
    if (send_all(fd, req, strlen(req)) < 0) { perror("send"); return 1; }

    char buf[4096];
    ssize_t n;
    while ((n = recv_all(fd, buf, sizeof(buf))) > 0) {
        write(STDOUT_FILENO, buf, n);   /* stream the response to stdout */
    }
    /* n == 0: server closed (EOF) — normal end of HTTP/1.0 response.
       n < 0:  error — check errno. */

    close(fd);   /* sends FIN; we enter TIME_WAIT (60s) on this side */
    return 0;
}

UNIX Domain Sockets vs. Network Sockets]] (where this lifecycle is the same for UDS, minus the 3-way handshake and the TCP options) up to every runtime in section 04 — Java's `Socket.connect(addr, timeout)`, Node's `net.connect({host, port}).on('connect', cb).on('error', cb)`, Python's `socket.create_connection((host, port), timeout)`, PHP's `stream_socket_client('tcp://host:port', $errno, $errstr, $timeout)`. Each runtime wraps the same `connect` + `send` + `recv` + `close` syscalls and exposes them in its idiom. The production failure modes are: (1) the missing `TCP_NODELAY` (a service whose p99 is mysteriously 40 ms instead of the expected 1 ms — the diagnosis is `tcpdump` showing 40 ms gaps between small sends, the fix is one `setsockopt` line); (2) the missing keepalive (a service that holds 50,000 idle connections to a dead database, never noticing the database is gone until the application tries to use the connection — the diagnosis is `ss -tan` showing 50,000 ESTABLISHED connections that should have been pruned); (3) the `EPIPE`/`SIGPIPE` bug (a service that randomly dies because a peer closed early and the default `SIGPIPE` action killed the process — the diagnosis is `dmesg` or the application's signal log, the fix is `signal(SIGPIPE, SIG_IGN)` at startup or `MSG_NOSIGNAL` on every send). Every connection-pool library in section 06 (HikariCP, pg-pool, SQLAlchemy, Doctrine) handles these three correctly by default; if you write your own socket code, you must handle them yourself.

## How This Connects to the Runtimes

Every runtime covered in section 04 is a user-space wrapper around this exact lifecycle. **JVM**: `ServerSocket` and `ServerSocketChannel` map to `socket`+`bind`+`listen`+`accept`; `Socket` and `SocketChannel` map to `socket`+`connect`. The JVM's NIO selector (`Selector`) is `epoll` underneath, and `SelectionKey.OP_ACCEPT` / `OP_CONNECT` / `OP_READ` / `OP_WRITE` map directly to `EPOLLIN` / `EPOLLOUT` event flags. Netty's `EpollEventLoop` uses `epoll` directly via JNI; Netty's `NioEventLoop` uses the JVM's selector, which uses `epoll` on Linux. The JVM's `Socket.setTcpNoDelay(true)` and `Socket.setKeepAlive(true)` are direct `setsockopt` calls. **Node.js / libuv**: `net.Server` calls `socket`+`bind`+`listen`, then registers the FD with libuv's `uv_poll_t` (which is `epoll` on Linux). The `'connection'` event fires when `epoll_wait` returns the listener as readable, and the callback receives a `net.Socket` wrapping the FD returned by `accept4(..., SOCK_NONBLOCK | SOCK_CLOEXEC)`. `net.connect({host, port})` calls `socket`+`connect` non-blocking, returns a `Socket` immediately, and emits `'connect'` on success or `'error'` on failure — exactly the `EINPROGRESS` + `poll` + `SO_ERROR` pattern above. **CPython**: `socket.socket()` is a thin wrapper around the syscall; `socket.accept()` returns a new `socket` object (not just an FD); `socketserver.ForkingMixIn` and `ThreadingMixIn` are `accept`-then-`fork` or `accept`-then-`pthread_create`. `asyncio`'s `loop.sock_accept()` and `loop.sock_connect()` are the non-blocking variants, with `loop.add_reader(fd, callback)` registering the FD with `epoll`. **PHP-FPM**: the master process opens the listening socket once (with `SO_REUSEADDR`), then `fork`s workers that all `accept` on the same FD (with `SO_REUSEPORT` since PHP-FPM 5.5+ for explicit load balancing). Each accepted connection is processed by a worker, then closed; the worker goes back to `accept` — the classic prefork model. When you read the runtime notes in section 04, every runtime's "production server" recipe is one of these lifecycle wrappings, and every runtime's "production bug" — high latency, FD leak, SIGPIPE crash, EMFILE cascade — maps onto a mistake at one of the eight lifecycle stages taught here.

## Hands-On Exercise

Open a terminal on a Linux machine and run the following commands to see the POSIX socket lifecycle in action, end-to-end, at syscall granularity.

```bash
# 1. Watch the full lifecycle with strace on a tiny server.
$ strace -e trace=socket,bind,listen,accept4,recvfrom,sendto,close -f \
         python3 -m http.server 8080 2>&1 | head -10
socket(AF_INET, SOCK_STREAM|SOCK_CLOEXEC, IPPROTO_TCP) = 3
bind(3, {sa_family=AF_INET, sin_port=htons(8080), sin_addr=inet_addr("0.0.0.0")}, 16) = 0
listen(3, 5)                    = 0
# (now connect to it from another shell with: curl http://localhost:8080/)
accept4(3, {sa_family=AF_INET, sin_port=htons(54321), sin_addr=inet_addr("127.0.0.1")}, ...) = 4
recvfrom(4, "GET / HTTP/1.1\r\nHost: localhost:8080\r\n\r\n", 8192, 0, ...) = 41
sendto(4, "HTTP/1.0 200 OK\r\n...", 234, 0, NULL, 0) = 234
close(4)                        = 0

# 2. Inspect the listening socket's queue depths during a connection burst.
$ python3 -m http.server 8080 &
$ for i in $(seq 1 200); do curl -s http://localhost:8080/ -o /dev/null & done
$ ss -tlnp 'sport = :8080'
State  Recv-Q  Send-Q  Local Address:Port  Peer Address:Port
LISTEN 12      5       0.0.0.0:8080        0.0.0.0:*
#       ^^      ^^
#       ^^      └── the configured backlog (5 — Python's default!)
#       └── current accept-queue depth (12 — wait, that's > 5? Because Linux
#           silently rounds up to the nearest power of 2 ≥ backlog.)

# 3. Watch the 3-way handshake and the FIN sequence.
$ sudo tcpdump -i lo -n 'port 8080' &
$ curl http://localhost:8080/
# tcpdump output:
# IP 127.0.0.1.54321 > 127.0.0.1.8080: Flags [S], ...        ← client SYN
# IP 127.0.0.1.8080 > 127.0.0.1.54321: Flags [S.], ...       ← server SYN-ACK
# IP 127.0.0.1.54321 > 127.0.0.1.8080: Flags [.], ack 1      ← client ACK (connected)
# IP 127.0.0.1.54321 > 127.0.0.1.8080: Flags [P.], ...: GET  ← client data
# IP 127.0.0.1.8080 > 127.0.0.1.54321: Flags [P.], ...: HTTP ← server response
# IP 127.0.0.1.54321 > 127.0.0.1.8080: Flags [F.], ...       ← client FIN
# IP 127.0.0.1.8080 > 127.0.0.1.54321: Flags [F.], ...       ← server FIN
# IP 127.0.0.1.54321 > 127.0.0.1.8080: Flags [.], ack 2      ← final ACK

# 4. Demonstrate the byte-order bug.
$ python3 -c "
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
# Correct:
s.bind(('', 8080)); print('correct port:', 8080); s.close()
# Bug — bind to a different port than you think:
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
import struct
s.bind(('', 8080))   # htons is done internally by Python — but in C you'd need it
"
$ ss -tln | grep ':8080'
LISTEN 0 5 0.0.0.0:8080 ...   # correct port (8080)
# (If you forget htons() in C, you'd see ':36895' instead — see the H3 above.)

# 5. Demonstrate the SO_REUSEADDR fix for EADDRINUSE.
$ python3 -m http.server 8080 &
$ kill -9 %1                 # abrupt kill — leaves the socket in TIME_WAIT or LISTEN
$ python3 -m http.server 8080
# (might fail with "Address already in use" if you don't have SO_REUSEADDR)
$ python3 -c "
import socket
s = socket.socket()
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
s.bind(('', 8080)); s.listen()
print('OK with SO_REUSEADDR')
"

# 6. Demonstrate the EMFILE cascade.
$ ulimit -n 50               # artificially low FD limit
$ python3 -m http.server 8080 &
$ for i in $(seq 1 100); do curl -s http://localhost:8080/ -o /dev/null & done
# (server logs show EMFILE errors; some curl calls fail with "connection reset")

# 7. Inspect the TCP options on a real connection.
$ python3 -c "
import socket
s = socket.socket(); s.connect(('example.com', 80))
info = s.getsockopt(socket.IPPROTO_TCP, socket.TCP_INFO, 256)
import struct
# TCP_INFO struct fields (Linux): state, ca_state, retransmits, probes, backoff, ...
print('TCP state bytes (first 4 = state):', info[:4].hex())
print('TCP_NODELAY:', s.getsockopt(socket.IPPROTO_TCP, socket.TCP_NODELAY))
s.close()
"

# 8. Verify SO_LINGER with l_linger=0 sends RST instead of FIN.
$ sudo tcpdump -i lo -n 'port 8080' &
$ python3 -c "
import socket, struct
s = socket.socket(); s.connect(('127.0.0.1', 8080))
s.setsockopt(socket.SOL_SOCKET, socket.SO_LINGER, struct.pack('ii', 1, 0))
s.close()   # should send RST, not FIN
"
# (tcpdump should show 'Flags [R.]' instead of 'Flags [F.]'.)
```
