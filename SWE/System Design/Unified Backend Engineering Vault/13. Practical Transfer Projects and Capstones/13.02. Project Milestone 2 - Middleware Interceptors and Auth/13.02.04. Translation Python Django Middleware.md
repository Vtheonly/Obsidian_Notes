# 13.02.04. Translation Python Django Middleware

## Scope

This is a single-ecosystem implementation file inside a capstone milestone. It is a reference implementation to reproduce, not a tutorial to copy. The contract is defined in [[13.02.01. System Specification]] and implemented in Spring Boot (anchor, [[13.02.02. Anchor Implementation Spring Security]]), Express ([[13.02.03. Translation Express TypeScript Middleware]]), and Laravel ([[13.02.05. Translation PHP Laravel Middleware]]). Read the anchor note first — this file explains only the deltas from Spring Boot.

## What You Are Building

A Python 3.12 + Django 5.0 application that satisfies the Milestone 2 contract: JWT auth (HS256, 15-min access + 7-day refresh with rotation and reuse detection), RBAC (`ADMIN > MEMBER > VIEWER`, org-scoped), distributed tracing headers (`X-Request-Id`, `X-Trace-Id`, `X-Span-Id`), and execution timers (Prometheus histogram with monotonic clock). Persistence uses Django's ORM against Postgres 16, served by gunicorn with 4 sync workers behind an nginx ingress. Tests use `pytest` + `pytest-django` + `httpx`. The deliverable is `python manage.py runserver`-able in dev and `gunicorn config.wsgi:application`-able in prod, containerised with a multi-stage Dockerfile, and load-tested with `k6`.

The structural delta from Spring Boot and Express is that Django middleware is **bidirectional**: each middleware has `__call__` (processes the request going in) and can wrap the response coming out. This is more powerful than Express's `(req, res, next)` model because the same middleware can do pre- and post-processing in one function, and it is more powerful than Spring's `OncePerRequestFilter` for the same reason. The cost is that the order is reversed on the way out (LIFO) — the last middleware registered is the first to see the response, which is the opposite of what you would naively expect.

## Implementation Steps

1. **Bootstrap.** `django-admin startproject ms2_django && cd ms2_django && python manage.py startapp auth_app && python manage.py startapp orgs && python manage.py startapp common`. `pip install django==5.0 psycopg==3.1 pyjwt==2.9 bcrypt==4.2 prometheus-client==0.20 structlog==24.4 django-cors-headers==4.4`.
2. **Wire dependencies.** Install only what the spec requires — Django, `psycopg` (Postgres driver, the v3 async-capable one), `pyjwt` for JWT, `bcrypt` for password hashing, `prometheus-client` for the histogram, `structlog` for structured logging. Do not install `djangorestframework` — the spec is plain JSON and DRF's serializer machinery adds 200 ms of import time and 60 lines of boilerplate per model for no benefit. Do not install `django-rest-knox` or `dj-rest-auth` — those are session/DRF-coupled and fight the JWT-only contract.
3. **Implement the contract.** Match the spec exactly — same paths, status codes, JSON shapes. Django's `JsonResponse` for success, a custom `ProblemDetailResponse` for errors.
4. **Wire observability.** `structlog` configured with a processor that reads the `trace_id` from `threading.local` (set by the trace middleware); `prometheus_client.Histogram` for `http_request_duration_seconds` recorded in the timer middleware using `time.monotonic()`.
5. **Containerize.** Multi-stage Dockerfile: `FROM python:3.12-slim-bookworm AS build` → `pip install --user -r requirements.txt` → `FROM python:3.12-slim-bookworm AS run` → `COPY --from=build /root/.local /root/.local` → `CMD ["gunicorn", "-w", "4", "-b", "0.0.0.0:8000", "config.wsgi:application"]`. Image size target: <170 MB.
6. **Test.** `pytest` with `pytest-django`, `httpx.AsyncClient` for the integration tests, and a `pytest-postgresql` fixture for the test DB. Test cases cover the same matrix as the anchor.

## Implementation Deltas

The Spring Boot anchor taught you the contract; Django teaches you five deltas worth recording.

- **Middleware is a class with `__call__`, not a function list.** Express middleware is `(req, res, next) => void`. Django middleware is a class that exposes `def __call__(self, request):` and can do work before and after calling `self.get_response(request)`. The pre/post symmetry is cleaner for cross-cutting concerns like timing (start the timer before, record it after) but requires you to remember that the response path is LIFO — the last middleware to see the request is the first to see the response.
- **`request.user` is set by middleware, not by a framework context.** Django ships with `AuthenticationMiddleware` that sets `request.user` from the session. For JWT, you replace that middleware with your own `JwtAuthMiddleware` that sets `request.user` from the JWT. This is more direct than Spring's `SecurityContextHolder` thread-local and more verbose than Express's `req.user` because Django's `request.user` is typed (`AbstractBaseUser | AnonymousUser`) and the type system enforces it.
- **`pyjwt`'s `decode()` accepts `leeway` for clock skew.** This is the equivalent of Spring's `clockSkewSeconds` and Express's `clockTolerance`. The default is 0 — always set `leeway=60`.
- **`time.monotonic()` is the monotonic clock.** `time.time()` is the wall clock and can jump on NTP sync. `time.perf_counter()` is also monotonic and higher-resolution (nanoseconds vs microseconds); use `perf_counter` for sub-microsecond timing.
- **Django's ORM exposes `select_for_update()` for row-level locking.** This is the equivalent of Postgres `SELECT FOR UPDATE`. JPA has `@Lock(LockModeType.PESSIMISTIC_WRITE)`; Prisma needs `$queryRaw`; Django has it natively as a query method. This is one of the rare cases where Django is more ergonomic than the alternatives.

## Auth Middleware

Django middleware is defined as a class with `__init__(self, get_response)` and `__call__(self, request)`. The factory pattern (`get_response`) is Django 1.10+ and replaces the old `MIDDLEWARE_CLASSES` two-function (`process_request` / `process_response`) pattern. The class is registered in `settings.MIDDLEWARE`.

```python
# common/middleware.py
import time
import uuid
import logging
import threading
import hashlib
import secrets
from typing import Optional

import jwt
import bcrypt
from django.conf import settings
from django.http import JsonResponse, HttpRequest
from django.contrib.auth.models import AnonymousUser
from prometheus_client import Histogram

from auth_app.models import User
from auth_app.cache import user_cache

logger = logging.getLogger(__name__)

#  Thread-local for trace context — equivalent to Java's ThreadLocal.
#  Django's request object already carries the trace context, but the
#  logger needs access from deep in the call stack (e.g. inside a model
#  method), so we mirror it into a thread-local that structlog reads.
_trace_local = threading.local()

#  Prometheus histogram — same shape as Spring Boot's micrometer timer.
HTTP_DURATION = Histogram(
    "http_request_duration_seconds",
    "Wall-clock duration of HTTP requests",
    ["method", "route", "status"],
)


class TraceContextMiddleware:
    """Reads X-Request-Id / X-Trace-Id / X-Span-Id from the request (or
    generates UUIDv4), propagates them into the response headers and into
    a thread-local that structlog reads."""

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request: HttpRequest):
        request_id = request.headers.get("X-Request-Id") or str(uuid.uuid4())
        trace_id   = request.headers.get("X-Trace-Id")   or str(uuid.uuid4())
        span_id    = str(uuid.uuid4())
        request.request_id = request_id
        request.trace_id   = trace_id
        request.span_id    = span_id
        _trace_local.trace_id   = trace_id
        _trace_local.request_id = request_id
        try:
            response = self.get_response(request)
        finally:
            #  Critical: clear thread-local to avoid leaking into the next
            #  request that reuses this worker thread.
            _trace_local.trace_id   = None
            _trace_local.request_id = None
        response["X-Request-Id"] = request_id
        response["X-Trace-Id"]   = trace_id
        response["X-Span-Id"]    = span_id
        return response


class TimerMiddleware:
    """Records request duration into a Prometheus histogram using the
    monotonic clock.  Must run before auth so 401s are timed."""

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request: HttpRequest):
        start = time.perf_counter()    #  monotonic, sub-µs
        response = self.get_response(request)
        duration = time.perf_counter() - start
        #  request.resolver_match.route is set by Django's URL dispatcher;
        #  fall back to request.path if middleware ran before matching.
        route = (request.resolver_match.route
                 if hasattr(request, "resolver_match") and request.resolver_match
                 else request.path)
        HTTP_DURATION.labels(
            method=request.method,
            route=route,
            status=str(response.status_code),
        ).observe(duration)
        response["X-Response-Time-ms"] = f"{duration * 1000:.2f}"
        return response


class JwtAuthMiddleware:
    """Extracts the Bearer token, verifies it, loads the user from DB
    (cached 60s), and attaches to request.user.  If no token or invalid,
    request.user is AnonymousUser — the view-level @require_role
    decorator returns 401."""

    HEADER_PREFIX = "Bearer "

    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request: HttpRequest):
        header = request.headers.get("Authorization", "")
        if header.startswith(self.HEADER_PREFIX):
            token = header[len(self.HEADER_PREFIX):]
            try:
                claims = jwt.decode(
                    token,
                    settings.JWT_SECRET,
                    algorithms=["HS256"],
                    leeway=60,                #  60s clock skew
                )
                user_id = int(claims["sub"])
                #  Cache lookup; falls through to DB on miss.
                user = user_cache.get(user_id)
                if user is None:
                    user = self._load_user(user_id)
                    if user is not None:
                        user_cache.set(user_id, user)
                #  Always trust the DB-loaded role/orgId over the JWT claim,
                #  so role changes land within the 60s cache TTL.
                if user is not None:
                    request.user = user
                    request.jwt_claims = claims
                else:
                    request.user = AnonymousUser()
            except jwt.InvalidTokenError:
                request.user = AnonymousUser()
        else:
            request.user = AnonymousUser()
        return self.get_response(request)

    @staticmethod
    def _load_user(user_id: int) -> Optional[User]:
        try:
            return (User.objects
                    .select_related("org")
                    .get(pk=user_id, enabled=True))
        except User.DoesNotExist:
            return None


#  ── structlog processor that pulls trace_id out of the thread-local ──
def inject_trace_context(_logger, _method, event_dict):
    trace_id   = getattr(_trace_local, "trace_id", None)
    request_id = getattr(_trace_local, "request_id", None)
    if trace_id:
        event_dict["trace_id"] = trace_id
    if request_id:
        event_dict["request_id"] = request_id
    return event_dict
```

The middleware is registered in `settings.py` in this exact order — Django runs them top-to-bottom on the request and bottom-to-top on the response, so `TraceContext` runs first on the request and last on the response:

```python

    "common.middleware.TraceContextMiddleware",   #  trace first → 401s are traced

    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.middleware.clickjacking.XFrameOptionsMiddleware",
]
```

## RBAC Decorator

The `require_role` decorator is the Django equivalent of Spring's `@PreAuthorize`. It is applied per-view and checks `request.user` against the required role and the path's `org_id` against `request.user.org_id`.

```python
# common/decorators.py
from functools import wraps
from django.http import JsonResponse
from django.contrib.auth.models import AnonymousUser

ROLE_LEVEL = {"ADMIN": 0, "MEMBER": 1, "VIEWER": 2}


def require_role(required: str, org_scoped: bool = False):
    """View decorator: 401 if no user, 403 if role insufficient or org
    mismatch.  Usage:

        @require_role("ADMIN", org_scoped=True)
        def delete_org(request, id: int): ...
    """
    def decorator(view):
        @wraps(view)
        def wrapper(request, *args, **kwargs):
            if isinstance(request.user, AnonymousUser) or not request.user.is_authenticated:
                return problem(401, "Unauthorized", "authentication required", request)
            user = request.user
            if ROLE_LEVEL[user.role] > ROLE_LEVEL[required]:
                return problem(403, "Forbidden",
                               f"role {required} required, you are {user.role}", request)
            if org_scoped:
                try:
                    path_org_id = int(kwargs["id"])
                except (KeyError, ValueError):
                    return problem(403, "Forbidden", "invalid org id", request)
                if user.is_system_admin and user.role == "ADMIN":
                    pass   #  system admin can access any org
                elif user.org_id != path_org_id:
                    return problem(403, "Forbidden",
                                   "not a member of this organization", request)
            return view(request, *args, **kwargs)
        return wrapper
    return decorator


def problem(status: int, title: str, detail: str, request) -> JsonResponse:
    """RFC 9457 Problem Details response."""
    return JsonResponse({
        "type":     f"https://http.cat/{status}",
        "title":    title,
        "status":   status,
        "detail":   detail,
        "instance": request.path,
        "trace_id": getattr(request, "trace_id", "unknown"),
    }, status=status, content_type="application/problem+json")
```

The decorator-based approach has one subtle disadvantage vs Spring's `@PreAuthorize`: it cannot reference method parameters via SpEL, so the `org_scoped=True` flag must hard-code the path parameter name `id` (via `kwargs["id"]`). Spring's `@PreAuthorize("@rbac.canAccessOrg(#id, T ...Role.MEMBER)")` reads the parameter named `id` from the method signature via reflection. The cost is that Django's decorator is simpler to write but more rigid — if you rename the path parameter you must rename the decorator's `kwargs["id"]` lookup. Always write an integration test per endpoint.

## Auth Views (login, refresh, register, me)

```python
# auth_app/views.py
import secrets
import hashlib
from datetime import timedelta
from django.utils import timezone
from django.conf import settings
from django.http import JsonResponse, HttpRequest
from django.views.decorators.http import require_http_methods
import jwt
import bcrypt

from auth_app.models import User, RefreshToken, RefreshTokenHistory
from auth_app.cache import user_cache
from common.decorators import require_role
from common.middleware import _trace_local
from common.errors import AuthError, ConflictError, problem_response
import logging
logger = logging.getLogger(__name__)


@require_http_methods(["POST"])
def register(request: HttpRequest):
    import json
    try:
        body = json.loads(request.body)
    except json.JSONDecodeError:
        return problem_response(400, "Bad Request", "invalid JSON", request)
    email, password, name = body.get("email"), body.get("password"), body.get("name")
    if not email or not password or len(password) < 8 or not name:
        return problem_response(400, "Bad Request",
                                 "email, password (>=8 chars), name required", request)
    if User.objects.filter(email=email).exists():
        return problem_response(409, "Conflict", "email already exists", request)
    user = User.objects.create(
        email=email,
        password_hash=bcrypt.hashpw(password.encode(), bcrypt.gensalt(rounds=12)).decode(),
        name=name,
        role="VIEWER",
    )
    return JsonResponse({
        "id": user.id, "email": user.email, "name": user.name,
        "role": user.role, "created_at": user.created_at.isoformat(),
    }, status=201)


@require_http_methods(["POST"])
def login(request: HttpRequest):
    import json
    body = json.loads(request.body)
    email, password = body.get("email"), body.get("password")
    try:
        user = User.objects.get(email=email)
    except User.DoesNotExist:
        return problem_response(401, "Unauthorized", "invalid credentials", request)
    if not user.enabled or not bcrypt.checkpw(password.encode(), user.password_hash.encode()):
        return problem_response(401, "Unauthorized", "invalid credentials", request)
    access  = issue_access_token(user)
    refresh = issue_refresh_token(user.id)
    return JsonResponse({
        "accessToken": access, "refreshToken": refresh,
        "user": serialize_user(user),
    })


@require_http_methods(["POST"])
def refresh(request: HttpRequest):
    import json
    body = json.loads(request.body)
    token = body.get("refreshToken")
    if not token:
        return problem_response(401, "Unauthorized", "refreshToken required", request)
    result = rotate_refresh_token(token)
    if result == "REUSE_DETECTED":
        logger.warning("refresh token reuse detected — family revoked",
                       extra={"token_hash": hash_token(token)})
        revoke_family(token)
        return problem_response(401, "Unauthorized",
                                "refresh token reuse detected — family revoked", request)
    if result in ("NOT_FOUND", "EXPIRED"):
        return problem_response(401, "Unauthorized", "invalid refresh token", request)
    user = User.objects.get(pk=result["user_id"])
    user_cache.delete(user.id)    #  force fresh role/orgId on next request
    return JsonResponse({
        "accessToken":  issue_access_token(user),
        "refreshToken": result["new_token"],
        "user":         serialize_user(user),
    })


@require_http_methods(["GET"])
@require_role("VIEWER")
def me(request: HttpRequest):
    user = request.user
    memberships = list(user.membership_set.select_related("org").all())
    return JsonResponse({**serialize_user(user), "memberships": [
        {"org_id": m.org_id, "org_name": m.org.name, "role": m.role}
        for m in memberships
    ]})


#  ── Helpers ────────────────────────────────────────────────────────────

def issue_access_token(user: User) -> str:
    now = timezone.now()
    payload = {
        "sub":   str(user.id),
        "email": user.email,
        "name":  user.name,
        "org_id": user.org_id,
        "role":  user.role,
        "iat":   now,
        "exp":   now + timedelta(seconds=settings.JWT_ACCESS_TTL_SEC),
    }
    return jwt.encode(payload, settings.JWT_SECRET, algorithm="HS256")


def issue_refresh_token(user_id: int) -> str:
    token = secrets.token_urlsafe(32)
    family_id = (RefreshToken.objects.filter(user_id=user_id)
                 .order_by("-family_id").first())
    next_family = (family_id.family_id + 1) if family_id else 1
    RefreshToken.objects.create(
        token_hash=hash_token(token),
        family_id=next_family, user_id=user_id,
        expires_at=timezone.now() + timedelta(days=settings.JWT_REFRESH_TTL_DAYS),
    )
    return token


def rotate_refresh_token(token: str):
    """Atomic rotation with reuse detection.  Uses SELECT FOR UPDATE
    inside a transaction with REPEATABLE READ isolation."""
    from django.db import transaction
    h = hash_token(token)
    with transaction.atomic():
        #  Django's select_for_update() emits SELECT ... FOR UPDATE.
        row = (RefreshToken.objects
               .select_for_update()
               .filter(token_hash=h).first())
        if row is None:
            #  Was it ever valid?  If so, reuse → revoke family.
            was_valid = RefreshTokenHistory.objects.filter(token_hash=h).exists()
            return "REUSE_DETECTED" if was_valid else "NOT_FOUND"
        if row.expires_at < timezone.now():
            row.delete()
            return "EXPIRED"
        #  Atomic rotate: delete old, insert new with same family_id, archive old.
        new_token = secrets.token_urlsafe(32)
        new_hash  = hash_token(new_token)
        RefreshToken.objects.create(
            token_hash=new_hash, family_id=row.family_id, user_id=row.user_id,
            expires_at=timezone.now() + timedelta(days=settings.JWT_REFRESH_TTL_DAYS),
        )
        RefreshTokenHistory.objects.create(
            token_hash=h, family_id=row.family_id,
        )
        row.delete()
        return {"user_id": row.user_id, "new_token": new_token}


def revoke_family(token: str):
    from django.db import connection
    with connection.cursor() as cur:
        cur.execute("""
            DELETE FROM refresh_tokens WHERE family_id = (
                SELECT family_id FROM refresh_tokens_history WHERE token_hash = %s
            )
        """, [hash_token(token)])


def hash_token(token: str) -> str:
    return hashlib.sha256(token.encode()).hexdigest()


def serialize_user(user: User) -> dict:
    return {
        "id":    user.id,
        "email": user.email,
        "name":  user.name,
        "org_id": user.org_id,
        "role":  user.role,
        "is_system_admin": user.is_system_admin,
    }
```

The `select_for_update()` call is the critical bit — it emits `SELECT ... FOR UPDATE` and locks the row for the duration of the transaction. Combined with `transaction.atomic()` (which uses the default isolation level, `READ_COMMITTED` on Postgres), this makes rotation safe: two concurrent calls with the same token both block on the `FOR UPDATE`; the first commits and deletes the row; the second's `FOR UPDATE` returns no rows, so it falls through to the `was_valid` check and triggers `REUSE_DETECTED`. To upgrade to `REPEATABLE_READ` (which is what Spring Boot uses), add `connections["default"].set_isolation_level(RepeatableRead)` — but for this race, `READ_COMMITTED` + `FOR UPDATE` is sufficient because the row-level lock serialises the two transactions.

The org views are the same shape as Milestone 1's, with `@require_role` added:

```python
# orgs/views.py
from django.http import JsonResponse, HttpRequest
from django.views.decorators.http import require_http_methods
from common.decorators import require_role
from orgs.models import Organization, Membership


@require_http_methods(["GET"])
@require_role("VIEWER")
def list_orgs(request: HttpRequest):
    #  VIEWER can see only orgs they are a member of.
    qs = (Organization.objects
          .filter(membership__user=request.user, deleted_at__isnull=True))
    return JsonResponse({"orgs": [{"id": o.id, "name": o.name} for o in qs]})

@require_role("VIEWER", org_scoped=True)

    org = Organization.objects.get(pk=id, deleted_at__isnull=True)

                         "description": org.description})


@require_http_methods(["DELETE"])
@require_role("ADMIN", org_scoped=True)
def delete_org(request: HttpRequest, id: int):
    from django.utils import timezone
    org = Organization.objects.get(pk=id)
    org.deleted_at = timezone.now()
    org.save()
    return JsonResponse({"deleted": org.id})
```

## What This Teaches

Building the same JWT+RBAC contract in Django after Spring Boot teaches five ecosystem-specific lessons:

1. **Django middleware's bidirectional `__call__` is cleaner than Spring's `OncePerRequestFilter` for cross-cutting concerns.** Spring's filter has `doFilterInternal(req, res, chain)` and you must remember to call `chain.doFilter(req, res)` and put post-processing in a `finally` block. Django's `__call__(self, request)` lets you write `response = self.get_response(request); ... modify response ...; return response` — the pre/post symmetry is in the language, not the discipline. The cost is that the response path is LIFO (last middleware in is first to see the response), which is the opposite of what you would naively expect. The mental model is "middleware is a stack of `with` blocks, not a pipeline."

2. **`request.user` is a typed attribute, not a thread-local.** Django's `request.user` is typed as `AbstractBaseUser | AnonymousUser`, and your IDE (or `mypy --strict`) will flag any access that does not handle the `AnonymousUser` case. This is a real safety net that Spring's `SecurityContextHolder.getContext().getAuthentication().getPrincipal()` (which returns `Object`) does not provide. The cost is that you must always write `if isinstance(request.user, AnonymousUser): return 401` at the top of every protected view — the `@require_role` decorator encapsulates this, but the explicit check is what makes the type system work.

3. **`select_for_update()` is native to Django's ORM.** This is one of the rare cases where Django is more ergonomic than JPA (which needs `@Lock(LockModeType.PESSIMISTIC_WRITE)`) and far more ergonomic than Prisma (which needs `$queryRaw`). The refresh-token rotation race is solved in 3 lines: `with transaction.atomic(): row = Model.objects.select_for_update().filter(...).first()`. The lesson is: when you reach for an escape hatch in another ORM, check whether Django already has it native — it usually does.

4. **`pyjwt`'s `leeway=60` is the same as Spring's `clockSkewSeconds=60` and Express's `clockTolerance=60`.** All three libraries implement the same JWT spec (RFC 7519) but name the parameter differently. The default is 0 in all three. The interop failure mode is the same: a token issued by one ecosystem at `T` is rejected by another at `T+0.001s` if `leeway`/`clockTolerance`/`clockSkewSeconds` is 0. Always set it explicitly; never trust the default.

5. **Django's per-worker Postgres connection model bites at scale.** Each gunicorn worker holds a persistent connection (`CONN_MAX_AGE=20` by default for persistent connections; without it, Django opens a fresh connection per request, which is worse). With 4 workers × `CONN_MAX_AGE=20` = 80 connections minimum, you exceed Postgres's `max_connections=80` immediately. The fix is `PgBouncer` in `transaction` mode in front of Postgres, multiplexing all 80 client connections onto 25 server connections. This is the same fix Spring Boot and Express need, but Django's per-worker default makes it bite first — Django was the first ecosystem to fail in the Milestone 1 post-mortem (see [[13.01.06. Architectural Comparison and Post-Mortem]]), and the same failure mode recurs here.
