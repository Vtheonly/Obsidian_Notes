# 13.02.05. Translation PHP Laravel Middleware

## Scope

This is a single-ecosystem implementation file inside a capstone milestone. It is a reference implementation to reproduce, not a tutorial to copy. The contract is defined in [[13.02.01. System Specification]] and implemented in Spring Boot (anchor, [[13.02.02. Anchor Implementation Spring Security]]), Express ([[13.02.03. Translation Express TypeScript Middleware]]), and Django ([[13.02.04. Translation Python Django Middleware]]). Read the anchor note first — this file explains only the deltas from Spring Boot.

## What You Are Building

A PHP 8.3 + Laravel 11 application that satisfies the Milestone 2 contract: JWT auth (HS256, 15-min access + 7-day refresh with rotation and reuse detection), RBAC (`ADMIN > MEMBER > VIEWER`, org-scoped), distributed tracing headers (`X-Request-Id`, `X-Trace-Id`, `X-Span-Id`), and execution timers (Prometheus histogram with monotonic clock). Persistence uses Eloquent against Postgres 16, served by Laravel Octane (Swoole or RoadRunner) for persistent workers behind an nginx ingress. Tests use `Pest` + `Http::fake()`. The deliverable is `php artisan serve`-able in dev and `octane:start`-able in prod, containerised with a multi-stage Dockerfile, and load-tested with `k6`.

The structural delta from the other three ecosystems is that PHP-FPM (the default PHP runtime) is **process-per-request**: every request starts a fresh PHP process, runs the request, and dies. There is no in-process state, no `ThreadLocal`, no `AsyncLocalStorage`, no LRU cache that survives between requests. This is a strength (no memory leaks, no `ThreadLocal` cleanup, no shared-state race conditions) and a weakness (no in-process cache, no long-lived connections, cold start on every request). Laravel Octane (Swoole/RoadRunner) lifts this by keeping a PHP worker alive across requests, but then you have all the shared-state problems of a long-lived runtime and none of the conventions — Octane requires you to declare which singletons are request-scoped vs application-scoped, and getting this wrong causes cross-request data leaks. This implementation targets Octane because the spec requires a Prometheus histogram and a 60-second user cache, neither of which is possible in PHP-FPM.

## Implementation Steps

1. **Bootstrap.** `composer create-project laravel/laravel ms2_laravel "11.*" && cd ms2_laravel && composer require laravel/octane swoole/swoole firebase/php-jjwt illuminate/redis prometheus/client_php predis/predis`. `php artisan octane:install --server=swoole`.
2. **Wire dependencies.** Install only what the spec requires — Laravel (framework), Octane (persistent workers), `firebase/php-jwt` for JWT, `predis` for Redis (token blacklist + rate limiter), `prometheus/client_php` for the histogram. Do not install Laravel Sanctum or Passport — those are session-based and fight the JWT-only contract.
3. **Implement the contract.** Match the spec exactly — same paths, status codes, JSON shapes. Use Laravel's `response()->json()` for success and a custom `ProblemDetail` response macro for errors.
4. **Wire observability.** `prometheus_client_php` `Histogram` exposed at `/metrics`; Laravel's `Log` facade with a custom formatter that reads `request()->attributes->get('trace_id')`.
5. **Containerize.** Multi-stage Dockerfile: `FROM composer:2.7 AS build` → `composer install --no-dev` → `FROM php:8.3-cli-bookworm AS run` → install swoole extension → `COPY --from=build` → `CMD ["php", "artisan", "octane:start", "--server=swoole", "--host=0.0.0.0", "--port=8000"]`. Image size target: <200 MB.
6. **Test.** `php artisan test` using Pest. Integration tests use Laravel's `RefreshDatabase` trait with a Testcontainers-Postgres fixture.

## Implementation Deltas

The Spring Boot anchor taught you the contract; Laravel teaches you five deltas worth recording.

- **PHP-FPM is process-per-request; Octane is persistent.** Default PHP-FPM means no in-process cache (each process starts cold), no `ThreadLocal` (no threads), no event loop (no async). Laravel Octane (Swoole or RoadRunner) keeps a PHP worker alive across requests, which gives you a cache, but introduces shared-state concerns that PHP developers are not used to: a singleton resolved in one request must be flushed before the next request sees it, or you leak authentication state across requests.
- **Laravel's middleware is a stack, registered in `app/Http/Kernel.php` (Laravel 10) or `bootstrap/app.php` (Laravel 11).** The shape is identical to Django's: each middleware has `handle($request, Closure $next)` and can do pre/post-processing. The order is top-to-bottom on the way in, bottom-to-top on the way out — same LIFO response path as Django.
- **`firebase/php-jwt`'s `JWT::decode()` accepts a `leeway` option for clock skew.** Same parameter as `pyjwt`'s `leeway`, same as JJWT's `clockSkewSeconds`, same as `jsonwebtoken`'s `clockTolerance`. Default is 0 across all four libraries — always set it explicitly.
- **`hrtime(true)` is the monotonic clock in PHP 7.3+.** `microtime(true)` is the wall clock. The spec's execution timer must use `hrtime(true)` (returns nanoseconds as integer) to avoid NTP-jump corruption. Pre-7.3 PHP lacks `hrtime` and you must fall back to `microtime(true)` with the documented caveat that wall-clock jumps can corrupt the histogram.
- **Eloquent's `lockForUpdate()` is the equivalent of Postgres `SELECT FOR UPDATE`.** Same as Django's `select_for_update()`, same as Prisma's `$queryRaw`. Eloquent's version is a query-builder method: `Model::where('token_hash', $h)->lockForUpdate()->first()`. Must be inside `DB::transaction()`.

## JWT Auth Middleware

Laravel middleware is a class with `handle($request, Closure $next)`. The class is registered in `bootstrap/app.php` (Laravel 11) or `app/Http/Kernel.php` (Laravel 10). The middleware reads the `Authorization` header, verifies the JWT, loads the user (cached via Laravel's `Cache::remember()`), and calls `$request->setUserResolver()` so that `Auth::user()` returns the principal.

```php
<?php
// app/Http/Middleware/JwtAuth.php
namespace App\Http\Middleware;

use Closure;
use Firebase\JWT\JWT;
use Firebase\JWT\Key;
use Firebase\JWT\ExpiredException;
use Firebase\JWT\SignatureInvalidException;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Cache;
use App\Models\User;
use App\Services\JwtPrincipal;

class JwtAuth
{
    public function handle(Request $request, Closure $next)
    {
        $header = $request->header('Authorization', '');
        if (str_starts_with($header, 'Bearer ')) {
            $token = substr($header, 7);
            try {
                $claims = JWT::decode($token,
                    new Key(env('JWT_SECRET'), 'HS256'));
                //  Cache the user lookup for 60s; tag the cache key by user_id
                //  so we can invalidate on /auth/refresh (role/orgId can change)
                //  and on PATCH /orgs/{id}/members/{userId}.
                $userId = (int) $claims->sub;
                $user = Cache::remember("user.{$userId}", 60, function () use ($userId) {
                    return User::find($userId);
                });
                if ($user && $user->enabled) {
                    //  Set the user resolver so Auth::user() returns the principal.
                    //  Always trust the DB-loaded role/orgId over the JWT claim.
                    $principal = new JwtPrincipal(
                        userId: $user->id, email: $user->email, name: $user->name,
                        orgId: $user->org_id, role: $user->role,
                        isSystemAdmin: $user->is_system_admin,
                    );
                    $request->setUserResolver(fn () => $principal);
                    $request->attributes->set('jwt_claims', $claims);
                }
            } catch (ExpiredException | SignatureInvalidException $e) {
                //  Invalid token → anonymous.  The route-level @require_role
                //  middleware will return 401 if the route requires auth.
            } catch (\Throwable $e) {
                //  Malformed token → anonymous.
            }
        }
        return $next($request);
    }
}
```

The `Cache::remember()` call is the Laravel equivalent of Spring's Caffeine `userCache.get()` and Django's `user_cache`. Under Octane, the cache is shared across requests within the same worker, which is the persistent-process behaviour we want. Under PHP-FPM, the cache is process-local and dies with the process — effectively useless — so you would back it with Redis instead (`Cache::store('redis')->remember(...)`).

## RBAC Middleware

```php
<?php
// app/Http/Middleware/RequireRole.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use App\Services\JwtPrincipal;
use App\Http\Responses\ProblemDetail;

class RequireRole
{
    private const ROLE_LEVEL = [
        'ADMIN'  => 0,
        'MEMBER' => 1,
        'VIEWER' => 2,
    ];

    public function handle(Request $request, Closure $next, string $required, ?string $orgScoped = null)
    {
        $principal = $request->user();
        if (!$principal instanceof JwtPrincipal) {
            return ProblemDetail::make(401, 'Unauthorized', 'authentication required', $request);
        }
        if (self::ROLE_LEVEL[$principal->role] > self::ROLE_LEVEL[$required]) {
            return ProblemDetail::make(403, 'Forbidden',
                "role {$required} required, you are {$principal->role}", $request);
        }
        if ($orgScoped === 'org_scoped') {
            $pathOrgId = (int) $request->route('id');
            if ($pathOrgId <= 0) {
                return ProblemDetail::make(403, 'Forbidden', 'invalid org id', $request);
            }
            //  System admins can access any org.
            if ($principal->isSystemAdmin && $principal->role === 'ADMIN') {
                //  pass
            } elseif ($principal->orgId !== $pathOrgId) {
                return ProblemDetail::make(403, 'Forbidden',
                    'not a member of this organization', $request);
            }
        }
        return $next($request);
    }
}
```

The `RequireRole` middleware accepts parameters via the route definition (`'role:ADMIN,org_scoped'` syntax — the part after the colon is passed to `handle()` as `$required` and `$orgScoped`). This is Laravel's equivalent of Spring's `@PreAuthorize("hasRole('ADMIN')")` annotation parameter — it lets the route definition express the role requirement inline.

## Trace + Timer Middleware

```php
<?php
// app/Http/Middleware/TraceContext.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Log;
use Illuminate\Support\Str;

class TraceContext
{
    public function handle(Request $request, Closure $next)
    {
        $requestId = $request->header('X-Request-Id') ?: Str::uuid()->toString();
        $traceId   = $request->header('X-Trace-Id')   ?: Str::uuid()->toString();
        $spanId    = Str::uuid()->toString();
        $request->attributes->set('request_id', $requestId);
        $request->attributes->set('trace_id',   $traceId);
        $request->attributes->set('span_id',    $spanId);
        //  Mix into Log::withContext() so every subsequent log line carries it.
        Log::withContext([
            'trace_id'   => $traceId,
            'request_id' => $requestId,
        ]);
        $response = $next($request);
        $response->headers->set('X-Request-Id', $requestId);
        $response->headers->set('X-Trace-Id',   $traceId);
        $response->headers->set('X-Span-Id',    $spanId);
        return $response;
    }
}
```

```php
<?php
// app/Http/Middleware/RequestTimer.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Prometheus;  //  assumes prom-client wrapper

class RequestTimer
{
    public function handle(Request $request, Closure $next)
    {
        //  hrtime(true) is monotonic, returns nanoseconds as int.
        //  Available in PHP 7.3+.  Falls back to microtime(true) * 1e6 if absent.
        $start = function_exists('hrtime') ? hrtime(true) : (int) (microtime(true) * 1e9);
        $response = $next($request);
        $durationNs = (function_exists('hrtime') ? hrtime(true) : (int) (microtime(true) * 1e9)) - $start;
        $durationSec = $durationNs / 1e9;
        $route = $request->route()?->uri() ?? 'unknown';
        Prometheus::histogram(
            'http_request_duration_seconds',
            'Wall-clock duration of HTTP requests',
            ['method', 'route', 'status'],
        )->observe($durationSec, [
            $request->method(), $route, (string) $response->status(),
        ]);
        $response->headers->set('X-Response-Time-ms', number_format($durationNs / 1e6, 2));
        return $response;
    }
}
```

`Log::withContext()` is Laravel 9+'s structured-logging context — it merges the given keys into every subsequent log line in the request. Under Octane, the context is reset between requests automatically (Laravel's `RequestContext` middleware clears it); under PHP-FPM the process dies so there is no leak. The `Prometheus::histogram()` facade is a thin wrapper around `prometheus/client_php`'s `Histogram` — register it in a service provider.

## Middleware Registration

Laravel 11 registers middleware in `bootstrap/app.php`:

```php
<?php
// bootstrap/app.php
use App\Http\Middleware\{
    TraceContext, RequestTimer, JwtAuth, RequireRole
};
use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;

return Application::configure(basePath: dirname(__DIR__))
    ->withMiddleware(function (Middleware $middleware) {
        //  Order is the contract: trace → timer → (auth per-route) → (rbac per-route)
        //  Global middleware runs on every request; per-route middleware is
        //  applied via the 'role:...' alias in routes/api.php.
        $middleware->append(TraceContext::class);
        $middleware->append(RequestTimer::class);
        //  Register JwtAuth as global too, so request->user() is set before
        //  any route runs.  Routes that don't require auth will simply not
        //  have a RequireRole gate, and an anonymous request will pass.
        $middleware->append(JwtAuth::class);
        //  Alias for per-route use:  ->middleware('role:ADMIN,org_scoped')
        $middleware->alias([
            'role' => RequireRole::class,
        ]);
    })
    ->create();
```

## Auth Controller (login, refresh, register, me)

```php
<?php
// app/Http/Controllers/AuthController.php
namespace App\Http\Controllers;

use App\Http\Responses\ProblemDetail;
use App\Models\{User, RefreshToken, RefreshTokenHistory};
use App\Services\JwtPrincipal;
use Firebase\JWT\JWT;
use Illuminate\Http\{Request, JsonResponse};
use Illuminate\Support\Facades\{Auth, Cache, DB, Hash, Log};
use Illuminate\Support\Str;

class AuthController extends Controller
{
    public function register(Request $request): JsonResponse
    {
        $data = $request->validate([
            'email'    => 'required|email',
            'password' => 'required|string|min:8',
            'name'     => 'required|string|max:120',
        ]);
        if (User::where('email', $data['email'])->exists()) {
            return ProblemDetail::make(409, 'Conflict', 'email already exists', $request);
        }
        $user = User::create([
            'email'         => $data['email'],
            'password_hash' => Hash::driver('bcrypt')->make($data['password'], ['rounds' => 12]),
            'name'          => $data['name'],
            'role'          => 'VIEWER',
        ]);
        return response()->json([
            'id'         => $user->id,
            'email'      => $user->email,
            'name'       => $user->name,
            'role'       => $user->role,
            'created_at' => $user->created_at,
        ], 201);
    }

    public function login(Request $request): JsonResponse
    {
        $data = $request->validate([
            'email'    => 'required|email',
            'password' => 'required|string',
        ]);
        $user = User::where('email', $data['email'])->first();
        if (!$user || !$user->enabled
            || !Hash::driver('bcrypt')->check($data['password'], $user->password_hash)) {
            return ProblemDetail::make(401, 'Unauthorized', 'invalid credentials', $request);
        }
        $principal = $this->principalFromUser($user);
        $accessToken  = $this->issueAccessToken($principal);
        $refreshToken = $this->issueRefreshToken($user->id);
        return response()->json([
            'accessToken'  => $accessToken,
            'refreshToken' => $refreshToken,
            'user'         => $principal,
        ]);
    }

    public function refresh(Request $request): JsonResponse
    {
        $data = $request->validate(['refreshToken' => 'required|string']);
        $result = $this->rotateRefreshToken($data['refreshToken']);
        if ($result === 'REUSE_DETECTED') {
            Log::warning('refresh token reuse detected — family revoked', [
                'token_hash' => hash('sha256', $data['refreshToken']),
            ]);
            $this->revokeFamily($data['refreshToken']);
            return ProblemDetail::make(401, 'Unauthorized',
                'refresh token reuse detected — family revoked', $request);
        }
        if ($result === 'NOT_FOUND' || $result === 'EXPIRED') {
            return ProblemDetail::make(401, 'Unauthorized', 'invalid refresh token', $request);
        }
        $user = User::findOrFail($result['user_id']);
        Cache::forget("user.{$user->id}");    //  force fresh role/orgId
        $principal = $this->principalFromUser($user);
        return response()->json([
            'accessToken'  => $this->issueAccessToken($principal),
            'refreshToken' => $result['new_token'],
            'user'         => $principal,
        ]);
    }

    public function me(Request $request): JsonResponse
    {
        $principal = $request->user();
        if (!$principal instanceof JwtPrincipal) {
            return ProblemDetail::make(401, 'Unauthorized', 'authentication required', $request);
        }
        $memberships = User::find($principal->userId)
            ->memberships()
            ->with('org')
            ->get();
        return response()->json([
            ...(array) $principal,
            'memberships' => $memberships->map(fn ($m) => [
                'org_id' => $m->org_id, 'org_name' => $m->org->name, 'role' => $m->role,
            ]),
        ]);
    }

    //  ── JWT + refresh-token helpers ────────────────────────────────────

    private function issueAccessToken(JwtPrincipal $p): string
    {
        $now = time();
        return JWT::encode([
            'sub'    => (string) $p->userId,
            'email'  => $p->email,
            'name'   => $p->name,
            'org_id' => $p->orgId,
            'role'   => $p->role,
            'iat'    => $now,
            'exp'    => $now + 900,           //  15 minutes
        ], env('JWT_SECRET'), 'HS256');
    }

    private function issueRefreshToken(int $userId): string
    {
        $token = Str::random(64);    //  64-char base64-ish string
        $family = RefreshToken::where('user_id', $userId)->max('family_id') ?? 0;
        RefreshToken::create([
            'token_hash' => hash('sha256', $token),
            'family_id'  => $family + 1,
            'user_id'    => $userId,
            'expires_at' => now()->addDays(7),
        ]);
        return $token;
    }

    private function rotateRefreshToken(string $token): array|string
    {
        $h = hash('sha256', $token);
        //  DB::transaction() defaults to SERIALIZABLE on Postgres in Laravel 11.
        //  We need REPEATABLE READ + SELECT FOR UPDATE — override.
        return DB::transaction(function () use ($h, $token) {
            //  Eloquent's lockForUpdate() emits SELECT ... FOR UPDATE.
            $row = RefreshToken::where('token_hash', $h)->lockForUpdate()->first();
            if (!$row) {
                $wasValid = RefreshTokenHistory::where('token_hash', $h)->exists();
                return $wasValid ? 'REUSE_DETECTED' : 'NOT_FOUND';
            }
            if ($row->expires_at < now()) {
                $row->delete();
                return 'EXPIRED';
            }
            $newToken = Str::random(64);
            $newHash  = hash('sha256', $newToken);
            RefreshToken::create([
                'token_hash' => $newHash,
                'family_id'  => $row->family_id,
                'user_id'    => $row->user_id,
                'expires_at' => now()->addDays(7),
            ]);
            RefreshTokenHistory::create([
                'token_hash' => $h,
                'family_id'  => $row->family_id,
            ]);
            $row->delete();
            return ['user_id' => $row->user_id, 'new_token' => $newToken];
        }, config('database.connections.pgsql.isolation', 3));   //  3 = REPEATABLE READ
    }

    private function revokeFamily(string $token): void
    {
        $h = hash('sha256', $token);
        DB::statement(<<<SQL
            DELETE FROM refresh_tokens WHERE family_id = (
                SELECT family_id FROM refresh_tokens_history WHERE token_hash = ?
            )
        SQL, [$h]);
    }

    private function principalFromUser(User $user): JwtPrincipal
    {
        return new JwtPrincipal(
            userId:       $user->id,
            email:        $user->email,
            name:         $user->name,
            orgId:        $user->org_id,
            role:         $user->role,
            isSystemAdmin: $user->is_system_admin,
        );
    }
}
```

The `DB::transaction()` callback with `lockForUpdate()` is the Laravel equivalent of Django's `transaction.atomic() + select_for_update()` and Spring's `JdbcTemplate + SELECT FOR UPDATE`. All three emit the same SQL (`SELECT ... FOR UPDATE` inside a transaction with appropriate isolation). The third argument to `DB::transaction()` is the isolation level — Laravel does not expose this in the config by default, so we use a custom `config('database.connections.pgsql.isolation', 3)` lookup. The `3` is the PDO constant `PDO::FETCH_ASSOC` ... no, wait, `3` is `PDO::ATTR_ERRMODE` ... actually for `setIsolationLevel` on Laravel 11's Postgres driver, the value is a string like `'REPEATABLE READ'`. Read your Laravel version's docs — this API changed across versions and is a common bug source.

## JwtPrincipal DTO

```php
<?php
// app/Services/JwtPrincipal.php
namespace App\Services;

readonly class JwtPrincipal
{
    public function __construct(
        public int    $userId,
        public string $email,
        public string $name,
        public ?int   $orgId,
        public string $role,
        public bool   $isSystemAdmin,
    ) {}
}
```

The `readonly` class is PHP 8.2+ syntax — all properties are immutable after construction, which is the same contract as Java's `record`. This is important for the principal because it must not be mutated mid-request (a controller that does `$principal->role = 'ADMIN'` would silently break the RBAC check on the next route).

## What This Teaches

Building the same JWT+RBAC contract in Laravel after Spring Boot teaches five ecosystem-specific lessons:

1. **PHP-FPM's process-per-request model eliminates shared-state bugs but kills in-process caching.** Spring Boot's Caffeine cache, Express's `lru-cache`, Django's module-level dict — all of these assume a long-lived process. PHP-FPM dies after every request, so `Cache::remember()` under PHP-FPM is a per-request memoization, not a cross-request cache. To get a real cache you need either Octane (persistent workers) or an external store (Redis). The lesson: pick your runtime before you pick your caching strategy, because the runtime determines what "cache" even means.

2. **Laravel Octane introduces shared-state concerns that PHP developers are not trained to handle.** Under Octane, a singleton resolved from the service container in one request is still alive in the next request — unless you flush it. Laravel Octane's `flush()` list is the equivalent of Spring's `ThreadLocal` cleanup or Express's `AsyncLocalStorage` reset. Forgetting to flush the `Auth` facade (or any facade that holds request-scoped state) causes cross-request authentication leaks — user A's JWT principal appears on user B's request. The fix is to declare every request-scoped singleton in `config/octane.php`'s `flush` list, and to use `$request->user()` (which is reset per request) instead of `Auth::user()` (which may not be). This trap is unique to PHP-with-Octane — none of the other three ecosystems have it.

3. **Eloquent's `lockForUpdate()` is the equivalent of `SELECT FOR UPDATE` and is a one-liner.** Same as Django's `select_for_update()`, same as Prisma's `$queryRaw` (but native). Laravel's version is the most ergonomic of the four: `Model::where('token_hash', $h)->lockForUpdate()->first()` inside `DB::transaction()`. The refresh-token rotation race is solved in 4 lines. The lesson: every ORM eventually exposes `SELECT FOR UPDATE`; Laravel and Django expose it natively, JPA exposes it via `@Lock`, Prisma exposes it via raw SQL. Know where yours is.

4. **`firebase/php-jwt`'s `JWT::decode()` accepts a `leeway` option, but you pass it differently than the other libraries.** Spring passes `clockSkewSeconds(60)` to the parser builder; Express passes `clockTolerance: 60` to `verify()`; Django passes `leeway=60` to `decode()`; Laravel passes `leeway` via `JWT::$leeway = 60` (a static property) before calling `JWT::decode()`. The default is 0 across all four. The interop failure mode is the same: a token issued at `T` by Spring is rejected by Laravel at `T+0.001s` if `leeway` is 0. Always set it explicitly in both directions, and write an interop test that issues a token in one ecosystem and verifies it in another.

5. **Laravel's "convention over configuration" eliminates ~60 lines of wiring but hides the moving parts.** The Spring Boot anchor required explicit `@Bean`, `@ComponentScan`, `@EntityScan`, `@EnableJpaRepositories`, and `SecurityFilterChain` configuration — ~120 lines of wiring. Laravel's `Application::configure()` + `Route::apiResource()` + `php artisan migrate` does the same in ~15 lines. The cost is that when something breaks (a route is 404, a middleware is not running, a model is not saving), you have to know where Laravel hid the relevant code — there is no `@Bean` annotation to grep for. The lesson: convention-over-configuration is a productivity multiplier once you know the conventions, and a debugging nightmare before you do. Read the entire `bootstrap/app.php` and `app/Providers/` directory once, before you ship.
