# 13.02.03. Translation Express TypeScript Middleware

## Scope

This is a single-ecosystem implementation file inside a capstone milestone. It is a reference implementation to reproduce, not a tutorial to copy. The contract it implements is defined in [[13.02.01. System Specification]] and the same contract is implemented in Spring Boot (anchor, [[13.02.02. Anchor Implementation Spring Security]]), Django ([[13.02.04. Translation Python Django Middleware]]) and Laravel ([[13.02.05. Translation PHP Laravel Middleware]]). Read the anchor note first — this note assumes you have already internalised the filter-chain ordering, the JWT verification shape, and the refresh-token rotation race, and explains only the deltas from the Spring Boot anchor.

## What You Are Building

A Node.js 20 + Express 4 + TypeScript 5 application that satisfies the Milestone 2 contract: JWT auth (HS256, 15-min access + 7-day refresh with rotation and reuse detection), RBAC (`ADMIN > MEMBER > VIEWER`, org-scoped), distributed tracing headers (`X-Request-Id`, `X-Trace-Id`, `X-Span-Id`), and execution timers (Prometheus histogram with monotonic clock). Persistence uses Prisma against Postgres 16. Tests use `supertest` + `vitest`. The deliverable is `npm run dev`-able, containerised with a multi-stage Dockerfile, and load-tested with `k6`.

The structural delta from Spring Boot is that Express has no framework-level "filter chain" — middleware is just a list of functions `(req, res, next) => void` that run in registration order on every request. This is more verbose but more debuggable: every line of middleware is app code you can read, not framework DSL you have to reverse-engineer. The cost is that you must hand-wire the order (Trace → Timer → Auth → RBAC → handler) and you must remember to `next()` in every branch, including the error branch, or the request hangs forever.

## Implementation Steps

1. **Bootstrap.** `npm init -y && npm i express@4 jsonwebtoken@9 bcrypt@5 @prisma/client@5 zod@3 pino@9 prom-client@15 && npm i -D typescript@5 @types/express @types/jsonwebtoken @types/bcrypt vitest@2 supertest@7 tsx@4 prisma@5`. `npx tsc --init` with `strict: true`, `module: NodeNext`, `moduleResolution: NodeNext`.
2. **Wire dependencies.** Install only what the spec requires — Express, JJWT-equivalent (`jsonwebtoken`), bcrypt, Prisma, zod for DTO validation, pino for structured logging, prom-client for the Prometheus histogram. No ORM-with-opinions (no TypeORM, no Sequelize), no auth framework (no Passport — Passport's session model fights JWT).
3. **Implement the contract.** Match the spec exactly — same paths (`/auth/login`, `/auth/refresh`, `/auth/me`, `/orgs/{id}`, `/orgs/{id}/members`), same status codes (200/201/401/403/409/429), same JSON shapes (Problem Details for errors, defined DTOs for success).
4. **Wire observability.** Pino logger with `trace_id` and `request_id` merged from the request context; `prom-client` histogram `http_request_duration_seconds{method,route,status}` recorded in the timer middleware using `performance.now()`.
5. **Containerize.** Multi-stage Dockerfile: `FROM node:20-bookworm-slim AS build` → `npm ci` → `FROM node:20-bookworm-slim AS run` → `COPY --from=build` → `USER node` → `CMD ["node", "dist/server.js"]`. Image size target: <130 MB.
6. **Test.** `vitest run` against an integration suite that uses `supertest` against the real Express app and a Testcontainers-Postgres instance. Test cases: register/login happy path, expired token, wrong role, wrong org, refresh-token rotation, refresh-token reuse → family revocation.

## Implementation Deltas

The Spring Boot anchor taught you the contract; Express teaches you five deltas worth recording.

- **No `SecurityFilterChain` DSL — middleware is an array.** Spring's filter chain is a framework-managed linked list with explicit ordering rules (`addFilterAfter`, `addFilterBefore`). Express's middleware is just `app.use(trace); app.use(timer); app.use(auth); app.use(rbac); app.use(router);` — order is the registration order. Easier to read; easier to get wrong because there is no compile-time check that "auth is before rbac".
- **`req.user` is the principal carrier, not a `ThreadLocal`.** Spring's `SecurityContextHolder` is a `ThreadLocal` that propagates automatically (within the request thread). Express attaches the principal to `req.user` (or `(req as AuthedRequest).user` in TypeScript). This is more explicit but requires you to thread `req` through every function that needs the principal — you cannot call a service that does `SecurityContextHolder.getContext().getAuthentication()` because there is no thread-local.
- **`jsonwebtoken` library has zero clock skew by default.** JJWT defaults to 60s of skew. `jsonwebtoken` defaults to 0 — you must pass `clockTimestamp` or accept that an `exp` of `T+900s` is rejected at `T+900.001s`. Always pass `{ algorithms: ["HS256"], clockTolerance: 60 }` to `jwt.verify()`.
- **`performance.now()` is the monotonic clock, `Date.now()` is the wall clock.** Node exposes both; the equivalent of Java's `System.nanoTime()` is `performance.now()` (returns a `DOMHighResTimeStamp` in milliseconds with sub-millisecond precision). Use it for every duration measurement.
- **`process.env.JWT_SECRET` is read at startup, not lazily.** Spring's `@Value("${jwt.secret}")` is read once at bean construction. Express's `process.env.JWT_SECRET` is read every time the variable is accessed — fine for `string` constants, dangerous if you ever conditionally set it. Cache it in a `const` at module scope: `const JWT_SECRET = process.env.JWT_SECRET ?? assertEnv("JWT_SECRET");`.

## Auth Middleware

The `authenticate` middleware extracts the Bearer token, verifies it, loads the user from the DB (cached for 60s), and attaches it to `req.user`. If there is no token or verification fails, it calls `next()` without setting `req.user` — the RBAC middleware will then return 401. This is the Express idiom for "anonymous pass-through": do not throw, do not return a response, just `next()` and let the downstream check decide.

```typescript
// src/middleware/auth.middleware.ts
import { Request, Response, NextFunction } from "express";
import jwt, { JwtPayload } from "jsonwebtoken";
import { LRUCache } from "lru-cache";
import { db } from "../db/client.js";
import { AuthError } from "../errors.js";

export interface AuthedRequest extends Request {
  user?: Principal;
}

export interface Principal {
  userId: number;
  email: string;
  name: string;
  orgId: number | null;
  role: "ADMIN" | "MEMBER" | "VIEWER";
  isSystemAdmin: boolean;
}

interface JwtClaims extends JwtPayload {
  sub: string;
  email: string;
  org_id: number | null;
  role: "ADMIN" | "MEMBER" | "VIEWER";
  name: string;
}

const JWT_SECRET = process.env.JWT_SECRET ?? (() => { throw new Error("JWT_SECRET missing"); })();
const ACCESS_TTL_SEC = 900;

//  In-process LRU cache, 60s TTL.  At 5 000 RPS with 10K active users, hit
//  rate is ~95 %.  Cache is invalidated on /auth/refresh (role/orgId can change)
//  and on PATCH /orgs/{id}/members/{userId} (role can change).
const userCache = new LRUCache<number, Principal>({
  max: 10_000,
  ttl: 60_000,
});

export function clearUserCache(userId: number) { userCache.delete(userId); }

export function authenticate(req: AuthedRequest, _res: Response, next: NextFunction) {
  const header = req.header("authorization") ?? "";
  if (!header.startsWith("Bearer ")) return next();   //  anonymous; RBAC middleware will 401
  const token = header.slice(7);
  try {
    const claims = jwt.verify(token, JWT_SECRET, {
      algorithms: ["HS256"],
      clockTolerance: 60,           //  60s skew — matches Spring Boot's default
    }) as JwtClaims;
    //  Load from DB (with cache) to pick up role/org changes within 60s.
    const userId = Number(claims.sub);
    const cached = userCache.get(userId);
    if (cached) { req.user = cached; return next(); }
    //  DB lookup is async — Express middleware can return a Promise.
    loadPrincipal(userId)
      .then((principal) => {
        if (!principal) return next(new AuthError("user not found"));
        userCache.set(userId, principal);
        req.user = principal;
        next();
      })
      .catch((err) => next(err));
    return;
  } catch (err) {
    //  Invalid signature, expired, malformed — treat as anonymous.
    //  RBAC middleware will 401 if route requires auth.
    return next();
  }
}

async function loadPrincipal(userId: number): Promise<Principal | null> {
  const row = await db.user.findUnique({
    where: { id: userId },
    select: { id: true, email: true, name: true, orgId: true,
              role: true, isSystemAdmin: true, enabled: true },
  });
  if (!row || !row.enabled) return null;
  return {
    userId: row.id,
    email: row.email,
    name: row.name,
    orgId: row.orgId,
    role: row.role as Principal["role"],
    isSystemAdmin: row.isSystemAdmin,
  };
}

export function issueAccessToken(p: Principal): string {
  const now = Math.floor(Date.now() / 1000);
  return jwt.sign(
    { sub: p.userId.toString(), email: p.email, org_id: p.orgId,
      role: p.role, name: p.name, iat: now, exp: now + ACCESS_TTL_SEC },
    JWT_SECRET,
    { algorithm: "HS256" }
  );
}
```

The `lru-cache` package (v10+) is the standard cache — Node has no built-in LRU. The `ttl: 60_000` is in milliseconds. Note that `jwt.verify()` is synchronous in `jsonwebtoken` (it uses Node's `crypto.createHmac`, which is sync) — that is fine for HS256, but if you ever switch to RS256 (asymmetric), use `jwt.verify()`'s callback form to avoid blocking the event loop on the public-key lookup.

## RBAC Middleware

The `requireRole` middleware factory returns a middleware that checks `req.user` against the required role and the path's `{id}` against `req.user.orgId`. It is applied per-route, not globally, because each route has a different required role.

```typescript
// src/middleware/rbac.middleware.ts
import { AuthedRequest } from "./auth.middleware.js";
import { Response, NextFunction } from "express";
import { AuthError, ForbiddenError } from "../errors.js";

type Role = "ADMIN" | "MEMBER" | "VIEWER";
const ROLE_LEVEL: Record<Role, number> = { ADMIN: 0, MEMBER: 1, VIEWER: 2 };

//  requireRole("ADMIN") → caller must be ADMIN or system admin.
//  requireRole("MEMBER") → caller must be ADMIN or MEMBER.
//  requireRole("VIEWER") → any authenticated caller.
export function requireRole(required: Role, opts: { orgScoped?: boolean } = {}) {
  return (req: AuthedRequest, _res: Response, next: NextFunction) => {
    if (!req.user) return next(new AuthError("authentication required"));
    const { user } = req;
    if (ROLE_LEVEL[user.role] > ROLE_LEVEL[required]) {
      return next(new ForbiddenError(`role ${required} required, you are ${user.role}`));
    }
    if (opts.orgScoped) {
      const pathOrgId = Number(req.params.id);
      if (!Number.isFinite(pathOrgId)) {
        return next(new ForbiddenError("invalid org id"));
      }
      //  System admins can access any org.
      if (user.isSystemAdmin && user.role === "ADMIN") return next();
      if (user.orgId !== pathOrgId) {
        return next(new ForbiddenError("not a member of this organization"));
      }
    }
    next();
  };
}
```

The middleware is applied per-route in the router:

```typescript
// src/routes/org.routes.ts
import { Router } from "express";
import { authenticate } from "../middleware/auth.middleware.js";
import { requireRole } from "../middleware/rbac.middleware.js";
import * as ctrl from "../controllers/org.controller.js";

export const orgRouter = Router();

orgRouter.get("/",
  authenticate, requireRole("VIEWER"),
  ctrl.listOrgs);
orgRouter.post("/",
  authenticate, requireRole("ADMIN"),
  ctrl.createOrg);
orgRouter.get("/:id",
  authenticate, requireRole("VIEWER", { orgScoped: true }),
  ctrl.getOrg);
orgRouter.patch("/:id",
  authenticate, requireRole("ADMIN", { orgScoped: true }),
  ctrl.updateOrg);
orgRouter.delete("/:id",
  authenticate, requireRole("ADMIN", { orgScoped: true }),
  ctrl.deleteOrg);
orgRouter.get("/:id/members",
  authenticate, requireRole("VIEWER", { orgScoped: true }),
  ctrl.listMembers);
orgRouter.post("/:id/members",
  authenticate, requireRole("ADMIN", { orgScoped: true }),
  ctrl.addMember);
orgRouter.patch("/:id/members/:userId",
  authenticate, requireRole("ADMIN", { orgScoped: true }),
  ctrl.updateMemberRole);
orgRouter.delete("/:id/members/:userId",
  authenticate, requireRole("ADMIN", { orgScoped: true }),
  ctrl.removeMember);
```

The middleware chain on each route is `authenticate → requireRole → controller`. Express runs them in order; if `authenticate` calls `next(new AuthError(...))`, the error bubbles to the error-handling middleware (registered last via `app.use(errorHandler)`) and never reaches `requireRole`. If `authenticate` calls `next()` without setting `req.user` (anonymous), `requireRole` returns 401. If `authenticate` sets `req.user` but `requireRole` denies, `requireRole` returns 403. The controller only runs if both pass.

## Trace + Timer Middleware

Both run before `authenticate` so 401/403 responses are traced and timed. The trace middleware uses `crypto.randomUUID()` (Node 14.17+) for UUIDv4 generation; the timer uses `performance.now()` (monotonic, sub-millisecond).

```typescript
// src/middleware/trace.middleware.ts
import { Request, Response, NextFunction } from "express";
import { randomUUID } from "node:crypto";
import { AsyncLocalStorage } from "node:async_hooks";

//  AsyncLocalStorage is the Node equivalent of Java's ThreadLocal —
//  it propagates the trace context across async boundaries (await,
//  Promise.then, setImmediate) without explicit threading.
export const traceContext = new AsyncLocalStorage<TraceContext>();

export interface TraceContext {
  requestId: string;
  traceId: string;
  spanId: string;
}

export function traceMiddleware(req: Request, res: Response, next: NextFunction) {
  const ctx: TraceContext = {
    requestId: req.header("x-request-id") || randomUUID(),
    traceId:   req.header("x-trace-id")   || randomUUID(),
    spanId:    randomUUID(),
  };
  res.setHeader("X-Request-Id", ctx.requestId);
  res.setHeader("X-Trace-Id",   ctx.traceId);
  res.setHeader("X-Span-Id",    ctx.spanId);
  traceContext.run(ctx, () => next());
}

// src/middleware/timer.middleware.ts
import { Request, Response, NextFunction } from "express";
import { performance } from "node:perf_hooks";
import { httpRequestDuration } from "../metrics.js";
import { traceContext } from "./trace.middleware.js";

export function timerMiddleware(req: Request, res: Response, next: NextFunction) {
  const start = performance.now();    //  monotonic, sub-ms
  res.on("finish", () => {
    const durationSec = (performance.now() - start) / 1000;
    //  req.route.path is set by Express after route matching; fall back to
    //  req.path if middleware ran before matching (shouldn't happen here).
    const route = req.route?.path ?? req.path ?? "unknown";
    httpRequestDuration
      .labels(req.method, route, String(res.statusCode))
      .observe(durationSec);
    res.setHeader("X-Response-Time-ms", ((performance.now() - start).toFixed(2)));
  });
  next();
}
```

`AsyncLocalStorage` is the Node 16+ replacement for `cls-hooked` (the old continuation-local-storage package). It is the correct way to make `trace_id` available to loggers deep in the call stack without threading it through every function. The logger picks it up like this:

```typescript
// src/logger.ts
import pino from "pino";
import { traceContext } from "./middleware/trace.middleware.js";

export const logger = pino({
  level: process.env.LOG_LEVEL ?? "info",
  //  Mix trace_id and request_id into every log line automatically.
  mixin: () => {
    const ctx = traceContext.getStore();
    return ctx ? { trace_id: ctx.traceId, request_id: ctx.requestId } : {};
  },
});
```

## Auth Controller (login, refresh, register, me)

```typescript
// src/controllers/auth.controller.ts
import { Router, Response } from "express";
import bcrypt from "bcrypt";
import { AuthedRequest, issueAccessToken, clearUserCache } from "../middleware/auth.middleware.js";
import { db } from "../db/client.js";
import { AuthError, ConflictError } from "../errors.js";
import { randomBytes, createHash } from "node:crypto";
import { logger } from "../logger.js";

export const authRouter = Router();

authRouter.post("/register", async (req, res, next) => {
  try {
    const { email, password, name } = req.body;
    if (!email || !password || password.length < 8 || !name) {
      throw new AuthError("email, password (>=8 chars), name required");
    }
    const existing = await db.user.findUnique({ where: { email } });
    if (existing) throw new ConflictError("email already exists");
    const user = await db.user.create({
      data: { email, passwordHash: await bcrypt.hash(password, 12),
              name, role: "VIEWER" },
    });
    res.status(201).json({
      id: user.id, email: user.email, name: user.name,
      role: user.role, created_at: user.createdAt,
    });
  } catch (err) { next(err); }
});

authRouter.post("/login", async (req, res, next) => {
  try {
    const { email, password } = req.body;
    const user = await db.user.findUnique({ where: { email } });
    if (!user || !user.enabled) throw new AuthError("invalid credentials");
    const ok = await bcrypt.compare(password, user.passwordHash);
    if (!ok) throw new AuthError("invalid credentials");
    const principal = {
      userId: user.id, email: user.email, name: user.name,
      orgId: user.orgId, role: user.role as "ADMIN"|"MEMBER"|"VIEWER",
      isSystemAdmin: user.isSystemAdmin,
    };
    const accessToken  = issueAccessToken(principal);
    const refreshToken = await issueRefreshToken(user.id);
    res.json({ accessToken, refreshToken, user: principal });
  } catch (err) { next(err); }
});

authRouter.post("/refresh", async (req, res, next) => {
  try {
    const { refreshToken } = req.body;
    const result = await rotateRefreshToken(refreshToken);
    if (result === "REUSE_DETECTED") {
      logger.warn({ token: hashToken(refreshToken) }, "refresh token reuse detected — family revoked");
      await revokeFamily(refreshToken);
      throw new AuthError("refresh token reuse detected — family revoked");
    }
    if (result === "NOT_FOUND" || result === "EXPIRED") {
      throw new AuthError("invalid refresh token");
    }
    const user = await db.user.findUniqueOrThrow({ where: { id: result.userId } });
    clearUserCache(user.id);     //  force fresh role/orgId on next request
    const principal = {
      userId: user.id, email: user.email, name: user.name,
      orgId: user.orgId, role: user.role as "ADMIN"|"MEMBER"|"VIEWER",
      isSystemAdmin: user.isSystemAdmin,
    };
    res.json({ accessToken: issueAccessToken(principal),
               refreshToken: result.newToken, user: principal });
  } catch (err) { next(err); }
});

authRouter.get("/me", authenticate, async (req: AuthedRequest, res: Response, next) => {
  try {
    if (!req.user) throw new AuthError("authentication required");
    const memberships = await db.membership.findMany({
      where: { userId: req.user.userId },
      include: { org: true },
    });
    res.json({ ...req.user, memberships });
  } catch (err) { next(err); }
});

//  ── Refresh-token rotation with reuse detection ──────────────────────────
//  Postgres SELECT FOR UPDATE on the token_hash row makes rotation atomic
//  across concurrent requests.  Prisma does not expose FOR UPDATE directly,
//  so we drop to $queryRaw for the critical section.

async function rotateRefreshToken(token: string): Promise<
  | "REUSE_DETECTED" | "NOT_FOUND" | "EXPIRED"
  | { userId: number; newToken: string }
> {
  const hash = hashToken(token);
  return await db.$transaction(async (tx) => {
    //  SELECT FOR UPDATE on the row matching this token hash.
    const rows = await tx.$queryRaw<{ family_id: bigint; user_id: bigint; expires_at: Date }[]>`
      SELECT family_id, user_id, expires_at FROM refresh_tokens
      WHERE token_hash = ${hash} FOR UPDATE`;
    if (rows.length === 0) {
      //  Was this token ever valid?  If so, reuse → revoke family.
      const hist = await tx.$queryRaw<{ count: bigint }[]>`
        SELECT COUNT(*)::bigint AS count FROM refresh_tokens_history
        WHERE token_hash = ${hash}`;
      return hist[0].count > 0 ? "REUSE_DETECTED" : "NOT_FOUND";
    }
    const row = rows[0];
    if (row.expires_at < new Date()) {
      await tx.$executeRaw`DELETE FROM refresh_tokens WHERE token_hash = ${hash}`;
      return "EXPIRED";
    }
    //  Atomic rotate: delete old, insert new, archive old hash.
    const newToken  = randomBytes(32).toString("base64url");
    const newHash   = hashToken(newToken);
    await tx.$executeRaw`DELETE FROM refresh_tokens WHERE token_hash = ${hash}`;
    await tx.$executeRaw`
      INSERT INTO refresh_tokens (token_hash, family_id, user_id, expires_at)
      VALUES (${newHash}, ${row.family_id}, ${row.user_id}, NOW() + INTERVAL '7 days')`;
    await tx.$executeRaw`
      INSERT INTO refresh_tokens_history (token_hash, family_id, revoked_at)
      VALUES (${hash}, ${row.family_id}, NOW())`;
    return { userId: Number(row.user_id), newToken };
  }, { isolationLevel: "RepeatableRead" });
}

async function issueRefreshToken(userId: number): Promise<string> {
  const token = randomBytes(32).toString("base64url");
  const hash  = hashToken(token);
  const familyId = await db.$queryRaw`SELECT COALESCE(MAX(family_id), 0) + 1 AS next
                                       FROM refresh_tokens WHERE user_id = ${userId}`;
  await db.$executeRaw`
    INSERT INTO refresh_tokens (token_hash, family_id, user_id, expires_at)
    VALUES (${hash}, ${Number(familyId[0].next)}, ${userId}, NOW() + INTERVAL '7 days')`;
  return token;
}

async function revokeFamily(token: string): Promise<void> {
  const hash = hashToken(token);
  await db.$executeRaw`
    DELETE FROM refresh_tokens WHERE family_id = (
      SELECT family_id FROM refresh_tokens_history WHERE token_hash = ${hash}
    )`;
}

function hashToken(token: string): string {
  return createHash("sha256").update(token).digest("base64url");
}
```

The `$queryRaw` calls are the equivalent of Spring's `JdbcTemplate` — escape hatches to raw SQL when Prisma's query builder does not expose the feature you need (`FOR UPDATE` and `INTERVAL` arithmetic are both missing from Prisma as of v5). The `isolationLevel: "RepeatableRead"` is the critical detail — without it, two concurrent refresh calls can both see the row, both delete it, and both issue new tokens. Always test this with a `Promise.all([refresh(token), refresh(token)])` test case.

## App Wiring + Error Handler

```typescript
// src/app.ts
import express, { ErrorRequestHandler } from "express";
import { traceMiddleware } from "./middleware/trace.middleware.js";
import { timerMiddleware } from "./middleware/timer.middleware.js";
import { authenticate } from "./middleware/auth.middleware.js";
import { authRouter } from "./controllers/auth.controller.js";
import { orgRouter } from "./routes/org.routes.js";
import { AuthError, ConflictError, ForbiddenError } from "./errors.js";

export const app = express();

app.use(express.json());
//  Order is the contract: trace → timer → (auth via per-route middleware) → router
app.use(traceMiddleware);
app.use(timerMiddleware);

app.get("/health", (_req, res) => res.json({ status: "ok" }));
app.use("/auth", authRouter);
app.use("/orgs", orgRouter);

//  Error handler — last middleware.  Converts thrown errors to ProblemDetail JSON.
const errorHandler: ErrorRequestHandler = (err, req, res, _next) => {
  const traceId = req.header("x-trace-id") ?? "unknown";
  if (err instanceof AuthError) {
    return res.status(401).contentType("application/problem+json").json({
      type: "https://http.cat/401", title: "Unauthorized", status: 401,
      detail: err.message, instance: req.path, trace_id: traceId,
    });
  }
  if (err instanceof ForbiddenError) {
    return res.status(403).contentType("application/problem+json").json({
      type: "https://http.cat/403", title: "Forbidden", status: 403,
      detail: err.message, instance: req.path, trace_id: traceId,
    });
  }
  if (err instanceof ConflictError) {
    return res.status(409).contentType("application/problem+json").json({
      type: "https://http.cat/409", title: "Conflict", status: 409,
      detail: err.message, instance: req.path, trace_id: traceId,
    });
  }
  console.error("unhandled error", err);
  res.status(500).contentType("application/problem+json").json({
    type: "https://http.cat/500", title: "Internal Server Error", status: 500,
    detail: "an unexpected error occurred", instance: req.path, trace_id: traceId,
  });
};
app.use(errorHandler);
```

## What This Teaches

Building the same JWT+RBAC contract in Express after Spring Boot teaches five ecosystem-specific lessons:

1. **Middleware as a flat list is more debuggable than a framework DSL, but more error-prone.** Spring's `addFilterAfter(X, Y)` documents the order in code; Express's `app.use(a); app.use(b);` documents it by reading order. The Express version is easier to read; the Spring version is harder to get wrong because the framework enforces the contract. This trade-off (debuggability vs safety) is the recurring theme across the four ecosystems.

2. **`AsyncLocalStorage` is the Node equivalent of `ThreadLocal`, and it actually works across `await`.** This was not true before Node 13 — `cls-hooked` was a fragile monkey-patch on `async_hooks`. `AsyncLocalStorage` is the supported API and it propagates the trace context across `await`, `Promise.then`, `setImmediate`, and even `worker_threads` (with explicit transfer). It is the reason Express can have a `trace_id` in every log line without threading it through every function. Spring's `ThreadLocal` does not need this because Java threads are cheap and blocking; Node's event loop needs it because there is no thread.

3. **`jsonwebtoken`'s zero-default clock skew is a footgun.** JJWT defaults to 60s; `jsonwebtoken` defaults to 0. The same JWT issued by Spring and verified by Express will intermittently fail at the millisecond boundary if you do not pass `{ clockTolerance: 60 }`. This is a real interop bug — your Spring backend issues a token, your Express middleware rejects it, and the error is "jwt expired" with no obvious cause. Always set `clockTolerance` explicitly in both directions.

4. **Prisma's `$queryRaw` is the escape hatch you will need.** Prisma's query builder is excellent for CRUD but does not expose `SELECT FOR UPDATE`, `INTERVAL` arithmetic, `RETURNING`, or `ON CONFLICT` (until very recently). The refresh-token rotation's atomicity depends on `FOR UPDATE`, which means dropping to `$queryRaw`. This is not a Prisma failing — every ORM has the same escape hatch (JPA's `EntityManager.createNativeQuery`, Django's `connection.cursor().execute`, Laravel's `DB::statement`). The lesson is: know where your ORM's escape hatch is before you need it at 03:00.

5. **The error-handler middleware must be registered last and must handle every error class.** Express's error handling is opt-in: if you do not register an error-handler middleware (4-argument function), errors bubble up as plain 500s with HTML stack traces. The handler must distinguish `AuthError` (401), `ForbiddenError` (403), `ConflictError` (409), and fall through to 500 for everything else. The Problem Details shape (RFC 9457) must be respected on every error path, including the 500 fallback, because the load test's assertions check for `application/problem+json` on every non-2xx response.
