# 13.01.05. Translation PHP Laravel

## Scope

This is a single-ecosystem implementation file inside a capstone milestone. It is a reference implementation to reproduce, not a tutorial to copy. The contract is fixed by [[13.01.01. System Specification]] — read that first. This note shows how that contract is expressed in PHP 8.3 + Laravel 11.

## What You Are Building

You are reproducing the eight-endpoint Organization and Membership REST API from the Spring Boot anchor ([[13.01.02. Anchor Implementation Spring Boot]]) in PHP. The stack is Laravel 11 on PHP 8.3 (the latest LTS), the Eloquent ORM (Laravel's ActiveRecord-style data layer, equivalent to Hibernate), the Laravel Form Request (the validation layer, equivalent to Bean Validation), Laravel's resource routes (the equivalent of Spring's `@RequestMapping`), and `php artisan serve` for development or PHP-FPM + Nginx for production. The framework's fluent, expressive API is the philosophical opposite of Spring Boot's annotation-heavy, interface-driven style — but the runtime invariants (Postgres connections, transaction boundaries, validation constraints, RFC 7807 error bodies) are identical.

## Implementation Steps

1. **Bootstrap.** `composer create-project laravel/laravel delta-laravel "11.*"`, then `cd delta-laravel && php artisan install:api` (installs the `routes/api.php` file + Laravel Sanctum, which we will not use here but is required for the API scaffolding).
2. **Wire dependencies.** The Laravel framework already includes Eloquent, the validation layer, and the routing layer. Add `ext-pdo_pgsql` to `composer.json`'s `require` block (the PHP Postgres driver, which the Docker image must have compiled in). Add `laravel/telescope` only in dev for request introspection — do not install it in production.
3. **Implement the contract.** Generate the Eloquent models (`php artisan make:model Organization -mf` creates the model + migration + factory in one shot), the Form Requests (`php artisan make:request StoreOrganizationRequest`), the controller (`php artisan make:controller OrgController --api`), and wire the resource routes in `routes/api.php`.
4. **Wire observability.** Add `spatie/laravel-structured-logging` or hand-roll a `TraceIdMiddleware` that sets `request()->traceId`. Expose a `/metrics` endpoint via `prometheus/laravel-prometheus` or a hand-rolled counter.
5. **Containerize.** Multi-stage Dockerfile: builder stage runs `composer install --no-dev`, runtime stage uses `php:8.3-fpm-alpine` + Nginx sidecar (or `php:8.3-cli` with `php artisan serve` for the simplest possible setup).
6. **Test.** Write integration tests using Laravel's built-in `TestCase` + `$this->postJson('/orgs', [...])` methods. Run via `php artisan test` (wraps Pest or PHPUnit).

### `bootstrap/app.php` (Laravel 11's slim bootstrap)

```php
<?php

use Illuminate\Foundation\Application;
use Illuminate\Foundation\Configuration\Exceptions;
use Illuminate\Foundation\Configuration\Middleware;
use Illuminate\Http\Request;
use Illuminate\Validation\ValidationException;

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(function (Middleware $middleware) {
        $middleware->append(\App\Http\Middleware\TraceIdMiddleware::class);
    })
    ->withExceptions(function (Exceptions $exceptions) {
        // Convert every exception into an RFC 7807 ProblemDetail JSON body.
        $exceptions->render(function (Throwable $e, Request $request) {
            if ($request->expectsJson() || $request->is('api/*')) {
                return problem_detail_response($e, $request);
            }
        });
    })->create();

function problem_detail_response(Throwable $e, Request $request): \Illuminate\Http\JsonResponse
{
    $status = match (true) {
        $e instanceof \Illuminate\Database\Eloquent\ModelNotFoundException => 404,
        $e instanceof ValidationException => 422,
        $e instanceof \Symfony\Component\HttpKernel\Exception\HttpException => $e->getStatusCode(),
        $e instanceof \Illuminate\Database\QueryException
            && str_contains($e->getMessage(), 'Unique violation') => 409,
        default => 500,
    };

    $title = match ($status) {
        400 => 'Bad request',
        401 => 'Unauthorized',
        403 => 'Forbidden',
        404 => 'Resource not found',
        409 => 'Conflict',
        422 => 'Validation failed',
        500 => 'Internal server error',
        default => 'Error',
    };
    $typeSlug = match ($status) {
        400 => 'bad-request',
        401 => 'unauthorized',
        403 => 'forbidden',
        404 => 'not-found',
        409 => 'conflict',
        422 => 'validation-failed',
        default => 'error',
    };

    $detail = match (true) {
        $e instanceof ValidationException => collect($e->errors())
            ->map(fn ($msgs, $f) => "$f: ".implode(', ', $msgs))
            ->implode('; '),
        $e instanceof \Illuminate\Database\Eloquent\ModelNotFoundException =>
            str($e->getMessage())
                ->replace('No query results for model [App\\Models\\', '')
                ->replace('].', '.')->toString(),
        default => $status === 500
            ? "An unexpected error occurred (trace_id={$request->attributes->get('trace_id')})"
            : $e->getMessage(),
    };

    if ($status === 500) {
        \Log::error('unhandled exception', [
            'trace_id' => $request->attributes->get('trace_id'),
            'exception' => $e::class,
            'message' => $e->getMessage(),
            'stack' => $e->getTraceAsString(),
        ]);
    }

    return response()->json([
        'type' => "https://errors.example.com/$typeSlug",
        'title' => $title,
        'status' => $status,
        'detail' => $detail,
        'instance' => $request->path(),
        'trace_id' => $request->attributes->get('trace_id'),
    ], $status, ['Content-Type' => 'application/problem+json']);
}
```

```php
<?php

namespace App\Models;

use Database\Factories\OrganizationFactory;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\Relations\HasMany;
use Illuminate\Database\Eloquent\SoftDeletes;

class Organization extends Model
{
    use HasFactory, SoftDeletes;

    protected $table = 'organizations';

    // SoftDeletes adds a deleted_at column and scopes all queries to where deleted_at IS NULL.
    // The `withTrashed()` and `onlyTrashed()` query scopes are the escape hatches.

    protected $fillable = ['name', 'slug'];
    protected $hidden = [];
    protected $casts = [
        'deleted_at' => 'datetime',
    ];

    public function members(): HasMany
    {
        return $this->hasMany(Member::class);
    }

    protected static function newFactory(): OrganizationFactory
    {
        return OrganizationFactory::new();
    }
}
```

### `app/Http/Controllers/OrgController.php`

```php
<?php

namespace App\Http\Controllers;

use App\Http\Requests\AddMemberRequest;
use App\Http\Requests\PatchOrganizationRequest;
use App\Http\Requests\StoreOrganizationRequest;
use App\Http\Resources\MemberResource;
use App\Http\Resources\OrganizationResource;
use App\Models\Member;
use App\Models\Organization;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\AnonymousResourceCollection;
use Illuminate\Http\Response;
use Illuminate\Support\Facades\DB;
use Illuminate\Validation\ValidationException;

class OrgController extends Controller
{
    public function index(Request $request): AnonymousResourceCollection
    {
        $page = (int) $request->query('page', 1);
        $size = (int) $request->query('size', 20);
        if ($page < 1 || $size < 1 || $size > 100) {
            throw ValidationException::withMessages([
                'page' => ['page must be >= 1'],
                'size' => ['size must be between 1 and 100'],
            ]);
        }
        $orgs = Organization::query()->orderBy('id')->simplePaginate($size, ['*'], 'page', $page);
        return OrganizationResource::collection($orgs);
    }

    public function store(StoreOrganizationRequest $request): JsonResponse
    {
        $data = $request->validated();
        // Wrap in a transaction so the unique-check + insert is atomic.
        $org = DB::transaction(function () use ($data) {
            if (Organization::withTrashed()->where('slug', $data['slug'])->exists()) {
                // Re-check inside the transaction — race window between two concurrent POSTs.
                // The DB unique index is the real backstop, but a pre-check gives a nicer 409.
                throw ValidationException::withMessages([
                    'slug' => ["slug '{$data['slug']}' already exists"],
                ]);
            }
            return Organization::create($data);
        });
        return (new OrganizationResource($org))
            ->response()
            ->setStatusCode(201)
            ->header('Location', "/orgs/{$org->id}");
    }

    public function show(Organization $org): OrganizationResource
    {
        // Implicit route-model binding resolves the org by ID, or returns 404.
        // SoftDeletes scopes the lookup so a soft-deleted org returns 404.
        return new OrganizationResource($org);
    }

    public function update(PatchOrganizationRequest $request, Organization $org): OrganizationResource
    {
        $data = $request->validated();
        // Only apply supplied fields (PATCH semantics).
        $org->fill($data);
        if (isset($data['slug']) && $data['slug'] !== $org->getOriginal('slug')) {
            if (Organization::where('slug', $data['slug'])->whereKeyNot($org->id)->exists()) {
                throw ValidationException::withMessages([
                    'slug' => ["slug '{$data['slug']}' already exists"],
                ]);
            }
        }
        $org->save();
        return new OrganizationResource($org);
    }

    public function destroy(Organization $org): Response
    {
        // SoftDeletes — sets deleted_at = NOW(), does not row-delete.
        $org->delete();
        return response()->noContent();
    }

    public function membersIndex(Organization $org): JsonResponse
    {
        return response()->json([
            'data' => MemberResource::collection($org->members),
        ]);
    }

    public function membersStore(AddMemberRequest $request, Organization $org): JsonResponse
    {
        $data = $request->validated();
        try {
            $member = DB::transaction(function () use ($org, $data) {
                if ($org->members()->where('user_id', $data['user_id'])->exists()) {
                    throw ValidationException::withMessages([
                        'user_id' => ["user {$data['user_id']} is already a member"],
                    ]);
                }
                return $org->members()->create($data);
            });
        } catch (\Illuminate\Database\QueryException $e) {
            if (str_contains($e->getMessage(), 'uk_members_org_user')) {
                throw ValidationException::withMessages([
                    'user_id' => ["user {$data['user_id']} is already a member"],
                ]);
            }
            throw $e;
        }
        return (new MemberResource($member))
            ->response()
            ->setStatusCode(201)
            ->header('Location', "/orgs/{$org->id}/members/{$member->user_id}");
    }

    public function membersDestroy(Organization $org, int $userId): Response
    {
        $member = $org->members()->where('user_id', $userId)->first();
        if (!$member) {
            throw (new \Illuminate\Database\Eloquent\ModelNotFoundException())
                ->setModel(Member::class, [$userId]);
        }
        $member->delete();
        return response()->noContent();
    }
}
```

```php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;
use Illuminate\Support\Str;

class TraceIdMiddleware
{
    public function handle(Request $request, Closure $next): Response
    {
        $traceId = $request->header('X-Request-Id') ?: (string) Str::uuid();
        $request->attributes->set('trace_id', $traceId);

        $response->headers->set('X-Request-Id', $traceId);

    }
```

## Delta from Spring Boot Anchor

The structural delta from the Spring Boot anchor ([[13.01.02. Anchor Implementation Spring Boot]]) is six-fold:

1. **Form Requests replace `@Valid` + Bean Validation.** Spring Boot annotates the DTO with `@NotBlank` / `@Size` / `@Pattern` and the controller method signature carries `@Valid @RequestBody`. Laravel puts the validation rules in a separate `FormRequest` class (`StoreOrganizationRequest::rules()`) and the controller method signature takes the FormRequest as the type hint. The framework resolves the FormRequest before the controller runs, runs the rules, and throws `ValidationException` (which the global handler translates to a 422 ProblemDetail) if any rule fails. The trade-off: Spring scatters validation across DTOs; Laravel centralises it per-route in a FormRequest — Spring's pattern is more discoverable from the controller signature, Laravel's pattern is more reusable across controllers.

2. **Implicit route-model binding replaces `@PathVariable Long id` + explicit lookup.** Spring Boot's `@GetMapping("/{id}")` gives the controller a `Long id`; the controller then calls `service.find(id)`. Laravel's `Route::get('/orgs/{org}', ...)` gives the controller a fully-resolved `Organization $org` model — Laravel's router runs `Organization::findOrFail($id)` before the controller method runs, and throws `ModelNotFoundException` (→ 404 ProblemDetail) if the row does not exist or is soft-deleted. The trade-off: fewer lines of controller code in Laravel, but a magic DB query happens before the controller — which means a 404 from `show()` and a 500 from a database outage look identical to the controller until the exception type is inspected.

3. **Eloquent's `SoftDeletes` trait replaces the manual `@Query("where o.deletedAt is null")` filter.** Spring Boot requires every repository method to explicitly filter `deletedAt is null`. Laravel's `SoftDeletes` trait automatically scopes every query (`SELECT * FROM organizations WHERE deleted_at IS NULL`), provides a `withTrashed()` escape hatch, and overrides `delete()` to set `deleted_at = NOW()` instead of executing `DELETE`. The trade-off: Laravel's pattern is much harder to forget, but the global scope can surprise you in migrations and admin tools — you must explicitly call `Organization::withTrashed()->forceDelete()` to actually remove a row.

4. **PHP-FPM's worker model is process-per-request, not thread-per-request.** Spring Boot's Tomcat runs 200 threads inside one JVM process; shared state is JVM-wide (the `@Service` singleton, the HikariCP pool, the `EntityManagerFactory`). PHP-FPM runs N worker processes (default 5), each handling one request at a time, with no shared in-memory state between requests — every request boots the Laravel framework fresh, including the service container, the Eloquent connection cache, and the route table. The implication: PHP has no in-process cache by default (you must use Redis or APCu for shared state), but it also has no thread-safety concerns (every request is isolated). The connection pool is also per-process: each PHP-FPM worker holds at most one Postgres connection, so a 5-worker pool uses 5 Postgres connections, scaled linearly with worker count — same as Django, very different from Spring's HikariCP.

5. **Laravel's `DB::transaction()` closure replaces Spring's `@Transactional` annotation.** Spring's `@Transactional` is a proxy-based annotation; the framework wraps the method in a transactional proxy at startup. Laravel's `DB::transaction(function () { ... })` is a runtime call that takes a closure, opens the transaction, runs the closure, commits on return, and rolls back on exception. The trade-off: Spring's annotation is more declarative (you read `@Transactional` on the method and you know it's transactional); Laravel's closure is more explicit (you see the `DB::transaction` call) but easier to forget (a method that does not wrap its writes in `DB::transaction` is silently non-transactional).

6. **Migrations are PHP classes, not SQL files or XML.** Spring Boot's `ddl-auto=validate` does not generate schema — you bring your own schema (typically via Flyway or Liquibase migrations, which are SQL files). Laravel's migrations are PHP classes with `up()` and `down()` methods that use the schema builder DSL (`$table->string('name', 100)`). The trade-off: Laravel's migrations are database-agnostic at the DSL level (the same migration runs on Postgres, MySQL, SQLite), but raw SQL is required for partial unique indexes and CHECK constraints — both of which the spec mandates, and both of which are visible in the migrations above as `DB::statement(...)` calls.

## What This Teaches

The Laravel translation teaches three things the Spring Boot anchor does not surface. First, PHP's shared-nothing process model is radically different from the JVM's shared-everything model: every PHP-FPM worker boots the framework fresh, which makes cold start time (~50-150 ms per request) a real production concern — the reason Laravel Octane exists is to keep the framework booted in memory between requests, the way the JVM does. Without Octane, the per-request overhead is the dominant cost at p99 under `wrk` load. Second, Laravel's "convention over configuration" style inverts Spring Boot's "configuration over convention" style: Spring Boot asks you to declare everything (the `@Bean`, the `@RequestMapping`, the `@Transactional` boundary); Laravel asks you to follow the conventions (`app/Models/Organization.php` is auto-discovered, `routes/api.php` is auto-loaded, the `Organization` model's `$table = 'organizations'` is auto-inferred from the class name). The trade-off: Laravel is faster to write but slower to debug when the convention breaks; Spring Boot is slower to write but the wiring is explicit in source.

Third, Laravel's resource classes (`OrganizationResource`) are the cleanest separation of internal model from external JSON shape of any of the four ecosystems. Spring Boot conflates them — the `Organization` entity's getters are what Jackson serialises to JSON, unless you write a separate DTO. Express conflates them — the Prisma model is what `res.json()` returns, unless you write a manual mapper. Django conflates them — the DRF serializer does double duty as validator and JSON shape. Laravel's `OrganizationResource::toArray()` is a dedicated class whose only job is to declare the external JSON shape, separate from the Eloquent model's database mapping, separate from the FormRequest's validation rules. This is the one design decision from Laravel that the post-mortem in [[13.01.06. Architectural Comparison and Post-Mortem]] will single out as worth porting back to the other three ecosystems.

## Run It

```bash
# 1. install deps
composer install

# 2. start Postgres
docker compose up -d postgres

# 3. copy .env.example to .env and set DB_*
cp .env.example .env
# edit .env to set DB_CONNECTION=pgsql, DB_HOST=localhost, etc.

# 4. generate application key
php artisan key:generate

# 5. run migrations (creates tables + partial unique index + CHECK constraint)
php artisan migrate

# 6. dev server (auto-reload on PHP file change via php artisan serve's built-in)
php artisan serve --host=0.0.0.0 --port=8083

# 7. verify
curl -s localhost:8083/api/orgs | jq
curl -s localhost:8083/up | jq

# 8. run tests (Pest or PHPUnit, both invoked via artisan test)
php artisan test

# 9. production server (PHP-FPM + Nginx, or php artisan serve for the simplest case)
docker compose up --build

# 10. load test
wrk -t8 -c200 -d30s http://localhost:8083/api/orgs
```
