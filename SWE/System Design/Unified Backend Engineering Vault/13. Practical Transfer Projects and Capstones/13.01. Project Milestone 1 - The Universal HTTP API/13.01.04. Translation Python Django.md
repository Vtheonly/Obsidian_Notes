# 13.01.04. Translation Python Django

## Scope

This is a single-ecosystem implementation file inside a capstone milestone. It is a reference implementation to reproduce, not a tutorial to copy. The contract is fixed by [[13.01.01. System Specification]] — read that first. This note shows how that contract is expressed in Python + Django 5 + Django REST Framework (DRF) 3.15.

## What You Are Building

You are reproducing the eight-endpoint Organization and Membership REST API from the Spring Boot anchor ([[13.01.02. Anchor Implementation Spring Boot]]) in Python. The stack is Django 5.0 on Python 3.12, Django REST Framework 3.15 for the serializer + viewset + router layer (the closest Python equivalent to Spring's `@RestController` + `JpaRepository` + `@RequestMapping`), `psycopg` 3 as the Postgres driver (the modern binary driver, replacing `psycopg2`), `gunicorn` as the production WSGI server (the Python equivalent of Tomcat), and `pytest-django` for the test suite. The Django ORM replaces Hibernate; the DRF serializer replaces Bean Validation; the DRF `DefaultRouter` replaces Spring's `RequestMappingHandlerMapping`.

## Implementation Steps

1. **Bootstrap.** `python -m venv .venv && source .venv/bin/activate && pip install django djangorestframework psycopg[binary] gunicorn pytest-django`. Then `django-admin startproject myproject .` and `python manage.py startapp orgs`.
2. **Wire dependencies.** Add `'rest_framework'` and `'orgs'` to `INSTALLED_APPS` in `settings.py`. Set `DATABASES` to point at Postgres. Do not add DRF's `DEFAULT_AUTHENTICATION_CLASSES` or `DEFAULT_PERMISSION_CLASSES` — those are Milestone 2 concerns.
3. **Implement the contract.** Define the `Organization` and `Member` Django models, the DRF serializers with field-level validation, the DRF `ModelViewSet` with a `@action` for the member sub-resource, and wire the `DefaultRouter` in `urls.py`.
4. **Wire observability.** Add `django-structlog` for structured logging with `trace_id`, or hand-roll a middleware that sets `request.correlation_id`. Expose a Prometheus metrics endpoint via `django-prometheus`.
5. **Containerize.** Multi-stage Dockerfile: builder stage installs deps from `requirements.txt`, runtime stage copies them into a `python:3.12-slim` base. Run via `gunicorn myproject.wsgi:application --workers 4 --bind 0.0.0.0:8082`.
6. **Test.** Write integration tests using DRF's `APIClient` against the viewset, with `pytest-django`'s `@pytest.mark.django_db` decorator for database access.

Note `CONN_MAX_AGE=60`: this is Django's equivalent of HikariCP, and it is much simpler. Each Django worker process holds at most one database connection; `CONN_MAX_AGE` is the seconds that connection stays alive at the back of a request before being closed and re-opened. Setting it to `0` (the default) means a new TCP connection per request — a disaster for latency. Setting it to `None` means the connection is never closed — a disaster for production where Postgres has a `max_connections=100` ceiling and you have 4 workers × 10 dynos = 40 connections. `60` is a reasonable middle ground.

### `orgs/models.py`

```python
from django.db import models


class ActiveOrganizationManager(models.Manager):
    """Default manager that excludes soft-deleted organizations."""

    def get_queryset(self):
        return super().get_queryset().filter(deleted_at__isnull=True)


class Organization(models.Model):
    name = models.CharField(max_length=100)
    slug = models.SlugField(max_length=50, unique=False)
    deleted_at = models.DateTimeField(null=True, blank=True)
    created_at = models.DateTimeField(auto_now_add=True)
    updated_at = models.DateTimeField(auto_now=True)

    # The default manager excludes soft-deleted rows from every query.
    # `Organization.objects.all()` returns only active orgs.
    objects = ActiveOrganizationManager()
    # The `all_objects` manager includes soft-deleted ones, for admin / migrations.
    all_objects = models.Manager()

    class Meta:
        db_table = "organizations"
        constraints = [
            # Partial unique index — only enforced on rows where deleted_at IS NULL.
            # This requires Postgres; SQLite (used in unit tests) ignores the predicate
            # and falls back to a plain UNIQUE, which is acceptable for tests.
            models.UniqueConstraint(
                fields=["slug"], condition=models.Q(deleted_at__isnull=True),
                name="uk_organizations_slug_active",
            ),
        ]

    def __str__(self):
        return f"Organization(id={self.id}, slug={self.slug!r})"


class Member(models.Model):
    class Role(models.TextChoices):
        ADMIN = "ADMIN", "Admin"
        MEMBER = "MEMBER", "Member"
        VIEWER = "VIEWER", "Viewer"

    organization = models.ForeignKey(
        Organization, on_delete=models.CASCADE, related_name="members"
    )
    user_id = models.BigIntegerField()
    role = models.CharField(max_length=10, choices=Role.choices)
    created_at = models.DateTimeField(auto_now_add=True)

    class Meta:
        db_table = "members"
        constraints = [
            models.UniqueConstraint(
                fields=["organization", "user_id"],
                name="uk_members_org_user",
            ),
        ]

    def __str__(self):
        return f"Member(org={self.organization_id}, user={self.user_id}, role={self.role})"
```

### `orgs/serializers.py` (DRF ModelSerializer — replaces Bean Validation)

```python
import re
from rest_framework import serializers
from .models import Organization, Member


NAME_NO_XSS = re.compile(r"^[^<>&\x00-\x1F]*$")
SLUG_PATTERN = re.compile(r"^[a-z0-9-]{3,50}$")


class OrganizationSerializer(serializers.ModelSerializer):
    class Meta:
        model = Organization
        fields = ["id", "name", "slug", "deleted_at"]
        read_only_fields = ["id", "deleted_at"]

    def validate_name(self, value):
        if not (1 <= len(value) <= 100):
            raise serializers.ValidationError("name must be 1-100 characters")
        if not NAME_NO_XSS.match(value):
            raise serializers.ValidationError(
                "name must not contain <, >, & or control characters"
            )
        return value

    def validate_slug(self, value):
        if not SLUG_PATTERN.match(value):
            raise serializers.ValidationError(
                "slug must be 3-50 lowercase alphanumeric or hyphen chars"
            )
        # Partial-unique check — only conflicts with other active orgs.
        qs = Organization.objects.filter(slug=value)
        if self.instance:
            qs = qs.exclude(pk=self.instance.pk)
        if qs.exists():
            raise serializers.ValidationError(
                f"slug '{value}' already exists"
            )
        return value


class PatchOrganizationSerializer(serializers.ModelSerializer):
    """All fields optional — PATCH semantics."""

    class Meta:
        model = Organization
        fields = ["name", "slug"]

    def validate_name(self, value):
        if value is not None and not NAME_NO_XSS.match(value):
            raise serializers.ValidationError(
                "name must not contain <, >, & or control characters"
            )
        return value

    def validate_slug(self, value):
        if value is not None and not SLUG_PATTERN.match(value):
            raise serializers.ValidationError(
                "slug must be 3-50 lowercase alphanumeric or hyphen chars"
            )
        return value


class MemberSerializer(serializers.ModelSerializer):
    user_id = serializers.IntegerField(min_value=1)
    role = serializers.ChoiceField(choices=[r[0] for r in Member.Role.choices])

    class Meta:
        model = Member
        fields = ["user_id", "role"]


class MemberListSerializer(serializers.ModelSerializer):
    class Meta:
        model = Member
        fields = ["user_id", "role"]
```

### `orgs/views.py` (DRF ModelViewSet + custom exception handler)

```python
from django.db import IntegrityError
from django.http import Http404
from rest_framework import status, viewsets
from rest_framework.decorators import action
from rest_framework.exceptions import ValidationError as DRFValidationError
from rest_framework.response import Response
from rest_framework.views import exception_handler as drf_default_handler
from .models import Organization, Member
from .serializers import (
    OrganizationSerializer,
    PatchOrganizationSerializer,
    MemberSerializer,
    MemberListSerializer,
)


def problem_detail_exception_handler(exc, context):
    """Translates every DRF/Django exception into an RFC 7807 ProblemDetail body."""
    response = drf_default_handler(exc, context)
    request = context.get("request")
    trace_id = getattr(request, "trace_id", None) if request else None

    if response is None:
        # Unhandled — 500
        return Response(
            {
                "type": "https://errors.example.com/internal-error",
                "title": "Internal server error",
                "status": 500,
                "detail": f"An unexpected error occurred (trace_id={trace_id})",
                "instance": request.path if request else "",
                "trace_id": trace_id,
            },
            status=status.HTTP_500_INTERNAL_SERVER_ERROR,
        )

    # Map DRF's default error shape to ProblemDetail
    title = {
        400: "Bad request",
        401: "Unauthorized",
        403: "Forbidden",
        404: "Resource not found",
        409: "Conflict",
        422: "Validation failed",
    }.get(response.status_code, "Error")

    type_slug = {
        400: "bad-request",
        401: "unauthorized",
        403: "forbidden",
        404: "not-found",
        409: "conflict",
        422: "validation-failed",
    }.get(response.status_code, "error")

    detail = (
        "; ".join(f"{k}: {v}" for k, v in response.data.items())
        if isinstance(response.data, dict)
        else str(response.data)
    )

    response.data = {
        "type": f"https://errors.example.com/{type_slug}",
        "title": title,
        "status": response.status_code,
        "detail": detail,
        "instance": request.path if request else "",
        "trace_id": trace_id,
    }
    return response


class OrganizationViewSet(viewsets.ModelViewSet):
    """Provides /orgs (list, create) and /orgs/{id} (retrieve, update, partial_update, destroy).

    We override `update` to require PATCH semantics (PUT is disabled at the URL level
    by only registering `patch` in the http_method_names).
    """

    queryset = Organization.objects.all()
    http_method_names = ["get", "post", "patch", "delete", "head", "options"]

    def get_serializer_class(self):
        if self.action == "partial_update":
            return PatchOrganizationSerializer
        if self.action in ("create",):
            return OrganizationSerializer
        return OrganizationSerializer

    def create(self, request, *args, **kwargs):
        serializer = self.get_serializer(data=request.data)
        serializer.is_valid(raise_exception=True)
        org = serializer.save()
        out = OrganizationSerializer(org).data
        return Response(out, status=status.HTTP_201_CREATED,
                        headers={"Location": f"/orgs/{org.id}"})

    def partial_update(self, request, *args, **kwargs):
        instance = self.get_object()
        serializer = self.get_serializer(instance, data=request.data, partial=True)
        serializer.is_valid(raise_exception=True)
        # Manually apply only the supplied fields
        for field in serializer.validated_data:
            setattr(instance, field, serializer.validated_data[field])
        # Re-run slug uniqueness check via full clean
        try:
            instance.save()
        except IntegrityError as e:
            if "uk_organizations_slug_active" in str(e):
                raise DRFValidationError(
                    {"slug": f"slug '{instance.slug}' already exists"}
                )
            raise
        return Response(OrganizationSerializer(instance).data)

    def destroy(self, request, *args, **kwargs):
        instance = self.get_object()
        from django.utils import timezone
        instance.deleted_at = timezone.now()
        instance.save(update_fields=["deleted_at"])
        return Response(status=status.HTTP_204_NO_CONTENT)

    @action(detail=True, methods=["get", "post"], url_path="members")
    def members(self, request, pk=None):
        org = self.get_object()
        if request.method == "GET":
            members = org.members.all()
            return Response({"data": MemberListSerializer(members, many=True).data})

        # POST — add member
        serializer = MemberSerializer(data=request.data)
        serializer.is_valid(raise_exception=True)
        try:
            member = Member.objects.create(
                organization=org,
                user_id=serializer.validated_data["user_id"],
                role=serializer.validated_data["role"],
            )
        except IntegrityError:
            raise DRFValidationError(
                {"user_id": f"user {serializer.validated_data['user_id']} is already a member"}
            )
        return Response(
            MemberSerializer(member).data,
            status=status.HTTP_201_CREATED,
            headers={"Location": f"/orgs/{org.id}/members/{member.user_id}"},
        )

    @action(
        detail=True,
        methods=["delete"],
        url_path=r"members/(?P<user_id>\d+)",
        url_name="member-detail",
    )
    def remove_member(self, request, pk=None, user_id=None):
        org = self.get_object()
        try:
            member = org.members.get(user_id=user_id)
        except Member.DoesNotExist:
            raise Http404(
                f"member: user {user_id} is not a member of organization {org.id}"
            )
        member.delete()
        return Response(status=status.HTTP_204_NO_CONTENT)
```

import uuid


class TraceIdMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        request.trace_id = request.headers.get("X-Request-Id") or str(uuid.uuid4())
        response = self.get_response(request)
        response["X-Request-Id"] = request.trace_id
        return response

## Delta from Spring Boot Anchor

The structural delta from the Spring Boot anchor ([[13.01.02. Anchor Implementation Spring Boot]]) is five-fold:

1. **DRF's `ModelViewSet` collapses the entire CRUD controller into one class.** Spring Boot requires a `@RestController` class with eight `@GetMapping` / `@PostMapping` / `@PatchMapping` / `@DeleteMapping` methods. DRF's `ModelViewSet` provides `list`, `create`, `retrieve`, `update`, `partial_update`, and `destroy` as built-in methods — you only override the ones that need custom behaviour. The custom `members` and `remove_member` actions are added via the `@action` decorator, which auto-registers them on the router. The trade-off: less explicit, more magic. Spring's controller is 60 lines you can read top-to-bottom; DRF's viewset is 30 lines plus 200 lines of inherited behaviour you must read the DRF source to understand.

2. **The DRF serializer replaces both Bean Validation and Jackson.** Spring Boot splits these: `@Valid` + `@Pattern` declare validation, Jackson's `ObjectMapper` does the JSON conversion. DRF's `ModelSerializer` does both: `to_representation(obj)` produces the dict that will be JSON-serialised, `to_internal_value(data)` parses and validates the incoming JSON. The `validate_<field>` methods are the equivalent of Bean Validation's `@Pattern` constraints. The trade-off: one class instead of two, but the validation logic is in Python methods, not declarative annotations — easier to test in isolation, harder to audit at a glance.

3. **Django's connection pool is per-worker, not per-process.** Spring Boot's HikariCP pool is JVM-wide: one pool, 20 connections, shared by all 200 Tomcat threads. Django's `CONN_MAX_AGE=60` is per-worker: each gunicorn worker has at most one persistent connection, and a 4-worker gunicorn deployment uses at most 4 Postgres connections. The implication: scaling gunicorn workers scales the database connection count linearly, whereas scaling Tomcat threads does not. To get a real connection pool in Django you need `django-db-connection-pool` (a third-party package that wraps SQLAlchemy's pool) or PgBouncer in front of Postgres. Without one of these, the HikariCP starvation Break-It test from the anchor is structurally impossible to reproduce in Django — what you see instead is request queueing inside gunicorn's worker model.

4. **Soft-delete is implemented as a custom manager, not a repository query.** Spring Boot's `OrganizationRepository` has `@Query("select o from Organization o where o.deletedAt is null")` — every query that wants to exclude soft-deleted rows must use that method explicitly. Django's `ActiveOrganizationManager` overrides `get_queryset()` so that `Organization.objects.all()` automatically excludes soft-deleted rows everywhere. The trade-off: Django's pattern is safer (no forgotten filter), but the `all_objects` escape hatch is required for migrations and admin, and forgetting which manager is the default is a classic Django footgun.

5. **The exception handler is a function, not a class.** Spring's `@ControllerAdvice` is a class with `@ExceptionHandler` methods; the framework scans it and applies it to every controller. DRF's `EXCEPTION_HANDLER` setting points to a single function `problem_detail_exception_handler(exc, context)` that gets called for every exception. The trade-off: DRF's pattern is one function instead of a class with many methods — simpler, but you must remember to set it in `REST_FRAMEWORK['EXCEPTION_HANDLER']` or you get DRF's default error shape (`{"detail": "..."}`) instead of RFC 7807.

## What This Teaches

The Django translation teaches three things the Spring Boot anchor does not surface. First, the WSGI worker model is fundamentally different from the thread-per-request model: gunicorn runs N worker processes (default 4), each handling one request at a time; concurrency comes from running multiple workers, not from threads. The implication is that a single slow request does not block other requests, but a single worker crash kills every in-flight request on that worker. Second, Python's `BigAutoField` returns `int` (not `str`) for the `id` field in JSON — unlike JavaScript's `BigInt`-as-string problem in the Express translation. This means cross-ecosystem tests against `id` pass cleanly between Spring Boot and Django but fail between Django and Express, which is why the spec's API contract uses `id` of either numeric or string type depending on the ecosystem. Third, Django migrations are first-class: `python manage.py makemigrations` introspects the model changes and generates a versioned migration file that ships with the code; Spring Boot's `ddl-auto=validate` only checks that the schema matches the entities, it does not generate migrations. For production deployments, Django's migration discipline is a significant operational advantage — every schema change is reviewed, committed, and applied in order.
