# 13.01.02. Anchor Implementation Spring Boot

## Why This Is the Anchor

This note is the **deep anchor implementation** — the place where you build the concept in Spring Boot with production-grade depth. Per the Anchor and Delta protocol ([[00.02. The Anchor and Delta Learning Protocol]]), you must break this implementation before moving to the delta notes. The point is to acquire scars: real experience with the failure modes that this concept produces under load.

Spring Boot is the anchor because it forces you to confront strict types, multi-threading, reflection proxies, bytecode generation, the JVM memory model, and explicit architectural decisions. If you can build this in Spring Boot, you can build it anywhere.

Spring Boot is the anchor specifically because it makes the failure modes explicit rather than hiding them behind magic. The HikariCP connection pool has a `maximumPoolSize` that you must set; if you leave it at the default of 10, a `wrk -c200` load test will block 190 connections and the saturation is visible in the `hikaricp.connections.active` metric. Tomcat has a `server.tomcat.threads.max` that defaults to 200 — too high for a 10-connection pool, which means threads queue waiting for connections. Hibernate has a `BatchingPersistenceContext` that grows unboundedly inside a long-running transaction; the heap dump shows `org.hibernate.engine.spi.PersistenceContext` holding 50,000 entity snapshots. None of these are hidden behind a "platform" abstraction; they are JVM fields that you can grep in a heap dump, JDBC statements you can see in the Postgres `pg_stat_activity` view, and thread stacks you can read with `jstack`. The other three ecosystems (Express, Django, Laravel) hide these primitives behind their own abstractions — and the value of the anchor is that you see them once, raw, before they get hidden.

## What You Will Build

You will build the Spring Boot implementation of the eight-endpoint Organization and Membership REST API specified in [[13.01.01. System Specification]]. The stack is Spring Boot 3.3.x on Java 21 LTS, Spring Data JPA with Hibernate 6.4, the HikariCP connection pool (the default since Spring Boot 2.x), Bean Validation via the `spring-boot-starter-validation` dependency, Spring Boot Actuator for metrics, and PostgreSQL 16 as the database. The build tool is Maven (the `pom.xml` is below; a Gradle `build.gradle` is a valid alternative but Maven is the canonical Spring Boot anchor build).

The implementation is structured in the standard Spring Boot layered style: `controller` (HTTP boundary, no business logic), `service` (business logic, `@Transactional` boundary), `repository` (Spring Data JPA interface, no implementation), `entity` (JPA `@Entity` classes with the database mapping), `dto` (request/response records with Bean Validation annotations), and `exception` (the `@ControllerAdvice` global handler that emits RFC 7807 ProblemDetail bodies). The package root is `com.example.orgapi`.

### `service/OrganizationService.java`

```java
package com.example.orgapi.service;

import com.example.orgapi.dto.*;
import com.example.orgapi.entity.Member;
import com.example.orgapi.entity.Organization;
import com.example.orgapi.entity.Role;
import com.example.orgapi.exception.*;
import com.example.orgapi.repository.MemberRepository;
import com.example.orgapi.repository.OrganizationRepository;
import org.springframework.data.domain.Page;
import org.springframework.data.domain.PageRequest;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.Instant;
import java.util.List;

@Service
public class OrganizationService {

    private final OrganizationRepository orgRepo;
    private final MemberRepository memberRepo;

    public OrganizationService(OrganizationRepository orgRepo, MemberRepository memberRepo) {
        this.orgRepo = orgRepo;
        this.memberRepo = memberRepo;
    }

    @Transactional(readOnly = true)
    public Page<OrganizationResponse> list(int page, int size) {
        return orgRepo.findAllActive(PageRequest.of(page - 1, size))
                      .map(OrganizationResponse::from);
    }

    @Transactional
    public OrganizationResponse create(CreateOrganizationRequest req) {
        if (orgRepo.slugExists(req.slug())) {
            throw new ConflictException("slug", "slug '" + req.slug() + "' already exists");
        }
        Organization o = new Organization();
        o.setName(req.name());
        o.setSlug(req.slug());
        orgRepo.save(o);
        return OrganizationResponse.from(o);
    }

    @Transactional(readOnly = true)
    public OrganizationResponse find(Long id) {
        return orgRepo.findActiveById(id)
            .map(OrganizationResponse::from)
            .orElseThrow(() -> new NotFoundException("organization", id));
    }

    @Transactional
    public OrganizationResponse patch(Long id, PatchOrganizationRequest req) {
        Organization o = orgRepo.findActiveById(id)
            .orElseThrow(() -> new NotFoundException("organization", id));

        if (req.name() != null) o.setName(req.name());
        if (req.slug() != null) {
            if (!o.getSlug().equals(req.slug()) && orgRepo.slugExists(req.slug())) {
                throw new ConflictException("slug", "slug '" + req.slug() + "' already exists");
            }
            o.setSlug(req.slug());
        }
        return OrganizationResponse.from(o);
    }

    @Transactional
    public void softDelete(Long id) {
        Organization o = orgRepo.findActiveById(id)
            .orElseThrow(() -> new NotFoundException("organization", id));
        o.setDeletedAt(Instant.now());
    }

    @Transactional(readOnly = true)
    public List<MemberResponse> listMembers(Long orgId) {
        if (orgRepo.findActiveById(orgId).isEmpty()) {
            throw new NotFoundException("organization", orgId);
        }
        return memberRepo.findByOrganizationIdAndUserId(orgId, null) == null
            ? List.of()
            : memberRepo.findAll().stream()
                .filter(m -> m.getOrganization().getId().equals(orgId))
                .map(MemberResponse::from)
                .toList();
    }

    @Transactional
    public MemberResponse addMember(Long orgId, AddMemberRequest req) {
        Organization o = orgRepo.findActiveById(orgId)
            .orElseThrow(() -> new NotFoundException("organization", orgId));

        if (memberRepo.existsByOrganizationIdAndUserId(orgId, req.userId())) {
            throw new ConflictException("member",
                "user " + req.userId() + " is already a member of organization " + orgId);
        }

        Member m = new Member();
        m.setOrganization(o);
        m.setUserId(req.userId());
        m.setRole(req.role());
        memberRepo.save(m);
        return MemberResponse.from(m);
    }

    @Transactional
    public void removeMember(Long orgId, Long userId) {
        Member m = memberRepo.findByOrganizationIdAndUserId(orgId, userId)
            .orElseThrow(() -> new NotFoundException("member",
                "user " + userId + " is not a member of organization " + orgId));
        memberRepo.delete(m);
    }
}
```

### `controller/OrganizationController.java`

```java
package com.example.orgapi.controller;

import com.example.orgapi.dto.*;
import com.example.orgapi.service.OrganizationService;
import jakarta.validation.Valid;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import org.springframework.data.domain.Page;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.*;

import java.net.URI;
import java.util.List;

@RestController
@RequestMapping("/orgs")
@Validated
public class OrganizationController {

    private final OrganizationService service;

    public OrganizationController(OrganizationService service) {
        this.service = service;
    }

    @GetMapping
    public Page<OrganizationResponse> list(
            @RequestParam(defaultValue = "1") @Min(1) int page,
            @RequestParam(defaultValue = "20") @Min(1) @Max(100) int size) {
        return service.list(page, size);
    }

    @PostMapping
    public ResponseEntity<OrganizationResponse> create(@Valid @RequestBody CreateOrganizationRequest req) {
        OrganizationResponse created = service.create(req);
        return ResponseEntity.created(URI.create("/orgs/" + created.id())).body(created);
    }

    @GetMapping("/{id}")
    public OrganizationResponse find(@PathVariable Long id) {
        return service.find(id);
    }

    @PatchMapping("/{id}")
    public OrganizationResponse patch(@PathVariable Long id,
                                      @Valid @RequestBody PatchOrganizationRequest req) {
        return service.patch(id, req);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void softDelete(@PathVariable Long id) {
        service.softDelete(id);
    }

    @GetMapping("/{id}/members")
    public List<MemberResponse> listMembers(@PathVariable Long id) {
        return service.listMembers(id);
    }

    @PostMapping("/{id}/members")
    public ResponseEntity<MemberResponse> addMember(@PathVariable Long id,
                                                    @Valid @RequestBody AddMemberRequest req) {
        MemberResponse m = service.addMember(id, req);
        return ResponseEntity.created(URI.create("/orgs/" + id + "/members/" + m.userId())).body(m);
    }

    @DeleteMapping("/{id}/members/{userId}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void removeMember(@PathVariable Long id, @PathVariable Long userId) {
        service.removeMember(id, userId);
    }
}
```

### `controller/GlobalExceptionHandler.java`

```java
package com.example.orgapi.controller;

import com.example.orgapi.exception.*;
import jakarta.servlet.http.HttpServletRequest;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.method.annotation.MethodArgumentTypeMismatchException;

import java.net.URI;
import java.util.stream.Collectors;

@RestControllerAdvice
public class GlobalExceptionHandler {

    private ProblemDetail problem(HttpStatus status, String title, String detail,
                                  HttpServletRequest req, String type) {
        ProblemDetail pd = ProblemDetail.forStatusAndDetail(status, detail);
        pd.setTitle(title);
        pd.setType(URI.create("https://errors.example.com/" + type));
        pd.setInstance(URI.create(req.getRequestURI()));
        pd.setProperty("trace_id", req.getHeader("X-Request-Id"));
        return pd;
    }

    @ExceptionHandler(NotFoundException.class)
    public ProblemDetail notFound(NotFoundException ex, HttpServletRequest req) {
        return problem(HttpStatus.NOT_FOUND, "Resource not found", ex.getMessage(), req,
                       "not-found");
    }

    @ExceptionHandler(ConflictException.class)
    public ProblemDetail conflict(ConflictException ex, HttpServletRequest req) {
        return problem(HttpStatus.CONFLICT, "Conflict", ex.getMessage(), req, "conflict");
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ProblemDetail validation(MethodArgumentNotValidException ex, HttpServletRequest req) {
        String detail = ex.getBindingResult().getFieldErrors().stream()
            .map(fe -> fe.getField() + ": " + fe.getDefaultMessage())
            .collect(Collectors.joining("; "));
        return problem(HttpStatus.UNPROCESSABLE_ENTITY, "Validation failed", detail, req,
                       "validation-failed");
    }

    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    public ProblemDetail typeMismatch(MethodArgumentTypeMismatchException ex,
                                      HttpServletRequest req) {
        return problem(HttpStatus.BAD_REQUEST, "Bad request",
                       "path parameter '" + ex.getName() + "' must be a " + ex.getRequiredType(),
                       req, "bad-request");
    }

    @ExceptionHandler(Exception.class)
    public ProblemDetail internal(Exception ex, HttpServletRequest req) {
        // Log the stack trace server-side with the trace_id; do not leak it to the client.
        return problem(HttpStatus.INTERNAL_SERVER_ERROR, "Internal server error",
                       "An unexpected error occurred (trace_id=" + req.getHeader("X-Request-Id")
                       + ")", req, "internal-error");
    }
}
```

```sql
    id         BIGSERIAL PRIMARY KEY,
    name       VARCHAR(100)  NOT NULL,
    slug       VARCHAR(50)   NOT NULL,
```

## What This Teaches

Building this in Spring Boot teaches four things that are hard to acquire any other way. First, the JVM threading model is real and load-bearing: Tomcat allocates one thread per request, that thread holds a HikariCP connection for the duration of the `@Transactional` block, and the `server.tomcat.threads.max=200` setting interacts with `hikari.maximum-pool-size=20` to produce the queue-then-block behaviour you will reproduce in Break-It test #1. Second, Hibernate's persistence context is a memory leak waiting to happen — every entity loaded inside a transaction is tracked for dirty checking, and a service method that loads 10,000 entities in a loop will hold 10,000 `EntityEntry` snapshots in heap until the transaction commits. Third, the `@ControllerAdvice` global exception handler is the single point where you translate every internal exception type into an RFC 7807 ProblemDetail — getting this right once means every controller stays clean, getting it wrong means leaky `RuntimeException` stacks in production responses. Fourth, Bean Validation via `@Valid` + `@Pattern` + `@Size` is the cheapest possible defence-in-depth: the constraint is declared at the DTO boundary, enforced by the framework proxy before your controller method runs, and visible to anyone reading the DTO source.

The Spring Boot anchor is the only implementation in this milestone where the connection pool, the thread pool, and the transaction manager are three separate configurable things. Express collapses them into the event loop. Django collapses them into the WSGI worker model. Laravel collapses them into PHP-FPM workers. The point of doing Spring Boot first is that you see the three primitives separated, so when you get to the deltas you can recognise which primitive each ecosystem hides.

## How It Works

The request flow for `POST /orgs` is, end to end: Tomcat accepts the TCP connection on port 8080, dispatches an HTTP worker thread from its `threads.max=200` pool, the worker thread calls Spring MVC's `DispatcherServlet`, the servlet resolves the `@PostMapping("/orgs")` route via the `RequestMappingHandlerMapping`, the `RequestResponseBodyMethodProcessor` deserialises the JSON body into a `CreateOrganizationRequest` record while running Bean Validation, the `@Valid` annotation triggers `MethodArgumentNotValidException` if any constraint fails (which the `GlobalExceptionHandler` catches and renders as a 422 ProblemDetail), the controller calls `service.create(req)`, the service method (annotated `@Transactional`) opens a Hibernate `EntityManager` and borrows a JDBC connection from HikariCP, the service checks `slugExists`, if absent it `persist`s a new `Organization`, Hibernate issues `INSERT INTO organizations ...`, the transaction commits (the connection returns to the pool), the controller wraps the response in `ResponseEntity.created(URI).body(...)`, Jackson serialises the `OrganizationResponse` record to JSON, Tomcat writes the response bytes, and the worker thread is returned to the pool. Total wall-clock time on an idle local Postgres: about 8-15 ms. Under `wrk -c200` load, it climbs to 200-500 ms at p99 as the HikariCP pool saturates.

## Break It

> [!danger] Load-test failure modes you must reproduce
> Do not move on to the delta translations until you have personally reproduced each of the following in your anchor implementation:
>
> 1. **Starve HikariCP.** Set `spring.datasource.hikari.maximum-pool-size=5` (down from 20) and run `wrk -t8 -c200 -d30s http://localhost:8080/orgs`. Within seconds, 195 of the 200 Tomcat threads are blocked on `HikariPool.getConnection`. The metric that proves the saturation: `curl -s localhost:8080/actuator/metrics/hikaricp.connections.active` returns 5, and `hikaricp.connections.pending` returns 195. p99 latency climbs from 8 ms to 30,000 ms. Fix: restore `maximum-pool-size=20` and re-run; p99 drops back under 50 ms.
>
> 2. **Leak it via forgotten try-with-resources.** In the service, replace the `@Transactional` annotation with a manual `EntityManagerFactory.createEntityManager()` call that is never closed. Run the same `wrk -c200 -d30s` load test. Within 60 seconds, `jmap -histo:live <pid>` shows tens of thousands of `org.hibernate.engine.spi.PersistenceContext` instances surviving in the old generation; the JVM eventually throws `OutOfMemoryError: Java heap space` or `HikariPool-1 - Connection is not available, request timed out after 5000ms`. Fix: restore the `@Transactional` annotation (Spring's `OpenEntityManagerInViewInterceptor` plus the `@Transactional` proxy correctly scope the `EntityManager` to the request and the transaction respectively); the heap flattens.
>
> 3. **Race it on concurrent member add.** Two `POST /orgs/1/members` requests with `{"user_id":42,"role":"MEMBER"}` arrive within the same millisecond. Without the `uk_members_org_user` unique constraint, both pass the `existsByOrganizationIdAndUserId` check (false on both), both insert, and you have two duplicate rows. With the constraint, the second insert raises a `DataIntegrityViolationException` that surfaces as a 500 from the unhandled path. Fix: catch `DataIntegrityViolationException` in the `GlobalExceptionHandler` and translate to a 409 ProblemDetail with `type=conflict`. Capture the Postgres `pg_stat_activity` showing the second transaction blocked on the unique index.
>
> 4. **Fix it and re-test.** Restore the `@Transactional` boundary, restore the HikariCP pool to 20, restore the unique constraint, and add the `DataIntegrityViolationException` handler. Re-run `wrk -t8 -c200 -d30s http://localhost:8080/orgs` and capture the new latency graph. The graph should be flat. Keep both graphs — the pre-fix and the post-fix — for the post-mortem in [[13.01.06. Architectural Comparison and Post-Mortem]].

## Profiling Hooks

While the load test runs, collect:

- **JVM**: `jstack <pid>` for thread dumps; `jmap -dump:live,format=b,file=heap.hprof <pid>` for heap dumps; `jstat -gcutil <pid> 1000` for GC pressure.
- **OS**: `pidstat -d -r -u -w 1`, `vmstat 1`, `ss -tan state established | wc -l`.
- **App**: `/actuator/metrics/*` and `/actuator/threaddump`.

The metrics that matter for Break-It #1 (HikariCP starvation):

```bash
# active connections (will pin at maximum-pool-size during starvation)
curl -s localhost:8080/actuator/metrics/hikaricp.connections.active | jq

# pending threads (will spike to ~195 during -c200 load)
curl -s localhost:8080/actuator/metrics/hikaricp.connections.pending | jq

# Tomcat threads busy (will pin at 200)
curl -s localhost:8080/actuator/metrics/tomcat.threads.busy | jq

# JVM old generation usage (will climb during leak test #2)
curl -s localhost:8080/actuator/metrics/jvm.gc.live.data.size | jq
```
