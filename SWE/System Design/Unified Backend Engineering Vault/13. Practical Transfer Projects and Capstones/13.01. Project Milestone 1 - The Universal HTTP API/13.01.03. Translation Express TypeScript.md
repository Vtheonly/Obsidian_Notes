# 13.01.03. Translation Express TypeScript

## Scope

This is a single-ecosystem implementation file inside a capstone milestone. It is a reference implementation to reproduce, not a tutorial to copy. The contract is fixed by [[13.01.01. System Specification]] — read that first. This note shows how that contract is expressed in the Node.js + Express + TypeScript + Prisma + Zod ecosystem.

## What You Are Building

You are reproducing the eight-endpoint Organization and Membership REST API from the Spring Boot anchor ([[13.01.02. Anchor Implementation Spring Boot]]) in Node.js. The stack is Express 4 (the dominant Node.js HTTP framework, used by NestJS under the hood), TypeScript 5 in strict mode (no implicit `any`, no implicit `null`), Zod for runtime schema validation (the TypeScript-native equivalent of Bean Validation), Prisma 5 as the ORM with a PostgreSQL datasource (the equivalent of Spring Data JPA + Hibernate), and `tsx` for hot-reload during development. The output of this exercise is not just "another implementation of the same API" — it is a direct comparison of how the Node.js runtime, the V8 event loop, and the Prisma query engine differ from the JVM, Tomcat threads, and Hibernate.

## Implementation Steps

1. **Bootstrap.** `npm init -y`, then `npm install express zod @prisma/client`, then `npm install -D typescript tsx @types/express @types/node prisma`. Run `npx tsc --init` to generate `tsconfig.json`. Run `npx prisma init` to generate the Prisma schema and `.env`.
2. **Wire dependencies.** Install only what the spec requires: express, zod, @prisma/client. Do not install body-parser (Express 4.16+ has it built in). Do not install helmet, cors, morgan — those are Milestone 2 concerns.
3. **Implement the contract.** Match the spec exactly — same paths (`/orgs`, `/orgs/:id`, `/orgs/:id/members`, `/orgs/:id/members/:userId`), same status codes, same JSON shapes, same RFC 7807 ProblemDetail error body.
4. **Wire observability.** Add structured logging with `trace_id` (a UUID v4 generated per request, attached to `req.traceId` by a tiny middleware). Emit at least one Prometheus metric (use `prom-client` and expose `/metrics`).
5. **Containerize.** Write a multi-stage Dockerfile: builder stage runs `tsc`, runtime stage copies `dist/` + `node_modules` + `prisma/` into a `node:20-alpine` base.
6. **Test.** Write integration tests using `supertest` against the Express app, with `@testcontainers/postgresql` for an ephemeral Postgres.

### `src/db.ts` (Prisma client singleton)

```typescript
import { PrismaClient } from "@prisma/client";

// Global singleton — prevents multiple PrismaClient instances in dev hot-reload.
const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient };

export const prisma: PrismaClient =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === "development" ? ["query", "warn", "error"] : ["warn", "error"],
  });

if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = prisma;
}
```

The singleton is non-negotiable: `tsx watch` reloads the module on every save, and without the global cache you create a new `PrismaClient` per reload, each holding a connection pool of 10, until Postgres rejects new connections with `FATAL: sorry, too many clients already`. The same bug exists in the Spring Boot anchor (where it would manifest as multiple HikariPools) but Spring's `@Bean` singleton scoping handles it for you; in Express you write it yourself.

```typescript
import type { Request } from "express";

export interface ProblemDetail {
  type: string;
  title: string;
  status: number;
  detail: string;
  instance: string;
  trace_id?: string;
}

export function problem(
  status: number,
  title: string,
  detail: string,
  type: string,
  req: Request
): ProblemDetail {
  return {
    type: `https://errors.example.com/${type}`,
    title,
    status,
    detail,
    instance: req.path,
    trace_id: (req as any).traceId,
  };
}

export class ApiError extends Error {
  constructor(
    public readonly status: number,
    public readonly title: string,
    message: string,
    public readonly type: string
  ) {
    super(message);
  }
}

export const notFound = (resource: string, id: string | number, req: Request) =>
  new ApiError(404, "Resource not found",
    `${resource} with id ${id} does not exist or was deleted`, "not-found");

export const conflict = (field: string, detail: string, req: Request) =>
  new ApiError(409, "Conflict", `${field}: ${detail}`, "conflict");

export const validationError = (detail: string, req: Request) =>
  new ApiError(422, "Validation failed", detail, "validation-failed");
```

### `src/services/orgService.ts`

```typescript
import { prisma } from "../db.js";
import { ApiError, notFound, conflict } from "../errors/problemDetail.js";
import type { Request } from "express";
import type { CreateOrgSchema, PatchOrgSchema, AddMemberSchema } from "../schemas/orgSchema.js";
import type { z } from "zod";

type CreateOrgInput = z.infer<typeof CreateOrgSchema>;
type PatchOrgInput = z.infer<typeof PatchOrgSchema>;
type AddMemberInput = z.infer<typeof AddMemberSchema>;

// Prisma does not natively support soft-delete; we filter manually everywhere.
// The `where: { deletedAt: null }` clause is the equivalent of the Spring
// repository's @Query("... where o.deletedAt is null").
const activeOnly = { deletedAt: null } as const;

export async function listOrgs(page: number, size: number) {
  const [data, total] = await Promise.all([
    prisma.organization.findMany({
      where: activeOnly,
      skip: (page - 1) * size,
      take: size,
      orderBy: { id: "asc" },
    }),
    prisma.organization.count({ where: activeOnly }),
  ]);
  return {
    data: data.map((o) => ({ ...o, id: o.id.toString() })),
    page,
    size,
    total,
  };
}

export async function createOrg(input: CreateOrgInput, req: Request) {
  const existing = await prisma.organization.findFirst({
    where: { slug: input.slug, deletedAt: null },
  });
  if (existing) throw conflict("slug", `slug '${input.slug}' already exists`, req);

  const created = await prisma.organization.create({
    data: { name: input.name, slug: input.slug },
  });
  return { ...created, id: created.id.toString() };
}

export async function findOrg(id: bigint, req: Request) {
  const org = await prisma.organization.findFirst({
    where: { id, deletedAt: null },
  });
  if (!org) throw notFound("organization", id.toString(), req);
  return { ...org, id: org.id.toString() };
}

export async function patchOrg(id: bigint, input: PatchOrgInput, req: Request) {
  const org = await prisma.organization.findFirst({ where: { id, deletedAt: null } });
  if (!org) throw notFound("organization", id.toString(), req);

  if (input.slug && input.slug !== org.slug) {
    const clash = await prisma.organization.findFirst({
      where: { slug: input.slug, deletedAt: null, NOT: { id } },
    });
    if (clash) throw conflict("slug", `slug '${input.slug}' already exists`, req);
  }

  const updated = await prisma.organization.update({
    where: { id },
    data: {
      ...(input.name !== undefined && { name: input.name }),
      ...(input.slug !== undefined && { slug: input.slug }),
    },
  });
  return { ...updated, id: updated.id.toString() };
}

export async function softDeleteOrg(id: bigint, req: Request) {
  const org = await prisma.organization.findFirst({ where: { id, deletedAt: null } });
  if (!org) throw notFound("organization", id.toString(), req);
  await prisma.organization.update({
    where: { id },
    data: { deletedAt: new Date() },
  });
}

export async function listMembers(orgId: bigint, req: Request) {
  const org = await prisma.organization.findFirst({ where: { id: orgId, deletedAt: null } });
  if (!org) throw notFound("organization", orgId.toString(), req);

  const members = await prisma.member.findMany({ where: { organizationId: orgId } });
  return { data: members.map((m) => ({ userId: m.userId.toString(), role: m.role })) };
}

export async function addMember(orgId: bigint, input: AddMemberInput, req: Request) {
  const org = await prisma.organization.findFirst({ where: { id: orgId, deletedAt: null } });
  if (!org) throw notFound("organization", orgId.toString(), req);

  const exists = await prisma.member.findUnique({
    where: { organizationId_userId: { organizationId: orgId, userId: input.userId } },
  });
  if (exists) {
    throw conflict(
      "member",
      `user ${input.userId} is already a member of organization ${orgId}`,
      req
    );
  }

  const created = await prisma.member.create({
    data: { organizationId: orgId, userId: input.userId, role: input.role },
  });
  return { userId: created.userId.toString(), role: created.role };
}

export async function removeMember(orgId: bigint, userId: bigint, req: Request) {
  const member = await prisma.member.findUnique({
    where: { organizationId_userId: { organizationId: orgId, userId } },
  });
  if (!member) {
    throw notFound("member", `user ${userId} is not a member of organization ${orgId}`, req);
  }
  await prisma.member.delete({ where: { id: member.id } });
}
```

### `src/middleware/traceId.ts`

```typescript
import type { Request, Response, NextFunction } from "express";
import { randomUUID } from "node:crypto";

export function traceId(req: Request, res: Response, next: NextFunction) {
  const incoming = req.header("X-Request-Id");
  (req as any).traceId = incoming || randomUUID();
  res.setHeader("X-Request-Id", (req as any).traceId);
  next();
}
```

### `src/middleware/errorHandler.ts`

```typescript
import type { Request, Response, NextFunction } from "express";
import { ZodError } from "zod";
import { ApiError, problem } from "../errors/problemDetail.js";
import { Prisma } from "@prisma/client";

export function errorHandler(err: unknown, req: Request, res: Response, _next: NextFunction) {
  if (err instanceof ApiError) {
    res.status(err.status).json(problem(err.status, err.title, err.message, err.type, req));
    return;
  }
  if (err instanceof ZodError) {
    const detail = err.errors.map((e) => `${e.path.join(".")}: ${e.message}`).join("; ");
    res.status(422).json(problem(422, "Validation failed", detail, "validation-failed", req));
    return;
  }
  if (err instanceof Prisma.PrismaClientKnownRequestError && err.code === "P2002") {
    // unique constraint violation
    res.status(409).json(problem(409, "Conflict",
      "duplicate key value violates unique constraint", "conflict", req));
    return;
  }
  // log the stack server-side, do not leak to the client
  console.error("unhandled error", { traceId: (req as any).traceId, err });
  res.status(500).json(problem(500, "Internal server error",
    `An unexpected error occurred (trace_id=${(req as any).traceId})`, "internal-error", req));
}
```

### `src/routes/orgs.ts`

```typescript
import { Router } from "express";
import { CreateOrgSchema, PatchOrgSchema, AddMemberSchema, PaginationSchema } from "../schemas/orgSchema.js";
import * as service from "../services/orgService.js";

export const orgsRouter: Router = Router();

orgsRouter.get("/", (req, res, next) => {
  const parsed = PaginationSchema.safeParse(req.query);
  if (!parsed.success) {
    return next(parsed.error);
  }
  service.listOrgs(parsed.data.page, parsed.data.size)
    .then((result) => res.json(result))
    .catch(next);
});

orgsRouter.post("/", (req, res, next) => {
  const parsed = CreateOrgSchema.safeParse(req.body);
  if (!parsed.success) return next(parsed.error);
  service.createOrg(parsed.data, req)
    .then((created) => res.status(201).header("Location", `/orgs/${created.id}`).json(created))
    .catch(next);
});

orgsRouter.get("/:id", (req, res, next) => {
  const id = BigInt(req.params.id); // throws SyntaxError on non-numeric; caught below
  if (isNaN(Number(id))) {
    return res.status(400).json({
      type: "https://errors.example.com/bad-request",
      title: "Bad request",
      status: 400,
      detail: `path parameter 'id' must be a number`,
      instance: req.path,
      trace_id: (req as any).traceId,
    });
  }
  service.findOrg(id, req).then((org) => res.json(org)).catch(next);
});

orgsRouter.patch("/:id", (req, res, next) => {
  const id = BigInt(req.params.id);
  const parsed = PatchOrgSchema.safeParse(req.body);
  if (!parsed.success) return next(parsed.error);
  service.patchOrg(id, parsed.data, req).then((org) => res.json(org)).catch(next);
});

orgsRouter.delete("/:id", (req, res, next) => {
  const id = BigInt(req.params.id);
  service.softDeleteOrg(id, req).then(() => res.status(204).end()).catch(next);
});

orgsRouter.get("/:id/members", (req, res, next) => {
  const id = BigInt(req.params.id);
  service.listMembers(id, req).then((members) => res.json(members)).catch(next);
});

orgsRouter.post("/:id/members", (req, res, next) => {
  const id = BigInt(req.params.id);
  const parsed = AddMemberSchema.safeParse(req.body);
  if (!parsed.success) return next(parsed.error);
  service.addMember(id, parsed.data, req)
    .then((m) => res.status(201).header("Location", `/orgs/${id}/members/${m.userId}`).json(m))
    .catch(next);
});

orgsRouter.delete("/:id/members/:userId", (req, res, next) => {
  const orgId = BigInt(req.params.id);
  const userId = BigInt(req.params.userId);
  service.removeMember(orgId, userId, req).then(() => res.status(204).end()).catch(next);
});
```

### `src/index.ts` (entry point)

```typescript
import express, { type Request, type Response, type NextFunction } from "express";
import { env } from "./env.js";
import { orgsRouter } from "./routes/orgs.js";
import { traceId } from "./middleware/traceId.js";
import { errorHandler } from "./middleware/errorHandler.js";
import promClient from "prom-client";

const app = express();

// JSON body parser — built into Express 4.16+ (no body-parser needed)
app.use(express.json({ limit: "100kb" }));

// trace_id middleware — must be before routes so req.traceId is set on every request
app.use(traceId);

// Prometheus metrics
const httpDuration = new promClient.Histogram({
  name: "http_request_duration_seconds",
  help: "HTTP request duration in seconds",
  labelNames: ["method", "route", "status"],
});
app.use((req: Request, res: Response, next: NextFunction) => {
  const start = process.hrtime.bigint();
  res.on("finish", () => {
    const elapsed = Number(process.hrtime.bigint() - start) / 1e9;
    httpDuration.labels(req.method, req.route?.path || req.path, String(res.statusCode)).observe(elapsed);
  });
  next();
});

// Routes
app.use("/orgs", orgsRouter);

// Metrics endpoint
app.get("/metrics", async (_req, res) => {
  res.set("Content-Type", promClient.register.contentType);
  res.end(await promClient.register.metrics());
});

// Health
app.get("/health", (_req, res) => res.json({ status: "up" }));

// Error handler — must be the last middleware
app.use(errorHandler);

app.listen(env.PORT, () => {
  console.log(`orgapi-express listening on :${env.PORT}`);
});
```

## Delta from Spring Boot Anchor

The structural delta from the Spring Boot anchor ([[13.01.02. Anchor Implementation Spring Boot]]) is six-fold:

1. **No thread pool.** Spring Boot runs on Tomcat with `threads.max=200`; each request owns a thread for its entire lifetime, blocked I/O is fine because the thread is happy to wait. Express runs on a single Node.js event loop; there is no per-request thread, and blocking I/O on the loop blocks every other in-flight request. The implication: every database call must use `await` on a Promise that resolves when the libuv worker thread completes the I/O. A synchronous `fs.readFileSync` in a request handler would freeze the entire server. The Prisma client is async-by-default; the equivalent of Spring's `@Transactional` is Prisma's `$transaction` which accepts an async callback — but you do not need it here because each handler is single-statement.

2. **No connection pool config visible at the framework level.** Spring Boot exposes HikariCP via `spring.datasource.hikari.maximum-pool-size`; you tune it explicitly. Prisma manages its own connection pool internally via the `DATABASE_URL` query parameters (`?connection_limit=20&pool_timeout=10`); you tune it via the connection string. The `pg` driver that Prisma uses under the hood opens a pool of 10 by default, scalable via `?connection_limit=`. The HikariCP starvation Break-It test from the anchor (set max=5, watch 195 Tomcat threads block on `getConnection`) does not have a direct Express equivalent — what you see instead is Prisma's `PoolTimeout` error after the configured `pool_timeout` seconds, and the event loop never blocks because every database call is already async.

3. **Zod replaces Bean Validation.** Spring Boot's `@Valid` + `@Size` + `@Pattern` annotations declare constraints at the type level; the framework's proxy runs them before the controller method body. Express has no equivalent proxy; you call `Schema.safeParse(req.body)` explicitly at the top of each route handler and `return next(parsed.error)` if it fails. The trade-off: Spring's annotations are declarative and beautiful but require a reflection-based validator; Zod's `safeParse` is explicit and ugly but type-safe at compile time (the parsed result is correctly typed, no cast needed).

4. **The error handler is `app.use(errorHandler)` at the bottom of the chain — there is no `@ControllerAdvice`.** Spring's `@RestControllerAdvice` is a class-level annotation that the framework scans for and applies to every controller. Express's pattern is to register a single `(err, req, res, next) => void` middleware at the end of the chain and to call `next(err)` from any handler that wants to forward to it. The Express pattern is more explicit (you see the wiring in `index.ts`) but easier to forget (a handler that does not call `next(err)` swallows the error).

5. **Prisma's schema is a single file, not JPA annotations.** Hibernate scatters the database schema across `@Entity` classes via `@Column`, `@Table`, `@Index` annotations; the schema is the union of all those annotations. Prisma centralises it in `schema.prisma`, generates the TypeScript client from it via `prisma generate`, and runs migrations via `prisma migrate dev`. The trade-off: Prisma's schema is easier to read and review (one file), but Prisma's TypeScript client is generated code that must be checked in or regenerated on every CI run, whereas Hibernate's reflection-based client reads the `@Entity` classes directly at startup.

6. **No partial unique index in the ORM layer.** Postgres supports `CREATE UNIQUE INDEX ... WHERE deleted_at IS NULL` for the soft-delete-aware slug uniqueness constraint. Hibernate's `@Index(unique=true)` does not support partial indexes either — both anchors apply it via a raw SQL migration. But Prisma's `@@unique([slug])` is even more limited: it creates a plain `UNIQUE (slug)` constraint that would block slug reuse after soft delete. The fix is to drop the Prisma-generated constraint in a raw migration and replace it with the partial index, which is what the comment in `schema.prisma` above instructs.

## What This Teaches

The Express translation teaches three things the Spring Boot anchor does not surface. First, the event loop is a single-threaded scheduler, not a thread pool: there is no `tomcat.threads.busy` metric to watch, only the event loop lag (the time between when a callback was scheduled and when it actually ran, exposed via `perf_hooks.monitorEventLoopDelay`). Second, JavaScript's lack of an `int64` primitive type forces every `BigInt` to be a string in JSON — the Spring Boot anchor returns `"id": 1` (a JSON number), the Express translation returns `"id": "1"` (a JSON string). This is the single most common source of cross-ecosystem test-suite breakage, and it is why the spec's API contract uses `Long id` (Spring) and `string id` (Express) interchangeably. Third, the Prisma client's connection pool is opaque: you cannot easily inspect `connections.active` the way you can with HikariCP's actuator endpoint. The production workaround is to expose a custom `/metrics` endpoint that wraps `pg`'s pool stats — or, more commonly, to rely on Postgres's own `pg_stat_activity` view for connection-pool observability.
