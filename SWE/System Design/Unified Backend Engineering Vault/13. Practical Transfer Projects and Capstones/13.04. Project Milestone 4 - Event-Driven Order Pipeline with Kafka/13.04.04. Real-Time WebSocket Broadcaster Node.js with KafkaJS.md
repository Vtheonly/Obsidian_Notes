# 13.04.04. Real-Time WebSocket Broadcaster Node.js with KafkaJS

## Scope

This is the **Node.js delta** for Milestone 4 — a service that consumes `OrderCreated` events from the `orders.events` topic and pushes them in real time to connected browser clients over WebSocket. It is the only consumer in the milestone that has a **human in the loop**: the Python aggregator writes to a database nobody watches in real time, the PHP worker writes PDFs to S3, but this broadcaster's output is rendered on a screen within 200 ms of the order being created. That latency budget is unforgiving and shapes every design choice in the file.

Two libraries are non-negotiable and load-bearing: **`kafkajs`** (the only production-grade pure-JS Kafka client — `node-rdkafka` is a C-binding alternative that is faster but ships a native build step that breaks on Alpine and on M-series Macs, and at our target throughput of 10k events/sec the V8 event loop is the bottleneck long before librdkafka would be) and **`ws`** (the de facto WebSocket library for Node — `socket.io` adds a 100 KB client bundle and a custom protocol that browsers don't natively speak). The broadcaster exposes a raw WebSocket endpoint at `/ws/orders?user_id=X&token=Y`, authenticates the user, subscribes them to a `Set<userId>` of interest, and pushes JSON messages when matching events arrive.

The lesson this delta teaches that the anchor hides is **backpressure in a single-threaded runtime**. The Python consumer can spend 50 ms on a Postgres UPSERT and the librdkafka poll loop continues in another thread; the Node.js broadcaster has one event loop, and if a WebSocket client's TCP send buffer fills (slow client on a mobile connection), the `ws.send()` call either buffers indefinitely in memory (OOM) or returns `false` to signal backpressure (which the handler must respect). The broadcaster's correctness depends on tracking per-socket `BufferedBytes` and disconnecting clients that exceed a threshold — a defensive pattern that dynamic-language developers rarely encounter until a production incident.

### Step 3 — Connection manager (the heart of the broadcaster)

```typescript
// src/connectionManager.ts
import { WebSocket } from "ws";
import { gauge, counter } from "./metrics.js";
import { logger } from "./logger.js";

interface ClientMeta {
  userId: string;
  socket: WebSocket;
  bufferedBytes: number;
  connectedAt: number;
  lastPong: number;
}

const CONNECTIONS = gauge("ws_connections_total", "Active WebSocket connections");
const BUFFERED_BYTES = gauge("ws_buffered_bytes_total", "Bytes buffered per socket",
  ["user_id"]);
const MESSAGES_SENT = counter("ws_messages_sent_total", "Messages pushed to clients",
  ["outcome"]);
const CLIENTS_DROPPED = counter("ws_clients_dropped_total", "Clients dropped",
  ["reason"]);

export class ConnectionManager {
  // userId → set of active sockets (a user can have multiple sessions)
  private byUser = new Map<string, Set<ClientMeta>>();
  // socket → meta (reverse index for O(1) cleanup)
  private bySocket = new Map<WebSocket, ClientMeta>();

  add(userId: string, socket: WebSocket): ClientMeta {
    if (this.bySocket.size >= MAX_CLIENTS) {
      socket.close(1013, "server overloaded");
      CLIENTS_DROPPED.labels("max_clients").inc();
      throw new Error("max clients exceeded");
    }
    const meta: ClientMeta = {
      userId, socket,
      bufferedBytes: 0,
      connectedAt: Date.now(),
      lastPong: Date.now(),
    };
    this.bySocket.set(socket, meta);
    if (!this.byUser.has(userId)) this.byUser.set(userId, new Set());
    this.byUser.get(userId)!.add(meta);
    CONNECTIONS.set(this.bySocket.size);
    return meta;
  }

  /** Broadcast to every client subscribed to either buyerId or sellerId. */
  broadcast(interestedUserIds: string[], payload: string): void {
    const deduped = new Set(interestedUserIds);
    for (const uid of deduped) {
      const set = this.byUser.get(uid);
      if (!set) continue;
      for (const meta of set) {
        this.sendToClient(meta, payload);
      }
    }
  }

  private sendToClient(meta: ClientMeta, payload: string): void {
    if (meta.socket.readyState !== WebSocket.OPEN) return;

    // BACKPRESSURE: ws.send returns false when the kernel send buffer is full.
    // If we keep calling send() we buffer in memory until OOM.
    if (meta.bufferedBytes > MAX_BUFFERED_BYTES) {
      meta.socket.close(1011, "backpressure timeout");
      CLIENTS_DROPPED.labels("backpressure").inc();
      return;
    }

    const sendResult = meta.socket.send(payload, (err) => {
      if (err) {
        logger.warn({ err, user_id: meta.userId }, "ws_send_failed");
        MESSAGES_SENT.labels("error").inc();
        meta.socket.terminate();
      } else {
        MESSAGES_SENT.labels("ok").inc();
      }
    });

    // ws.send returns true if data is flushed immediately, false if buffered.
    if (sendResult === false) {
      meta.bufferedBytes += Buffer.byteLength(payload);
      BUFFERED_BYTES.labels(meta.userId).set(meta.bufferedBytes);
    } else {
      // Flushed — reset the buffer counter (the data is on the wire)
      if (meta.bufferedBytes > 0) {
        meta.bufferedBytes = 0;
        BUFFERED_BYTES.labels(meta.userId).set(0);
      }
    }
  }

  remove(socket: WebSocket): void {
    const meta = this.bySocket.get(socket);
    if (!meta) return;
    this.bySocket.delete(socket);
    const set = this.byUser.get(meta.userId);
    if (set) {
      set.delete(meta);
      if (set.size === 0) this.byUser.delete(meta.userId);
    }
    CONNECTIONS.set(this.bySocket.size);
  }

  /** On rebalance: notify clients whose subscriptions are about to be revoked. */
  notifyRevocation(partitions: number[]): void {
    // The broadcaster doesn't know which user_ids are on which partition without
    // re-hashing. The safe thing is to tell ALL clients a rebalance is happening.
    const msg = JSON.stringify({
      type: "rebalance",
      reason: "partition_revoked",
      partitions,
    });
    for (const meta of this.bySocket.values()) {
      if (meta.socket.readyState === WebSocket.OPEN) {
        meta.socket.send(msg);
      }
    }
  }

  size(): number { return this.bySocket.size; }
}
```

### Step 4 — Kafka consumer (kafkajs, manual commits)

```typescript
// src/kafkaConsumer.ts
import { Kafka, EachMessagePayload, logLevel } from "kafkajs";
import { config } from "./config.js";
import { ConnectionManager } from "./connectionManager.js";
import { counter, gauge } from "./metrics.js";
import { logger, runWithTraceId } from "./logger.js";

const MESSAGES = counter("consumer_messages_processed_total", "",
  ["outcome"]);
const LAG = gauge("consumer_lag_partitions", "Per-partition lag",
  ["topic", "partition"]);

export class OrderConsumer {
  private kafka = new Kafka({
    clientId: "ws-broadcaster",
    brokers: [config.KAFKA_BOOTSTRAP],
    logLevel: logLevel.WARN,
  });
  private consumer = this.kafka.consumer({
    groupId: config.KAFKA_GROUP,
    sessionTimeout: config.KAFKA_SESSION_TIMEOUT,
    maxPollIntervalMs: config.KAFKA_MAX_POLL_INTERVAL,
    partitionAssigners: [cooperativeStickyAssigner],
    allowAutoTopicCreation: false,
  });
  private running = true;

  constructor(private cm: ConnectionManager) {}

  async start() {
    await this.consumer.connect();
    await this.consumer.subscribe({
      topic: config.KAFKA_TOPIC,
      fromBeginning: false,
    });

    await this.consumer.run({
      eachMessage: async (payload: EachMessagePayload) => {
        await runWithTraceId(payload, async () => {
          await this.handle(payload);
        });
      },
    });

    // The rebalance listener is set up after .run() because kafkajs v2
    // requires the consumer to be connected first.
    this.consumer.on(this.consumer.events.HEARTBEAT, () => {
      // session is alive — implicit
    });
    this.consumer.on(this.consumer.events.REBALANCE, (e) => {
      logger.info({ payload: e.payload }, "rebalance_event");
      // Notify clients so they can re-subscribe if their user_id is on a
      // partition that moved.
      this.cm.notifyRevocation(e.payload.assignment?.topicPartitions
        ?.map(p => p.partition) ?? []);
    });
  }

  private async handle(payload: EachMessagePayload) {
    const { message, partition, topic } = payload;
    if (!message.value) return;

    let evt: any;
    try {
      evt = JSON.parse(message.value.toString());
    } catch (e) {
      MESSAGES.labels("error").inc();
      logger.error({ err: e, partition, offset: message.offset }, "parse_failed");
      await payload.commit();           // poison pill — skip past
      return;
    }

    // Determine which user IDs are interested in this event.
    const interested = [evt.buyer_id, evt.seller_id];
    const wsPayload = JSON.stringify({
      type:        "order.created",
      order_id:    evt.aggregate_id,
      buyer_id:    evt.buyer_id,
      seller_id:   evt.seller_id,
      total_cents: evt.total_cents,
      currency:    evt.currency,
      occurred_at: evt.occurred_at,
      trace_id:    evt.trace_id,
    });

    this.cm.broadcast(interested, wsPayload);
    MESSAGES.labels("ok").inc();

    // MANUAL COMMIT — only after the broadcast has been queued for send.
    // If we crash before commit, the event is redelivered on next start,
    // and clients may see a duplicate — they MUST dedupe by order_id.
    await payload.commit();
    LAG.labels({ topic, partition: String(partition) }).set(0);
  }

  async stop() {
    this.running = false;
    await this.consumer.disconnect();
  }
}

// kafkajs cooperative-sticky assigner (must be imported explicitly)
import { CooperativeStickyAssigner } from "kafkajs";
const cooperativeStickyAssigner = (config: any) => new CooperativeStickyAssigner(config);
```

### Step 5 — Server (Fastify + ws)

```typescript
// src/server.ts
import Fastify from "fastify";
import fastifyWebsocket from "@fastify/websocket";
import { config } from "./config.js";
import { ConnectionManager } from "./connectionManager.js";
import { OrderConsumer } from "./kafkaConsumer.js";
import { verifyToken } from "./auth.js";
import { startMetricsServer } from "./metrics.js";
import { logger } from "./logger.js";

const cm = new ConnectionManager();
const consumer = new OrderConsumer(cm);

const app = Fastify({ logger: false });
await app.register(fastifyWebsocket, {
  options: {
    maxPayload: 1024,                  // 1 KB — we only ever receive "ping"
    clientTracking: false,             // we track ourselves in ConnectionManager
    skipUTF8Validation: false,         // utf-8-validate native addon if installed
  },
});

app.get("/health", async () => ({ status: "ok", connections: cm.size() }));

app.get("/ws/orders", { websocket: true }, async (socket, req) => {
  const userId = (req.query as any).user_id as string | undefined;
  const token  = (req.query as any).token  as string | undefined;
  if (!userId || !token) {
    socket.close(4400, "missing user_id or token");
    return;
  }
  try { await verifyToken(token, userId); }
  catch (e) {
    socket.close(4401, "unauthorized");
    return;
  }

  const meta = cm.add(userId, socket);
  socket.send(JSON.stringify({
    type: "hello",
    client_id: `ws_${meta.connectedAt.toString(36)}`,
    subscriptions: [userId],
  }));

  // Heartbeat: server pings every 30s; client must pong or be dropped.
  const pingTimer = setInterval(() => {
    if (Date.now() - meta.lastPong > config.CLIENT_TIMEOUT_MS * 2) {
      socket.terminate();
      return;
    }
    if (socket.readyState === 1 /* OPEN */) socket.ping();
  }, config.CLIENT_TIMEOUT_MS);

  socket.on("pong", () => { meta.lastPong = Date.now(); });
  socket.on("message", (data) => {
    // We don't accept client messages other than the literal "ping" string.
    if (data.toString() === "ping") socket.send("pong");
  });
  socket.on("close", () => {
    clearInterval(pingTimer);
    cm.remove(socket);
  });
  socket.on("error", (err) => {
    logger.warn({ err, user_id: userId }, "ws_error");
    clearInterval(pingTimer);
    cm.remove(socket);
  });
});

// Graceful shutdown: stop consuming, drain clients, then close.
const shutdown = async (sig: string) => {
  logger.info({ sig }, "shutdown");
  await consumer.stop();
  // Give clients 2 seconds to receive any in-flight messages.
  await new Promise(r => setTimeout(r, 2000));
  await app.close();
  process.exit(0);
};
process.on("SIGINT",  () => shutdown("SIGINT"));
process.on("SIGTERM", () => shutdown("SIGTERM"));

await app.listen({ port: config.HTTP_PORT, host: "0.0.0.0" });
startMetricsServer(config.METRICS_PORT);
await consumer.start();
logger.info({ port: config.HTTP_PORT }, "broadcaster_ready");
```

### Step 6 — Logger with AsyncLocalStorage for trace_id

```typescript
// src/logger.ts
import pino from "pino";
import { AsyncLocalStorage } from "node:async_hooks";
import type { EachMessagePayload } from "kafkajs";

const als = new AsyncLocalStorage<{ traceId: string | null }>();

export const logger = pino({
  level: process.env.LOG_LEVEL || "info",
  mixin: () => {
    const ctx = als.getStore();
    return ctx?.traceId ? { trace_id: ctx.traceId } : {};
  },
});

export async function runWithTraceId(
  payload: EachMessagePayload,
  fn: () => Promise<void>,
) {
  const headers = payload.message.headers || {};
  const tid = headers["trace_id"]
    ? Buffer.from(headers["trace_id"]).toString()
    : null;
  return als.run({ traceId: tid }, fn);
}
```

`AsyncLocalStorage` is Node's equivalent of Python's `contextvars` or Java's `ThreadLocal` — it propagates a value through an async call chain without explicit parameter passing. The `mixin` function in pino pulls the `trace_id` out on every log line. This is how the broadcaster's logs end up correlatable with the producer's logs in Loki via the same `trace_id` despite crossing a Kafka boundary.


The expected failure mode at extreme load (10k connections × 10k events/sec) is V8 event-loop saturation: the `eachMessage` callback takes >5 ms, the librdkajs internal queue grows, `consumer_lag_partitions` climbs unboundedly. The fix is horizontal scaling — spin up a second broadcaster instance, both join `KAFKA_GROUP=ws-broadcaster`, kafkajs cooperative-sticky assigner redistributes partitions without stopping either instance, and each instance handles half the events. The WebSocket clients must reconnect if their `rebalance` notification tells them their user_id's partition moved — this is why the `notifyRevocation` method exists.

## What This Teaches

This delta teaches three lessons the Spring Boot anchor and the Python consumer hide:

**1. Backpressure is a single-threaded-runtime pathology.** The Python consumer with librdkafka can spend 50 ms on a Postgres UPSERT and the C poll loop continues in another thread; the only consequence is that `poll()` returns a batch of 100 instead of 1 the next time. The Node.js broadcaster has one event loop and one `eachMessage` callback at a time. If a single WebSocket client's TCP buffer is full and `ws.send` returns `false`, the broadcaster has to either buffer (and risk OOM) or drop the client. The `ConnectionManager.sendToClient` method tracks `bufferedBytes` per socket and disconnects clients that exceed `MAX_BUFFERED_BYTES` — this is the kind of defensive code that Python/Java developers never have to write because their consumers write to a database, not to a fickle mobile client. Every Node.js WebSocket server in production needs this pattern or it will OOM on the first slow client.

**2. `AsyncLocalStorage` is Node's `ThreadLocal`, and it is the only way to propagate context across `await`.** The Spring Boot anchor uses `MDC.put("trace_id", ...)` and Logback's `%X{trace_id}` pattern; the Python consumer uses `contextvars.ContextVar`. The Node.js equivalent is `AsyncLocalStorage` from `node:async_hooks`, which propagates a value through an async call chain without explicit parameter passing. The `runWithTraceId` wrapper sets up the store at the top of `eachMessage`, and every `logger.info()` call inside the handler pulls the `trace_id` out via the pino `mixin` function. This is non-trivial: without AsyncLocalStorage, you'd have to thread `traceId` through every function signature in the call chain, which is what Go forces you to do with `context.Context` as the first parameter of every function. Node gives you the choice; always choose AsyncLocalStorage for cross-cutting concerns like tracing.

**3. Cooperative-sticky partition assignment is the only correct rebalance strategy for stateful consumers.** The default kafkajs assigner is `roundrobin`, which on every rebalance reassigns ALL partitions to ALL consumers from scratch — every consumer stops consuming for the duration of the rebalance (typically 5–30 seconds), and every connected WebSocket client gets a `rebalance` notification. The `cooperative-sticky` assigner only moves partitions that need to move (i.e., the partitions owned by a consumer that just left the group), leaving everyone else's assignments untouched. For the broadcaster this is the difference between "one consumer died, its clients reconnect, everyone else is unaffected" and "one consumer died, every client in the system disconnects." The cooperative-sticky assigner is a one-line config change (`partitionAssigners: [cooperativeStickyAssigner]`) but it changes the entire operational character of the system.
