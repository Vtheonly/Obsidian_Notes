# Bits, Bytes, and Data Units

#fundamentals/data-units #networking/bandwidth #hardware/storage

## The Fundamental Relationship: 1 Byte = 8 Bits

The **bit** (binary digit) is the smallest unit of information in computing. It can hold exactly one of two values: 0 or 1. The **byte** is the next unit up, defined as exactly 8 bits. This is not arbitrary—8 bits can represent 256 distinct values ($2^8 = 256$), which is sufficient to encode all English letters (upper and lowercase), digits, punctuation marks, and control characters in the ASCII standard.

This 8:1 ratio between bits and bytes is the source of endless confusion in computing, because **network speeds are measured in bits per second** while **storage and memory sizes are measured in bytes**. This is a historical convention:

- **Network equipment** (routers, switches, NICs) measures data at the physical layer, where bits are transmitted serially—one at a time. A 10 Gbps link transmits 10 billion bits per second.
- **Storage devices** (hard drives, SSDs, RAM) measure data in bytes, which are the smallest addressable unit of memory. You cannot read or write a single bit from RAM; you read or write at least one byte.

## The Unit Hierarchy

Computing uses binary prefixes based on powers of 2 (though there is a parallel SI system based on powers of 10):

| Unit | Bytes (Binary) | Bytes (Decimal/SI) | Common Use |
|------|----------------|---------------------|------------|
| KB (Kilobyte) | 1,024 ($2^{10}$) | 1,000 | Small files, config |
| MB (Megabyte) | 1,048,576 ($2^{20}$) | 1,000,000 | Images, documents |
| GB (Gigabyte) | 1,073,741,824 ($2^{30}$) | $10^9$ | RAM, video, large files |
| TB (Terabyte) | $2^{40}$ | $10^{12}$ | Database sizes, backups |
| PB (Petabyte) | $2^{50}$ | $10^{15}$ | Data warehouse, analytics |

The binary system (1 KB = 1,024 bytes) is technically called **kibibyte (KiB)**, **mebibyte (MiB)**, etc. under the IEC standard. However, in practice, the KB/MB/GB notation is used ambiguously. Storage manufacturers use decimal (1 TB = $10^{12}$ bytes), while operating systems often use binary, which is why a "1 TB" hard drive shows as only ~931 GB in your OS.

## The Critical Conversion: Network Bits to Storage Bytes

This is where most confusion occurs in high-scale systems. To convert network bandwidth (in bits) to data throughput (in bytes), **divide by 8**:

$$\text{Throughput (bytes/s)} = \frac{\text{Bandwidth (bits/s)}}{8}$$

### Practical Examples

| Network Speed | Bits per Second | Bytes per Second | Common Name |
|---------------|-----------------|-------------------|-------------|
| 1 Gbps | $10^9$ | 125,000,000 (125 MB/s) | Gigabit Ethernet |
| 10 Gbps | $10 \times 10^9$ | 1,250,000,000 (1.25 GB/s) | 10 Gigabit Ethernet |
| 25 Gbps | $25 \times 10^9$ | 3,125,000,000 (3.125 GB/s) | Data center interconnect |
| 50 Gbps | $50 \times 10^9$ | 6,250,000,000 (6.25 GB/s) | High-performance compute |
| 100 Gbps | $100 \times 10^9$ | 12,500,000,000 (12.5 GB/s) | Backbone network |
| 400 Gbps | $400 \times 10^9$ | 50,000,000,000 (50 GB/s) | Hyperscale backbone |

### Why This Matters for 1M RPS

Consider a server with a 10 Gbps network card. If each HTTP request generates a 1 KB response:

- Maximum throughput in bytes/s: **1.25 GB/s**
- Bytes per request (1 KB = 1,024 bytes): **1,024**
- Maximum requests per second (bandwidth-limited): $\frac{1,250,000,000}{1,024} \approx$ **1,220,000 RPS**

So a 10 Gbps network card can theoretically support ~1.22M RPS for 1 KB responses, *if* the CPU can process requests fast enough. This is why the [[2.6 Network Cards and Bandwidth]] is often the binding constraint rather than compute at these scales.

Now consider 50 Gbps (as found on AWS C8i.32xlarge):
- Throughput: **6.25 GB/s**
- Maximum RPS for 1 KB responses: **~6.1 million RPS**

The network card is no longer the bottleneck—the CPU and application logic become the limiting factors.

## Common Confusion Points

### "My internet is 100 Mbps, why can't I download at 100 MB/s?"

100 Mbps = 100 megabits per second = 12.5 megabytes per second. Your 100 Mbps connection can download at most ~12.5 MB/s. The factor of 8 is always the culprit.

### "The server has 256 GB RAM and a 50 Gbps network card."

These are different units measuring different things:
- 256 GB = 256 gigabytes of storage capacity
- 50 Gbps = 50 gigabits per second of transfer speed (6.25 GB/s)

### Moving Terabytes Per Minute

At 50 Gbps, the maximum data transfer rate is 6.25 GB/s:
- Per minute: $6.25 \times 60 = 375$ GB/minute
- Per hour: $6.25 \times 3,600 = 22.5$ TB/hour
- Per day: $6.25 \times 86,400 = 540$ TB/day

Moving terabytes per minute is entirely feasible with modern network hardware—a single 50 Gbps link can move 375 GB per minute, or roughly 22.5 TB per hour. At hyperscale, companies use 100-400 Gbps links, enabling petabyte-per-hour transfer rates between data centers.

## Protocol Overhead

The conversions above assume raw data transfer. In practice, protocols add overhead:
- **TCP/IP headers**: ~40-88 bytes per packet (depending on options and timestamp)
- **Ethernet framing**: ~18-26 bytes per frame
- **HTTP headers**: Variable, but typically 200-500 bytes per request/response pair
- **TLS encryption**: ~20-30 bytes per record + computational overhead

For small payloads (e.g., a 100-byte API response), the protocol overhead can exceed the payload size, effectively halving or worse the useful throughput. This is why protocols like HTTP/2 (header compression), QUIC (reduced handshake overhead), and gRPC (binary serialization) are critical at scale.
