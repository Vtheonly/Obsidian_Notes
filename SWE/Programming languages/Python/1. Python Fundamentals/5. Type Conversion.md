# 5. Type Conversion

## Why This Matters

Type conversion — also called **type casting** — is one of the most frequent operations in any Python program. Every time you `int(input("age? "))`, every time you `str(42) + " items"`, every time you `list(dict.keys())`, you are converting. Get it wrong and you get `ValueError`, `TypeError`, or worse: silent data corruption (e.g., `int("0x10")` raising when you meant `int("0x10", 16)`).

This note covers the two flavors of conversion (implicit vs. explicit), the full set of conversion functions, **truthiness and falsiness** (which is conversion to `bool`), the conversion matrix among built-in types, and the gotchas that catch every Python beginner at least once: `int("3.14")` fails, `bool("False")` is `True`, `list("abc")` is `['a', 'b', 'c']`, and `set("hello")` is `{'h', 'e', 'l', 'o'}`.

---

## Background

Python is **strongly typed**: it does not silently coerce incompatible types (`"5" + 5` raises). But it is also **dynamically typed**: you can convert at runtime with explicit calls. Python distinguishes:

1. **Implicit conversion** — automatic, performed by Python when no information would be lost. Example: `int + float → float`.
2. **Explicit conversion** — performed by the programmer with `int()`, `float()`, `str()`, `bool()`, `list()`, `tuple()`, `set()`, `dict()`, etc. Often called *casting*, though Python programmers rarely use that term.

The boundary between the two is small and deliberate: Python does implicit promotion only between numeric types (and the always-correct `bool → int`). Everything else is your responsibility.

---

## Implicit Conversion

### Numeric promotion

```python
3 + 4.0        # 7.0    int + float → float
3 + 4 + 0j     # (7+0j) int + complex → complex
True + 1       # 2      bool + int → int (bool is a subclass)
2 * 3.0        # 6.0    int * float → float
```

The rule: the "wider" type wins. Order of width: `bool` < `int` < `float` < `complex`. So:

| Operands | Result |
|----------|--------|
| `int + int` | `int` |
| `int + float` | `float` |
| `int + complex` | `complex` |
| `float + complex` | `complex` |
| `bool + bool` | `int` (boolean operators use `bool`, arithmetic uses int) |

Note that **division always returns float**, even when both operands are ints:

```python
4 / 2      # 2.0   (float)
4 // 2     # 2     (int)
```

### Why no implicit str → int?

Python deliberately does **not** do `"3" + 4 → "34"` (JavaScript) or `"3" + 4 → 7` (some BASICs). The principle from the Zen: *Explicit is better than implicit*. You must write `int("3") + 4` or `"3" + str(4)` — both unambiguous.

## Explicit Conversion Functions

### `int(x, base=10)` — convert to integer

```python
int("42")          # 42
int("0xff", 16)    # 255   — base 16
int("777", 8)      # 511   — base 8
int("1010", 2)     # 10    — base 2
int(3.99)          # 3     — truncates toward zero (NOT floor!)
int(-3.99)         # -3
int(True)          # 1
int("  42  ")      # 42    — leading/trailing whitespace OK
```

Common pitfalls:

```python
int("3.14")        # ValueError — int() can't parse a decimal point
int("0x10")        # ValueError — base 10 by default
int("0x10", 16)    # 16        — base 16 OK; "0x" prefix tolerated
int("1_000")       # 1000      — underscores allowed (PEP 515)
int("12", base=2)  # ValueError — '2' is not a binary digit
```

If you have a string like `"3.14"` and want an int, do `int(float("3.14"))`.

### `float(x)` — convert to float

```python
float("3.14")      # 3.14
float("  3  ")     # 3.0
float("1e3")       # 1000.0   — scientific notation
float("inf")       # inf
float("-inf")      # -inf
float("nan")       # nan
float(42)          # 42.0
float(True)        # 1.0
float("3.14abc")   # ValueError
```

### `complex(real, imag=0)` — convert to complex

```python
complex("3+4j")    # (3+4j)
complex(3, 4)      # (3+4j)
complex(3.0)       # (3+0j)
```

### `str(x)` — convert anything to its string representation

```python
str(42)            # '42'
str(3.14)          # '3.14'
str([1, 2, 3])     # '[1, 2, 3]'
str(None)          # 'None'
str(True)          # 'True'
class C: pass
str(C())           # '<__main__.C object at 0x7f...>'
```

`str()` calls `__str__`, which is meant for end-user display. `repr()` calls `__repr__`, meant for unambiguous programmer display. For most built-ins they coincide; for custom classes, define both.

### `bool(x)` — convert to boolean (truthiness)

```python
bool(0)            # False
bool(0.0)          # False
bool(0j)           # False
bool("")           # False
bool([])           # False
bool({})           # False
bool(None)         # False
bool(0.0001)       # True
bool("False")      # True ← surprising! Any non-empty string is truthy
bool(" ")          # True — whitespace is non-empty
bool([0])          # True — list with one element (even 0) is truthy
```

The full list of **falsy** values:

- `False`
- `None`
- `0`, `0.0`, `0j`, `Decimal(0)`, `Fraction(0, 1)`
- Empty sequences: `""`, `[]`, `()`, `b""`, `bytearray()`, `range(0)`
- Empty mappings: `{}`
- Custom objects whose `__bool__` returns `False` or whose `__len__` returns 0

**Everything else is truthy** — including `"False"`, `"0"`, `[[]]`, and `float("nan")`.

> [!warning] `bool("False")` is `True`
> A common mistake when reading a flag from environment or CLI:

```python
debug = bool(os.environ.get("DEBUG", "False"))
# Always True! Because "False" is a non-empty string.
```

Fix:

```python
debug = os.environ.get("DEBUG", "").lower() in ("1", "true", "yes")
```

### `list(iterable)` — convert to list

```python
list("abc")        # ['a', 'b', 'c']
list((1, 2, 3))    # [1, 2, 3]
list({1, 2, 3})    # [1, 2, 3]   (order not guaranteed)
list({"a": 1})     # ['a']        (iterating dict yields keys)
list(range(5))     # [0, 1, 2, 3, 4]
list(enumerate("ab"))  # [(0, 'a'), (1, 'b')]
```

### `tuple(iterable)` — convert to tuple

Same as `list()` but produces an immutable tuple. Useful for hashing or as a dict key:

```python
tuple([1, 2, 3])      # (1, 2, 3)
tuple("ab")           # ('a', 'b')
```

### `set(iterable)` — convert to set

```python
set("hello")       # {'h', 'e', 'l', 'o'}   — duplicates removed
set([1, 1, 2, 3])  # {1, 2, 3}
set({"a": 1})      # {'a'}
```

### `frozenset(iterable)` — convert to immutable set

```python
frozenset([1, 2, 3])   # frozenset({1, 2, 3})  — hashable
```

### `dict(iterable)` — convert to dict

The iterable must yield pairs (2-tuples or 2-element lists):

```python
dict([("a", 1), ("b", 2)])   # {'a': 1, 'b': 2}
dict([("a", 1)], b=2)        # {'a': 1, 'b': 2}  — keyword args also accepted
dict(a=1, b=2)               # {'a': 1, 'b': 2}
dict(zip(["a", "b"], [1, 2]))  # {'a': 1, 'b': 2}
```

You cannot directly convert a list of single values to a dict:

```python
dict(["a", "b"])             # ValueError: dictionary update sequence element #0 has length 1
```

### `bytes()` and `bytearray()` — convert to bytes

```python
bytes("hello", "utf-8")         # b'hello'
bytes([72, 105])                # b'Hi'
"hello".encode("utf-8")         # b'hello'  — preferred idiom
b"hello".decode("utf-8")        # "hello"
```

### `chr()` and `ord()` — between characters and code points

```python
ord("A")    # 65
chr(65)     # 'A'
chr(0x1F600)  # 
ord("")     # 128512
```

### `hex()`, `oct()`, `bin()` — int to prefixed string

```python
hex(255)    # '0xff'
oct(8)      # '0o10'
bin(10)     # '0b1010'
format(255, "x")   # 'ff'    — no prefix
format(255, "#x")  # '0xff'
```

## The Conversion Matrix

```mermaid
flowchart LR
    INT["int"]
    FLT["float"]
    CMP["complex"]
    STR["str"]
    BOOL["bool"]
    LST["list"]
    TUP["tuple"]
    SET["set"]
    DCT["dict"]
    BYT["bytes"]

    INT -->|float\(\)| FLT
    FLT -->|int\(\) truncates toward 0| INT
    INT -->|complex\(\)| CMP
    INT -->|str\(\)| STR
    STR -->|int\(s, base\)| INT
    STR -->|float\(\)| FLT
    INT -->|bool\(\)| BOOL
    BOOL -->|int\(\)| INT
    STR -->|list\(\)/tuple\(\)/set\(\)| LST
    LST -->|"".join\(\)| STR
    LST -->|tuple\(\)| TUP
    TUP -->|list\(\)| LST
    LST -->|set\(\)| SET
    SET -->|list\(\)| LST
    LST -->|dict\(\) if pairs| DCT
    DCT -->|list\(\) keys only| LST
    STR -->|s.encode\(\)| BYT
    BYT -->|b.decode\(\)| STR
```

Read this diagram as "X can be converted to Y via the labeled function." Note that some conversions are lossy (e.g., `float → int` truncates) and some require validation (e.g., `str → int` may raise).

## Truthiness and Falsiness — Deep Dive

When you write `if items:`, Python calls `bool(items)`. The rules:

1. If the class defines `__bool__`, use it (must return `True` or `False`).
2. Else if it defines `__len__`, use `len(x) != 0`.
3. Else the object is truthy.

This is why `if my_list:` works without explicit comparison. The idiom is preferred:

```python
# Bad
if len(my_list) > 0: ...
if my_list != []: ...

# Good
if my_list: ...
```

But be explicit when checking for `None`:

```python
# Bad — treats empty list same as None
def f(x):
    if x: ...        # None and [] both fail

# Good
def f(x):
    if x is not None: ...
```

### Custom truthiness

```python
class Stack:
    def __init__(self): self._items = []
    def push(self, x): self._items.append(x)
    def __len__(self): return len(self._items)
    def __bool__(self): return bool(self._items)

s = Stack()
print(bool(s))      # False
s.push(1)
print(bool(s))      # True
```

## Annotated Code Examples

### Example 1: Reading numbers safely

```python
def read_int(prompt):
    while True:
        s = input(prompt)
        try:
            return int(s)
        except ValueError:
            try:
                # accept "3.0" → 3, reject "3.14"
                f = float(s)
                if f.is_integer():
                    return int(f)
            except ValueError:
                pass
            print("Please enter a whole number.")

age = read_int("Age? ")
```

### Example 2: Parsing a comma-separated list

```python
raw = "1, 2, 3, 4"
nums = [int(x.strip()) for x in raw.split(",")]
print(nums)        # [1, 2, 3, 4]
```

### Example 3: Boolean from environment

```python
import os

def env_bool(name, default=False):
    v = os.environ.get(name)
    if v is None:
        return default
    return v.strip().lower() in ("1", "true", "yes", "on")

debug = env_bool("DEBUG")
```

### Example 4: Bytes <-> string round trip

```python
s = "héllo "
b = s.encode("utf-8")        # bytes
print(b)                     # b'h\xc3\xa9llo \xf0\x9f\x8c\x8d'
s2 = b.decode("utf-8")       # string again
assert s == s2
```

### Example 5: Building a dict from parallel lists

```python
keys = ["a", "b", "c"]
vals = [1, 2, 3]
d = dict(zip(keys, vals))
print(d)        # {'a': 1, 'b': 2, 'c': 3}
```

### Example 6: Convert a list of pairs to a dict, ignoring bad pairs

```python
raw = [("a", 1), ("b",), ("c", 3)]
d = {k: v for k, v in raw if len((k, v) if isinstance((k,), tuple) else ()) >= 2}
# Cleaner version:
d = {}
for pair in raw:
    if len(pair) == 2:
        k, v = pair
        d[k] = v
print(d)        # {'a': 1, 'c': 3}
```

## Numeric Coercion in Mixed Arithmetic

When you mix numeric types in arithmetic, Python promotes to the wider type:

```python
3 + 4.0       # 7.0      int + float → float
3 + 4 + 0j    # (7+0j)   int + complex → complex
True + 1      # 2        bool + int → int (bool is a subclass)
2 * 3.0       # 6.0      int * float → float
1.0 + 2.0     # 3.0      float + float → float
```

Order of "width": `bool` < `int` < `float` < `complex`.

If you mix in `Decimal` or `Fraction`, the rules differ:

```python
from decimal import Decimal
from fractions import Fraction

# Decimal + int → Decimal
Decimal("1.5") + 2    # Decimal('3.5')

# Fraction + int → Fraction
Fraction(1, 3) + 1    # Fraction(4, 3)

# But Decimal + float → TypeError!
Decimal("1.5") + 1.5  # TypeError: unsupported operand type(s)
```

`Decimal` and `Fraction` don't auto-coerce with `float` — you must convert explicitly. This is intentional: floats have precision issues that would silently corrupt `Decimal` math.

## `__bool__` and `__len__` — Custom Truthiness

Your classes can participate in truth-value testing:

```python
class Stack:
    def __init__(self): self._items = []
    def push(self, x): self._items.append(x)
    def __len__(self): return len(self._items)
    def __bool__(self): return bool(self._items)

s = Stack()
print(bool(s))   # False — empty
s.push(1)
print(bool(s))   # True

if s:            # uses __bool__ (or __len__ as fallback)
    print("has items")
```

If a class defines `__bool__`, Python uses it. Otherwise, it falls back to `__len__` (truthy if non-zero). If neither, the object is always truthy.

This is how `if my_list:`, `if my_dict:`, `if my_string:` all "just work" — they implement `__len__` and (for strings and others) `__bool__`.

## Conversion to Custom Types

You can make your class convertible from existing types via `__init__`:

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @classmethod
    def from_fahrenheit(cls, f):
        return cls((f - 32) * 5 / 9)

    @classmethod
    def from_kelvin(cls, k):
        return cls(k - 273.15)

t1 = Temperature(25)
t2 = Temperature.from_fahrenheit(77)
t3 = Temperature.from_kelvin(298.15)
```

This is more idiomatic than overloading `int(Temperature)` — Python doesn't have implicit construction from arbitrary types. Use classmethods for alternative constructors.

## Common Pitfalls

### 1. `int("3.14")` raises

```python
int("3.14")    # ValueError
int(float("3.14"))   # 3 — works
```

### 2. `int("0x10")` raises — base defaults to 10

```python
int("0x10")        # ValueError
int("0x10", 16)    # 16
int("10", 16)      # 16 (same result; no need for "0x")
```

### 3. `int()` truncates toward zero, not floors

```python
int(3.99)      # 3
int(-3.99)     # -3   ← truncates toward zero
math.floor(3.99)    # 3
math.floor(-3.99)   # -4  ← floors toward -inf
```

### 4. `bool("False")` is `True`

```python
bool("False")    # True — non-empty string
bool("")         # False
```

### 5. `list("abc")` is character list, not `["abc"]`

```python
list("abc")     # ['a', 'b', 'c']
["abc"]         # ['abc']
```

### 6. `dict([("a", 1), "b"])` raises

```python
dict([("a", 1), "b"])   # ValueError — 'b' has length 1, not 2
```

### 7. Floats from strings lose precision

```python
float("0.1") + float("0.2") == 0.3   # False — same float issues
```

### 8. `bytes("abc")` requires an encoding

```python
bytes("abc")              # TypeError — encoding required
bytes("abc", "utf-8")     # b'abc'
"abc".encode()            # b'abc'   — preferred
```

### 9. Converting a dict's items to a list doesn't preserve type

```python
list({"a": 1}.items())   # [('a', 1)]   — list of tuples
```

### 10. `set("hello")` removes duplicates

```python
set("hello")   # {'h', 'e', 'l', 'o'}  ← not {'hello'}
```

## Tips and Tricks

- **`int(x, base)`** is bi-directional with `bin/oct/hex` — round-trip integers in any base.
- **`str.join` is the inverse of `list.split`**: `",".join(["a", "b"]) == "a,b"`.
- **`{**d1, **d2}`** merges dicts (3.5+). **`d1 | d2`** also (3.9+).
- **Use `Decimal` for money** — `Decimal("3.14")`, not `Decimal(3.14)` (which has the float's rounding error baked in).
- **`ord`/`chr`** for code-point conversion; remember that characters above U+FFFF may be two UTF-16 code units in other languages but Python handles them as one.
- **`str(x)` for display, `repr(x)` for debugging.** Use `f"{x!r}"` in f-strings.
- **`__bool__` is your friend** — make objects truthy/falsy meaningfully.
- **`bool(np.array([1, 2]))`** raises in NumPy because it's ambiguous — use `.any()` or `.all()`.
- **`isinstance(x, (int, float))`** for numeric checks — handles `bool` too.
- **`numbers.Number`** ABC includes all numeric types (including Decimal and Fraction) — useful for duck typing.
