# 4. Input and Output

## Why This Matters

Every program you will ever write consumes input and produces output. Python gives you **five distinct mechanisms for output formatting** (f-strings, `str.format`, `%`-formatting, `print`'s `sep`/`end`, and template strings), **three standard streams** (`stdin`, `stdout`, `stderr`), and **two main input functions** (`input()` and direct stream reads). Knowing which to use — and why f-strings are now the default — is the difference between clean, idiomatic, performant Python and code that looks like it was written in 2008.

Beyond the surface, this note covers subtleties: `print`'s `flush` parameter for piping, `file=sys.stderr` for diagnostics, why `input()` always returns a `str` (and how to handle that gracefully), how to pretty-print nested structures, and how to safely read large files without loading them into memory.

---

## Background: Standard Streams

Every process inherits three open streams from its parent:

| Stream | Python name | File descriptor | Default target |
|--------|-------------|-----------------|----------------|
| Standard input  | `sys.stdin`  | 0 | Terminal (keyboard) or piped input |
| Standard output | `sys.stdout` | 1 | Terminal (screen) or piped output |
| Standard error  | `sys.stderr` | 2 | Terminal (screen) or piped output |

```mermaid
flowchart LR
    KB["Keyboard / pipe<br/>(fd 0)"] --> STDIN["sys.stdin<br/>(text stream)"]
    STDIN -->|input(), .read()| PROG["Python program"]
    PROG -->|print(file=...) default| STDOUT["sys.stdout<br/>(fd 1)"]
    PROG -->|print(file=sys.stderr)| STDERR["sys.stderr<br/>(fd 2)"]
    STDOUT --> SCREEN1["Terminal / pipe"]
    STDERR --> SCREEN2["Terminal / pipe (unbuffered)"]
```

Separating `stdout` (program output, the "answer") from `stderr` (diagnostics, errors, logs) is a Unix convention that lets pipelines work:

```bash
python script.py 2> errors.log | grep RESULT
```

Here, `RESULT` lines from stdout flow to `grep`; error messages go to `errors.log`; the user sees them interleaved on a terminal.

`sys.stdout` and `sys.stderr` are **text streams** (mode `"w"`, encoding usually UTF-8). They are **line-buffered when attached to a terminal, block-buffered when piped**. This is why a long-running script with `print(...)` may appear to produce no output until it exits when its stdout is piped. Fix with `flush=True` or `print(..., flush=True)`.

## The `print()` Function

`print` is a built-in function (since Python 3; it was a statement in Python 2). Its signature:

```python
print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)
```

| Parameter | Meaning |
|-----------|---------|
| `*objects` | Any number of positional arguments; each is converted with `str()` |
| `sep`      | String inserted between objects (default: single space) |
| `end`      | String appended after the last object (default: newline) |
| `file`     | Output stream; default `sys.stdout`, but can be any file-like object |
| `flush`    | Force flush the stream after writing (default `False`) |

### Examples

```python
print("hello", "world")              # hello world
print("hello", "world", sep=" | ")   # hello | world
print("hello", end=""); print("world")   # helloworld
print(1, 2, 3, sep=", ")             # 1, 2, 3
print("error", file=sys.stderr)      # writes to stderr

# Custom file-like object
class Tee:
    def write(self, s): print(s, end="")
    def flush(self): pass
print("captured", file=Tee())
```

### `flush=True` — when and why

When stdout is piped, Python block-buffers it. If your script prints progress and then hangs, the user sees nothing. Force the output:

```python
print("processing...", flush=True)
```

Or call `sys.stdout.flush()` explicitly. Logging to `sys.stderr` is unbuffered by default, which is why progress bars sometimes use stderr.

> [!tip] `print` is slow for huge output
> Calling `print` per line is fine for small jobs. For millions of lines, write to a file object directly with `f.write("\n".join(lines))` or use `io.StringIO`.

## Formatted Output

Python has five ways to format strings. We'll cover the four serious ones.

### 1. f-strings (Python 3.6+) — the modern default

```python
name = "Alice"
age = 30
print(f"Hello, {name}. You are {age} years old.")
# Hello, Alice. You are 30 years old.
```

Features:

- **Expressions allowed**: `f"{2 + 2}"` → `"4"`.
- **Method calls**: `f"{name.upper()}"`.
- **Format specs** after `:`: `f"{3.14159:.2f}"` → `"3.14"`.
- **Alignment**: `f"{x:>10}"` (right), `f"{x:<10}"` (left), `f"{x:^10}"` (centre).
- **Zero-padding**: `f"{42:05d}"` → `"00042"`.
- **Thousands separator**: `f"{1234567:,}"` → `"1,234,567"`.
- **Conversion flags**: `f"{name!r}"` (repr), `f"{name!s}"` (str), `f"{name!a}"` (ascii).
- **Nested fields**: `f"{x:{width}}"` uses `width` from the surrounding scope.
- **Debugging (Python 3.8+)**: `f"{x=}"` produces `x=42`.

```python
import math
print(f"π ≈ {math.pi:.4f}")          # π ≈ 3.1416
print(f"{255:#010b}")                # 0b11111111
print(f"{0.15:.2%}")                 # 15.00%
print(f"{[1,2,3]!r}")                # [1, 2, 3]

width = 10
for s in ["a", "bb", "ccc"]:
    print(f"{s:>{width}}")            # right-aligned in width-10 column

x = 42
print(f"{x = }")                     # x = 42  (Python 3.8+)
```

> [!warning] Don't put expressions with side effects in f-strings
> `f"{db.delete(id)}"` works but is unclear. Use a temporary variable.

### 2. `str.format()` — pre-3.6, still useful for templates

```python
"Hello, {0}. You are {1} years old.".format("Alice", 30)
"Hello, {name}.".format(name="Alice")
"{x:>10.2f}".format(x=3.14159)
"{:*^30}".format("centered")   # **********centered**********
```

Use `str.format` when the template is **data**, not code — for example, when the template comes from a config file or a translation catalog. f-strings are evaluated at compile time, so they cannot be loaded from external text.

### 3. `%`-formatting (legacy C-style)

```python
"Hello, %s. You are %d years old." % ("Alice", 30)
"%05.2f" % 3.14159     # '03.14'
```

You will still see `%` in old code and in `logging` calls (the logger lazily formats only if the level is enabled — `"msg %s" % arg` is replaced by `logging.info("msg %s", arg)`).

> [!danger] Don't use `%` for new code
> It's slower, less expressive, and error-prone with tuples (`"%s" % (x,)` vs `"%s" % x`).

### 4. `string.Template` — safest for user-provided templates

```python
from string import Template
t = Template("Hello, $name. You are $age years old.")
print(t.substitute(name="Alice", age=30))
print(t.safe_substitute({"name": "Bob"}))    # missing keys left intact
```

`Template` only supports `$name` and `${name}` — no expressions, no format specs. This is a **feature** when the template string is user-supplied: f-strings would execute arbitrary code if you did `eval(f"{user_template}")`, but `Template` is safe.

### Comparison

| Method | Speed | Expressiveness | Safe for user templates | Use case |
|--------|-------|----------------|--------------------------|----------|
| f-strings | Fastest | Most | No | General purpose |
| `str.format` | Fast | High | No | Templates stored as data |
| `%` | Slow | Low | No | Legacy, `logging` |
| `string.Template` | Slow | Low | Yes | User-supplied templates |

```mermaid
flowchart TD
    Q["Need to format a string?"]
    Q -->|Template is in source code| F["f-string"]
    Q -->|Template is data/config| SF["str.format"]
    Q -->|Template comes from user| ST["string.Template"]
    Q -->|Logging call| LOG["logging.info('msg %s', arg)"]
    F --> DONE[""]
    SF --> DONE
    ST --> DONE
    LOG --> DONE
```

## Reading Input

### `input()` — read a line from stdin

```python
name = input("What is your name? ")
print(f"Hello, {name}!")
```

`input()` always returns a `str` (stripping the trailing newline). If you need an int, you must convert:

```python
try:
    age = int(input("Age? "))
except ValueError:
    print("Please enter a whole number.")
```

> [!warning] `input()` blocks
> Calling `input()` with no terminal attached (e.g., in a CI job) raises `EOFError`. Always handle that case if your script may be run unattended.

### Reading many lines

```python
# All of stdin, line by line
for line in sys.stdin:
    process(line)

# All of stdin as one string
text = sys.stdin.read()

# All of stdin as a list of lines
lines = sys.stdin.readlines()
```

The first form (line-by-line iteration) is **memory-efficient** for huge inputs. The last form loads everything into memory — fine for small files, catastrophic for log files.

### Reading from a file

```python
with open("data.txt", "r", encoding="utf-8") as f:
    for line in f:
        process(line)
```

The `with` statement ensures the file is closed even on exceptions. Always pass `encoding=` explicitly — relying on the platform default (often `cp1252` on Windows) is a common source of Unicode errors.

### Command-line arguments

`sys.argv` is a list of strings; `argv[0]` is the script name:

```python
import sys
print(sys.argv)        # ['script.py', 'arg1', 'arg2']
```

For serious argument parsing, use `argparse` (built-in) or `click` / `typer` (third-party). See Chapter 7 ([[1. Modules and Packages]] onward).

## Pretty-Printing

For nested data (dicts of lists of dicts), use the `pprint` module:

```python
import pprint
data = {"users": [{"id": 1, "name": "Alice"}, {"id": 2, "name": "Bob"}],
        "config": {"debug": True, "timeout": 30}}
pprint.pprint(data, width=60, sort_dicts=False)
```

Output:

```
{'users': [{'id': 1, 'name': 'Alice'},
           {'id': 2, 'name': 'Bob'}],
 'config': {'debug': True, 'timeout': 30}}
```

For full Python syntax (so you can paste back into source), use `pprint.pformat` or `reprlib.repr` for truncated output:

```python
import reprlib
print(reprlib.repr(list(range(1000))))   # [0, 1, 2, ..., 999]
```

For JSON output, use `json.dumps(obj, indent=2)`.

## Annotated Code Examples

### Example 1: A small CLI progress reporter

```python
import sys, time

def work(n):
    for i in range(n):
        print(f"\r{i+1}/{n}", end="", flush=True)
        time.sleep(0.05)
    print(" done.")

work(20)
```

The `\r` returns the cursor to the start of the line; `end=""` suppresses the newline; `flush=True` forces the output.

### Example 2: f-string format spec mini-reference

```python
x = 1234.5678
print(f"{x:.2f}")        # 1234.57    — 2 decimals
print(f"{x:>10.2f}")     #    1234.57 — width 10, right-aligned
print(f"{x:<10.2f}")     # 1234.57    
print(f"{x:^10.2f}")     #  1234.57  
print(f"{x:,.2f}")       # 1,234.57   — thousands separator
print(f"{x:+.2f}")       # +1234.57   — always show sign
print(f"{x:0=10.2f}")    # 0001234.57 — pad with zeros before sign
print(f"{x:.2e}")        # 1.23e+03   — scientific
print(f"{x:.2%}")        # 123456.78% — percentage
```

### Example 3: Safe template

```python
from string import Template
user_template = input("Template: ")   # "Hello $who"
t = Template(user_template)
print(t.safe_substitute(who="world"))
```

### Example 4: Reading a CSV-like file

```python
import csv, sys
with open("data.csv", newline="", encoding="utf-8") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["name"], row["age"])
```

### Example 5: Tee — write to stdout and a file simultaneously

```python
class Tee:
    def __init__(self, *streams): self.streams = streams
    def write(self, s):
        for st in self.streams: st.write(s)
    def flush(self):
        for st in self.streams: st.flush()

with open("log.txt", "w") as f:
    sys.stdout = Tee(sys.stdout, f)
    print("this goes to both")
```

## Reading and Writing Files

The built-in `open()` function is the gateway to file I/O:

```python
# Read
with open("data.txt", "r", encoding="utf-8") as f:
    text = f.read()       # whole file as one string
    # or
    for line in f:        # one line at a time (memory-efficient)
        process(line)

# Write
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("hello\n")
    print("world", file=f)   # print also writes to files

# Append
with open("log.txt", "a", encoding="utf-8") as f:
    f.write("new entry\n")

# Binary
with open("image.png", "rb") as f:
    data = f.read()
```

Modes: `"r"` (read, default), `"w"` (write, truncate), `"a"` (append), `"x"` (exclusive create), `"b"` (binary), `"t"` (text, default), `"+"` (read+write).

The `with` statement ensures the file is closed even on exceptions. **Always use `with`** for file operations.

### `pathlib` — modern path handling

```python
from pathlib import Path

p = Path("data") / "users.json"   # OS-independent path joining
if p.exists():
    text = p.read_text(encoding="utf-8")
    data = p.read_bytes()
    p.write_text("new content", encoding="utf-8")

# Iterate over a directory
for child in Path(".").iterdir():
    print(child)

# Glob
for py_file in Path(".").rglob("*.py"):
    print(py_file)
```

`pathlib` is the modern (Python 3.4+) replacement for `os.path`. Use it for new code.

## `sys.stdin`, `sys.stdout`, `sys.stderr` — Stream Objects

These are text streams with methods like `.read()`, `.readline()`, `.write()`, `.flush()`. You can replace them (for testing or redirection):

```python
import sys, io

# Capture stdout
captured = io.StringIO()
sys.stdout = captured
print("hello")
sys.stdout = sys.__stdout__   # restore
print(captured.getvalue())    # "hello\n"
```

Or use `contextlib.redirect_stdout`:

```python
from contextlib import redirect_stdout

with redirect_stdout(io.StringIO()) as buf:
    print("captured")
print(buf.getvalue())   # "captured\n"
```

## Common Pitfalls

### 1. Forgetting `flush=True` when piping

```bash
python script.py | tee out.log
# If the script doesn't flush, output appears in chunks.
```

### 2. Using `print` in tight loops

`print` is surprisingly slow because it acquires a lock, builds a string, and writes. For high-volume output, write directly:

```python
sys.stdout.write("line\n")
```

### 3. Mixing `print` and `sys.stdout.write` order

`print` writes to `sys.stdout` *as it currently is*. If you reassign `sys.stdout`, both go to the new target. If you bypass `sys.stdout` (write to fd 1 directly via `os.write`), output may interleave weirdly.

### 4. `input()` returns a string

```python
age = input("Age? ")
if age > 18:        # TypeError: '>' not supported between 'str' and 'int'
    ...
```

Fix: `age = int(input("Age? "))` with a `try/except ValueError`.

### 5. f-strings with user templates

```python
template = input()
result = eval(f'f"""{template}"""')   #  arbitrary code execution
```

Use `string.Template` instead.

### 6. Default encoding

```python
open("data.txt")   # uses platform default — cp1252 on Windows, utf-8 on Linux
```

Always pass `encoding="utf-8"` (or your real encoding).

### 7. `print(x, y)` joins with space — not empty string

```python
print("a", "b", "c")      # a b c  (spaces added)
print("a", "b", "c", sep="")   # abc
```

### 8. Newline handling on Windows

Files opened in text mode translate `\n`  `\r\n`. If you need raw bytes, open in binary mode (`"rb"`/`"wb"`) or pass `newline=""`.

## Tips and Tricks

- **`print(*xs, sep="\n")`** prints each item on its own line — nicer than a `for` loop.
- **`f"{x=}"`** is the fastest debugging tool since 3.8.
- **`sys.stdout.reconfigure(line_buffering=True)`** (Python 3.7+) makes stdout line-buffered even when piped.
- **`os.write(1, b"data")`** bypasses the text layer for raw binary writes.
- **`io.StringIO`** is an in-memory text stream — handy for testing functions that write to files.
- **`contextlib.redirect_stdout(target)`** temporarily redirects `sys.stdout`.
- **`rich` / `colorama`** for coloured terminal output; `tqdm` for progress bars.
- **Always use `encoding="utf-8"`** when opening files.
- **`json.dumps(obj, indent=2, ensure_ascii=False)`** for human-readable Unicode JSON.
- **Use `print(..., file=sys.stderr)` for diagnostics** — keeps stdout clean for piping.
