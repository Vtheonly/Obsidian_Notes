# 2. Parameters and Arguments

## Why This Matters

The terms **parameter** and **argument** are routinely confused, even by experienced programmers. Once you separate them, the rest of function semantics falls into place. Python's argument-passing model — usually described as "**pass by object reference**" or "**pass by assignment**" — is subtly different from both pass-by-value (C) and pass-by-reference (C++ `&`). Get this wrong and you'll either mutate caller state accidentally, or fail to mutate it when you wanted to.

This note covers the parameter/argument distinction, the four kinds of arguments (positional, keyword, default, variadic), Python's passing semantics, and the **mutable default argument pitfall** — the most famous Python gotcha. Understanding this is essential before reading [[3. Default and Keyword Arguments]] and [[4. args and kwargs]].

---

## Background

### Parameters vs. arguments

- A **parameter** is a variable listed in the function's definition. It's a name.
- An **argument** is a value passed to the function when it's called. It's a value.

```python
def greet(name):       # `name` is a parameter
    print(f"Hello, {name}")

greet("Alice")         # "Alice" is an argument
```

This is like the difference between a parking spot (parameter) and the car that parks in it (argument). The spot exists even when empty; the car fills it when called.

### Function signature and arity

The **signature** of a function is the ordered list of parameters plus their kinds. The **arity** is the number of parameters (sometimes split into required/optional arity).

```python
def f(a, b, c=3, *args, **kwargs): ...
#  parameters: a, b, c, args, kwargs
#  arity: 2 required, 1 optional (c), plus variadic
```

## Kinds of Arguments

### Positional arguments

Arguments are bound to parameters **in order**:

```python
def subtract(a, b):
    return a - b

subtract(10, 3)    # a=10, b=3 → 7
subtract(3, 10)    # a=3, b=10 → -7
```

### Keyword arguments

You can name arguments explicitly, in any order:

```python
subtract(b=3, a=10)   # 7
subtract(a=10, b=3)   # 7
```

You can mix positional and keyword, but positional must come first:

```python
subtract(10, b=3)     # OK
subtract(a=10, 3)     # SyntaxError — positional after keyword
```

### Default values

Parameters can have defaults (see [[3. Default and Keyword Arguments]]):

```python
def greet(name="World"):
    print(f"Hello, {name}")

greet()         # Hello, World
greet("Alice")  # Hello, Alice
```

### Variadic arguments

`*args` collects extra positional arguments into a tuple; `**kwargs` collects extra keyword arguments into a dict. See [[4. args and kwargs]].

```python
def f(*args, **kwargs):
    print(args, kwargs)

f(1, 2, 3, x=10, y=20)   # (1, 2, 3) {'x': 10, 'y': 20}
```

## Python's Passing Semantics: Pass by Object Reference

Python is **not** pass-by-value (which would copy the value into the parameter). Python is **not** pass-by-reference (which would let you rebind the caller's variable). Python is **pass by object reference** — sometimes called "pass by assignment" or "pass by sharing."

The model:

1. The caller has a name bound to an object.
2. The function is called with that object as an argument.
3. The function's parameter is bound to **the same object**.
4. Mutations to the object inside the function are visible to the caller.
5. Rebinding the parameter inside the function does **not** affect the caller.

```python
def mutate(xs):
    xs.append(99)         # mutation — visible to caller

def rebind(xs):
    xs = [1, 2, 3]        # rebind — not visible to caller

my_list = [1, 2]
mutate(my_list)
print(my_list)            # [1, 2, 99]

my_list = [1, 2]
rebind(my_list)
print(my_list)            # [1, 2] — unchanged
```

```mermaid
flowchart LR
    C["Caller<br/>my_list → [#1,#2]"] -->|pass to function| P["Function<br/>xs → [#1,#2]<br/>(same object)"]
    P -->|xs.append\(99\)| M["Object now [#1,#2,#99]<br/>caller sees mutation"]
    P -->|xs = [#1,#2,#3\]| R["Function's xs rebinds<br/>caller's my_list unchanged"]
```

### Why "pass by assignment"?

You can think of `def f(x): ...; f(arg)` as equivalent to `x = arg` inside the function. The parameter `x` is just a name in the function's local namespace, bound to whatever object was passed. Mutating the object shows up in the caller; rebinding `x` does not.

### Comparing to other languages

| Language | Model |
|----------|-------|
| C | Pass by value (pointers simulate pass-by-reference) |
| C++ | Pass by value, reference (`&`), or pointer — explicit |
| Java | Pass by value (object references are passed by value) |
| Python | Pass by object reference (a.k.a. pass by sharing) |
| Ruby | Pass by object reference (similar to Python) |

## Mutable Default Argument Pitfall

This is the most famous Python gotcha. Default values are evaluated **once** when the function is defined, not each time the function is called. If the default is a mutable object (list, dict, set), all calls that use the default share the same object.

```python
def add_item(item, items=[]):     #  BAD
    items.append(item)
    return items

print(add_item(1))    # [1]
print(add_item(2))    # [1, 2]  — surprise!
print(add_item(3))    # [1, 2, 3]
```

The `items=[]` is evaluated once at function definition. Each call without an explicit `items` argument uses the same list, which keeps growing.

### The fix: use `None` as a sentinel

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(add_item(1))    # [1]
print(add_item(2))    # [2]   — fresh list each time
```

This is the **canonical Python idiom** for mutable defaults. Use `None` as a placeholder, then create the real default inside the function.

### Why does Python do this?

Two reasons:

1. **Performance.** Evaluating the default once is faster than re-evaluating on every call.
2. **Closure semantics.** Defaults are stored on the function object (`f.__defaults__`), making them inspectable and consistent.

The downside is the mutable-default trap, which Python designers considered an acceptable cost.

### Detecting the pitfall

You can see the shared default on the function object:

```python
def f(x=[]):
    x.append(1)
    return x

print(f.__defaults__)   # ([],) — initially
f()
print(f.__defaults__)   # ([1],) — mutated!
f()
print(f.__defaults__)   # ([1, 1],)
```

### Other variants of the bug

```python
def f(x={}):           # dict default
    x["count"] = x.get("count", 0) + 1
    return x

def f(x=set()):        # set default
    x.add(1)
    return x
```

All have the same root cause: mutable default, evaluated once.

## Annotated Code Examples

### Example 1: Positional vs keyword

```python
def create_user(name, email, role="user", active=True):
    return {"name": name, "email": email, "role": role, "active": active}

create_user("Alice", "alice@example.com")
create_user("Bob", "bob@example.com", role="admin")
create_user("Carol", "carol@example.com", active=False)
create_user(email="dave@example.com", name="Dave")  # keyword order can differ
```

### Example 2: Pass by object reference

```python
def append_one(xs):
    xs.append(1)

def replace(xs):
    xs = [1, 2, 3]    # rebind — caller's list unchanged

data = [0]
append_one(data)
print(data)    # [0, 1]

data = [0]
replace(data)
print(data)    # [0]
```

### Example 3: Mutable default fixed

```python
def add_tag(note, tags=None):
    if tags is None:
        tags = []
    tags.append(note)
    return tags

print(add_tag("python"))   # ['python']
print(add_tag("java"))     # ['java']
```

### Example 4: Immutable arguments can't be mutated

```python
def increment(n):
    n = n + 1     # rebind — caller's n unchanged

x = 5
increment(x)
print(x)    # 5
```

To return a new value, use `return`:

```python
def increment(n):
    return n + 1

x = 5
x = increment(x)
print(x)    # 6
```

### Example 5: Mutating a dict argument

```python
def add_default(config):
    config.setdefault("timeout", 30)

settings = {"host": "localhost"}
add_default(settings)
print(settings)    # {'host': 'localhost', 'timeout': 30}
```

### Example 6: Avoiding unintended mutation

```python
def process_items(items):
    # Make a copy so we don't mutate caller's list
    items = list(items)
    items.sort()
    return [transform(x) for x in items]

caller_list = [3, 1, 2]
result = process_items(caller_list)
print(caller_list)   # [3, 1, 2] — unchanged
print(result)        # [transformed(1), transformed(2), transformed(3)]
```

### Example 7: Function with default that references other parameters

```python
def f(a, b=a_default):    #  NameError — `a_default` not defined
    ...
```

Defaults are evaluated at definition time, in the defining scope. They cannot reference other parameters.

```python
def f(a, b=None):
    if b is None:
        b = a * 2         # compute default from another parameter
    ...
```

## Argument Binding and `inspect.signature`

Python's `inspect` module lets you see how arguments bind to parameters at runtime:

```python
import inspect

def f(a, b, c=3, *args, d=4, **kwargs): ...

sig = inspect.signature(f)
bound = sig.bind(1, 2, 4, 5, 6, d=10, x=99, y=100)
bound.apply_defaults()
print(bound.arguments)
# OrderedDict([('a', 1), ('b', 2), ('c', 4), ('args', (5, 6)),
#              ('d', 10), ('kwargs', {'x': 99, 'y': 100})])
```

This is how `functools.partial`, `inspect`, and frameworks like FastAPI introspect your functions. If you're writing a dispatcher, CLI builder, or framework, `Signature.bind` is your friend.

## Argument Passing — A Deeper Look

When you call `f(arg)`, Python does the following:

1. Evaluates `arg` to get an object reference.
2. Looks up the parameter `x` in `f`'s signature.
3. Binds `x` to the object (puts `x` → object in the function's local namespace).
4. Executes the function body.
5. The function's local namespace is discarded on return.

The object itself is never copied (unless you explicitly call `copy.copy` or `copy.deepcopy`). The function has a name (`x`) that points to the same object as the caller's name.

```python
def f(x):
    print(f"inside f, id(x) = {id(x)}")

a = [1, 2, 3]
print(f"in caller, id(a) = {id(a)}")
f(a)
# in caller, id(a) = 1407...
# inside f, id(x) = 1407...   ← same id, same object
```

This is why "pass by object reference" is the precise description: the object's identity is preserved, and both caller and callee see the same memory.

## Why Some Languages Differ

- **C** is pass-by-value: `void f(int x) { x = 5; }` doesn't change the caller's variable. Pointers simulate pass-by-reference: `void f(int *x) { *x = 5; }` does change it.
- **C++** has explicit `void f(int &x)` for true pass-by-reference.
- **Java** is pass-by-value, but object references are values — so mutating the object the reference points to is visible to the caller, but reassigning the reference is not. Same as Python.
- **Python** is pass-by-object-reference: similar to Java's reference semantics, but with mutable default types and no explicit pointer syntax.

Understanding this helps you port code between languages without surprises.

## Common Pitfalls

### 1. Mutable default arguments

Covered above. Use `None` sentinel.

### 2. Order of arguments

```python
def f(a, b, c=3, d=4): ...
f(1, 2)              # OK — a=1, b=2, c=3, d=4
f(1, 2, 5)           # OK — c=5
f(1, 2, d=8)         # OK — c=3, d=8
f(1, c=5)            # OK — b missing? NO — TypeError: missing 'b'
```

Non-default parameters must come before default parameters in the signature.

### 3. Using `=` for default values inside the call

```python
def f(a, b): ...
f(a=1, b=2)    # keyword args
f(1, 2)        # positional
```

Don't confuse default values in the definition (`def f(a=1):`) with keyword arguments in the call (`f(a=1)`).

### 4. Modifying arguments you don't own

If a function receives a list and mutates it, the caller's list changes. This can be surprising. If you don't intend to mutate, either copy the input or document the behaviour clearly.

### 5. Rebinding a parameter that the caller expected to be mutated

```python
def reset(items):
    items = []      # caller's list is NOT reset

xs = [1, 2, 3]
reset(xs)
print(xs)           # [1, 2, 3]
```

To actually clear the caller's list, mutate in place:

```python
def reset(items):
    items.clear()   # caller's list is now []

xs = [1, 2, 3]
reset(xs)
print(xs)           # []
```

### 6. Forgetting `self`/`cls`

```python
class C:
    def method(x):    #  should be (self, x) or (cls, x) for classmethod
        ...
```

When called as `c.method(1)`, Python passes `c` as the first argument; `x` gets `1`. The first parameter should be `self` (instance methods) or `cls` (class methods).

### 7. Calling with too many/few arguments

```python
def f(a, b): ...
f(1)              # TypeError: missing 'b'
f(1, 2, 3)        # TypeError: too many positional
f(1, b=2, c=3)    # TypeError: unexpected keyword 'c'
```

### 8. Default values evaluated once (mutable default)

Covered above.

### 9. Late-bound defaults

Some languages evaluate defaults at call time (so `def f(a, b=a)` works). Python doesn't:

```python
def f(a, b=a):    # NameError — `a` not defined at function definition time
    ...
```

Use `None` and compute inside the body.

### 10. Argument unpacking mistakes

```python
def f(a, b, c): ...
args = (1, 2, 3)
f(args)         # TypeError — passes a tuple as one argument
f(*args)        # OK — unpacks the tuple into three arguments
```

## Tips and Tricks

- **Use `None` sentinel for mutable defaults** — every time, no exceptions.
- **Document mutation behaviour** in the docstring: "Returns a new list" vs. "Modifies the input list in place."
- **Copy inputs when you don't want to mutate**: `items = list(items)` at the top of a function.
- **Use `*` to force keyword arguments** — covered in [[3. Default and Keyword Arguments]].
- **Use `*args`/`**kwargs` to forward to another function** — preserves signature.
- **`functools.partial`** to fix some arguments: `double = partial(mul, 2)`.
- **`inspect.signature(f)`** to introspect a function's parameters at runtime.
- **Type hints** make parameter contracts explicit — see [[9. Type Hinting for Functions]].
- **Keyword-only args** improve readability for functions with many parameters.
- **Don't mutate arguments you don't own** unless the function name signals it (`sort`, `reverse`, `append`).
