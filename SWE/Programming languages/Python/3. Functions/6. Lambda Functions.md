# 6. Lambda Functions

## Why This Matters

Lambdas — Python's anonymous, single-expression functions — are simultaneously loved and abused. They enable concise callbacks for `sorted`, `map`, `filter`, `functools.reduce`, GUI event handlers, and key functions throughout the standard library. But they are limited to a single expression (no statements), they cannot have docstrings (well, sort of — see below), and over-using them produces unreadable code. Knowing when a lambda is the right tool and when a `def` is clearer is a hallmark of mature Python style.

This note covers lambda syntax, the single-expression limitation, idiomatic use cases (`map`, `filter`, `sorted`, `key` functions), the late-binding closure pitfall, and the line where lambdas become a liability.

---

## Background

The `lambda` keyword creates a function object inline. The syntax:

```python
lambda parameters: expression
```

This is equivalent to:

```python
def name(parameters):
    return expression
```

except the lambda has no name (`__name__` is `"<lambda>"`) and the body must be a single **expression**, not a sequence of statements.

```python
square = lambda x: x * x
print(square(5))   # 25

# Equivalent to:
def square(x):
    return x * x
```

The name "lambda" comes from the lambda calculus — Alonzo Church's formal system of computation based on function abstraction and application. Lisp popularised the keyword; Python borrowed it.

---

## Syntax and Semantics

### Basic forms

```python
lambda: 42                 # no parameters, returns 42
lambda x: x * 2            # one parameter
lambda x, y: x + y         # two parameters
lambda x, y=10: x + y      # default value
lambda *args: sum(args)    # variadic
lambda **kwargs: kwargs    # keyword variadic
lambda x, *, y: x + y      # keyword-only
```

Lambdas support the same parameter syntax as `def` — defaults, `*args`, `**kwargs`, keyword-only, positional-only.

### Single expression only

A lambda body must be a single expression. **No statements**: no `=`, no `if`/`for`/`while`/`try` blocks, no `return`.

```python
lambda x: x + 1            # OK — single expression
lambda x: print(x)         # OK — print is an expression (returns None)
lambda x: x = 1            # SyntaxError — assignment is a statement
lambda x: if x > 0: ...    # SyntaxError — if statement not allowed
```

The conditional **expression** (ternary) is allowed because it's an expression:

```python
classify = lambda x: "positive" if x > 0 else ("zero" if x == 0 else "negative")
classify(5)    # 'positive'
classify(-3)   # 'negative'
classify(0)    # 'zero'
```

Walrus `:=` is allowed in expressions, so technically:

```python
f = lambda x: (y := x * 2, y + 1)[1]
f(5)   # 11 — sets y=10, returns y+1
```

But this is unreadable. Use `def`.

### Lambdas are first-class objects

```python
f = lambda x: x * 2
print(type(f))         # <class 'function'>
print(f.__name__)      # '<lambda>'
print(f(3))            # 6

# Pass as argument
sorted([3, 1, 2], key=lambda x: -x)

# Store in collection
ops = [lambda x: x + 1, lambda x: x * 2, lambda x: x ** 2]

# Return from function
def multiplier(factor):
    return lambda x: x * factor
```

## Use Case: `sorted`, `min`, `max` with `key`

The most common use of lambdas is the `key` argument:

```python
users = [{"name": "Alice", "age": 30}, {"name": "Bob", "age": 25}]

# Sort by age
sorted(users, key=lambda u: u["age"])
# [{'name': 'Bob', 'age': 25}, {'name': 'Alice', 'age': 30}]

# Sort by name length
sorted(users, key=lambda u: len(u["name"]))

# Sort by age descending
sorted(users, key=lambda u: -u["age"])

# Multi-key sort
sorted(users, key=lambda u: (u["age"], u["name"]))
```

For complex keys, extract a function:

```python
def user_sort_key(u):
    return (u["age"], u["name"])

sorted(users, key=user_sort_key)
```

`operator.itemgetter` and `operator.attrgetter` are also excellent:

```python
from operator import itemgetter, attrgetter

sorted(users, key=itemgetter("age"))
sorted(users, key=itemgetter("age", "name"))

class User:
    def __init__(self, name, age): self.name, self.age = name, age

users = [User("Alice", 30), User("Bob", 25)]
sorted(users, key=attrgetter("age"))
```

`itemgetter` and `attrgetter` are faster than lambdas (C-implemented) and clearer.

## Use Case: `map`, `filter`, `reduce`

```python
nums = [1, 2, 3, 4, 5]

# map: apply function to each
doubled = list(map(lambda x: x * 2, nums))
# [2, 4, 6, 8, 10]

# filter: keep elements where function returns truthy
evens = list(filter(lambda x: x % 2 == 0, nums))
# [2, 4]

# reduce: cumulatively apply function
from functools import reduce
product = reduce(lambda a, b: a * b, nums)
# 120  (= 1*2*3*4*5)
```

### Pythonic alternatives

Python's list comprehensions and generator expressions often replace `map`/`filter`:

```python
# map
doubled = [x * 2 for x in nums]

# filter
evens = [x for x in nums if x % 2 == 0]

# Both
even_doubled = [x * 2 for x in nums if x % 2 == 0]
```

Most Pythonistas prefer comprehensions for clarity. But `map` and `filter` can be slightly faster for built-in functions:

```python
# Faster than [str(x) for x in nums]
list(map(str, nums))
```

`reduce` is less common; explicit loops are usually clearer.

## Use Case: Event Handlers and Callbacks

Lambdas are handy for short callbacks in GUI/web/async code:

```python
import tkinter as tk

root = tk.Tk()
for i, label in enumerate(["A", "B", "C"]):
    btn = tk.Button(root, text=label, command=lambda i=i: print(f"clicked {i}"))
    btn.pack()
root.mainloop()
```

In async code:

```python
import asyncio

async def main():
    await asyncio.gather(
        *(lambda i: asyncio.sleep(i, result=i))(i) for i in range(3)
    )
```

Or more cleanly:

```python
async def main():
    await asyncio.gather(*[asyncio.sleep(i, result=i) for i in range(3)])
```

In tests, lambdas make quick stubs:

```python
mock_client = MagicMock()
mock_client.fetch.side_effect = lambda url: {"data": url}
```

## Late Binding Pitfall (Revisited)

```python
funcs = [lambda: i for i in range(3)]
for f in funcs: print(f())   # 2 2 2 — same i
```

Fix:

```python
funcs = [lambda i=i: i for i in range(3)]
for f in funcs: print(f())   # 0 1 2
```

The default argument `i=i` captures the value at lambda-creation time. See [[5. Scope and Closures]] for the full story.

## When to Use Lambdas vs `def`

### Use a lambda when:

- The function is short (one line, one expression).
- It's used in exactly one place (passed inline to `sorted`, `map`, etc.).
- It doesn't need a docstring or name.
- It doesn't need to be tested in isolation.

### Use `def` when:

- The function is more than one expression.
- The function needs statements (`try`, `for`, `while`, assignment).
- The function is called from multiple places (give it a name).
- The function needs a docstring.
- The function is recursive (lambdas can't refer to themselves by name easily).
- The function raises exceptions and you want a traceback with a real name.
- You're decorating the function (lambdas can be decorated but it's ugly).

> [!tip] Rule of thumb
> If your lambda doesn't fit on one line of readable code, write a `def`. If you can't describe what it does in a short comment, write a `def`.

## Annotated Code Examples

### Example 1: Simple

```python
square = lambda x: x * x
print(square(5))   # 25
```

### Example 2: Sort by key

```python
words = ["banana", "apple", "cherry", "date"]
sorted(words, key=lambda w: len(w))
# ['date', 'apple', 'banana', 'cherry']
```

### Example 3: `itemgetter` is better

```python
from operator import itemgetter

rows = [{"id": 3}, {"id": 1}, {"id": 2}]
sorted(rows, key=itemgetter("id"))
# [{'id': 1}, {'id': 2}, {'id': 3}]
```

### Example 4: Multi-key

```python
people = [("Alice", 30), ("Bob", 25), ("Alice", 25)]
sorted(people, key=lambda p: (p[0], p[1]))
# [('Alice', 25), ('Alice', 30), ('Bob', 25)]
```

### Example 5: Callback with captured state

```python
import tkinter as tk
root = tk.Tk()
for i in range(3):
    tk.Button(root, text=str(i), command=lambda i=i: print(i)).pack()
```

### Example 6: Filter then map (use comprehension instead)

```python
nums = list(range(10))

# With map/filter
result = list(map(lambda x: x * x, filter(lambda x: x % 2 == 0, nums)))
# [0, 4, 16, 36, 64]

# With comprehension — clearer
result = [x * x for x in nums if x % 2 == 0]
```

### Example 7: Reduce

```python
from functools import reduce
product = reduce(lambda a, b: a * b, [1, 2, 3, 4, 5], 1)
# 120
```

### Example 8: Conditional expression in lambda

```python
classify = lambda x: "even" if x % 2 == 0 else "odd"
print(classify(4), classify(5))   # even odd
```

### Example 9: Lambda as a default argument value

```python
def process(data, transform=lambda x: x):
    return [transform(x) for x in data]

print(process([1, 2, 3]))                  # [1, 2, 3]
print(process([1, 2, 3], lambda x: x*2))   # [2, 4, 6]
```

> [!warning] Mutable default... but lambdas are immutable
> A lambda as a default value is fine — lambdas are immutable function objects. The mutable-default pitfall applies to lists/dicts/sets, not to lambdas.

### Example 10: Immediately Invoked Lambda (IIFE)

```python
result = (lambda x: x * 2)(5)
print(result)   # 10
```

IIFEs are occasionally useful for one-off computations but are usually clearer as a regular expression or a `def`.

## Lambdas and Default Argument Trick

Lambdas can have default arguments, which is useful for capturing loop variables (the late-binding fix):

```python
# Without default — late binding bug
funcs = [lambda: i for i in range(3)]
[f() for f in funcs]   # [2, 2, 2]

# With default — captures value at lambda-creation time
funcs = [lambda i=i: i for i in range(3)]
[f() for f in funcs]   # [0, 1, 2]
```

This is the most common "advanced" use of lambdas: as inline closures that need to capture a loop variable.

## Lambdas with `*args` and `**kwargs`

Lambdas support the full parameter syntax:

```python
sum_all = lambda *args: sum(args)
configure = lambda **kwargs: kwargs

sum_all(1, 2, 3)            # 6
configure(host="localhost", port=8080)  # {'host': 'localhost', 'port': 8080}
```

This is handy for one-off callbacks that need flexibility:

```python
sorted(items, key=lambda *args: args[0])   # silly but valid
```

## Lambdas and Sorting

The `key` parameter to `sorted`, `min`, `max` is the most common lambda use case:

```python
# Sort by absolute value
sorted([-3, 1, -2, 5, -4], key=lambda x: abs(x))
# [1, -2, -3, -4, 5]

# Sort by string length, then alphabetically
sorted(words, key=lambda w: (len(w), w))

# Sort dict by value
sorted(d.items(), key=lambda kv: kv[1])

# Sort list of dicts by multiple keys
sorted(users, key=lambda u: (-u["age"], u["name"]))   # age desc, name asc
```

For simple attribute access, prefer `operator.attrgetter` and `operator.itemgetter`:

```python
from operator import itemgetter, attrgetter

sorted(users, key=itemgetter("age"))
sorted(products, key=attrgetter("price"))
```

These are C-implemented and faster than lambdas, and they're self-documenting.

## Lambda Performance

Lambdas have a small creation overhead (a function object is built). For tight loops, prefer:

```python
# Slower — creates a new lambda each iteration
for x in data:
    result = (lambda y: y * 2)(x)

# Faster — direct expression
for x in data:
    result = x * 2

# Fastest — vectorised with NumPy
result = data * 2   # if data is a numpy array
```

Lambdas shine when passed once to a higher-order function (`sorted`, `map`, `filter`), not in tight numerical loops.

## Common Pitfalls

### 1. Using a lambda where a `def` would be clearer

```python
# Bad
process_data = lambda data: [transform(x) for x in data if validate(x) and not excluded(x)]

# Good
def process_data(data):
    return [transform(x) for x in data if validate(x) and not excluded(x)]
```

### 2. Late binding in lambdas in loops

Covered above.

### 3. Lambda with statements

```python
f = lambda x: x = 1    # SyntaxError
```

### 4. Trying to assign within a lambda

```python
f = lambda x: (x := x + 1)   # works but useless
```

Walrus makes it legal but not clear.

### 5. No docstrings

```python
f = lambda x: x + 1
f.__doc__ = "Add one"   # you can assign, but linters won't see it
```

`def` is the way to document.

### 6. Confusing `lambda x: x` with `lambda: x`

```python
lambda x: x       # one parameter, returns it
lambda: x         # no parameter, returns the global/enclosing x
```

### 7. Lambda in a list comprehension

```python
# Bad — nested lambdas
funcs = [lambda x: x + i for i in range(3)]
# All capture same i

# Better
funcs = [lambda x, i=i: x + i for i in range(3)]
```

### 8. Overusing `map`/`filter` with lambdas

```python
# Less Pythonic
list(map(lambda x: x.upper(), words))

# More Pythonic
[w.upper() for w in words]
```

### 9. Lambda with too many parameters

```python
# Hard to read
f = lambda a, b, c, d, e: a + b + c + d + e

# Use a def
def f(a, b, c, d, e):
    return a + b + c + d + e
```

### 10. Using lambdas for class methods

```python
# Bad
class C:
    method = lambda self, x: x * 2

# Good
class C:
    def method(self, x):
        return x * 2
```

Lambdas assigned as class attributes work but are unconventional and harder to test.

### 11. Decorator on lambda

```python
@decorator
f = lambda x: x   # SyntaxError — can't decorate an assignment
```

Lambdas can be decorated with `f = decorator(lambda x: x)`, but it's ugly.

## Tips and Tricks

- **Prefer `def` for anything non-trivial.**
- **Use lambdas for short `key` callbacks** in `sorted`, `min`, `max`, `itertools.groupby`.
- **`operator.itemgetter`/`attrgetter`** are faster and clearer than lambdas for attribute/item access.
- **`operator.methodcaller`** for calling a method by name: `sorted(items, key=methodcaller("lower"))`.
- **List comprehensions usually beat `map`/`filter` + lambda** for clarity.
- **`functools.partial`** is often cleaner than a lambda for partial application: `partial(add, 1)` instead of `lambda x: add(1, x)`.
- **Avoid lambdas in loops** unless you handle late binding.
- **Don't assign lambdas to variables** — use `def`. (`f = lambda x: x*2` should be `def f(x): return x*2`.)
- **PEP 8 says**: "Always use a def statement instead of an assignment statement that binds a lambda expression directly to an identifier."
- **Use lambdas freely in tests** — short stubs are perfect.
