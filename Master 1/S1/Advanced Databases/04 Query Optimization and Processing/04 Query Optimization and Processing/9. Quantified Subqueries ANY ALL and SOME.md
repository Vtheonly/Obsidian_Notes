# Quantified Subqueries: `ANY`, `SOME`, and `ALL`

Quantified comparison operators extend ordinary predicates by comparing one value with a set returned by a subquery. They are useful when the condition depends on whether a comparison is true for **at least one** or **every** value in a relation.

## 1. `ANY` and `SOME`

`ANY` and `SOME` are synonyms in SQL. The comparison is true when it succeeds for **at least one** value returned by the subquery.

```sql
SELECT name
FROM Employee
WHERE salary > ANY (
    SELECT salary
    FROM Employee
    WHERE department = 'HR'
);
```

This means: find employees whose salary is greater than the salary of **at least one** HR employee.

For a non-empty set, `x > ANY(S)` behaves like comparing `x` against the smallest relevant value for the `>` operator. The exact treatment of `NULL` follows SQL three-valued logic.

## 2. `ALL`

`ALL` requires the comparison to be true for **every** value returned by the subquery.

```sql
SELECT name
FROM Employee
WHERE salary > ALL (
    SELECT salary
    FROM Employee
    WHERE department = 'HR'
);
```

This finds employees whose salary is greater than **every** HR salary.

For a non-empty set, `x > ALL(S)` is equivalent to saying that `x` is greater than the maximum relevant value. Again, `NULL` values can produce `UNKNOWN` according to SQL's three-valued logic.

## 3. `IN` as a Special Equality Case

For equality, `x IN (subquery)` is conceptually similar to:

```sql
x = ANY (subquery)
```

This is useful when explaining why `ANY` is a generalized quantified comparison rather than merely another form of `IN`.

## 4. `NOT EXISTS` Double-Negation Pattern

Universal queries can also be expressed without `ALL` by using double negation:

> Find an entity for which there does not exist a required related item that it does not possess.

Example: find cars supplied to **all** London dealers.

```sql
SELECT V.NV
FROM VOITURE V
WHERE NOT EXISTS (
    SELECT R.NR
    FROM REVEND R
    WHERE R.VilleR = 'LONDRES'
      AND NOT EXISTS (
          SELECT 1
          FROM FVR F
          WHERE F.NR = R.NR
            AND F.NV = V.NV
      )
);
```

The inner `NOT EXISTS` detects a dealer for which the car is missing. The outer `NOT EXISTS` rejects the car if any such dealer exists.

## 5. Semi-Join and Anti-Join Interpretation

From a relational-algebra perspective:

* `EXISTS` corresponds naturally to a **semi-join**: return rows from the left relation for which a matching row exists on the right.
* `NOT EXISTS` corresponds naturally to an **anti-join**: return rows from the left relation for which no matching row exists on the right.

These forms are often useful to the optimizer because they do not require returning all columns of the matching relation.

## 6. `NULL` and Empty-Set Edge Cases

Quantified predicates are affected by SQL's three-valued logic. A comparison with `NULL` may evaluate to `UNKNOWN`, and the combination of `ANY`/`ALL` with an empty subquery has defined logical behavior that should not be confused with ordinary equality. For exam work, always identify whether the subquery can return `NULL` and whether it can return zero rows before simplifying a quantified predicate.
