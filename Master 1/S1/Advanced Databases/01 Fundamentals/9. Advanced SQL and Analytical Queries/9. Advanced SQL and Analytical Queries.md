# 9. Advanced SQL and Analytical Queries

This note is the entry point for advanced declarative SQL topics that complement the core relational-algebra material.

## Views, Security, and Data Control

Views can be used to expose only the rows or columns appropriate for a user or application. They can therefore act as a logical security boundary when privileges are granted on the view rather than directly on the base table.

### Example: Restricted Service View

```sql
CREATE VIEW V_Service_A003 AS
SELECT EMP_Num, EMP_Nom, EMP_Titre, SRV_Num
FROM EMPLOYE
WHERE SRV_Num = 'A003'
WITH CHECK OPTION;
```

`WITH CHECK OPTION` prevents modifications made through an updatable view from producing rows that no longer satisfy the view predicate.

## Data Control Language (DCL)

DCL commands define and remove privileges.

### `GRANT`

```sql
GRANT SELECT, UPDATE
ON V_Service_A003
TO Manager, Director
WITH GRANT OPTION;
```

`WITH GRANT OPTION` allows the recipient to delegate the granted privilege to other users, subject to the DBMS's privilege model.

### `REVOKE`

```sql
REVOKE ALL PRIVILEGES
ON V_Service_A003
FROM Manager, Director;
```

Revocation can affect privileges that were delegated by the revoked user according to the DBMS's privilege-dependency and cascade rules. Always verify the target engine's exact behavior.

## Declarative Business Constraints

For rules that concern only the row being written, prefer declarative constraints such as `PRIMARY KEY`, `UNIQUE`, `NOT NULL`, and `CHECK`. Cross-table or state-dependent rules require broader mechanisms such as foreign keys, assertions where supported, triggers, or transactional procedural validation.
