# 16.1. Resilient Atomic Checkpointing and State Verification

Every checkpoint must capture enough information to reproduce and safely resume the exact training state.

## Required fields

- stage and epoch;
- global optimizer step;
- model state;
- optimizer state;
- scheduler state;
- RNG states for Python, NumPy, PyTorch and CUDA;
- complete experiment configuration;
- dataset manifest hash;
- catalog/index signature;
- source code commit;
- evaluator configuration when relevant.

## Atomic persistence

Write to a temporary path, flush/fsync when supported, then atomically replace the final checkpoint path.

## Verification

A checkpoint is marked verified only after:

1. serialization succeeds;
2. file hash is recorded;
3. required keys exist;
4. tensors can be loaded onto CPU;
5. a dry-run restores the checkpoint successfully.

Only verified checkpoints may become automatic resume candidates.
