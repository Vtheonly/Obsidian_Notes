# 2.2. Computation and Memory Complexity Profiles

| Module | Dominant cost |
|---|---|
| Ensemble backbone | O(K E d) |
| HENF | O(Nq Np d) before locality pruning |
| CPDF | O(Nq Np d) before spatial sparsification |
| Spatial attention | O(H Np d_k) per planning query |
| Catalog retrieval | sublinear approximate-nearest-neighbor traversal |
| Top-128 re-ranking | O(128 d) to first order |
| Torus flow | O(S[C_v+C_J+C_rep]) |

The revised architecture deliberately removes dense 75k-way logits and routine CPU minimization from the rollout path.

## Optimization order

1. locality / sparse neighborhood construction;
2. fused radial and attention operations;
3. precomputed catalog descriptors;
4. approximate-nearest-neighbor retrieval;
5. only then compiler/kernel tuning.

Latency goals such as <6 ms per flow step are empirical benchmark targets, not properties guaranteed by the equations.
