# 13.1. Roofline Intensity and Compute versus Memory Bounds

The Roofline model is used to reason about implementation bottlenecks, not to prescribe a specific neural head.

\[
I=\frac{\text{FLOPs}}{\text{bytes transferred}},
\qquad
I^*=\frac{P_{\mathrm{peak}}}{B_{\mathrm{peak}}}.
\]

For an RTX 6000 Ada-class configuration, the exact peak values depend on the precision and clock assumptions used in the benchmark.

## SynPath-3D workload classes

**Likely memory-sensitive**

- sparse radius-graph gathering;
- coordinate and distance operations;
- LayerNorm and elementwise activations;
- ANN index traversal.

**Likely compute-intensive**

- dense attention / MLP projections;
- equivariant tensor products;
- local candidate re-ranking.

The old 75,000-way tied-dot-product head is no longer a workload in the canonical architecture.

All roofline claims must be accompanied by measured kernel time, achieved bandwidth or FLOP throughput, and the exact batch/configuration.
