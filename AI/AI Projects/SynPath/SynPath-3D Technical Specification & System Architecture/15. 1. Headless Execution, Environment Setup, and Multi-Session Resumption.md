# 15.1. Headless Execution, Environment Setup, and Multi-Session Resumption

The notebook or launcher is an execution wrapper. Model, data and training logic remain in version-controlled code.

## Startup

1. verify Python/PyTorch/CUDA compatibility;
2. verify GPU availability and BF16 support;
3. verify dataset and catalog manifests;
4. verify experiment configuration;
5. load the last verified checkpoint when resuming.

## Reference command

~~~bash
python main.py --mode train --config configs/stage1_canonical_production.json --resume-auto
~~~

Stage 0 and Stage 2 must use their own explicit configuration or stage selector. Do not reuse a Stage-1 filename to launch another stage.

## Session expiry

Checkpoint cadence is platform-dependent. The launcher must detect the available runtime budget and save a verified checkpoint before termination rather than assuming one universal session limit.

## Reproducibility

A resumed run must restore model state, optimizer state, scheduler state and RNG states, and record the originating code commit and dataset manifest.
