### 1. Concrete Sizing for SynPath-3D
Let SynPath-3D have $P = 32\text{ million parameters}$ ($3.2 \times 10^7$), trained with native `bfloat16` and the AdamW optimizer:

```text
Static Memory Footprint (Constant, Batch-Independent):
1. Model Weights (BF16):       3.2 x 10^7 x 2 bytes  =   64 MB
2. Gradients (BF16):           3.2 x 10^7 x 2 bytes  =   64 MB
3. AdamW Optimizer States:
   - FP32 Master Weights:      3.2 x 10^7 x 4 bytes  =  128 MB
   - FP32 First Moment (m_t):  3.2 x 10^7 x 4 bytes  =  128 MB
   - FP32 Second Moment (v_t): 3.2 x 10^7 x 4 bytes  =  128 MB
4. Synthon Catalog Table:      75,000 x 256 x 2 bytes=   38.4 MB
   Static Baseline Total:                           ≈ 0.55 GB
```

### 2. Dynamic Activation Footprint for Batch Size $B=64$
Let total pocket atoms per batch be $N_{\text{total}} \approx 64 \times 150 = 9,600$ atoms. Let total radius edges be $E_{\text{total}} \approx 307,200$:
* 6-Layer Equiformer Backbone Activations: $\approx 12.5\text{ GB}$.
* Cross-Attention Core Activations: $\approx 4.2\text{ GB}$.
* TIF Anchor and Flow Head Activations: $\approx 3.8\text{ GB}$.
* Workspace Allocations & CuDNN Buffers: $\approx 6.0\text{ GB}$.
$$\text{Total Dynamic Activations at Peak} \approx \mathbf{26.5\text{ GB}}$$

Because total consumption ($\approx 42\text{ GB}$) is well below the $96\text{ GB}$ hardware limit, the training run has significant memory headroom, avoiding out-of-memory errors on large pockets.
