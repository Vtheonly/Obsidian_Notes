# 07.1. Taxonomy, Hierarchy, and DAGs in Medicine

The original vault presented medical ontologies as simple trees: *"Level 1 → Level 2 → Level 3 → Level 4 → Nystagmus."* This is dangerously wrong. **Medical ontologies are not trees; they are Directed Acyclic Graphs (DAGs)**, in which a node can have multiple parents. *Nystagmus* is simultaneously an "Abnormality of Eye Movement" and an "Abnormality of the Nervous System" — a tree representation cannot capture this. The original vault's tree model also omitted **transitive closures** (the pre-computation of all ancestor-descendant relationships that makes path lookup fast) and the algorithms for traversing DAGs without infinite loops.

This note covers: (1) taxonomy vs. ontology, (2) the "Is-A" relationship and inheritance, (3) why ontologies are DAGs not trees, (4) multiple inheritance, (5) transitive closures and their computation, (6) cycle detection, and (7) the project's graph-traversal algorithms.

---

## 1. Taxonomy vs. Ontology

A **taxonomy** is a simple classification — a tree of categories. The Linnaean taxonomy of living things (Kingdom → Phylum → Class → Order → Family → Genus → Species) is the canonical example. Each node has exactly one parent.

An **ontology** is richer: it defines not just the entities but also the **relationships** between them, and it allows an entity to have multiple parents. The Human Phenotype Ontology (HPO) defines:

- **Entities**: phenotypic abnormalities (e.g., *Nystagmus*, *HP:0000639*).
- **"Is-A" relationships**: *Nystagmus* **is-a** *Abnormal Eye Movement* (HP:0000490), which **is-a** *Abnormality of the Eye* (HP:0000478), which **is-a** *Phenotypic Abnormality* (HP:0000118).
- **Other relationships**: *Nystagmus* **has-onset** *Congenital onset*; *Marfan syndrome* **has-cause** *FBN1 mutation*.

The "Is-A" relationship is the backbone of the ontology, but it is not the only one. The full richness requires a graph, not a tree.

---

## 2. The "Is-A" Relationship and Inheritance

The **"Is-A" relationship** encodes **subclass** hierarchy. If *A is-a B*, then:

- Every instance of *A* is also an instance of *B*.
- Every property of *B* is inherited by *A*.

For example, *Nystagmus* is-a *Abnormal Eye Movement*. This means:

- A patient with *Nystagmus* also has an *Abnormal Eye Movement* (the more general phenotype).
- Any disease that causes *Abnormal Eye Movement* is a candidate for a patient with *Nystagmus* (because *Nystagmus* is a subtype).

### 2.1. Why Inheritance Matters for Retrieval

If the patient note mentions *Nystagmus* and the disease database contains a disease annotated with *Abnormal Eye Movement* (but not specifically with *Nystagmus*), a flat-set similarity metric (Jaccard) would miss the match. A hierarchy-aware metric (Resnik, Lin — Chapter 8.3) would recognise that *Nystagmus* is a descendant of *Abnormal Eye Movement* and count the match.

This is the **biological generalisation** that the project's Knowledge Graph exploits. Without hierarchy-aware reasoning, the system would only find diseases annotated with the exact phenotypes the patient has — missing many correct diagnoses annotated at a higher level.

---

## 3. Why Ontologies Are DAGs, Not Trees

The original vault's tree model:

```
Phenotypic Abnormality
  └── Abnormality of the Eye
        └── Abnormal Eye Movement
              └── Nystagmus
```

This is wrong. In HPO, *Nystagmus* has **two parents**:

```
Phenotypic Abnormality
  ├── Abnormality of the Eye
  │     └── Abnormal Eye Movement
  │           └── Nystagmus  ◄── also child of:
  └── Abnormality of the Nervous System
        └── Abnormality of Eye Movement
              └── Nystagmus  ◄── same node, two parents
```

*Nystagmus* is both an eye abnormality and a nervous system abnormality. A tree cannot represent this; a **Directed Acyclic Graph (DAG)** can.

### 3.1. Definition of a DAG

A **Directed Acyclic Graph** is a directed graph with no directed cycles. Every node has zero or more parents (incoming edges) and zero or more children (outgoing edges). The "acyclic" constraint means you cannot follow the directed edges and return to the starting node — there are no "A is-a B is-a C is-a A" loops.

### 3.2. Why Multiple Inheritance Is Common in Medicine

Phenotypes are inherently multi-faceted:

- *Hepatomegaly* (enlarged liver) is both a *Hepatic abnormality* and an *Abdominal mass*.
- *Intellectual disability* is both a *Neurological abnormality* and a *Cognitive abnormality*.
- *Seizure* is both a *Neurological abnormality* and a *Behavioral abnormality*.

Each of these phenotypes belongs to multiple branches of the hierarchy. A tree forces a single branch, losing information; a DAG preserves all branches.

### 3.3. Why the Original Vault's Tree Model Breaks

If the project's Knowledge Graph treated HPO as a tree and tried to traverse upward from *Nystagmus*, it would:

- Find *Abnormal Eye Movement* (one parent).
- Miss *Abnormality of Eye Movement* (the other parent).
- Miss all diseases annotated with nervous-system-level eye-movement abnormalities.

This would produce false negatives in retrieval. The DAG model is not optional — it is the only correct representation.

---

## 4. Multiple Inheritance and Its Algorithmic Consequences

Multiple inheritance introduces three algorithmic challenges that trees do not have:

### 4.1. Path Enumeration

For a given node, the set of **all ancestors** is the union of ancestors across all parent paths. For *Nystagmus*:

- Path 1: Nystagmus → Abnormal Eye Movement → Abnormality of the Eye → Phenotypic Abnormality
- Path 2: Nystagmus → Abnormality of Eye Movement → Abnormality of the Nervous System → Phenotypic Abnormality

The ancestor set is the union: {Abnormal Eye Movement, Abnormality of the Eye, Abnormality of Eye Movement, Abnormality of the Nervous System, Phenotypic Abnormality}. Note that *Phenotypic Abnormality* appears in both paths but is in the set only once.

### 4.2. Common-Ancestor Computation

For two nodes $A$ and $B$, the **Most Informative Common Ancestor (MICA)** is the common ancestor with the highest Information Content (Chapter 8.3). With multiple inheritance, there may be multiple common ancestors at different depths, and the MICA is the deepest (most specific) one.

### 4.3. Cycle Risk in Malformed Ontologies

Real-world ontologies occasionally contain accidental cycles (e.g., due to editing errors where *A is-a B* and *B is-a A* are both added). A tree cannot have cycles by definition, but a DAG can. The traversal algorithm must **detect cycles** to avoid infinite loops.

---

## 5. Transitive Closures

The **transitive closure** of a DAG is the set of all (ancestor, descendant) pairs reachable by following one or more "Is-A" edges. For HPO, this is a pre-computed table that answers the question "is $A$ an ancestor of $B$?" in $O(1)$ time.

### 5.1. Why Transitive Closures Are Necessary

Without a transitive closure, answering "is *Nystagmus* a descendant of *Phenotypic Abnormality*?" requires a graph traversal (BFS or DFS) from *Nystagmus* upward. For a single query, this is $O(|V| + |E|)$ — acceptable. For the project's retrieval, which asks this question millions of times (once per (patient-phenotype, disease-phenotype) pair), the per-query cost must be $O(1)$.

The transitive closure pre-computes all answers:

$$\text{TC}(A, B) = \begin{cases} \text{True} & \text{if } A \text{ is an ancestor of } B \\ \text{False} & \text{otherwise} \end{cases}$$

Lookup is then a hash-table access: $O(1)$.

### 5.2. Computing the Transitive Closure

The standard algorithm (Floyd-Warshall adapted for DAGs) is:

```python
def compute_transitive_closure(graph):
    # graph is a dict: node -> list of parents
    tc = {node: set() for node in graph}
    for node in graph:
        # BFS upward
        queue = list(graph[node])
        while queue:
            parent = queue.pop(0)
            if parent not in tc[node]:
                tc[node].add(parent)
                queue.extend(graph[parent])
    return tc
```

For HPO (~17,000 nodes, ~25,000 edges), this computation takes ~10 seconds and produces a closure with ~200,000 (ancestor, descendant) pairs. The closure is computed once at load time and cached.

### 5.3. Storage

The closure can be stored as:

- A **set of frozen tuples**: $\{(\text{ancestor}, \text{descendant}), \dots\}$. Lookup: $O(1)$ via hash set.
- A **bit matrix**: $|V| \times |V|$ bits, where bit $(i, j) = 1$ iff $i$ is an ancestor of $j$. For HPO, this is $17000^2 / 8$ bytes = ~36 MB. Lookup: $O(1)$ via bit access.

The bit matrix is more memory-efficient for dense closures; the set is more flexible for sparse closures. The project uses the set representation.

## 6. Cycle Detection

Although HPO and MONDO are curated to be acyclic, accidental cycles can appear in edited versions or in custom ontologies. The traversal algorithm must detect cycles to avoid infinite loops.

### 6.1. DFS-Based Cycle Detection

```python
def has_cycle(graph):
    WHITE, GRAY, BLACK = 0, 1, 2
    color = {node: WHITE for node in graph}
    
    def dfs(node):
        color[node] = GRAY
        for parent in graph.get(node, []):
            if color[parent] == GRAY:
                return True  # Back edge → cycle
            if color[parent] == WHITE and dfs(parent):
                return True
        color[node] = BLACK
        return False
    
    return any(dfs(node) for node in graph if color[node] == WHITE)
```

The algorithm uses three colours: WHITE (unvisited), GRAY (in current DFS path), BLACK (fully explored). A back edge (to a GRAY node) indicates a cycle.

### 6.2. What to Do When a Cycle Is Found

If a cycle is detected:

1. **Log** the cycle for ontology maintainers.
2. **Break** the cycle by removing one edge (heuristic: remove the edge that connects the most-distantly-related nodes).
3. **Continue** with the acyclic graph.

The project's pipeline runs cycle detection at ontology-load time and refuses to start if a cycle is found, forcing the developer to fix the ontology.

## 7. The Project's Graph-Traversal Algorithms

The project uses three traversal algorithms on the ontology DAG:

### 7.1. Ancestor Lookup (for Hierarchical Similarity)

Given a phenotype $p$, find all ancestors of $p$:

```python
def get_ancestors(phenotype, tc):
    return tc[phenotype]  # O(1) lookup
```

This is used by the Resnik and Lin similarity metrics (Chapter 8.3) to find the Most Informative Common Ancestor.

### 7.2. Descendant Lookup (for Generalisation)

Given a phenotype $p$, find all descendants of $p$ (more specific terms):

```python
def get_descendants(phenotype, reverse_tc):
    return reverse_tc[phenotype]
```

This is used when the patient note mentions a general phenotype (e.g., *Abnormal Eye Movement*) and the system must find all diseases annotated with any specific descendant (e.g., *Nystagmus*, *Oscillopsia*, *Saccadic Pursuit*).

### 7.3. Shortest Path (for Explainability)

Given two phenotypes $p_1, p_2$, find the shortest path between them in the DAG. This is used for the explainability paths in Chapter 8.4 — the system shows the doctor the biological reasoning path from symptom to diagnosis.

```python
from collections import deque

def shortest_path(p1, p2, graph):
    # Bidirectional BFS
    forward = {p1: None}
    backward = {p2: None}
    forward_queue = deque([p1])
    backward_queue = deque([p2])
    
    while forward_queue and backward_queue:
        # Expand forward
        node = forward_queue.popleft()
        for parent in graph.get(node, []):
            if parent not in forward:
                forward[parent] = node
                if parent in backward:
                    return reconstruct_path(forward, backward, parent)
                forward_queue.append(parent)
        # Expand backward (symmetric)
        # ...
    return None  # No path
```

The bidirectional BFS is $O(b^{d/2})$ where $b$ is the branching factor and $d$ is the path length — much faster than unidirectional BFS ($O(b^d)$) for long paths.

## 8. Summary

| Concept | Tree Model (Original Vault) | DAG Model (Corrected) |
| :--- | :--- | :--- |
| Number of parents per node | Exactly 1 | Zero or more |
| Nystagmus's parents | Abnormal Eye Movement only | Abnormal Eye Movement + Abnormality of Eye Movement |
| Path enumeration | Single path | Union of all paths |
| Transitive closure | Trivial (one path per node) | Required for $O(1)$ lookup |
| Cycle risk | Impossible by definition | Possible; must detect |
| Hierarchical similarity | Limited (one path) | Full (MICA across all paths) |

The DAG model is not optional — it is the only correct representation of medical ontologies, and every downstream algorithm (similarity, traversal, explainability) depends on it.
