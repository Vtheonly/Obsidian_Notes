# 10.4. Reproducible Notebook Flow

The original vault's Chapter 10.4 detailed the 24-module notebook sequence but did not mention **random seed configuration** or the **validation splitting strategy**. The audit identified both as **high-severity** gaps. Without seed configuration, every run of the notebook produces different results (because PyTorch, NumPy, and the LLM API all use random numbers). Without a stratified, patient-level validation split, the evaluation is biased and the model may fail on out-of-distribution patients.

This note covers: (1) the 24-module notebook sequence (corrected), (2) random seed configuration across all libraries, (3) the patient-stratified validation split, (4) the cross-validation strategy, (5) the configuration manifest, and (6) the reproducibility checklist.

## 2. Random Seed Configuration (Critical)

Without seed configuration, the notebook is **non-reproducible**: every run produces different embeddings (PyTorch CUDA non-determinism), different train/val splits (sklearn random), different LLM outputs (API non-determinism), and different tournament rankings (PyTorch inference). The audit identified this as a **high-severity** gap.

### 2.1. The Seed Configuration Module

```python
# Module 1: Seed Configuration
import os
import random
import numpy as np
import torch

SEED = 42

def set_all_seeds(seed):
    """Set seeds for all libraries that use randomness."""
    # Python's built-in random
    random.seed(seed)
    
    # NumPy
    np.random.seed(seed)
    
    # PyTorch (CPU and CUDA)
    torch.manual_seed(seed)
    torch.cuda.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    
    # cuDNN determinism (may reduce performance)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
    
    # Python hash seed (for reproducible dict ordering)
    os.environ['PYTHONHASHSEED'] = str(seed)
    
    # TF-cpp determinism (if TensorFlow is used)
    os.environ['TF_DETERMINISTIC_OPS'] = '1'
    
    # LLM API determinism
    # (Set temperature=0.0 in the LLM Cleaner — Chapter 6.3)

set_all_seeds(SEED)
print(f"All seeds set to {SEED}")
```

### 2.2. Why Each Seed Matters

- **`random.seed`**: Affects Python's `random` module (used by some sklearn functions).
- **`np.random.seed`**: Affects NumPy's random (used by sklearn's train_test_split, bootstrap, etc.).
- **`torch.manual_seed`**: Affects PyTorch's weight initialisation and dropout (critical for the Neural Ranker).
- **`torch.backends.cudnn.deterministic`**: Forces cuDNN to use deterministic algorithms (some are non-deterministic by default for speed).
- **`PYTHONHASHSEED`**: Affects dict iteration order, which can affect which candidates are processed first.
- **LLM `temperature=0.0`**: Makes the LLM API deterministic (Chapter 6.3).

### 2.3. The Cost of Determinism

Setting `torch.backends.cudnn.deterministic = True` and `benchmark = False` can slow down training by 10–20% because cuDNN cannot use its fastest (non-deterministic) algorithms. This is an acceptable cost for scientific reproducibility.

## 3. The Patient-Stratified Validation Split

The audit identified the missing validation split as a **high-severity** gap. The corrected split is:

### 3.1. Three-Way Split

```python
from sklearn.model_selection import StratifiedShuffleSplit

def patient_stratified_three_way_split(patient_notes, test_size=0.15, val_size=0.15, seed=42):
    """
    Three-way split: train / val / test, stratified by disease family.
    
    Returns: (train_notes, val_notes, test_notes)
    """
    # Extract disease family for stratification
    families = [note.disease_family for note in patient_notes]
    
    # First split: train vs. (val + test)
    sss1 = StratifiedShuffleSplit(n_splits=1, test_size=test_size + val_size, random_state=seed)
    train_idx, temp_idx = next(sss1.split(patient_notes, families))
    train_notes = [patient_notes[i] for i in train_idx]
    temp_notes = [patient_notes[i] for i in temp_idx]
    
    # Second split: val vs. test
    temp_families = [note.disease_family for note in temp_notes]
    relative_val_size = val_size / (val_size + test_size)
    sss2 = StratifiedShuffleSplit(n_splits=1, test_size=1 - relative_val_size, random_state=seed)
    val_idx, test_idx = next(sss2.split(temp_notes, temp_families))
    val_notes = [temp_notes[i] for i in val_idx]
    test_notes = [temp_notes[i] for i in test_idx]
    
    return train_notes, val_notes, test_notes
```

### 3.2. Why Stratified

Rare-disease datasets are **highly imbalanced**: some disease families (e.g., Albinism) may have 50 patient notes, while others (e.g., Marfan) may have only 5. A random (non-stratified) split could put all 5 Marfan notes in the test set, leaving the model with no Marfan training examples.

Stratification ensures that each disease family is proportionally represented in train, val, and test. With a 70/15/15 split, a family with 20 notes has 14 train, 3 val, 3 test; a family with 5 notes has 3-4 train, 1 val, 1 test.

### 3.3. Why Patient-Level (Not Note-Level)

Some patients have multiple notes (e.g., a follow-up visit). All notes from the same patient must go in the **same** split to prevent leakage. The split is therefore at the patient level, not the note level:

```python
# Group notes by patient ID before splitting
notes_by_patient = group_by(patient_notes, key=lambda n: n.patient_id)
patients = list(notes_by_patient.keys())
# Split the patients, then expand back to notes
```

### 3.4. Why Three-Way (Not Two-Way)

A two-way split (train/test) does not leave a held-out validation set for hyperparameter tuning. If hyperparameters are tuned on the test set, the test performance is biased upward. The three-way split reserves:

- **Train**: For model training (Neural Ranker weights).
- **Val**: For hyperparameter tuning (learning rate, dropout, K, thresholds).
- **Test**: For final evaluation only — touched once, at the end.

## 4. Cross-Validation Strategy

For small datasets (the project's 200-note test set), a single train/test split has high variance. **K-fold cross-validation** reduces this variance by averaging over K splits.

### 4.1. Stratified K-Fold

```python
from sklearn.model_selection import StratifiedKFold

def stratified_k_fold_cv(patient_notes, k=5, seed=42):
    """
    Stratified K-fold cross-validation.
    Returns list of (train_notes, val_notes) tuples.
    """
    families = [note.disease_family for note in patient_notes]
    skf = StratifiedKFold(n_splits=k, shuffle=True, random_state=seed)
    
    folds = []
    for train_idx, val_idx in skf.split(patient_notes, families):
        train_notes = [patient_notes[i] for i in train_idx]
        val_notes = [patient_notes[i] for i in val_idx]
        folds.append((train_notes, val_notes))
    
    return folds
```

### 4.2. When to Use CV vs. Single Split

- **Single split**: When the dataset is large enough (>1000 notes) that the split's variance is low.
- **Cross-validation**: When the dataset is small (<500 notes) and the single-split variance is high.

The project uses **5-fold cross-validation** on the 200-note test set, reporting the mean and standard deviation across folds.

### 4.3. Nested CV for Hyperparameter Tuning

For rigorous hyperparameter tuning, **nested cross-validation** is used: an outer K-fold for evaluation, an inner K-fold for hyperparameter selection. This prevents the hyperparameter-tuning bias that occurs when the same data is used for tuning and evaluation.

The project does not currently use nested CV (the hyperparameters were tuned once on the val set and fixed), but it is a future improvement if the test set grows.

## 6. The Reproducibility Checklist

Before declaring a notebook run "final," verify:

- [ ] **Seed set**: All seeds (Python, NumPy, PyTorch, cuDNN, PYTHONHASHSEED) are configured.
- [ ] **LLM temperature 0.0**: The LLM Cleaner is deterministic.
- [ ] **Stratified split**: Train/val/test are stratified by disease family.
- [ ] **Patient-level split**: All notes from the same patient are in the same split.
- [ ] **No test-set leakage**: Hyperparameters were tuned on val, not test.
- [ ] **Ontology versions recorded**: The manifest specifies exact HPO/Orphanet/MONDO versions.
- [ ] **Model versions recorded**: The manifest specifies exact model checkpoints (e.g., `biobert-v1.1-cased` hash).
- [ ] **Bootstrap CIs**: All reported metrics have 95% confidence intervals.
- [ ] **Results saved**: `pfe_master_results.json` and the manifest are saved to a versioned directory.
- [ ] **Run is reproducible**: Re-executing the notebook with the same manifest produces the same results (within floating-point tolerance).
