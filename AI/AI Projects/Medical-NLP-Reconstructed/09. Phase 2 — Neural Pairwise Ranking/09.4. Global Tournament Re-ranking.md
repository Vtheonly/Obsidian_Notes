# 09.4. Global Tournament Re-ranking

Once the Neural Ranker is trained, the project runs a **Global Tournament** to determine the final rank of the Top-20 candidates. The original vault's Chapter 9.4 described simple win-counting to determine the rank, but it made two assumptions that the audit identified as problematic:

1. **It assumed transitivity.** If $A > B$ and $B > C$, the model assumes $A > C$. But neural pairwise classifiers are prone to **non-transitive cycles** (the "Rock-Paper-Scissors" phenomenon): $A > B$, $B > C$, and $C > A$. Simple win-counting produces ties or unstable rankings when cycles occur.
2. **It did not discuss pruning.** The all-pairs tournament is $O(K^2) = 380$ comparisons per patient note, which is tractable at $K = 20$ but does not scale.

This note covers: (1) the all-pairs tournament, (2) the non-transitivity problem, (3) the **Bradley-Terry model** for resolving cycles, (4) **Copeland's method**, (5) PageRank on the tournament graph, (6) active candidate elimination for pruning, and (7) the project's production tournament configuration.

---

## 1. The All-Pairs Tournament

For each patient note, every candidate in the Top-20 "plays" against every other candidate. With $K = 20$, each candidate plays $K - 1 = 19$ matches, for a total of $K(K-1)/2 = 190$ unique matches (or $K(K-1) = 380$ directed matches if both directions are evaluated).

### 1.1. The Win-Counting Algorithm

```python
def all_pairs_tournament(candidates, ranker, note_embedding, cosine_scores):
    """
    Run all-pairs tournament among Top-K candidates.
    
    Args:
        candidates: list of K candidate embeddings
        ranker: trained NeuralRanker
        note_embedding: patient note embedding
        cosine_scores: list of K Stage 1 cosine scores
    Returns:
        ranked list of candidates by win count
    """
    K = len(candidates)
    wins = [0] * K
    
    for i in range(K):
        for j in range(K):
            if i == j:
                continue
            # P(candidate_i > candidate_j)
            p = ranker.predict_pair(
                note_embedding, candidates[i], candidates[j],
                cosine_scores[i], cosine_scores[j]
            )
            if p > 0.5:
                wins[i] += 1
    
    # Sort by win count (descending)
    ranked = sorted(range(K), key=lambda i: wins[i], reverse=True)
    return ranked, wins
```

### 1.2. The Tie-Breaker

When two candidates have the same win count, the project uses the **Stage 1 cosine similarity** as the tie-breaker: the candidate with the higher cosine wins. This is the original vault's correct suggestion ("we combine the wins and the original score"), and it works well in practice because cosine similarity is a continuous signal that breaks most ties.

---

## 2. The Non-Transitivity Problem

The audit identified this as a **medium-severity** issue. Neural pairwise classifiers are not guaranteed to be transitive. The model can predict:

- $P(A > B) = 0.7$ → A beats B.
- $P(B > C) = 0.6$ → B beats C.
- $P(C > A) = 0.55$ → C beats A.

This is a **voting cycle** (Condorcet paradox). With simple win-counting:

- A has 1 win (beat B), 1 loss (lost to C).
- B has 1 win (beat C), 1 loss (lost to A).
- C has 1 win (beat A), 1 loss (lost to B).

All three candidates have 1 win and 1 loss. Simple win-counting produces a three-way tie, and the tie-breaker (cosine similarity) determines the final order — but this order is essentially arbitrary because the cycle provides no information about which candidate is best.

### 2.1. Why Cycles Happen

Cycles arise because the pairwise model learns a **local** decision boundary, not a global ordering. The model can learn that "A is preferred to B when feature X is high" and "B is preferred to C when feature Y is high" and "C is preferred to A when feature Z is high" — three local rules that are individually correct but collectively inconsistent.

This is the **Rock-Paper-Scissors** phenomenon: each candidate beats another under certain conditions, but no candidate dominates.

### 2.2. The Cost of Cycles

In the project's tournament, cycles occur in ~5% of patient notes (per empirical measurement). Without a cycle-resolution mechanism, these notes get arbitrary rankings determined by the tie-breaker, which degrades Top-1 accuracy by ~2 percentage points.

---

## 3. The Bradley-Terry Model

The **Bradley-Terry model** (Bradley & Terry, 1952) is the standard statistical framework for resolving pairwise comparison cycles. It assigns each candidate a **latent "strength"** parameter $\alpha_i$, and models the probability that $i$ beats $j$ as:

$$P(i > j) = \frac{\alpha_i}{\alpha_i + \alpha_j}$$

### 3.1. Maximum Likelihood Estimation

Given a set of pairwise outcomes, the Bradley-Terry parameters are estimated by maximising the likelihood:

$$\mathcal{L}(\alpha) = \prod_{(i,j) \in \text{wins}} \frac{\alpha_i}{\alpha_i + \alpha_j}$$

The log-likelihood is:

$$\log \mathcal{L}(\alpha) = \sum_{(i,j) \in \text{wins}} \left[\log \alpha_i - \log(\alpha_i + \alpha_j)\right]$$

This is a convex optimisation problem that can be solved iteratively (e.g., via the MM algorithm or L-BFGS).

### 3.2. The Iterative Algorithm

```python
import numpy as np

def bradley_terry(wins_matrix, max_iter=100, tol=1e-6):
    """
    Estimate Bradley-Terry strengths from a wins matrix.
    
    Args:
        wins_matrix: (K, K) matrix where wins_matrix[i, j] = number of times i beat j
    Returns:
        strengths: (K,) vector of positive strength parameters
    """
    K = wins_matrix.shape[0]
    strengths = np.ones(K)  # Initialise uniformly
    
    for iteration in range(max_iter):
        new_strengths = np.zeros(K)
        for i in range(K):
            denom = 0
            for j in range(K):
                if i == j:
                    continue
                total_wins = wins_matrix[i, j] + wins_matrix[j, i]
                if total_wins > 0:
                    denom += total_wins / (strengths[i] + strengths[j])
            if denom > 0:
                new_strengths[i] = wins_matrix[i, :].sum() / denom
            else:
                new_strengths[i] = strengths[i]
        
        # Normalise (the model is identifiable only up to a constant)
        new_strengths = new_strengths / new_strengths.sum()
        
        # Check convergence
        if np.max(np.abs(new_strengths - strengths)) < tol:
            break
        strengths = new_strengths
    
    return strengths
```

### 3.3. Why Bradley-Terry Resolves Cycles

The Bradley-Terry model converts the cyclic pairwise outcomes into a **global ranking** by fitting each candidate's latent strength. The candidate with the highest strength is the "best" overall, even if it lost to one specific opponent. This is the standard statistical resolution of the Condorcet paradox.

### 3.4. The Probability Output

The Bradley-Terry strengths can be converted back to pairwise probabilities for any pair, including pairs not directly compared. This is useful for the tournament: if A and B did not play each other directly, $P(A > B) = \alpha_A / (\alpha_A + \alpha_B)$ gives a probability estimate from the global model.

---

## 4. Copeland's Method

**Copeland's method** is a simpler cycle-resolution mechanism: each candidate's Copeland score is the number of wins minus the number of losses.

$$\text{Copeland}(i) = |\{j : i \text{ beat } j\}| - |\{j : j \text{ beat } i\}|$$

### 4.1. Properties

- **Simple**: Easy to compute (just win-count minus loss-count).
- **Condorcet-consistent**: If a Condorcet winner exists (a candidate that beats all others), Copeland elects it.
- **Bounded**: Copeland scores range from $-(K-1)$ to $K-1$.

### 4.2. Limitations

- Does not resolve all cycles — ties can still occur.
- Does not use the **magnitude** of the pairwise probabilities (only the binary win/loss).

For the project, Copeland is used as a fast baseline; Bradley-Terry is used when Copeland produces ties.

## 5. PageRank on the Tournament Graph

A third cycle-resolution mechanism is to construct a **directed graph** from the pairwise outcomes (edge from $i$ to $j$ if $i$ beat $j$) and compute **PageRank**:

```python
import networkx as nx

def pagerank_tournament(wins_matrix, alpha=0.85):
    """
    Compute PageRank on the tournament graph.
    
    Args:
        wins_matrix: (K, K) matrix where wins_matrix[i, j] = 1 if i beat j
        alpha: PageRank damping factor
    Returns:
        pagerank scores: (K,) vector
    """
    G = nx.DiGraph()
    K = wins_matrix.shape[0]
    for i in range(K):
        for j in range(K):
            if wins_matrix[i, j] > 0:
                G.add_edge(i, j, weight=wins_matrix[i, j])
    
    return nx.pagerank(G, alpha=alpha, weight='weight')
```

PageRank rewards candidates that beat **strong** opponents (a win over a high-PageRank candidate contributes more than a win over a low-PageRank candidate). This naturally resolves cycles by weighting wins by opponent strength.

### 5.1. Comparison to Bradley-Terry

- **Bradley-Terry** is a statistical model with a clean probabilistic interpretation.
- **PageRank** is a graph algorithm with a "random surfer" interpretation.

Both produce similar rankings in practice. Bradley-Terry is preferred when the pairwise probabilities are available (because it uses the magnitudes); PageRank is preferred when only binary win/loss is available.

## 6. Active Candidate Elimination — Pruning the Tournament

The all-pairs tournament is $O(K^2)$. For $K = 20$, this is 380 comparisons per patient note — tractable. For $K = 100$, it is 9,900 — slow. Two pruning strategies reduce the cost:

### 6.1. Single-Elimination Bracket

Run a single-elimination tournament: 10 matches in round 1, 5 in round 2, etc. Total matches: $K - 1 = 19$ (linear, not quadratic). The tradeoff is that the winner is not necessarily the same as the all-pairs winner — single-elimination can produce a different winner if the bracket is unlucky.

### 6.2. Active Candidate Elimination

After each comparison, eliminate candidates that have lost to many others. If candidate $A$ has lost to 5 other candidates, it cannot be in the Top-5 (because those 5 are all above it), so it can be removed from subsequent comparisons. This reduces the effective $K$ as the tournament progresses.

```python
def active_elimination_tournament(candidates, ranker, note_emb, cos_scores, top_n=5):
    """
    Tournament with active candidate elimination.
    Stop when only top_n candidates remain.
    """
    K = len(candidates)
    losses = [0] * K
    eliminated = [False] * K
    
    for i in range(K):
        if eliminated[i]:
            continue
        for j in range(K):
            if i == j or eliminated[j]:
                continue
            p = ranker.predict_pair(note_emb, candidates[i], candidates[j],
                                    cos_scores[i], cos_scores[j])
            if p <= 0.5:
                losses[i] += 1
                if losses[i] > K - top_n:
                    eliminated[i] = True
                    break
            else:
                losses[j] += 1
                if losses[j] > K - top_n:
                    eliminated[j] = True
    
    survivors = [i for i in range(K) if not eliminated[i]]
    return survivors
```

### 6.3. The Project's Choice

The project uses **all-pairs at $K = 20$** (380 comparisons, ~5 ms per patient note on GPU) because the cost is tractable and all-pairs produces the most stable ranking. If $K$ grows to 50+, the project would switch to active elimination.

## 7. The Project's Production Tournament Configuration

The production tournament runs three methods in sequence and uses the Bradley-Terry ranking as the final output:

```python
def global_tournament(candidates, ranker, note_emb, cos_scores):
    """
    Full tournament with cycle resolution.
    
    Returns: final ranking (list of candidate indices, best first)
    """
    K = len(candidates)
    
    # Step 1: All-pairs comparison → wins matrix
    wins_matrix = np.zeros((K, K))
    for i in range(K):
        for j in range(K):
            if i == j:
                continue
            p = ranker.predict_pair(note_emb, candidates[i], candidates[j],
                                    cos_scores[i], cos_scores[j])
            if p > 0.5:
                wins_matrix[i, j] = 1
    
    # Step 2: Copeland scores (fast baseline)
    copeland = wins_matrix.sum(axis=1) - wins_matrix.sum(axis=0)
    
    # Step 3: Bradley-Terry (cycle resolution)
    bt_strengths = bradley_terry(wins_matrix)
    
    # Step 4: Final ranking by Bradley-Terry strength,
    #         with Copeland as tie-breaker, with cosine as final tie-breaker
    ranked = sorted(
        range(K),
        key=lambda i: (-bt_strengths[i], -copeland[i], -cos_scores[i])
    )
    
    return ranked
```

### 7.1. Why Three Layers

1. **Copeland** is fast and provides a baseline ranking.
2. **Bradley-Terry** resolves cycles that Copeland cannot.
3. **Cosine** is the final tie-breaker for any remaining ties.

The three-layer approach produces a stable, defensible ranking even in the presence of cycles. Empirically, it improves Top-1 accuracy by ~2 points over simple win-counting on the project's validation set.

## 8. Summary

| Method | Complexity | Cycle-Resolution | Project Use |
| :--- | :--- | :--- | :--- |
| Simple win-counting | $O(K^2)$ | None (ties) | Original vault's approach (insufficient) |
| Copeland | $O(K^2)$ | Partial (win-loss diff) | Step 2 baseline |
| **Bradley-Terry** | $O(K^2 I)$ (I iterations) | **Yes (statistical)** | **Step 3 final ranking** |
| PageRank | $O(K^2 I)$ | Yes (graph-based) | Alternative to BT |
| Single-elimination | $O(K)$ | None (bracket-dependent) | Future option for large K |
| Active elimination | $O(K^2)$ amortised | None | Future option for large K |

The project's production tournament uses **all-pairs + Copeland + Bradley-Terry + cosine tie-breaker**, which resolves cycles and produces a stable, defensible ranking.
