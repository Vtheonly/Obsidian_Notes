# 06.3. Deterministic AI (Temperature and Top-P)

In medicine, **scientific reproducibility** is mandatory. If you analyse a patient note today, you must get the same result if you run it again tomorrow. The original vault explained that "T=0 ensures reproducibility" but did not provide the **mathematical formula for temperature-scaled softmax**, did not explain how temperature collapses the distribution into a Kronecker delta as $T \to 0$, and did not cover **Top-P (nucleus sampling)** with its formal cumulative-probability formulation. This note fills all three gaps.

This chapter covers: (1) the standard softmax, (2) temperature-scaled softmax with the formula and its limiting behaviour, (3) top-k sampling, (4) top-p (nucleus) sampling with the formal definition, (5) why the project uses $T = 0$, and (6) hallucination grounding.

---

## 1. The Standard Softmax

A decoder LLM outputs a vector of **logits** $\mathbf{z} \in \mathbb{R}^{|V|}$ (one per vocabulary token). To convert logits to a probability distribution, the model applies the **softmax** function:

$$P(y_i \mid x) = \frac{e^{z_i}}{\sum_{j=1}^{|V|} e^{z_j}}$$

where $z_i$ is the logit for token $i$ and $|V|$ is the vocabulary size (~50,000 for modern LLMs).

At **greedy decoding** (no sampling), the model picks the argmax: $y = \arg\max_i P(y_i \mid x)$. This is deterministic — the same logits always produce the same token.

At **stochastic decoding**, the model samples from the distribution: $y \sim P(\cdot \mid x)$. This is non-deterministic — the same logits can produce different tokens on different runs.

---

## 2. Temperature-Scaled Softmax

**Temperature** is a parameter $T > 0$ that scales the logits before softmax:

$$P_T(y_i \mid x) = \frac{e^{z_i / T}}{\sum_{j=1}^{|V|} e^{z_j / T}}$$

The temperature controls the **sharpness** of the distribution:

### 2.1. $T = 1$ (Standard Softmax)

The distribution is the model's "honest" probability estimate. If the model is 80% confident in token A and 20% in token B, sampling will pick A 80% of the time and B 20% of the time.

### 2.2. $T \to 0$ (Greedy / Deterministic)

As $T \to 0$, the temperature-scaled softmax collapses to a **Kronecker delta**:

$$\lim_{T \to 0^+} P_T(y_i \mid x) = \begin{cases} 1 & \text{if } i = \arg\max_j z_j \\ 0 & \text{otherwise} \end{cases}$$

**Proof sketch**: Let $z_{\max} = \max_j z_j$ and let $i^* = \arg\max_j z_j$. Then:

$$P_T(y_{i^*} \mid x) = \frac{e^{z_{\max}/T}}{e^{z_{\max}/T} + \sum_{j \neq i^*} e^{z_j/T}} = \frac{1}{1 + \sum_{j \neq i^*} e^{(z_j - z_{\max})/T}}$$

For each $j \neq i^*$, $z_j - z_{\max} < 0$, so $(z_j - z_{\max})/T \to -\infty$ as $T \to 0^+$, and $e^{(z_j - z_{\max})/T} \to 0$. Therefore:

$$\lim_{T \to 0^+} P_T(y_{i^*} \mid x) = \frac{1}{1 + 0} = 1$$

So at $T = 0$, the model always picks the argmax token. This is mathematically equivalent to greedy decoding, and it is **deterministic** — the same logits always produce the same token.

### 2.3. $T \to \infty$ (Uniform)

As $T \to \infty$, all logits are scaled toward 0, and the softmax approaches a **uniform distribution**:

$$\lim_{T \to \infty} P_T(y_i \mid x) = \frac{1}{|V|}$$

Every token is equally likely. The output is pure noise.

### 2.4. Intermediate $T$ (Creative)

At $T = 0.7$ (the original vault's "creative" example), the distribution is sharpened relative to $T = 1$ but not collapsed. The model is more likely to pick high-probability tokens than at $T = 1$, but it still occasionally picks lower-probability ones. This is what makes the output "creative" — it is not deterministic, but it is not pure noise either.

### 2.5. Why the Project Uses $T = 0$

For the LLM Clinical Cleaner, the project uses $T = 0$ because:

1. **Reproducibility.** The same patient note must produce the same extracted phenotypes on every run. At $T > 0$, the LLM might call a symptom *"Fever"* on one run and *"Pyrexia"* on the next, changing the downstream cosine similarity score. At $T = 0$, the output is fixed.
2. **Scientific defensibility.** A jury reviewing the project's results must be able to reproduce them. Non-deterministic output is not defensible.
3. **Audit trail.** If a diagnosis is wrong, the project must be able to trace back through the extraction to find the error. Non-deterministic extraction makes this impossible.

The only setting where $T > 0$ is appropriate is **data augmentation** — generating synthetic patient notes for training the Neural Ranker (Chapter 9.2) — where diversity is desired and reproducibility is not.

## 3. Top-K Sampling

**Top-k sampling** restricts the sampling pool to the $k$ highest-probability tokens. The procedure:

1. Compute the full softmax distribution.
2. Keep only the top $k$ tokens; set the rest to probability 0.
3. Renormalise the kept probabilities to sum to 1.
4. Sample from the renormalised distribution.

$$P_{\text{top-}k}(y_i \mid x) = \begin{cases} \frac{P(y_i \mid x)}{\sum_{j \in \text{top-}k} P(y_j \mid x)} & \text{if } i \in \text{top-}k \\ 0 & \text{otherwise} \end{cases}$$

Top-k with $k = 1$ is equivalent to greedy decoding. Top-k with $k = |V|$ is equivalent to standard sampling.

### 3.1. Why Top-K Is Useful

Top-k prevents the model from sampling very-low-probability tokens (which are usually wrong or nonsensical). At $T = 0.7$ with $k = 40$, the model samples only from the 40 most likely tokens, which excludes the long tail of bizarre outputs.

### 3.2. Why the Project Does Not Use Top-K

At $T = 0$, top-k is irrelevant — the model always picks the argmax, so the size of the sampling pool does not matter. The project uses $T = 0$ alone.

---

## 4. Top-P (Nucleus) Sampling

**Top-p sampling**, also called **nucleus sampling** (Holtzman et al., 2020), restricts the sampling pool to the smallest set of tokens whose cumulative probability exceeds $p$:

1. Sort tokens by descending probability.
2. Accumulate probabilities until the cumulative sum reaches $p$.
3. Keep only the tokens in this "nucleus"; set the rest to 0.
4. Renormalise and sample.

Formally, let the sorted probabilities be $p_{(1)} \geq p_{(2)} \geq \dots \geq p_{(|V|)}$. Define the nucleus as:

$$\mathcal{N}_p = \min\!\left\{n : \sum_{i=1}^n p_{(i)} \geq p\right\}$$

Then:

$$P_{\text{top-}p}(y_{(i)} \mid x) = \begin{cases} \frac{p_{(i)}}{\sum_{j=1}^{\mathcal{N}_p} p_{(j)}} & \text{if } i \leq \mathcal{N}_p \\ 0 & \text{otherwise} \end{cases}$$

### 4.1. Why Top-P Is Better Than Top-K

Top-k uses a fixed pool size ($k = 40$), which is wrong for both highly confident and highly uncertain predictions:

- **Confident prediction**: The model is 99% sure of the next token. Top-k = 40 still samples from 40 tokens, introducing unnecessary noise. Top-p = 0.9 would sample from just 1 token (the 99%-confident one).
- **Uncertain prediction**: The model is unsure among 100 tokens, each with ~1% probability. Top-k = 40 samples from only 40 of them, artificially excluding 60 plausible alternatives. Top-p = 0.9 would sample from ~90 tokens.

Top-p adapts the pool size to the model's confidence, which is why it has largely replaced top-k in modern LLM APIs.

### 4.2. The Project's Use of Top-P

At $T = 0$, top-p is irrelevant (the argmax token always has cumulative probability 1). The project sets `top_p = 1.0` (no nucleus restriction) and relies on $T = 0$ alone for determinism.

---

## 5. The Combined Decoding Formula

The full decoding distribution with temperature, top-k, and top-p is:

$$P_{\text{final}}(y_i \mid x) = \begin{cases} \frac{e^{z_i/T}}{\sum_{j \in \mathcal{S}} e^{z_j/T}} & \text{if } i \in \mathcal{S} \\ 0 & \text{otherwise} \end{cases}$$

where $\mathcal{S}$ is the set of tokens that survive both the top-k and top-p filters. At $T = 0$, this collapses to the argmax regardless of $\mathcal{S}$.

## 6. Hallucinations and Grounding

A **hallucination** is when the LLM produces an entity that does not exist in the target ontology. For example, the LLM might output a phenotype label *"Z-Virus-Eyes"* that is not in HPO. Hallucinations are not caused by temperature (they can occur at $T = 0$ if the model's training data contained the hallucinated term); they are caused by the model's imperfect internalisation of the ontology.

### 6.1. The Project's Grounding Mechanism

The project handles hallucinations via the **ontology lookup backstop** (Chapter 5.1 §5):

1. The LLM outputs a phenotype label.
2. The pipeline looks up the label in the HPO dictionary.
3. If exact match: accept.
4. If fuzzy match (SapBERT similarity ≥ 0.85): replace with canonical HPO label and accept.
5. If no match: **reject** as a hallucination.

This guarantees that only verified HPO terms enter the Knowledge Graph. The LLM's hallucinations are filtered out before they can corrupt the pipeline.

### 6.2. Why Temperature Does Not Solve Hallucinations

A common misconception is that $T = 0$ eliminates hallucinations. It does not. $T = 0$ makes the output **deterministic** — the same input always produces the same output — but it does not make the output **correct**. If the LLM's highest-probability token for a given context is a hallucinated term, $T = 0$ will deterministically produce that hallucinated term every time.

The only way to eliminate hallucinations is the **external grounding** step (the HPO lookup). Temperature controls reproducibility; grounding controls correctness.
