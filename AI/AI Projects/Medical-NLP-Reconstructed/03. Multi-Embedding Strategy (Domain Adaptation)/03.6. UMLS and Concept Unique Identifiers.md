# 03.6. UMLS and Concept Unique Identifiers

The original vault mentioned UMLS in passing (in the SapBERT note) but never defined it. This is a critical gap, because **UMLS is the foundational layer of clinical entity linking** — without it, SapBERT's training data does not exist, the SPECIALIST Lexicon (Chapter 7.3) has no home, and the cross-ontology mapping that MONDO provides (Chapter 7.2) has no precedent. Any engineer who tries to debug an entity-linking error without understanding UMLS CUIs will be reduced to guessing.

This note covers: (1) what UMLS is and why it exists, (2) the four major UMLS components (Metathesaurus, Semantic Network, SPECIALIST Lexicon, Metamap), (3) the Concept Unique Identifier (CUI) as the central pivot of clinical entity linking, (4) how SapBERT uses UMLS synonym pairs, and (5) how the project uses UMLS at three different stages of the pipeline.

---

## 1. What UMLS Is

The **Unified Medical Language System (UMLS)** is a compendium of biomedical vocabularies maintained by the U.S. National Library of Medicine (NLM) since 1986. Its purpose is to **interconnect the dozens of independent medical vocabularies** — MeSH, SNOMED-CT, ICD-10, RxNorm, HPO, OMIM, Orphanet, LOINC, and ~200 others — into a single graph of concepts. Without UMLS, mapping a patient note's mention of *"Hypertension"* (MeSH) to the same concept in ICD-10 (`I10`) and SNOMED-CT (`38341003`) would require pairwise mapping tables for every vocabulary pair — an $O(n^2)$ problem. UMLS reduces this to $O(n)$: every vocabulary maps to a UMLS CUI, and the CUI is the universal pivot.

### 1.1. Why This Is Necessary

Clinical data is fragmented across hospitals, countries, and specialties, each using a different vocabulary:

- **U.S. hospitals** use ICD-10 for billing and SNOMED-CT for problem lists.
- **Rare disease databases** use Orphanet and OMIM.
- **Pharmacy systems** use RxNorm for drugs.
- **Lab systems** use LOINC for laboratory tests.
- **Research literature** uses MeSH for indexing.

A patient may have a problem-list entry in SNOMED-CT, a billing code in ICD-10, a literature mention under MeSH, and a rare-disease registry entry under Orphanet — all referring to the same disease. UMLS unifies these under a single CUI so that any system can map any code to any other code via the CUI as an intermediate.

## 2. The Four UMLS Components

UMLS is not a single database; it is four interlocking components.

### 2.1. Metathesaurus

The Metathesaurus is the **cross-vocabulary mapping**. For each concept, it stores:

- A **CUI** (Concept Unique Identifier), e.g., `C0020538` for *Hypertension*.
- One or more **AUIs** (Atom Unique Identifiers), one per source vocabulary. Each AUI corresponds to a single string in a single source vocabulary.
- One or more **LUIs** (Lexical Unique Identifiers), grouping AUIs by lexical form (case-insensitive, plural-normalised).
- The **source vocabularies** (MeSH, SNOMED-CT, ICD-10, etc.) and their original codes.
- **Synonym relationships** between AUIs of the same CUI.
- **Hierarchical and associative relationships** between CUIs (broader-than, narrower-than, may-be-treated-by, etc.).

Example for CUI `C0020538` (Hypertension):

| AUI | LUI | Source Vocabulary | Source Code | String |
| :--- | :--- | :--- | :--- | :--- |
| A0012345 | L0001 | MeSH | D006973 | "Hypertension" |
| A0067890 | L0002 | SNOMED-CT | 38341003 | "Hypertension (disorder)" |
| A0099887 | L0003 | ICD-10 | I10 | "Essential (primary) hypertension" |
| A0023456 | L0004 | MedlinePlus | 000468 | "High Blood Pressure" |
| A0078901 | L0005 | HPO | HP:0000822 | "Hypertension" |

All five AUIs share CUI `C0020538`. This means a system can take an ICD-10 code from a hospital record, look up its CUI, then look up the corresponding HPO term for the same concept — without ever doing a direct ICD-10 → HPO mapping.

### 2.2. Semantic Network

The Semantic Network is a small, fixed taxonomy of **semantic types** and **semantic relations**. Every CUI is assigned one or more semantic types:

- **Semantic types** (127 total): `Pharmacologic Substance`, `Disease or Syndrome`, `Gene or Genome`, `Clinical Drug`, `Patient or Disabled Group`, etc.
- **Semantic relations** (54 total): `treats`, `causes`, `prevents`, `diagnoses`, `part_of`, `has_location`, etc.

For example, CUI `C0020538` (Hypertension) has semantic type `Disease or Syndrome`. CUI `C0020614` (lisinopril) has semantic type `Pharmacologic Substance`. The Metathesaurus contains a relation `lisinopril treats Hypertension`, which the Semantic Network classifies as a `treats` relation.

The Semantic Network is the **type system** of UMLS — it provides the categorisation that lets downstream applications filter by concept class (e.g., "give me all diseases mentioned in this note, not the drugs or procedures").

### 2.3. SPECIALIST Lexicon

The SPECIALIST Lexicon is a **lexical database** of biomedical terms. For each term, it stores:

- Syntactic category (noun, verb, adjective, etc.)
- Inflectional variants (singular/plural, verb conjugations)
- Spelling variants (American vs. British)
- Abbreviations and acronyms

This is the resource the project uses for **abbreviation expansion** (Chapter 7.3). When the LLM Cleaner encounters an ambiguous abbreviation like `APC`, the SPECIALIST Lexicon provides the candidate expansions and the project's WSD logic (Chapter 1.1 §6) selects the right one based on context.

### 2.4. MetaMap

MetaMap is a **software tool** (not a database) that maps arbitrary biomedical text to UMLS CUIs. Given a free-text phrase, MetaMap:

1. Parses the phrase syntactically.
2. Generates candidate CUIs for each detected concept.
3. Scores each candidate by lexical similarity and semantic type.
4. Returns the top-ranked CUI mappings.

MetaMap is widely used as a baseline for clinical entity linking, though it has been superseded by neural approaches (SapBERT, scispaCy) for accuracy. The project uses SapBERT for the entity-linking stage but can fall back to MetaMap for terms SapBERT has never seen.

## 3. The CUI — The Central Pivot

The **Concept Unique Identifier (CUI)** is the single most important concept in clinical NLP. A CUI is a 7-character alphanumeric code (e.g., `C0020538`) that uniquely identifies a biomedical concept across all UMLS source vocabularies.

### 3.1. Why the CUI Matters

The CUI solves the **vocabulary fragmentation problem** at the data layer. Instead of building pairwise mappings between every pair of vocabularies ($O(n^2)$ mappings), each vocabulary maps to the CUI ($O(n)$ mappings), and the CUI is the universal join key.

For the project's pipeline:

- The patient note mentions *"high blood pressure"*.
- The LLM Cleaner extracts this as a phenotype.
- SapBERT maps it to CUI `C0020538` (via its UMLS-trained entity-linking model).
- The CUI is then mapped to HPO `HP:0000822` for the Knowledge Graph.
- The same CUI could also map to ICD-10 `I10` for billing, MeSH `D006973` for literature search, or SNOMED-CT `38341003` for the EHR problem list.

Without the CUI, each of these mappings would require a separate lookup table. With the CUI, one lookup suffices.

### 3.2. CUI Granularity

CUIs are assigned at the **concept** level, not the term level. This means:

- *"Hypertension"*, *"High Blood Pressure"*, *"Elevated Blood Pressure"*, and *"HTN"* all share a single CUI (`C0020538`).
- Different stages of hypertension (Stage 1, Stage 2, malignant) have **different** CUIs because they are different clinical concepts.

This is the correct granularity for entity linking — synonymous expressions map to one CUI, while clinically distinct concepts get distinct CUIs.

### 3.3. CUIs vs. Ontology IDs

The relationship between CUIs and ontology IDs (HPO, MONDO, Orphanet) is many-to-many:

- One CUI may map to multiple ontology IDs (e.g., CUI for *"Albinism"* maps to HPO `HP:0001022` and to Orphanet `Orpha:92`).
- One ontology ID may map to multiple CUIs (e.g., HPO `HP:0000639` for *Nystagmus* may have separate CUIs for *congenital nystagmus*, *acquired nystagmus*, *spontaneous nystagmus*).

This many-to-many mapping is exactly why MONDO (Chapter 7.2) exists — MONDO is a curated ontology that resolves these ambiguities into a single canonical disease ID per concept.

## 4. How SapBERT Uses UMLS

SapBERT (Chapter 3.2) is trained on the UMLS Metathesaurus as follows:

1. **Extract synonym pairs.** For every CUI, collect all AUI strings (the synonyms). Every pair of AUIs sharing a CUI is a positive (synonym) pair. This produces ~10 million synonym pairs from the 2020AB UMLS release.
2. **Sample negative pairs.** For each positive pair, sample multiple negative pairs (AUIs from different CUIs).
3. **Train with Multi-Similarity Loss.** SapBERT is fine-tuned to minimise the distance between positive pairs and maximise the distance between negative pairs (see Chapter 3.2 §4.1 for the loss formula).

The result is a model whose embeddings cluster synonyms together — *"Hypertension"*, *"High Blood Pressure"*, and *"HTN"* all map to nearly the same 768-dim vector. This is what makes SapBERT the project's preferred model for entity-linking tasks.

### 4.1. UMLS Versioning and SapBERT Refresh

UMLS is updated quarterly (2020AB, 2021AA, 2021AB, etc.). Each release adds new CUIs, deprecates old ones, and updates synonym lists. SapBERT was trained on the 2020AB release; if a new clinical concept (e.g., a newly-characterised rare disease) is added to UMLS in 2024, SapBERT will not know about it.

The project's pipeline handles this by:

- **Periodic SapBERT refresh.** Re-train or download a SapBERT checkpoint trained on the latest UMLS release.
- **Fallback to MetaMap** for terms SapBERT does not recognise. MetaMap uses lexical matching and can handle novel terms, albeit with lower precision.

## 5. UMLS in the Project's Pipeline

UMLS appears at three stages:

### 5.1. Stage 1 — Abbreviation Expansion (via SPECIALIST Lexicon)

The LLM Cleaner consults the SPECIALIST Lexicon to expand abbreviations like `SOB` → *Shortness of Breath*, `PMH` → *Past Medical History*, and to disambiguate homonyms like `APC` (Chapter 1.1 §6). This is a lexical operation; no CUIs are involved yet.

### 5.2. Stage 1 → Stage 3 Handoff — Entity Linking (via SapBERT)

The LLM Cleaner outputs phenotype strings (e.g., *"high blood pressure"*). SapBERT maps these to CUIs (`C0020538`), which are then mapped to HPO IDs (`HP:0000822`) for the Knowledge Graph. The CUI is the pivot that allows the LLM Cleaner's free-text output to be matched to the graph's discrete IDs.

### 5.3. Stage 3 — Cross-Ontology Mapping (via Metathesaurus)

When the Knowledge Graph ingests a new disease from Orphanet (`Orpha:92`), it queries the Metathesaurus to find the corresponding MONDO, OMIM, and ICD-10 codes for the same CUI. This lets the graph interoperate with hospital EHRs (which use ICD-10) and research databases (which use OMIM) without pairwise mapping tables.

## 6. UMLS Licensing — A Practical Note

UMLS is **free for research use** in the U.S. and most countries, but requires a signed license agreement with the NLM. Some source vocabularies within UMLS (notably SNOMED-CT) have additional licensing restrictions for commercial use. The project's pipeline assumes a UMLS Metathesaurus installation is available; for production deployment in a commercial setting, the licensing must be reviewed.
