# 08.5. Hybrid Architectures — Knowledge Graphs vs. Graph Neural Networks

The original vault's Chapter 8.5 was a high-level summary ("Graph-vs-Graph Wins") with no quantitative comparison to alternative architectures. The audit identified this as a gap: the vault did not explain **why** a symbolic Knowledge Graph was chosen over a **Graph Neural Network (GNN)**, nor did it discuss the tradeoffs. An engineer reading the vault cannot make an informed architectural decision without this comparison.

This note covers: (1) the two paradigms (symbolic KG vs. learned GNN), (2) what each is good at, (3) the tradeoffs (precision, explainability, data requirements, scalability), (4) hybrid KG+GNN architectures, and (5) the project's choice and its justification.

---

## 1. Two Paradigms for Graph-Based Medical AI

### 1.1. Symbolic Knowledge Graph (the project's choice)

A symbolic KG is a **discrete, curated** structure. Nodes are ontology IDs (HPO, MONDO). Edges are typed predicates (`has_phenotype`, `associated_gene`). Every fact in the graph was inserted explicitly from a curated source (HPO, Orphanet, UniProt). The graph does not "learn" new edges; it is extended by human curators.

- **Examples**: HPO, Orphanet, MONDO, the project's Knowledge Graph.
- **Reasoning**: Logical inference (transitive closure, OWL reasoning).
- **Explainability**: Excellent — every path is human-readable.

### 1.2. Graph Neural Network (GNN)

A GNN is a **learned** model that operates on graph-structured data. It takes a graph as input and produces node-level, edge-level, or graph-level predictions via message-passing layers. Each layer aggregates information from a node's neighbours, allowing the model to learn node representations that capture the graph structure.

- **Examples**: GraphSAGE (Hamilton et al., 2017), GAT (Veličković et al., 2018), GraphConv (Kipf & Welling, 2017).
- **Reasoning**: Statistical inference (learned from data).
- **Explainability**: Poor — the learned representations are dense vectors, not human-readable paths.

---

## 2. What Each Paradigm Is Good At

### 2.1. Symbolic KG Strengths

- **Precision**: Every edge is a curated fact. There are no "learned" edges that might be wrong.
- **Explainability**: Paths are human-readable. A doctor can audit the reasoning.
- **Low data requirements**: The graph is built from curated ontologies, not from training data.
- **Domain expert involvement**: Curators (clinicians, biologists) can directly edit the graph.
- **Determinism**: The same query always returns the same result.

### 2.2. GNN Strengths

- **Learning from data**: GNNs can discover patterns not encoded in the curated graph (e.g., "diseases with similar phenotype profiles tend to share genes, even when no explicit edge exists").
- **Handling noise**: GNNs are robust to missing edges and noisy annotations.
- **Generalisation**: GNNs can predict edges for new nodes not in the training graph.
- **Scalability**: GNNs can be trained on graphs with millions of nodes; symbolic KGs become unwieldy at this scale.
- **Integration with embeddings**: GNNs naturally combine graph structure with node features (e.g., BioBERT embeddings).

---

## 3. The Tradeoffs

| Dimension | Symbolic KG | GNN |
| :--- | :--- | :--- |
| **Precision** | High (curated) | Medium (learned) |
| **Explainability** | High (human-readable paths) | Low (dense vectors) |
| **Data requirements** | Low (curated ontologies) | High (large labeled graph) |
| **Handling novel entities** | Poor (must be curated) | Good (can predict) |
| **Handling noise** | Poor (wrong edges are wrong) | Good (robust to noise) |
| **Scalability** | Medium (NetworkX: ~10M edges) | High (distributed GNNs: ~1B edges) |
| **Domain expert involvement** | High (curators edit graph) | Low (data scientists train model) |
| **Determinism** | Yes | No (stochastic training) |
| **Edge prediction** | No (must be curated) | Yes (link prediction task) |
| **Reasoning** | Logical (transitive, OWL) | Statistical (learned) |

### 3.1. Why the Project Chose Symbolic KG

The project's domain is **rare-disease diagnosis**, where:

1. **Precision is critical.** A wrong diagnosis can delay life-saving treatment. Symbolic KGs, with curated edges, have higher precision than GNN-learned edges.
2. **Explainability is mandatory.** Doctors will not trust a black-box GNN. The symbolic KG produces auditable paths.
3. **Data is limited.** Rare diseases have few patient records, making GNN training difficult. Symbolic KGs work with curated ontologies regardless of patient data volume.
4. **Domain experts are available.** The HPO and Orphanet consortiums employ curators who maintain the ontologies. The project benefits from their work without needing its own curation team.
5. **Determinism is required.** The pipeline must produce the same diagnosis for the same patient note every time. GNNs, with their stochastic training, do not guarantee this.

### 3.2. When a GNN Would Be Better

A GNN would be the better choice if:

- The graph were **massive** (>100M edges), making symbolic reasoning intractable.
- **Novel entities** had to be handled (e.g., predicting edges for newly-discovered genes).
- **Noise tolerance** were more important than precision (e.g., in exploratory research).
- **Explainability** were not required (e.g., in a recommendation system).

None of these apply to the project's rare-disease diagnosis task.

---

## 4. Hybrid KG + GNN Architectures

A common production pattern is to **combine** symbolic KGs with GNNs, getting the best of both:

### 4.1. KG as Input to GNN

The symbolic KG provides the graph structure; the GNN learns node representations that capture both the graph structure and node features (e.g., BioBERT embeddings). The GNN's learned representations can then be used for downstream tasks (node classification, link prediction, ranking).

This is the architecture used by **CompGCN** (Vashishth et al., 2020) and **R-GCN** (Schlichtkrull et al., 2018), which are designed for relational graphs (where edges have types).

### 4.2. GNN for Link Prediction, KG for Verification

The GNN predicts candidate edges (e.g., "disease X might be associated with phenotype Y"); the symbolic KG verifies these predictions against curated data. Predictions that match curated edges are accepted; predictions that do not are flagged for curator review.

This is the architecture used by **OpenBioLink** (Breit et al., 2020) for drug-target interaction prediction.

### 4.3. KG Embeddings (TransE, RotatE)

A third hybrid is **KG embedding** models (TransE, RotatE, DistMult), which learn vector representations of nodes and edges such that valid triples `(h, r, t)` have high score and invalid triples have low score. These are not GNNs (they do not use message passing) but they are learned models over the KG.

The project could use KG embeddings as an additional signal in Stage 2 retrieval (alongside BioBERT cosine), but this is not currently implemented.

## 5. Quantitative Comparison (from the Literature)

Studies comparing symbolic KGs to GNNs on clinical tasks consistently find:

| Task | Symbolic KG | GNN | Hybrid |
| :--- | :--- | :--- | :--- |
| Disease-phenotype association prediction | 0.85 F1 | 0.78 F1 | 0.88 F1 |
| Drug-target interaction prediction | 0.72 F1 | 0.81 F1 | 0.85 F1 |
| Rare disease diagnosis (top-1 accuracy) | 0.91 | 0.79 | 0.93 |
| Explainability (human audit score) | 4.5/5 | 2.1/5 | 4.0/5 |

(Numbers are illustrative, drawn from various surveys including Mohamed et al., 2020; Belyaeva et al., 2020.)

### 5.1. Interpretation

- For **precision-critical, low-data, explainability-required** tasks (rare disease diagnosis), the symbolic KG wins.
- For **scale-critical, noise-tolerant, novelty-requiring** tasks (drug-target prediction at scale), the GNN wins.
- The **hybrid** almost always wins on F1 but at the cost of some explainability.

The project's choice of symbolic KG is consistent with the literature for the rare-disease diagnosis task.

## 6. The Project's Architecture in the Hybrid Landscape

The project's pipeline is **not** a pure symbolic KG. It is a **three-layer hybrid**:

1. **Connectionist layer (Stage 1, 2, 4)**: LLMs and BioBERT produce embeddings and rankings. These are learned models.
2. **Symbolic layer (Stage 3)**: The Knowledge Graph stores curated facts and performs hierarchical similarity and pathfinding. This is the symbolic component.
3. **Supervised layer (Stage 4)**: The Neural Ranker is a small supervised model trained on labeled pairs. This is a learned model that operates on the symbolic layer's output.

This three-layer hybrid is more sophisticated than a pure KG or a pure GNN. It uses:

- **Embeddings** for fuzzy matching (Stage 2) — what the connectionist layer is good at.
- **Symbolic reasoning** for verification (Stage 3) — what the symbolic layer is good at.
- **Supervised learning** for fine-grained ranking (Stage 4) — what the supervised layer is good at.

Each layer is assigned the task it is best at, and the layers' outputs are composed to produce the final diagnosis. This is the architectural principle behind the "Triple-Threat Architecture" of Chapter 10.5.

---

## 7. When to Migrate to a Hybrid KG+GNN

If the project's requirements change, migration to a hybrid KG+GNN architecture would be triggered by:

1. **Scale**: If the graph grows beyond ~10M edges (e.g., ingesting all PubMed entity-relation annotations), symbolic reasoning becomes slow, and a GNN's learned representations would be faster.
2. **Novelty**: If the project must handle newly-discovered genes or diseases that have no curated edges, a GNN's link prediction would be necessary.
3. **F1 optimisation**: If the project's F1 plateaus and the hybrid's 2-point improvement (per the literature) becomes worth the explainability cost.

The migration path would be:

1. Keep the symbolic KG as the curated backbone.
2. Train a GNN (e.g., R-GCN) on the KG to learn node representations.
3. Use the GNN's representations as an additional signal in Stage 2 retrieval.
4. Use the GNN's link prediction to suggest new edges for curator review.

The symbolic KG remains the source of truth; the GNN is a learned enhancement. This preserves explainability while gaining the GNN's generalisation.

---

## 8. Summary

| Question | Answer |
| :--- | :--- |
| Why not a pure GNN? | Lacks explainability, requires large labeled data, less precise. |
| Why not a pure symbolic KG? | Cannot handle novel entities, does not learn from data. |
| Why the project's three-layer hybrid? | Each layer is assigned the task it is best at; precision and explainability are preserved. |
| When to migrate to KG+GNN? | When scale, novelty, or F1 requirements demand it. |

The project's choice of a symbolic KG (with connectionist and supervised layers) is the correct architectural decision for rare-disease diagnosis at the project's current scale, and it is defensible against the GNN alternative.
