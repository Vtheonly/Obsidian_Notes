# 3.5 Merging Multi-Source Data

## The Multi-Source Fusion Challenge

The solar forecasting system performs a **Multi-Source Fusion** that combines three distinct datasets into a single, coherent DataFrame: the Generation Log, the Weather Log, and the Irradiance Log. Each source has different timestamps, different column names, and different coverage.

## The Merge Process Step-by-Step

### Step 1: Filtering
Filter each dataset to the relevant entity (Site 25 for generation, Campus 1 for weather).

### Step 2: Time Alignment
Convert all timestamps to local time. The irradiance data is in UTC (+10 hours for Melbourne/Bundoora).

### Step 3: Inner Merge (Generation + Weather)
An **inner join** on Timestamp keeps only rows where the timestamp exists in both DataFrames.

### Step 4: As-Of Merge (Combined + Irradiance)
`pd.merge_asof` finds the closest timestamp in the irradiance data for each generation row, within a 15-minute tolerance.

### Step 5: Column Renaming and Selection
Rename columns to the canonical schema and select only needed columns.

## Common Merge Pitfalls

1. **Duplicate timestamps**: Can inflate the dataset through Cartesian products
2. **Sort order**: `merge_asof` requires both DataFrames sorted by the merge key
3. **Timezone mismatches**: Always convert to the same timezone before merging
4. **Missing merge keys**: Rows with NaN merge keys will not match anything

## Key Takeaways

- Multi-source fusion requires careful filtering, time alignment, and column renaming
- `pd.merge_asof` handles imperfect timestamp alignment with configurable tolerance
- Always convert all timestamps to the same timezone before merging
- Verify row counts and check for unexpected NaN after every merge operation

> **Important Reminder**: After merging, always print `df.shape` and `df.isna().sum()`. If the merged DataFrame has significantly fewer rows than expected, you likely have a timestamp alignment issue.
