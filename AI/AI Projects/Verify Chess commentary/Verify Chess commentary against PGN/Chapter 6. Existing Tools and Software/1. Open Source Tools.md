# 1. Open Source Tools

> **Open source tools in one sentence**: A survey of the open-source chess software ecosystem reveals many tools that analyze games, generate commentary, or coach players — but none that verify commentary against the board.

This note catalogs the relevant open-source tools and explains what each does and does not do.

---

## 1.1 Libraries (Building Blocks)

### 1.1.1 python-chess

- **Repository**: github.com/niklasf/python-chess
- **What it does**: PGN parsing, FEN handling, legality checking, attack maps, pin detection.
- **What it does NOT do**: Verification, commentary, evaluation.
- **Use in our project**: Core dependency. See [[Chapter 3. Core Components/1. python-chess|1. python-chess]].

### 1.1.2 Stockfish

- **Repository**: github.com/official-stockfish/Stockfish
- **What it does**: Chess engine, evaluation, best move, PV.
- **What it does NOT do**: PGN parsing for our purposes (it has a parser but it is not designed for data extraction), commentary, verification.
- **Use in our project**: Core dependency. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

### 1.1.3 lc0 (Leela Chess Zero)

- **Repository**: github.com/LeelaChessZero/lc0
- **What it does**: Neural-network-based chess engine. Provides evaluations and move probabilities.
- **What it does NOT do**: Verification, commentary.
- **Use in our project**: Optional. Could replace Stockfish in v2 if move-probability features are needed.

### 1.1.4 chess.js (JavaScript)

- **Repository**: github.com/jhlywa/chess.js
- **What it does**: JavaScript port of python-chess functionality.
- **Use in our project**: Could be useful for the Obsidian plugin (which runs in JavaScript). Not used in the Python verifier.

### 1.1.5 chessboard.js (JavaScript)

- **Repository**: chessboardjs.com
- **What it does**: Renders chess boards in the browser.
- **Use in our project**: Useful for the Obsidian plugin's UI (rendering positions in tooltips).

## 1.2 Analysis Tools

### 1.2.1 Scid vs. PC

- **Repository**: sourceforge.net/projects/scidvspc
- **What it does**: Chess database GUI with engine analysis. Plays PGNs, runs Stockfish, displays evaluations.
- **What it does NOT do**: Verify commentary. Scid does not parse English; it shows engine analysis alongside moves but does not check whether prose matches the moves.

### 1.2.2 ChessX

- **Repository**: github.com/novice79/chessx
- **What it does**: Similar to Scid. Cross-platform chess database.
- **What it does NOT do**: Verify commentary.

### 1.2.3 pychess

- **Repository**: github.com/pychess/pychess
- **What it does**: Python chess GUI. Plays games, runs engines.
- **What it does NOT do**: Verify commentary.

### 1.2.4 mila

- **Repository**: github.com/MarkZH/mila
- **What it does**: Command-line PGN tool. Searches, filters, and analyzes games.
- **What it does NOT do**: Verify commentary.

## 1.3 Commentary Generators

### 1.3.1 Ghostwriter

- **Repository**: github.com/wcmac3/ghostwriter (and similar)
- **What it does**: Generates commentary from PGN using GPT-2 or similar LLMs.
- **What it does NOT do**: Verify commentary. Goes in the wrong direction.

### 1.3.2 chess-commentary-generator (various)

- Multiple GitHub projects attempt to generate commentary from positions.
- All go in the wrong direction (board → text).
- None verify.

### 1.3.3 lichess-bot

- **Repository**: github.com/careless25/lichess-bot
- **What it does**: A bridge for running bots on Lichess. Some configurations include commentary features.
- **What it does NOT do**: Verify commentary.

## 1.4 AI Chess Coaches (Closest Existing Tools)

This category is the closest to our project. These tools analyze a user's game and provide natural-language explanations of mistakes. They typically combine Stockfish with an LLM.

### 1.4.1 chessreview (Reddit, 2025)

- **Link**: [Reddit post](https://www.reddit.com/r/lichess/comments/1uf8t5w/)
- **What it does**: Free chess review tool that explains why moves were mistakes in plain English, grounded in Stockfish.
- **Architecture**: PGN → Stockfish identifies mistakes → LLM generates explanation grounded in Stockfish's analysis.
- **What it does NOT do**: Verify user commentary. It generates its own commentary; it does not check user commentary.

This is the closest open-source tool to our project. It validates the architectural pattern (Stockfish + LLM, LLM only as translator), but it goes in the wrong direction (generating explanations, not verifying them).

### 1.4.2 Other AI coaches

- Several commercial AI coaches exist (Chessable, Aimchess, etc.).
- All generate commentary; none verify user commentary.
- All use the same architectural pattern as chessreview.

## 1.5 Verification-Adjacent Tools

### 1.5.1 PGN syntax validators

- Various tools validate PGN syntax (e.g., pgn-validator on npm).
- These check that PGN is well-formed; they do not check whether commentary matches the PGN.
- Useful as a preprocessing step in our pipeline.

### 1.5.2 Chess tactic detectors

- Tools that scan positions for tactical patterns (forks, pins, etc.).
- Examples: chess-tactics-detector (various).
- Useful as a component in our verifier (for tactical claim verification).
- Do not handle commentary.

### 1.5.3 Chess puzzle generators

- Tools that generate puzzles from game positions.
- Examples: lichess-puzzler, puzzle-generator.
- Useful for testing tactical claim verification but not directly relevant.

## 1.6 Why No Open Source Verifier Exists

The reasons mirror those in Chapter 5.6.4:

1. **Problem formulation is non-obvious.** Most developers think in terms of generation, not verification.
2. **Cross-disciplinary knowledge required.** NLP + chess engines + software engineering + chess domain expertise.
3. **No benchmark.** Without a public benchmark, open-source contributors have nothing to optimize for.
4. **Commercial incentive is weak.** Open source contributors often work on tools they would use themselves. Most chess players do not write commentary; they play. The audience for a verifier is narrow.

The implication: if you build and open-source a verifier, you will likely be the first. This is a research and engineering opportunity, not a competitive risk.

## 1.7 What to Reuse from Open Source

| Component | Reuse from | Notes |
|---|---|---|
| PGN parsing | python-chess | Standard, well-maintained. |
| Engine analysis | Stockfish | Standard, free. |
| Board rendering (Obsidian plugin) | chessboard.js | JavaScript, embeddable. |
| PGN syntax validation | pgn-validator | Preprocessing. |
| Tactic detection | Custom (no good library) | Build your own using python-chess attack maps. |
| Commentary generation | Do not reuse | Wrong direction. |

---

## 1.8 Key Reminders

- Open source ecosystem has many libraries (python-chess, Stockfish, lc0, chess.js) and many tools (Scid, ChessX, pychess).
- Commentary generators (Ghostwriter, etc.) go in the wrong direction.
- AI chess coaches (chessreview) are the closest existing tools. They combine Stockfish + LLM but generate commentary, not verify it.
- Verification-adjacent tools (PGN validators, tactic detectors) cover pieces of the problem but not the whole.
- No open-source verifier exists. The reasons are problem formulation, cross-disciplinary knowledge, no benchmark, weak commercial incentive.
- Reuse python-chess, Stockfish, chessboard.js. Build your own tactic detector. Do not reuse commentary generators.
- Building and open-sourcing a verifier is a research and engineering opportunity, not a competitive risk.
