## 4.2 Claim 1: Fork

**Claim**: `tactical_fork` with `{attacker_color: "white", attacking_piece: "knight", attacking_square: "f7", target_pieces: ["king", "queen"]}`

**Target ply hint**: 4 (use Position A)

### Your task

Verify the fork:
1. Confirm the attacking piece is on the attacking square.
2. Look up the attack map for the attacking square.
3. Check whether the target pieces are both in the attacked set.

### Worked solution

From Position A (after ply 4):

- White knight on f7: confirmed (check `board.piece_at(f7)`).
- Attack map for f7: `{g5, e5, h8, h6, d8, d6}`.
- Black king on h8: in the attacked set? Yes (`h8 ∈ {g5, e5, h8, h6, d8, d6}`).
- Black queen on d8: in the attacked set? Yes (`d8 ∈ {g5, e5, h8, h6, d8, d6}`).
- Both target pieces are attacked simultaneously by the knight on f7.

**Verdict**: Verified. "At ply 4, the white knight on f7 forks the black king on h8 and the black queen on d8. This is the classic royal fork."

### Verification code (Python with python-chess)

```python
def verify_fork(claim, facts):
    ply = facts.plies[claim.target_ply_hint]
    board = chess.Board(fply.fen_after)
    
    attacker_square = chess.parse_square(claim.params.attacking_square)
    piece = board.piece_at(attacker_square)
    
    if piece is None or piece.piece_type != piece_code(claim.params.attacking_piece):
        return Verdict("Contradicted", f"No {claim.params.attacking_piece} on {claim.params.attacking_square}.")
    
    attacked_squares = board.attacks(attacker_square)
    
    attacked_pieces = []
    for square in attacked_squares:
        target_piece = board.piece_at(square)
        if target_piece and target_piece.color != piece.color:
            attacked_pieces.append((square, target_piece))
    
    # Check that all claimed target pieces are attacked
    for target in claim.params.target_pieces:
        target_type = piece_code(target)
        if not any(p.piece_type == target_type for _, p in attacked_pieces):
            return Verdict("Contradicted", f"No {target} attacked by the {claim.params.attacking_piece} on {claim.params.attacking_square}.")
    
    return Verdict("Verified", 
        f"At ply {ply.ply_index}, the {claim.params.attacker_color} {claim.params.attacking_piece} on {claim.params.attacking_square} forks " + 
        ", ".join(claim.params.target_pieces) + ".")
```

### Tips

- Use `board.attacks(square)` to get the set of squares attacked by the piece on that square.
- Filter for enemy pieces (the target pieces must be enemy pieces).
- Check that ALL claimed target pieces are in the attacked set, not just some.
- A "royal fork" (king and queen) is the most common fork claim.

### Common mistakes

- **Counting pawns as forked pieces.** A knight attacking two pawns is technically a double attack but is rarely called a fork. The verifier should require at least two valuable pieces (king, queen, rook, or sometimes bishop/knight) for a `Verified` verdict.
- **Forgetting to check the attacker's square.** The claim specifies the attacker's square; verify the piece is actually there.
- **Confusing fork with pin.** A fork is one piece attacking two; a pin is one piece restricting another. The verifier should not conflate them.

## 4.3 Claim 2: Pin

**Claim**: `tactical_pin` with `{attacker_color: "white", attacking_piece: "bishop", attacking_square: "g5", target_pieces: ["knight", "king"]}` (the knight is the pinned piece, the king is the piece it is pinned to)

**Target ply hint**: 6 (use Position B)

### Your task

1. Confirm the attacker (bishop) is on the attacking square (g5).
2. Confirm the pinned piece (knight) is between the attacker and the back piece (king) on a line.
3. Confirm there is exactly one piece between attacker and back piece.
4. Confirm the back piece is more valuable than the pinned piece (or is the king).

### Worked solution

From Position B (after ply 6):

- White bishop on g5: confirmed.
- Black knight on f6: confirmed.
- Black king on e7: confirmed.
- Are g5, f6, e7 on the same line? g5 to f6: file -1, rank +1. f6 to e7: file -1, rank +1. Same diagonal. Yes.
- Is there exactly one piece between g5 and e7? The squares between g5 and e7 on the diagonal are f6. There is one piece on f6 (the knight). Yes, exactly one.
- Is the back piece (king) more valuable than the pinned piece (knight)? Yes (king is invaluable; knight is 3).
- Is the back piece the king? Yes — absolute pin.

**Verdict**: Verified. "At ply 6, the white bishop on g5 absolutely pins the black knight on f6 to the black king on e7. The knight cannot move without exposing the king to check."

### Verification code (using python-chess's built-in pin detection)

```python
def verify_pin(claim, facts):
    ply = facts.plies[claim.target_ply_hint]
    board = chess.Board(ply.fen_after)
    
    attacker_square = chess.parse_square(claim.params.attacking_square)
    attacker_piece = board.piece_at(attacker_square)
    
    if attacker_piece is None or attacker_piece.piece_type != piece_code(claim.params.attacking_piece):
        return Verdict("Contradicted", f"No {claim.params.attacking_piece} on {claim.params.attacking_square}.")
    
    # Use python-chess's pin detection
    # board.pin(color, square) returns the set of squares forming the pin ray
    pinned_piece_type = piece_code(claim.params.target_pieces[0])
    back_piece_type = piece_code(claim.params.target_pieces[1])
    
    # Find the pinned piece
    pinned_square = None
    for square in chess.SQUARES:
        p = board.piece_at(square)
        if p and p.piece_type == pinned_piece_type and p.color != attacker_piece.color:
            pinned_square = square
            break
    
    if pinned_square is None:
        return Verdict("Contradicted", f"No enemy {claim.params.target_pieces[0]} on the board.")
    
    # Check if the piece is pinned
    pin_ray = board.pin(not attacker_piece.color, pinned_square)
    if attacker_square not in pin_ray:
        return Verdict("Contradicted", f"The {claim.params.target_pieces[0]} is not pinned by the {claim.params.attacking_piece} on {claim.params.attacking_square}.")
    
    # Find the back piece (the piece the pinned piece is pinned to)
    back_square = None
    for square in pin_ray:
        if square != attacker_square and square != pinned_square:
            p = board.piece_at(square)
            if p and p.piece_type == back_piece_type:
                back_square = square
                break
    
    if back_square is None:
        return Verdict("Contradicted", f"The pinned piece is not pinned to a {claim.params.target_pieces[1]}.")
    
    # Check if the back piece is the king (absolute pin)
    if back_piece_type == chess.KING:
        return Verdict("Verified", 
            f"At ply {ply.ply_index}, the white bishop on {claim.params.attacking_square} absolutely pins "
            f"the {claim.params.target_pieces[0]} on {chess.square_name(pinned_square)} to the "
            f"{claim.params.target_pieces[1]} on {chess.square_name(back_square)}.")
    else:
        return Verdict("Verified", 
            f"At ply {ply.ply_index}, the white bishop on {claim.params.attacking_square} relatively pins "
            f"the {claim.params.target_pieces[0]} on {chess.square_name(pinned_square)} to the "
            f"{claim.params.target_pieces[1]} on {chess.square_name(back_square)}.")
```

### Tips

- Use python-chess's `board.pin(color, square)` to detect pins. This returns the set of squares forming the pin ray.
- Absolute pins (to the king) restrict legal moves. Relative pins (to a queen, rook, etc.) do not restrict legal moves but make moving tactically bad.
- Always distinguish absolute and relative pins in the explanation.

### Common mistakes

- **Confusing pin with skewer.** Pin = front piece cannot move; skewer = front piece must move. The verifier should check which.
- **Forgetting the "more valuable" requirement.** A rook pinned to a pawn is not a standard pin (the rook is more valuable than the back piece).
- **Missing the "exactly one piece between" requirement.** Two pieces between the attacker and back piece is not a pin.

## 4.4 Claim 3: Skewer

**Claim**: `tactical_skewer` with `{attacker_color: "white", attacking_piece: "bishop", attacking_square: "b2", target_pieces: ["king", "rook"]}` (the king is the front piece, the rook is the back piece)

Verify the skewer:
1. Confirm the attacker (bishop) is on the attacking square (b2).
2. Confirm the front piece (king) is on a line with the attacker and is directly attacked.
3. Confirm the back piece (rook) is behind the front piece on the same line.
4. Confirm there is no piece between the attacker and the front piece (direct attack).
5. Confirm the back piece is less valuable than the front piece.

### Worked solution

From Position C (after ply 8):

- White bishop on b2: confirmed.
- Black king on g7: confirmed.
- Black rook on h8: confirmed.
- Are b2, g7, h8 on the same line? b2 to g7: file +5, rank +5. Same slope (+1, +1). Yes, diagonal. g7 to h8: file +1, rank +1. Same diagonal. Yes.
- Is there any piece between b2 and g7? Squares between b2 and g7 on the diagonal: c3, d4, e5, f6. Are any occupied? In this position, no. Direct attack.
- Is the back piece (rook, value 5) less valuable than the front piece (king, invaluable)? Yes.
- Is the front piece the king (must move out of check)? Yes.

### Verification logic

Skewer verification is similar to pin verification, but the front piece is the more valuable piece (often the king) and the back piece is the less valuable piece.

```python

    # - The back piece is behind the front piece on the same line

    # - The front piece must move (e.g., it is the king in check)

```

### Tips

- Skewer is the inverse of pin: pin = front piece stuck; skewer = front piece must move.
- If the front piece is the king, the skewer is forced (king must move out of check).
- If the front piece is not the king, the skewer might not be effective (the front piece could move and defend the back piece, or counterattack).

### Common mistakes

- **Confusing skewer with pin.** Always check: does the front piece move (skewer) or is it stuck (pin)?
- **Forgetting the "front piece must move" requirement.** If the front piece is the king, this is automatic (king must move out of check). If it is another piece, the verifier should check whether moving is forced.

### Verification logic

```python
def verify_discovered_attack(claim, facts):
    ply_before = facts.plies[claim.target_ply_hint - 1]
    ply_after = facts.plies[claim.target_ply_hint]
    
    board_before = chess.Board(ply_before.fen_after)
    board_after = chess.Board(ply_after.fen_after)
    
    attacker_color = chess.WHITE if claim.params.attacker_color == "white" else chess.BLACK
    
    # Find squares that are newly attacked
    new_attacks = set()
    for square in chess.SQUARES:
        was_attacked = square in board_before.attacker_map(attacker_color)
        is_attacked = square in board_after.attacker_map(attacker_color)
        if is_attacked and not was_attacked:
            new_attacks.add(square)
    
    # Check if the target square is in the new attacks
    target_square = chess.parse_square(claim.params.target_square)
    if target_square not in new_attacks:
        return Verdict("Contradicted", f"No new attack on {claim.params.target_square} after ply {claim.target_ply_hint}.")
    
    # Check if the target piece is on the target square
    target_piece = board_after.piece_at(target_square)
    if target_piece is None or target_piece.piece_type != piece_code(claim.params.target_piece):
        return Verdict("Contradicted", f"No {claim.params.target_piece} on {claim.params.target_square} after ply {claim.target_ply_hint}.")
    
    return Verdict("Verified", 
        f"At ply {claim.target_ply_hint}, the {claim.params.attacker_color} {claim.params.attacking_piece}'s move "
        f"reveals a discovered attack by the {claim.params.discovered_attacker_piece} on {claim.params.discovered_attacker_square} "
        f"against the {claim.params.target_piece} on {claim.params.target_square}.")
```

### Tips

- Discovered attacks require comparing attack maps before and after a move.
- The moving piece and the discovering piece are different. The verifier should confirm this.
- If the target piece is the enemy king, the discovered attack is a discovered check (stronger).

### Common mistakes

- **Confusing discovered attack with double attack.** A double attack is one piece attacking two things; a discovered attack is two pieces (one moving, one revealing).
- **Missing the discovered check pattern.** If the revealed attack is on the enemy king, that is a discovered check, which is much stronger. The verifier should explicitly mention "discovered check" in the verdict.

### Verification logic

```python
def verify_double_check(claim, facts):
    ply = facts.plies[claim.target_ply_hint]
    board = chess.Board(ply.fen_after)
    
    attacker_color = chess.WHITE if claim.params.attacker_color == "white" else chess.BLACK
    target_color = not attacker_color
    
    # Find the enemy king
    king_square = board.king(target_color)
    if king_square is None:
        return Verdict("Contradicted", f"No {claim.params.target_color} king on the board.")
    
    # Count attackers
    attackers = board.attackers(attacker_color, king_square)
    
    if len(attackers) == 2:
        attacker_names = [f"{piece_name(board.piece_at(s).piece_type)} on {chess.square_name(s)}" for s in attackers]
        return Verdict("Verified", 
            f"At ply {ply.ply_index}, the {claim.params.target_color} king on {chess.square_name(king_square)} "
            f"is in double check from the {claim.params.attacker_color} " + " and ".join(attacker_names) + ". "
            f"The king must move; no other response is legal in double check.")
    elif len(attackers) == 1:
        return Verdict("Contradicted", 
            f"At ply {ply.ply_index}, the {claim.params.target_color} king is in check from only one piece. "
            f"This is a single check, not a double check.")
    else:
        return Verdict("Contradicted", 
            f"At ply {ply.ply_index}, the {claim.params.target_color} king is not in check.")
```

### Tips

- Use `board.attackers(color, square)` to count attackers on a square.
- Double check almost always involves a discovered check (one piece moves, giving check directly, while also revealing a check from another piece).
- In double check, the king MUST move. No other response (block, capture) is legal because there are two attackers.

### Common mistakes

- **Calling any check a double check.** A single check is just a check. The verifier must count exactly two attackers.
- **Forgetting that double check forces the king to move.** The verifier should mention this in the explanation; it is a key tactical point.

## 4.8 Patterns to Remember

1. **Fork**: one piece attacks two valuable pieces simultaneously. Use `board.attacks(square)`.
2. **Pin**: one piece restricts another from moving (because a more valuable piece is behind). Use `board.pin(color, square)`.
3. **Skewer**: one piece attacks a valuable piece, forcing it to move and exposing a less valuable piece behind.
4. **Discovered attack**: compare attack maps before and after a move; find newly revealed attacks.
5. **Double check**: count attackers on the enemy king; exactly two = double check. King must move.

---

## 4.9 Tips and Tricks

- Use python-chess's built-in methods: `board.attacks(square)`, `board.attackers(color, square)`, `board.pin(color, square)`, `board.is_pinned(color, square)`.
- For discovered attacks, compare attack maps before and after a move. Set difference reveals newly revealed attacks.
- For forks, count enemy valuable pieces in the attacked set. At least two = fork.
- For pins, check the back piece. If it is the king, the pin is absolute.
- For skewers, check the front piece. If it is the king, the skewer is forced.
- For double check, the king MUST move. Mention this in the explanation.

## 4.10 Common Mistakes to Avoid

- **Calling any double attack a fork.** A pin or skewer is also a "double attack" but is not a fork.
- **Confusing pin with skewer.** Pin = front piece stuck; skewer = front piece must move.
- **Missing the discovered check pattern.** If the revealed attack is on the king, mention "discovered check" explicitly.
- **Counting pawns as forked pieces.** A fork of two pawns is technically a double attack but is rarely called a fork.
- **Forgetting the "more valuable" requirement for pins.** A rook pinned to a pawn is not a standard pin.
- **Inventing the attacker's square.** The verifier must check that the claimed attacker is actually on the claimed square.

## 4.11 Key Reminders

- Five tactical claim types: fork, pin, skewer, discovered attack, double check.
- Each type has a specific verification algorithm using attack maps and python-chess's built-in methods.
- Use `board.attacks()` for forks, `board.pin()` for pins, attack map comparison for discovered attacks, `board.attackers()` for double check.
- Always check the claim's specifics: attacker's square, target pieces, special conditions.
- Distinguish absolute vs. relative pins. Distinguish single check vs. double check.
- Mention forced responses in the explanation (e.g., "king must move" for double check).
- Tactical claims are the hardest type to verify but also the most rewarding — they catch the most egregious LLM hallucinations.
