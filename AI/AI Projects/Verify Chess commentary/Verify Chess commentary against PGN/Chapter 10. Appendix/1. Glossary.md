# 1. Glossary

> Definitions of every term used in this vault. If a term is unfamiliar, look it up here.

---

## A

### Absolute pin
A pin where the back piece is the king. The pinned piece cannot legally move out of the line because doing so would expose the king to check. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### Attack map
A data structure that records, for each square, which pieces attack it. Stored per ply in the facts database. Used for tactical claim verification. See [[Chapter 2. System Architecture/4. The Facts Database|4. The Facts Database]].

### Ambiguous (verdict)
A verdict label indicating that the claim's parameters are too vague to verify, or that multiple matching plies exist. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

### Annotator
A person who labels claims with ground-truth verdicts for the CCVB benchmark. Annotators should be at least 1500 Elo; 2000+ for strategic claims. See [[Chapter 5. Research Landscape/4. Datasets|4. Datasets]].

### API
Application Programming Interface. Used to invoke LLMs (OpenAI, Anthropic, ZhipuAI) and to drive Stockfish via UCI. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

---

## B

### Backward pawn
A pawn on a half-open file that cannot advance safely because the advance square is controlled by enemy pawns. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

### Bishop pair
Having both bishops (light-squared and dark-squared). Generally considered worth about +0.5 pawns. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

### BLEU
Bilingual Evaluation Understudy. A metric for text similarity. Useful for generation tasks; not useful for verification. See [[Chapter 5. Research Landscape/1. Chess Commentary Generation|1. Chess Commentary Generation]].

---

## C

### Cannot verify automatically (verdict)
A verdict label indicating that the verifier does not handle this claim type, or that required facts are missing. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

### Captured piece
The piece that was taken in a capture move. Stored as `captured_piece` in the per-ply record. See [[Chapter 4. Claim Types and Verification/2. Captures|2. Captures]].

### Castling
A special king move that also moves a rook. Kingside (O-O) or queenside (O-O-O). Recorded as a king move with `is_castling: true`. See [[Chapter 4. Claim Types and Verification/1. Move Descriptions|1. Move Descriptions]].

### CCVB
Chess Commentary Verification Benchmark. The proposed 2000-example labeled dataset for commentary verification. See [[Chapter 5. Research Landscape/4. Datasets|4. Datasets]] and [[Chapter 7. Novelty and Research Value/4. Defining the Benchmark|4. Defining the Benchmark]].

### Check
A position where the king is attacked. The player to move must respond to the check. Stored as `is_check: true` on the move that gave check. See [[Chapter 4. Claim Types and Verification/1. Move Descriptions|1. Move Descriptions]].

### Checkmate
A position where the king is in check and has no legal response. The game is over. Stored as `is_checkmate: true`. See [[Chapter 4. Claim Types and Verification/1. Move Descriptions|1. Move Descriptions]].

### Claim
A structured assertion extracted from natural-language commentary. Has a type, parameters, and (optionally) a target ply hint. See [[Chapter 3. Core Components/3. LLM for Claim Extraction|3. LLM for Claim Extraction]].

### Claim type
The category of a claim. v1 supports: `move_description`, `capture`, `material_gain`. v2 adds tactical and strategic types. See [[Chapter 4. Claim Types and Verification/1. Move Descriptions|Chapter 4]].

### Cohen's kappa
A metric for inter-annotator agreement, corrected for chance. Target: >= 0.7 overall. See [[Chapter 8. Implementation Roadmap/3. Evaluation Strategy|3. Evaluation Strategy]].

### Contradicted (verdict)
A verdict label indicating that the claim is unambiguously false given the board state. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

---

## D

### Delta (material)
The material balance from White's perspective: `white_material - black_material`. Positive = White is up. Stored per ply in the material timeline. See [[Chapter 4. Claim Types and Verification/5. Material Claims|5. Material Claims]].

### Depth (Stockfish)
The search depth of the engine. Higher = more accurate = slower. Recommended: depth 18 for the verifier. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

### Discovered attack
A tactic where moving one piece reveals an attack from another piece. If the revealed attack is on the king, it is a discovered check. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### Double check
A position where the king is attacked by two pieces simultaneously. The king must move; no other response is legal. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### Doubled pawns
Two pawns of the same color on the same file. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

---

## E

### En passant
A special pawn capture where the capturing pawn lands on an empty square behind the enemy pawn that just moved two squares. The captured pawn is NOT on the destination square. See [[Chapter 4. Claim Types and Verification/2. Captures|2. Captures]].

### Evaluation (engine)
Stockfish's assessment of a position, in centipawns (positive = White is better) or mate-in-N. Stored per ply in the facts database. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

### Exchange
Winning the exchange means gaining a rook for a minor piece (knight or bishop), netting +2. See [[Chapter 4. Claim Types and Verification/5. Material Claims|5. Material Claims]].

---

## F

### Facts database
The precomputed per-ply record of board state, moves, attack maps, and engine evaluations. The single source of truth for the verifier. See [[Chapter 2. System Architecture/4. The Facts Database|4. The Facts Database]].

### FEN
Forsyth-Edwards Notation. A single-line description of a board position. Used by python-chess and Stockfish. See [[Chapter 3. Core Components/1. python-chess|1. python-chess]].

### Fork
A tactic where one piece attacks two or more valuable pieces simultaneously. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### F1
The harmonic mean of precision and recall. The primary metric for verification. See [[Chapter 8. Implementation Roadmap/3. Evaluation Strategy|3. Evaluation Strategy]].

---

## G

### Game-total (window)
A material claim window that compares material at the start of the game to material at the end. See [[Chapter 4. Claim Types and Verification/5. Material Claims|5. Material Claims]].

---

## H

### Half-open file
A file with pawns of only one color. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

### Hallucination
An LLM producing fluent text that is factually wrong. The central failure mode this project targets. See [[Chapter 1. Project Overview/2. The Core Problem|2. The Core Problem]].

### Hallucination laundering
The cycle where LLM-generated errors get reposted and enter the training data of future LLMs, making the errors more likely to be repeated. See [[Chapter 1. Project Overview/4. Why This Project Matters|4. Why This Project Matters]].

---

## I

### Initiative
A strategic concept referring to the ability to make threats that the opponent must respond to. See [[Chapter 4. Claim Types and Verification/4. Strategic Claims|4. Strategic Claims]].

### Isolated pawn
A pawn with no friendly pawns on either adjacent file. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

---

## K

### King safety
A strategic concept referring to how exposed the king is to attack. See [[Chapter 4. Claim Types and Verification/4. Strategic Claims|4. Strategic Claims]].

### Kappa
See Cohen's kappa.

---

## L

### Legal move
A move that complies with the rules of chess. python-chess's `board.legal_moves` returns an iterator of legal moves. See [[Chapter 3. Core Components/1. python-chess|1. python-chess]].

### LLM
Large Language Model. Used in this project for claim extraction only, never for verification. See [[Chapter 3. Core Components/3. LLM for Claim Extraction|3. LLM for Claim Extraction]].

---

## M

### Material balance
The total piece value for each color. White's material minus Black's material is the "delta". See [[Chapter 4. Claim Types and Verification/5. Material Claims|5. Material Claims]].

### Material timeline
A denormalized view in the facts database giving the material balance at every ply. Makes material claim verification O(1). See [[Chapter 2. System Architecture/4. The Facts Database|4. The Facts Database]].

### Move (chess)
A full move consists of two plies (White + Black). Distinguished from ply. See [[Chapter 2. System Architecture/4. The Facts Database|4. The Facts Database]].

### Move description (claim type)
A claim that a specific piece moved to a specific square. See [[Chapter 4. Claim Types and Verification/1. Move Descriptions|1. Move Descriptions]].

---

## O

### Open file
A file with no pawns of either color. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

### Outpost
A square on the opponent's side of the board that cannot be attacked by an enemy pawn, often occupied by a knight. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

---

## P

### Pawn shield
The pawns directly in front of a castled king. A full pawn shield (3 pawns) provides king safety. See [[Chapter 4. Claim Types and Verification/4. Strategic Claims|4. Strategic Claims]].

### PGN
Portable Game Notation. The standard text format for recording chess games. Parsed by python-chess. See [[Chapter 3. Core Components/1. python-chess|1. python-chess]].

### Pin
A tactic where a piece cannot move without exposing a more valuable piece behind it to attack. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### Ply
A half-move (one player's move). The atomic unit of the facts database. See [[Chapter 2. System Architecture/4. The Facts Database|4. The Facts Database]].

### Positional claim
A claim about a static feature of the position (pawn structure, piece placement, etc.). See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

### Possible hallucination (verdict)
A verdict label indicating that the claim has no support in the game or position. Stronger warning than `Contradicted`. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

### Precision
Of the claims the verifier labeled `Verified` or `Contradicted`, the fraction that match ground truth. See [[Chapter 8. Implementation Roadmap/3. Evaluation Strategy|3. Evaluation Strategy]].

### Promotion
A pawn reaching the 8th rank (for White) or 1st rank (for Black) and being replaced by a queen, rook, bishop, or knight. See [[Chapter 4. Claim Types and Verification/1. Move Descriptions|1. Move Descriptions]].

### PV (Principal Variation)
The engine's main line — the sequence of moves it considers best for both sides. Typically 8-15 plies. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

---

## R

### Recall
Of the claims the ground truth labels `Verified` or `Contradicted`, the fraction the verifier also labeled correctly. See [[Chapter 8. Implementation Roadmap/3. Evaluation Strategy|3. Evaluation Strategy]].

### Recapture
A capture on the same square as the immediately preceding capture. Detected by checking `ply[N].to_square == ply[N-1].to_square` with both being captures. See [[Chapter 4. Claim Types and Verification/2. Captures|2. Captures]].

### Relative pin
A pin where the back piece is not the king. The pinned piece can legally move, but doing so loses material. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

---

## S

### SAN
Standard Algebraic Notation. The move notation used inside PGN. Examples: `Nf3`, `Bxh7+`, `O-O`, `Qxe8#`. See [[Chapter 3. Core Components/1. python-chess|1. python-chess]].

### Sacrifice
A deliberate material loss for compensation. The verifier confirms the capture but does not judge sacrifice soundness in v1. See [[Chapter 4. Claim Types and Verification/2. Captures|2. Captures]].

### Separation of concerns
The architectural principle that the LLM extracts claims and the symbolic engine verifies them, with no overlap. See [[Chapter 2. System Architecture/2. The Core Idea Separation of Concerns|2. The Core Idea Separation of Concerns]].

### Skewer
A tactic where a valuable piece is attacked and must move, exposing a less valuable piece behind it. The inverse of a pin. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### Soft verdict
A verdict on a strategic or positional claim that includes a confidence score. Either `Supported (soft)` or `Contradicted (soft)`. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

### Stockfish
The strongest open-source chess engine. Used for evaluation and best-move computation. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

### Strategic claim
A claim about a dynamic feature of the position (initiative, king safety trend, etc.). See [[Chapter 4. Claim Types and Verification/4. Strategic Claims|4. Strategic Claims]].

### Structured output
A mode of LLM output where the response is constrained to a JSON schema. Essential for reliable claim extraction. See [[Chapter 3. Core Components/3. LLM for Claim Extraction|3. LLM for Claim Extraction]].

### Supported (soft) (verdict)
A verdict label for soft claims that are supported by engine analysis but are not binary facts. Includes a confidence score. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

---

## T

### Tactical claim
A claim about a tactical pattern (fork, pin, skewer, etc.). See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].

### Target ply hint
An optional field in a claim indicating which ply the claim refers to. When absent, the verifier searches for matching plies. See [[Chapter 3. Core Components/3. LLM for Claim Extraction|3. LLM for Claim Extraction]].

### Threefold repetition
A draw condition when the same position occurs three times. Not handled in v1 verification.

---

## U

### UCI
Universal Chess Interface. The protocol Stockfish uses to communicate. Driven via subprocess in this project. See [[Chapter 3. Core Components/2. Stockfish|2. Stockfish]].

### UCI move notation
A move format like `e2e4`, `g1f3`, `e7e8q` (promotion). Used internally by chess engines. See [[Chapter 3. Core Components/1. python-chess|1. python-chess]].

---

## V

### Verified (verdict)
A verdict label for binary claims that are unambiguously supported by the board state. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

### Verifier
The deterministic component that takes a claim and a facts database and emits a verdict. Pure function: `(claim, facts) -> verdict`. See [[Chapter 3. Core Components/4. Symbolic Verifier|4. Symbolic Verifier]].

### Verdict
The output of the verifier for a single claim. Includes a label (one of six) and an explanation string. See [[Chapter 2. System Architecture/3. Inputs and Outputs|3. Inputs and Outputs]].

---

## W

### Weak square
A square that cannot be defended by a friendly pawn and is controlled by an enemy piece. See [[Chapter 4. Claim Types and Verification/6. Positional Claims|6. Positional Claims]].

### Window (material claim)
The range of plies over which a material claim is evaluated. Three types: single-ply, move-sequence, game-total. See [[Chapter 4. Claim Types and Verification/5. Material Claims|5. Material Claims]].

---

## Z

### Zugzwang
A position where any move weakens the position; the player would prefer to pass. Difficult to verify; requires engine analysis. See [[Chapter 4. Claim Types and Verification/3. Tactical Claims|3. Tactical Claims]].
