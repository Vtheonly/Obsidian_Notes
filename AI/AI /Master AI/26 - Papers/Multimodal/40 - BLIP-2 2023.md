# 40 — BLIP-2 (Li et al., 2023)

> [!info] TL;DR
> BLIP-2 (Bootstrapping Language-Image Pretraining 2) is a multimodal architecture that bridges a frozen image encoder and a frozen LLM with a small, trainable **Q-Former** (Querying Transformer). The Q-Former learns to extract a fixed number of visual features (typically 32 tokens) from the image encoder, which are then fed to the LLM as soft prompts. By freezing both the expensive vision and language backbones, BLIP-2 trains a bridge with ~188M parameters instead of retraining a 10B+ parameter multimodal model from scratch. The pattern — freeze backbones, train a bridge — became the standard for VLMs (LLaVA, Qwen-VL, MiniGPT-4 all descend from BLIP-2's design philosophy).

## Citation

Li, J., Li, D., Savarese, S., & Hoi, S. (2023). *BLIP-2: Bootstrapping Language-Image Pre-training with Frozen Image Encoders and Large Language Models*. ICML 2023. arXiv:2301.12597.

## The Problem Being Solved

In 2022, multimodal models like [[37 - Flamingo 2022|Flamingo]] and the original BLIP trained the entire vision + language model end-to-end. This required massive compute (Flamingo 80B trained on thousands of TPUv4 for weeks). Two trends made this wasteful:

1. **Vision encoders had matured** — CLIP, ViT, and EVA-CLIP provided excellent frozen image encoders. Retraining them for each multimodal project was wasteful.
2. **LLMs had matured** — OPT, Flan-T5, Llama provided excellent frozen language models. Retraining them for each multimodal project was wasteful.

The BLIP-2 question: can we leave both backbones frozen and just train a small "bridge" between them? The answer was yes — with the right bridge architecture (the Q-Former), the bridge has ~188M parameters and trains in days on a few GPUs.

## The Architecture

BLIP-2 has three components:

```
[Image] → [Frozen Vision Encoder (e.g., ViT-G/14)] → [Q-Former (trainable)] → [Frozen LLM (e.g., OPT 6.7B)] → [Text output]
```

### 1. Frozen Vision Encoder

BLIP-2 uses a ViT-G/14 (1B parameters) pretrained with contrastive learning (CLIP-style). The image is encoded into a sequence of patch embeddings: 256 patches × 1408 dims. These are the "raw" visual features — too many (256) and too high-dimensional for direct LLM consumption.

### 2. Q-Former (The Bridge — Trainable)

The Q-Former is a small Transformer (~188M parameters) with two parts:

- **Learnable query tokens** — 32 fixed queries (analogous to the `[CLS]` token but 32 of them). These queries attend to the image features and extract the most relevant information.
- **Self-attention + cross-attention layers** — the queries self-attend among themselves and cross-attend to the image features. After 6–12 layers, the 32 queries contain a compact summary of the image.

The output: 32 "visual tokens" of dimension matching the LLM's hidden dim. These 32 tokens are the entire representation of the image that the LLM sees — regardless of the original image resolution.

### 3. Frozen LLM

The Q-Former's 32 visual tokens are projected (via a linear layer) into the LLM's embedding space, then prepended to the text prompt. The LLM processes them as if they were soft prompt tokens. The LLM is frozen — no gradient flows back into its weights.

BLIP-2 used both encoder-decoder LLMs (Flan-T5) and decoder-only LLMs (OPT). For decoder-only, the visual tokens are prepended to the text; for encoder-decoder, they're fed to the encoder.

## Two-Stage Training

BLIP-2's training was split into two stages, each focusing on a different capability:

### Stage 1: Vision-Language Representation Learning

Goal: teach the Q-Former to extract visual features that align with text.

Three losses, run jointly:

1. **Image-Text Contrastive (ITC)** — maximize similarity between image features (mean-pooled queries) and text features (from the LLM's text encoder). Aligns image and text in a shared space.
2. **Image-Text Matching (ITM)** — binary classifier on whether image and text match. Forces the Q-Former to preserve fine-grained alignment (not just global similarity).
3. **Image-grounded Text Generation (ITG)** — given the image, generate the text. The Q-Former's queries are fed to a small LM head; the model learns to produce text conditioned on visual features.

After Stage 1, the Q-Former can produce 32 tokens that summarize the image in a way that's useful for vision-language tasks.

### Stage 2: Vision-to-Language Generative Learning

Goal: teach the frozen LLM to use the Q-Former's visual tokens to generate text.

The Q-Former's 32 visual tokens are projected and prepended to the text prompt. The LLM is asked to generate the caption / answer the question. Only the Q-Former and the projection layer are updated; the LLM is frozen.

This stage uses a causal LM loss: maximize $P(\text{text} \mid \text{image}, \text{prompt})$.

## Why the Q-Former Works

The Q-Former solves a key bottleneck: the vision encoder produces too many features (256 patches × 1408 dims = ~360K numbers per image) for the LLM to consume efficiently. Feeding all 256 patches as soft prompts would:

- Slow down the LLM by 256 extra tokens per image.
- Dilute the LLM's attention with low-information patches (e.g., background regions).
- Make training expensive (gradient flows through all 256 patches).

The Q-Former compresses 256 patches into 32 query tokens, selecting only the information relevant to language tasks. This is a learned compression — the Q-Former is trained to extract language-relevant features, not just visual features.

The 32-token budget is a key design choice. More tokens (e.g., 64, 128) give the LLM more visual information but cost more LLM compute and dilute attention. Fewer tokens (e.g., 8, 16) compress too aggressively and lose detail. 32 is the empirical sweet spot.

## Empirical Results

On standard VLM benchmarks:

| Benchmark            | BLIP-2 (ViT-G + OPT 6.7B) | Previous SOTA (2022) |
|----------------------|---------------------------|----------------------|
| COCO Captioning (CIDEr) | 144.5                  | 135.8 (Flamingo)     |
| VQAv2 (test-dev)     | 65.2%                     | 60.4% (Flamingo)     |
| NoCaps (CIDEr)       | 121.6                     | 113.2                |
| OK-VQA               | 45.9%                     | 38.9%                |

BLIP-2 set SOTA on most image-captioning and VQA benchmarks while training only the Q-Former (~188M params), not the LLM or vision encoder.

The training cost: ~$1M (estimated) vs Flamingo's ~$10M+ — a 10× cost reduction from freezing backbones.

## Comparison with Contemporary VLMs

| Aspect                | Flamingo (2022)        | BLIP-2 (2023)             | LLaVA (2023)              |
|-----------------------|------------------------|---------------------------|---------------------------|
| Vision encoder        | NFNet, frozen          | ViT-G/14, frozen          | CLIP-ViT-L/14, frozen     |
| Language model        | Chinchilla, frozen     | OPT/Flan-T5, frozen       | Llama, frozen             |
| Bridge                | Perceiver Resampler    | Q-Former (deeper)         | Single linear projection  |
| Bridge param count    | ~200M                  | ~188M                     | ~10M                      |
| Visual tokens to LLM  | 64                     | 32                        | 256 (all patches)         |
| Training data         | 3B image-text pairs    | 129M image-text pairs     | 558K (much smaller)       |
| Training cost         | $10M+                  | ~$1M                      | ~$500 (LoRA on Llama)     |
| Quality on VQAv2      | 60.4%                  | 65.2%                     | 60.0% (LLaVA-1.5: 80%)    |
| Best for              | Few-shot, in-context   | Strong zero-shot VLM      | Cheap, open, instruct-tuned |

The trend: from Flamingo (expensive, all-in-one) → BLIP-2 (cheaper, freeze backbones) → LLaVA (cheapest, minimal bridge, more data). Each generation reduced the bridge complexity and relied more on pretrained components.

## The Q-Former Legacy

The Q-Former was a transitional idea. Later VLMs simplified or removed it:

- **LLaVA (2023)** replaced the Q-Former with a single linear projection layer. The argument: with enough instruction-tuning data, the LLM can learn to use raw CLIP features directly — no need for a separate bridge Transformer.
- **Qwen-VL, InternVL** use simplified Q-Formers (smaller, fewer layers) for slightly better compression.
- **GPT-4V, Gemini, Claude 3** (closed-source) likely use native multimodal training (vision and language trained together from scratch), not the BLIP-2 pattern.

The Q-Former is now seen as an artifact of the "frozen backbone era" — useful when compute was scarce and LLMs couldn't handle long visual token sequences. As LLMs scale to longer contexts and vision encoders improve, the bridge is becoming simpler.

## When BLIP-2 Patterns Still Apply

- **Adapting a frozen LLM to a new modality** (audio, video, 3D) — the Q-Former pattern of "trainable bridge between frozen encoder and frozen LLM" is the default approach.
- **Resource-constrained multimodal training** — when you can't afford to retrain a 70B LLM, the Q-Former pattern lets you train a small bridge on cheap GPUs.
- **Modular multimodal systems** — if you want to swap vision encoders (CLIP → DINOv2 → SigLIP) without retraining the LLM, the Q-Former pattern makes this possible.

## Why This Matters for AI

- **BLIP-2 established the "freeze and bridge" paradigm** for multimodal models. Even though the Q-Former is now often replaced by simpler projections, the core idea — don't retrain expensive backbones — is universal.
- **The Q-Former is a clean case study in learned compression**: how to take a high-dimensional representation (256 patches) and compress it to a fixed, small number of tokens (32) while preserving task-relevant information.
- **BLIP-2 made VLMs accessible**: by reducing training cost 10×, it enabled smaller labs to build VLMs. This contributed to the open-source VLM explosion of 2023–2024.
- **The Q-Former pattern extends beyond vision**: the same architecture (learnable query tokens + cross-attention to a frozen encoder) appears in audio-language models, video-language models, and even in some retrieval systems.

## Production Implications

- **BLIP-2 itself is mostly superseded** by LLaVA-NeXT, Qwen-VL, InternVL for new deployments. These are cheaper, better, and easier to fine-tune.
- **The Q-Former pattern is still relevant** for adapting LLMs to new modalities or for building VLMs on top of proprietary LLMs you can't retrain.
- **For multimodal RAG**, the bridge doesn't matter — what matters is the quality of the final image embedding. Use a modern VLM (LLaVA-NeXT, Qwen-VL) for image understanding tasks.
- **For cost-sensitive deployment**, prefer the simplest bridge that works. A linear projection (LLaVA-style) is often as good as a Q-Former and 10× cheaper.

## Common Pitfalls

- **Treating BLIP-2 as production-ready** — for new deployments, use LLaVA-NeXT or Qwen-VL. BLIP-2 is a research milestone, not a production model.
- **Misunderstanding the Q-Former's role** — the Q-Former compresses visual features, it doesn't "understand" them. The LLM does the understanding.
- **Comparing Q-Former to attention** — the Q-Former *uses* attention (self + cross); it's not an alternative to attention.
- **Forgetting that both backbones are frozen** — BLIP-2 trains only the Q-Former and the projection layer. This is why it's cheap.
- **Expecting the Q-Former to generalize to new modalities without retraining** — the Q-Former is trained for a specific (vision, language) pair. Adapting to a new modality requires retraining the Q-Former.

## Interview Questions

1. **Q: What is the Q-Former and what problem does it solve?**
   A: The Q-Former is a small Transformer (~188M params) that bridges a frozen vision encoder and a frozen LLM. It uses 32 learnable query tokens that cross-attend to the image features (256 patches × 1408 dims from ViT-G) and extract a compact 32-token summary. This solves the bottleneck that the vision encoder produces too many features for the LLM to consume efficiently — 256 patches would slow down the LLM, dilute its attention, and make training expensive. The Q-Former compresses to 32 tokens while preserving task-relevant information.

2. **Q: Why does BLIP-2 freeze both the vision encoder and the LLM?**
   A: Two reasons. (1) **Cost** — retraining a 1B-parameter vision encoder and a 6.7B-parameter LLM end-to-end requires massive compute (Flamingo 80B cost ~$10M+). By freezing both and training only the ~188M-parameter Q-Former, BLIP-2 reduced training cost 10× to ~$1M. (2) **Maturity** — by 2023, CLIP/ViT vision encoders and OPT/Flan-T5 LLMs were already excellent. Retraining them for each multimodal project was wasteful. Freezing preserves their capabilities while the Q-Former learns to bridge them.

3. **Q: How does BLIP-2's two-stage training work?**
   A: Stage 1 (Representation Learning): train the Q-Former with three losses — image-text contrastive (ITC) for global alignment, image-text matching (ITM) for fine-grained alignment, and image-grounded text generation (ITG) for generation capability. The LLM is not involved. Stage 2 (Generative Learning): feed the Q-Former's 32 visual tokens (projected to the LLM's embedding space) to the frozen LLM, prepend to the text prompt, train with causal LM loss. Only the Q-Former and projection layer are updated. This separates "learn to extract good visual features" (Stage 1) from "learn to use them for generation" (Stage 2).

4. **Q: Why did LLaVA replace the Q-Former with a simple linear projection?**
   A: LLaVA's argument: with enough instruction-tuning data (558K examples), the LLM can learn to use raw CLIP features (256 patches) directly — no need for a separate bridge Transformer. A linear projection (just a single matrix multiplying each patch embedding) is sufficient. This is 10× cheaper than the Q-Former and simpler to implement. The tradeoff: 256 visual tokens (vs 32 for BLIP-2) means more LLM compute per image, but the LLM gets richer visual information. As LLMs scaled to longer contexts, this tradeoff became favorable.

5. **Q: When is the Q-Former pattern still useful?**
   A: Three cases. (1) **Adapting a frozen LLM to a new modality** (audio, video, 3D) — the Q-Former pattern of "trainable bridge between frozen encoder and frozen LLM" is the default. (2) **Resource-constrained multimodal training** — when you can't afford to retrain a 70B LLM, the Q-Former pattern lets you train a small bridge on cheap GPUs. (3) **Modular multimodal systems** — if you want to swap vision encoders (CLIP → DINOv2 → SigLIP) without retraining the LLM, the Q-Former pattern makes this possible. For new vision-language deployments in 2026, prefer LLaVA-NeXT or Qwen-VL; use the Q-Former pattern for non-vision modalities.

6. **Q: How does BLIP-2 compare to Flamingo?**
   A: Both freeze backbones and train a bridge. Flamingo uses a Perceiver Resampler (~200M params, 64 output tokens); BLIP-2 uses a Q-Former (~188M params, 32 output tokens). Flamingo's training was more expensive ($10M+, 3B image-text pairs) and focused on few-shot in-context learning; BLIP-2 was cheaper (~$1M, 129M pairs) and focused on zero-shot. BLIP-2 also separated representation learning (Stage 1) from generative learning (Stage 2), which Flamingo did not. Empirically, BLIP-2 outperformed Flamingo on most benchmarks while costing 10× less to train.
