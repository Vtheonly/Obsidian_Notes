# 51 — EAGLE-3: Confidence-Aware Speculative Decoding (Li et al., 2025)

> [!info] TL;DR
> EAGLE-3 (2025) extends the EAGLE family of speculative-decoding methods with **confidence-aware dynamic tree scheduling**. Where EAGLE-2 used a fixed tree shape per step, EAGLE-3 dynamically allocates speculation budget based on per-position confidence — allocating more speculation to high-confidence continuations and pruning low-confidence branches. This pushes acceptance rates to 90–97% and end-to-end speedups to 4–6× on Llama-3 / Qwen-2.5 / DeepSeek-V3. EAGLE-3 is integrated into vLLM 0.7+ and SGLang as the default spec-decoding backend.

## Citation

Li, Y., Yu, Y., Li, Q., Cui, T., Zhang, W., Yao, Z., He, Y. et al. (2025). *EAGLE-3: Scaling up Inference Acceleration of Large Language Models via Training-Time Data*. arXiv preprint arXiv:2503.01840.

## The Problem Being Solved

EAGLE-2 (2024) achieved 3.5–4.5× speedup with 85–95% acceptance rate by predicting hidden features (not tokens) and using dynamic tree structures. But EAGLE-2 still has limitations:

1. **Fixed budget per step**: EAGLE-2 speculates a fixed number of tokens (e.g., K=4) per step regardless of confidence. When the model is uncertain (e.g., at branching points in code or mathematical reasoning), most speculated tokens get rejected, wasting verification compute.
2. **No training-time integration**: EAGLE-2 trains the draft head on top of a frozen target model. The target model was never trained to be spec-decoded — it just happens to be verifiable. EAGLE-3 introduces training-time data so the target model is aware it will be spec-decoded.
3. **Tree topology is reactive**: EAGLE-2 picks a tree shape after computing the draft probabilities. EAGLE-3 proactively shapes the tree before the forward pass, allowing better GPU utilization.

## EAGLE-3's Key Innovations

### 1. Confidence-Aware Dynamic Tree Scheduling

EAGLE-3 introduces a confidence estimator that predicts, *before* the verification forward pass, which speculated branches are likely to be accepted. The tree is then dynamically shaped:

- **High-confidence continuations** (predicted acceptance >90%): expand the tree deeper (speculate K+2 instead of K).
- **Low-confidence continuations** (predicted acceptance <60%): prune branches early to save verification compute.
- **Mixed branches**: allocate more budget to high-confidence subtrees, less to low-confidence ones.

The confidence estimator is a small MLP trained on the draft head's hidden states and probabilities. It's accurate enough that the pruned branches would have been rejected anyway.

**Result**: at any given step, the verification forward pass processes only the branches likely to be accepted, increasing effective acceptance rate from 85–95% (EAGLE-2) to 90–97% (EAGLE-3).

### 2. Training-Time Data Integration

EAGLE-3 introduces a multi-token prediction (MTP) auxiliary objective during target-model training. The target model is trained to predict not just the next token but also tokens at positions t+2, t+3, t+4 — using the same hidden state. This:

- **Improves the target model's hidden-state predictability** — the hidden states are now explicitly trained to support multi-token lookahead.
- **Boosts draft head acceptance** — the draft head (which predicts hidden states) has cleaner training signal because the target hidden states are themselves MTP-aware.

This requires retraining (or continual pretraining) the target model with the MTP objective. DeepSeek-V3 already uses MTP for training, which is why EAGLE-3 works especially well on DeepSeek-V3.

### 3. Longer Speculation Lengths

EAGLE-2's practical K was 4–8 (longer = lower acceptance). EAGLE-3's confidence-aware pruning makes K=8–16 practical. With K=16, the expected number of accepted tokens per step rises from ~3.5 (EAGLE-2) to ~6.5 (EAGLE-3), giving the 4–6× end-to-end speedup.

### Acceptance Rates

- EAGLE-2: 85–95% per position.
- EAGLE-3: 90–97% per position.

### Quality

Zero quality loss — the output distribution is provably identical to autoregressive decoding (rejection sampling preserves the target distribution). EAGLE-3 is bit-identical to vanilla decoding given the same random seed.

## Why This Paper Matters

### Production Default by 2026

By 2026, EAGLE-3 (or its derivatives) is the default speculative decoding method in production serving engines:

- **vLLM 0.7+**: native EAGLE-3 support; auto-fallback to EAGLE-2 if draft head not available.
- **SGLang 0.4+**: native EAGLE-3 with prefix-cache integration.
- **TensorRT-LLM**: EAGLE-3 supported; benchmarks show 5× throughput on Llama-3-70B.
- **HuggingFace TGI**: EAGLE-3 supported since v2.3+.

This makes spec decoding the default for latency-sensitive LLM serving — most production deployments of Llama-3, Mistral, Qwen-2.5, and DeepSeek-V3/R1 use EAGLE-3.

### Training-Time / Inference-Time Co-Design

EAGLE-3 is the first major spec-decoding method that explicitly co-designs training and inference. The MTP training objective makes the target model "speculation-friendly" — a fundamental shift from EAGLE-1/2's approach of bolting spec decoding onto a frozen target.

This pattern (training-time awareness of inference-time techniques) is increasingly common:
- MTP in DeepSeek-V3 (training-time multi-token prediction).
- EAGLE-3 (training-time MTP for spec decoding).
- Reasoning models (RL training explicitly produces thinking traces that match inference-time generation).

### Implications for Reasoning Models

Reasoning models (o1, R1, Claude thinking) generate 10K–50K CoT tokens per query. Without spec decoding, this is prohibitively expensive. EAGLE-3 reduces the cost 4–6×, making reasoning models practical for a broader range of applications. However, EAGLE-3 speculates on the CoT tokens, not the final answer — the final answer is still generated autoregressively to preserve quality.

## Limitations

- **Requires MTP-trained target model**: EAGLE-3 works best when the target model was trained with the MTP objective. For models without MTP training (e.g., Llama 3), EAGLE-3 falls back to EAGLE-2-style behavior. The full speedup requires DeepSeek-V3-style MTP training.
- **Memory overhead**: longer speculation (K=8–16) and the confidence estimator add ~10–15% memory overhead vs vanilla decoding.
- **Batched inference**: like EAGLE-2, EAGLE-3's speedup is best at batch=1 (interactive) and degrades at batch=64+. For high-throughput batched inference, vanilla continuous batching may be preferable.
- **Code and discrete-structure tasks**: while improved over EAGLE-2, EAGLE-3 still struggles with code generation (discrete structure, hard to predict) and creative writing (intentionally unpredictable).
- **Training cost**: training the EAGLE-3 draft head + confidence estimator requires ~4–8 GPU-hours per target model (vs ~1–4 for EAGLE-2).

## Reception and Follow-Ups

EAGLE-3 was rapidly adopted in production:

- **vLLM 0.7+** (Q1 2025): native EAGLE-3 support; production-ready.
- **SGLang 0.4+** (Q1 2025): native EAGLE-3 with prefix-cache integration.
- **TensorRT-LLM** (mid 2025): EAGLE-3 supported; 5× throughput on Llama-3-70B.
- **HuggingFace TGI v2.3+** (Q2 2025): EAGLE-3 supported.

By 2026, EAGLE-3 is the default spec-decoding method in production. The next research frontier is combining EAGLE-3 with:

- **Continuous batching** (currently degrades spec decoding speedup).
- **Reasoning models** (spec decoding on CoT tokens is emerging).
- **Multimodal models** (spec decoding on vision-language generation is unexplored).

## Limitations and Open Questions

- **Memory overhead**: longer speculation (K=8–16) and the confidence estimator add ~10–15% memory overhead.
- **Batched inference degradation**: like EAGLE-2, EAGLE-3's speedup degrades at high batch sizes. Combining spec decoding with continuous batching without throughput loss remains an open problem.
- **Reasoning models**: spec decoding on CoT (but not final answers) is an emerging pattern; o1-style models benefit but the technique needs adaptation.
- **Multimodal generation**: spec decoding on image tokens (for VLMs) or audio tokens (for speech models) is unexplored.
- **Information-theoretic limit**: EAGLE-3 achieves 6×; can we reach 10×? Information-theoretic analysis suggests ~8× may be the practical limit.

## Interview Questions

1. **Q: How does EAGLE-3's confidence-aware scheduling differ from EAGLE-2's dynamic trees?**
   A: EAGLE-2 picks a tree shape *after* computing the draft probabilities — the tree is reactive. EAGLE-3 predicts, *before* the verification forward pass, which branches are likely to be accepted (using a small confidence estimator MLP). High-confidence branches get more speculation budget (deeper); low-confidence branches get pruned early. This proactive shaping reduces wasted verification compute and pushes acceptance rate from 85–95% (EAGLE-2) to 90–97% (EAGLE-3).

2. **Q: Why does EAGLE-3 work best on DeepSeek-V3?**
   A: DeepSeek-V3 was trained with the MTP (Multi-Token Prediction) auxiliary objective — the model's hidden states are explicitly trained to support multi-token lookahead. EAGLE-3's draft head predicts hidden states; on an MTP-trained model, these hidden states are cleaner and more predictable, so the draft head's acceptance rate is higher. On models without MTP training (e.g., Llama 3), EAGLE-3 falls back to EAGLE-2-style behavior. This is the first major spec-decoding method that explicitly co-designs training and inference.

3. **Q: When does EAGLE-3 HURT performance?**
   A: Three cases. (1) **Very short generations** (<50 tokens): draft overhead > speedup benefit. (2) **Low acceptance rate** (<70%): pruned branches still waste compute; rare but happens with highly creative tasks. (3) **Large batch sizes** (>64): tree verification has diminishing returns at high batch; vanilla continuous batching may be preferable. EAGLE-3's adaptive routers detect these cases and fall back to vanilla decoding automatically.
