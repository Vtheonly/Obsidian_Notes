# 03. Regression Metrics — MAE, MSE, RMSE, R², MAPE, and When to Use Each

> **Prerequisites:** [[01. Model Evaluation and Metrics]], [[02. Model Evaluation Metrics Beyond Accuracy]] (classification metrics)
> **Connections:** [[04. Clustering Metrics]] (next), [[02. Loss Functions and Cost Optimization]] (MSE/MAE as losses vs. as metrics)

The vault's existing evaluation notes cover classification metrics thoroughly but barely mention regression metrics. This note fills that gap with the same depth: what each metric measures, when to use it, and its pitfalls.

---

## The regression evaluation problem

In regression, the model predicts a continuous value $\hat{y}$ for each input, and the true value is $y$. The question: how do we measure the error $\hat{y} - y$? There are many ways to aggregate per-sample errors into a single number, and each captures different aspects of model quality. The choice depends on the task.

---

## The metrics

### Mean Absolute Error (MAE)

$$\text{MAE} = \frac{1}{n} \sum_{i=1}^n |y_i - \hat{y}_i|$$

**What it measures:** the average absolute deviation between predicted and true values. In the same units as the target.

**When to use it:**
- When you want a metric interpretable in the target's units ("the model is off by $500 on average").
- When the data has outliers and you do not want them to dominate (MAE is robust to outliers — each error contributes linearly, not quadratically).
- When the cost of an error is proportional to its magnitude (e.g., delivery time prediction: being off by 2 hours is twice as bad as 1 hour).

**Pitfalls:**
- The gradient is constant magnitude regardless of error size, which can make training harder (the model gets the same "push" from a small error as a large one). This is why MAE is rarely used as a training loss, even when it is the evaluation metric.

### Mean Squared Error (MSE)

$$\text{MSE} = \frac{1}{n} \sum_{i=1}^n (y_i - \hat{y}_i)^2$$

**What it measures:** the average squared deviation. Heavily penalizes large errors (quadratic growth).

**When to use it:**
- When large errors are disproportionately bad (e.g., predicting drug dosage: being off by 10x is far more than 10× worse than being off by 1×).
- When the noise is Gaussian (MSE is the maximum-likelihood estimator under Gaussian noise — see [[Probability and Statistics for ML]]).
- As a training loss (the gradient grows with error size, so the model focuses on the worst predictions).

**Pitfalls:**
- Sensitive to outliers — a single large error can dominate the metric.
- Not interpretable in target units (squared units).

### Root Mean Squared Error (RMSE)

$$\text{RMSE} = \sqrt{\text{MSE}} = \sqrt{\frac{1}{n} \sum_{i=1}^n (y_i - \hat{y}_i)^2}$$

**What it measures:** the square root of MSE. Back in the target's units.

**When to use it:**
- When you want MSE's outlier sensitivity but interpretability in target units.
- The standard metric for reporting regression model quality in most scientific and industry contexts.

**Pitfalls:** Same outlier sensitivity as MSE.

### Root Mean Squared Logarithmic Error (RMSLE)

$$\text{RMSLE} = \sqrt{\frac{1}{n} \sum_{i=1}^n (\log(1 + y_i) - \log(1 + \hat{y}_i))^2}$$

**What it measures:** RMSE in log space. Penalizes relative errors rather than absolute errors.

**When to use it:**
- When the target spans multiple orders of magnitude (e.g., house prices from $10K to $10M, or counts from 1 to 10000). Being off by $1000 on a $10K house is bad; on a $10M house is fine — RMSLE captures this.
- When you care about *percentage* errors rather than absolute errors.
- Common in Kaggle competitions with skewed targets (e.g., store sales, ticket counts).

**Pitfalls:**
- Requires non-negative targets (log of negative is undefined).
- Asymmetric: under-prediction is penalized more than over-prediction (because $\log(1+y) - \log(1+\hat{y})$ is larger when $\hat{y} < y$). This can be a feature or a bug depending on the task.

### R² (Coefficient of Determination)

$$R^2 = 1 - \frac{\sum_i (y_i - \hat{y}_i)^2}{\sum_i (y_i - \bar{y})^2} = 1 - \frac{\text{SS}_{res}}{\text{SS}_{tot}}$$

**What it measures:** the proportion of variance in $y$ explained by the model. Compares the model's MSE to the MSE of a trivial "always predict the mean" model.

- $R^2 = 1$: perfect predictions.
- $R^2 = 0$: the model is no better than predicting the mean.
- $R^2 < 0$: the model is worse than predicting the mean (possible for bad models on test data).

**When to use it:**
- When you want a unitless, bounded measure of "how much of the variation does the model explain."
- As a quick sanity check: $R^2 < 0.5$ on a simple task suggests the model is missing something fundamental.

**Pitfalls:**
- **Adding features always increases R²** (or keeps it the same), even if the features are noise. This is because more features give the model more capacity to fit the training data. Use **Adjusted R²** (below) to correct for this.
- $R^2$ is only meaningful for in-distribution evaluation. On out-of-distribution data, $R^2$ can be arbitrarily negative.

### Adjusted R²

$$R^2_{adj} = 1 - \frac{(1 - R^2)(n - 1)}{n - p - 1}$$

where $p$ is the number of features.

**What it measures:** R² penalized for the number of features. Adding a feature increases $R^2_{adj}$ only if the feature improves the model more than would be expected by chance.

**When to use it:**
- When comparing models with different numbers of features.
- To guard against overfitting from adding irrelevant features.

**Pitfalls:** Assumes linear regression specifically; less meaningful for other model types.

### Mean Absolute Percentage Error (MAPE)

$$\text{MAPE} = \frac{100\%}{n} \sum_{i=1}^n \left| \frac{y_i - \hat{y}_i}{y_i} \right|$$

**What it measures:** the average percentage error. Unitless.

**When to use it:**
- When you want to compare error rates across datasets with different scales.
- When stakeholders think in percentages ("we're off by 5% on average").

**Pitfalls:**
- **Undefined when $y_i = 0$** (division by zero). Requires all targets to be non-zero.
- **Asymmetric:** over-predictions are penalized less than under-predictions (because the denominator is $y_i$, so errors when $y_i$ is small produce large percentages).
- **Infinite** if any $y_i$ is very small relative to the error.

---

## The decision framework

| Situation | Recommended metric |
| :--- | :--- |
| Interpretable error in target units, outliers present | MAE |
| Outliers matter heavily, training loss | MSE |
| Reporting quality in target units, outliers matter | RMSE |
| Target spans multiple orders of magnitude | RMSLE |
| "How much variance is explained?" | R² (or Adjusted R²) |
| Comparing across datasets/scales, stakeholder communication | MAPE |
| Skewed count targets (sales, clicks) | RMSLE or log-transform + MSE |

---

## The relationship to loss functions

MSE and MAE are both loss functions (used in training) and metrics (used in evaluation). But they are not always the same: you might train with MSE (for smooth gradients) but evaluate with MAE (for interpretability and robustness). This is fine — the loss determines what the model optimizes; the metric determines how you judge it.

A common pattern: train with **Huber loss** (smooth like MSE near zero, robust like MAE for large errors), evaluate with MAE or RMSE. Huber is:

$$L_\delta(y, \hat{y}) = \begin{cases} \frac{1}{2}(y - \hat{y})^2 & \text{if } |y - \hat{y}| \leq \delta \\ \delta(|y - \hat{y}| - \frac{1}{2}\delta) & \text{otherwise} \end{cases}$$

This combines MSE's smooth gradients (for well-predicted samples) with MAE's robustness (for outliers).

---

## What you should walk away with

1. MAE: average absolute error, robust to outliers, interpretable in target units.
2. MSE: average squared error, outlier-sensitive, the maximum-likelihood loss for Gaussian noise.
3. RMSE: square root of MSE, back in target units, standard for reporting.
4. RMSLE: RMSE in log space, for targets spanning multiple magnitudes, penalizes relative errors.
5. R²: proportion of variance explained, unitless, but inflates with added features (use Adjusted R²).
6. MAPE: average percentage error, unitless, but undefined for zero targets and asymmetric.
7. The choice depends on the task: outlier sensitivity, target scale, interpretability needs.
8. The training loss and evaluation metric need not match — train with MSE for smooth gradients, evaluate with MAE for robustness.
