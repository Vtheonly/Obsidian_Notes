# 01. Attention as Soft Lookup — From Bahdanau to Dot-Product

> **Prerequisites:** [[03. From RNNs to Attention - The Historical Bridge]] (the motivation), [[01. The Encoder-Decoder Pattern - Conditional Generation]] (the bottleneck being fixed)
> **Connections:** [[02. Queries Keys and Values - The Database Analogy]] (next), [[01. The Bottleneck Problem - Why One Vector Is Not Enough]] (the problem this solves)

## The core idea in one sentence

**Attention is a soft, differentiable lookup: given a query, retrieve a weighted average of a set of values, where the weights measure how relevant each value is to the query.**

Everything else — the Bahdanau formulation, the dot-product formulation, the scaling, the multi-head structure — is a specific instantiation of this idea. Hold onto the "soft lookup" framing and every variant will feel like a natural variation.

---

## The problem attention was invented to solve

Recall from [[01. The Bottleneck Problem - Why One Vector Is Not Enough]]: the Encoder-Decoder RNN compresses the entire input into a single vector $c$, and the decoder must generate the entire output from $c$ alone. This is a bottleneck.

Bahdanau, Cho, and Bengio (2015) proposed a fix: **let the decoder compute a *different* context vector $c_t$ at each output step $t$, as a weighted average of *all* encoder hidden states.**

$$c_t = \sum_{i=1}^{T} \alpha_{t,i} \cdot h_i^{enc}$$

The weights $\alpha_{t,i}$ are the **attention weights** — they measure how relevant input position $i$ is to output position $t$. When translating output word 5, the model might attend strongly to input word 3 (the word being translated) and weakly to everything else, so $c_5 \approx h_3^{enc}$.

This single change fixed the bottleneck: the decoder no longer depends on a single compressed vector but has direct, time-varying access to every encoder state.

---

## How the attention weights are computed

The attention weights $\alpha_{t,i}$ must be:

1. **Non-negative** (they are weights in a weighted average).
2. **Sum to 1** over $i$ (so $c_t$ is a convex combination).
3. **Differentiable** (so we can train them by backpropagation).
4. **A function of both the decoder state and the encoder state** (so the model can learn *what to attend to*).

The standard way to achieve all four: compute a **score** $s_{t,i}$ for each (decoder step $t$, encoder position $i$) pair, then softmax over $i$:

$$\alpha_{t,i} = \frac{\exp(s_{t,i})}{\sum_{j=1}^{T} \exp(s_{t,j})}$$

The score function $s_{t,i}$ is where variants differ. The two most important:

### Bahdanau (additive) attention

$$s_{t,i} = v^\top \tanh(W_s \cdot s_{t-1}^{dec} + W_h \cdot h_i^{enc})$$

where $s_{t-1}^{dec}$ is the decoder's previous hidden state, $h_i^{enc}$ is the encoder hidden state at position $i$, and $v, W_s, W_h$ are learnable parameters. This is called "additive" because the two states are projected and *added* before the tanh. It is a small feedforward network that scores the match between decoder and encoder states.

### Dot-product (multiplicative) attention

$$s_{t,i} = (s_{t-1}^{dec})^\top h_i^{enc}$$

or, with learned projections:

$$s_{t,i} = (W_Q \cdot s_{t-1}^{dec})^\top (W_K \cdot h_i^{enc})$$

This is just a dot product between (projected) decoder and encoder states. It is cheaper than Bahdanau (no tanh, no intermediate projection) and empirically works as well or better. **The Transformer uses dot-product attention** — so this is the variant we will develop.

---

## Why dot-product attention works — the geometric intuition

A dot product measures **alignment** — how much two vectors point in the same direction. If the decoder's state at output step $t$ and the encoder's state at input position $i$ point in similar directions, their dot product is large, and the attention weight $\alpha_{t,i}$ will be high.

Geometrically: the decoder is "asking a question" (what am I translating right now?), and each encoder position is "offering an answer" (I am this kind of word, with this kind of meaning). The dot product measures how well the question matches each answer. Softmax turns these match scores into a probability distribution, and the weighted average retrieves a blended answer.

This is exactly a **soft lookup** — a database query where the keys and query are vectors, the match function is a dot product, and the retrieval is a weighted average rather than a hard selection.

The next note ([[02. Queries Keys and Values - The Database Analogy]]) makes this database framing precise and introduces the Q/K/V notation that the Transformer uses. But before we get there, let's pin down the soft-lookup idea with a concrete example.

## A concrete example: translating "the black cat"

Suppose we are translating "the black cat" to French ("le chat noir"). The encoder produces three hidden states: $h_1^{enc}$ (for "the"), $h_2^{enc}$ (for "black"), $h_3^{enc}$ (for "cat"). The decoder generates three output words.

At output step 1 (generating "le"):
- The decoder's state asks: "I need the French determiner. Which input word is the determiner?"
- Scores: $s_{1,1}$ (with "the") is high; $s_{1,2}$ (with "black") and $s_{1,3}$ (with "cat") are low.
- Attention: $\alpha_{1,1} = 0.9, \alpha_{1,2} = 0.05, \alpha_{1,3} = 0.05$.
- Context: $c_1 \approx 0.9 \cdot h_1^{enc}$ — almost entirely "the".

At output step 2 (generating "chat"):
- The decoder's state asks: "I need the French noun. Which input word is the noun?"
- Scores: $s_{2,3}$ (with "cat") is high.
- Attention: $\alpha_{2,3} = 0.85$.
- Context: $c_2 \approx 0.85 \cdot h_3^{enc}$ — almost entirely "cat".

At output step 3 (generating "noir"):
- The decoder's state asks: "I need the French adjective. Which input word is the adjective?"
- Scores: $s_{3,2}$ (with "black") is high.
- Attention: $\alpha_{3,2} = 0.9$.
- Context: $c_3 \approx 0.9 \cdot h_2^{enc}$ — almost entirely "black".

Notice the alignment: the attention weights form a (roughly) diagonal matrix, because French and English word order happens to align here. For language pairs with different word order (e.g., English→Japanese), the attention matrix would be non-diagonal — and that is exactly the kind of structural information attention can learn.

---

## The key shift: from "one context" to "per-step context"

The single most important conceptual shift from the Encoder-Decoder RNN to attention is:

- **Before attention:** one context vector $c$ for the entire output.
- **With attention:** one context vector $c_t$ per output step, computed on-the-fly from all encoder states.

This shift is what makes the decoder a *selective reader* rather than a *fixed-memory generator*. And it is what makes the next generalization — self-attention — natural: if attention lets a decoder read an encoder, why not let a sequence read *itself*?

That generalization is the subject of [[01. Self-Attention - When the Sequence Attends to Itself]]. But first, we need the Q/K/V notation, which is the subject of the next note.

---

## What you should walk away with

1. Attention is a soft, differentiable lookup: given a query, retrieve a weighted average of values, weighted by relevance.
2. Bahdanau attention (2015) fixed the Encoder-Decoder bottleneck by letting the decoder compute a different context $c_t$ at each step, as a weighted average of all encoder hidden states.
3. The attention weights are softmaxed scores; the score function can be additive (Bahdanau) or dot-product (Transformer).
4. Dot-product attention measures geometric alignment between query and key vectors — this is the "match" in a soft lookup.
5. The key shift is from "one context" to "per-step context," which turns the decoder into a selective reader.
