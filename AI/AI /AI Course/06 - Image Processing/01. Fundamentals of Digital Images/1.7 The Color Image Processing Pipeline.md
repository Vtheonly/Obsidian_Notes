# 1.7 The Color Image Processing Pipeline — From Sensor to RGB

> **Prerequisites:** [[1.1 What is a Digital Image]], [[1.4 Color Spaces and Models]], [[2.2 Point Processing Operations]] (gamma)
> **Connections:** [[1.5 Image File Formats]] (JPEG uses this pipeline), [[5.5 Deep Learning for Imaging]]

When you take a photo with a digital camera or phone, the image sensor does **not** produce RGB pixels directly. It produces a **mosaic** of single-channel measurements that must be converted into a full-color image through a multi-step pipeline. This note explains that pipeline — **demosaicing, white balance, color correction, and gamma encoding** — because understanding it explains why raw camera images look different from JPEGs, why white balance matters, and why deep learning models that train on JPEGs are training on heavily-processed data.

---

## Step 0: The sensor and the Bayer pattern

A camera sensor is a grid of **photodiodes** that measure light intensity. Each photodiode produces a single number — the total light that hit it. The sensor is **color-blind**: it measures intensity, not color.

To capture color, a **Color Filter Array (CFA)** is placed over the sensor, so each photodiode sees only one color (red, green, or blue). The standard CFA is the **Bayer pattern** (Bryce Bayer, 1976), which arranges filters in a 2×2 repeating pattern:

```
R  G
G  B
```

Note that there are **two green filters** for every one red and one blue. This is because the human eye is most sensitive to green light (see [[1.4 Color Spaces and Models]] — the luminance formula weights green at 0.587), so the sensor captures more green detail to match human perception.

The raw sensor output is therefore a **single-channel** image where each pixel is either R, G, or B — but not all three. This is called a **Bayer-pattern image** or **RAW image**.

---

## Step 1: Demosaicing (interpolating the missing colors)

Each pixel has only one color measurement, but we need all three (R, G, B) at every pixel. **Demosaicing** interpolates the missing values.

For a green pixel at position $(x, y)$:
- We have the green value directly.
- We need R and B. These are interpolated from neighboring R and B pixels (bilinear interpolation, or more sophisticated edge-aware methods).

For a red pixel:
- We have red directly.
- We need G and B, interpolated from neighbors.

The simplest demosaicing is **bilinear interpolation** (average the nearest same-color neighbors). More sophisticated methods (edge-directed, frequency-domain) produce sharper results with fewer artifacts (zipper patterns, false colors).

**Why this matters for deep learning:** the demosaicing algorithm introduces **correlations** between neighboring pixels (they share interpolated values). A CNN trained on demosaiced JPEGs sees these correlations, not the raw sensor data. This is one reason why training on RAW data (where available) can produce different results.

---

## Step 2: White balance

Different light sources have different "colors" — incandescent bulbs are yellowish, fluorescent lights are greenish, shade is bluish. The human visual system **automatically adapts** (color constancy) so that a white object looks white under any light. A camera must do this computationally — **white balance**.

**The problem:** the sensor measures the light as it actually is. Under incandescent light, a white card produces R=250, G=220, B=150 (yellowish). Without white balance, the photo looks yellow.

**The fix:** scale each channel so that a "neutral" (gray) object has equal R, G, B. Common methods:

- **Gray world assumption:** assume the average of the scene is gray. Scale channels so their means are equal. Simple but often wrong.
- **White patch / max RGB:** assume the brightest pixels are white. Scale channels so the max values are equal. Also simple, also often wrong.
- **Manual / preset:** the photographer specifies the light source (daylight, cloudy, incandescent, fluorescent) and the camera applies a known correction.
- **Learning-based:** modern cameras and phones use neural networks or statistical methods to estimate the illuminant. This is how phone cameras produce good white balance automatically.

**White balance is a per-image, per-channel scaling** — it multiplies each channel by a gain factor. The order matters: white balance is applied **before** color correction and gamma.

---

## Step 3: Color correction (camera RGB → standard RGB)

The camera's RGB (after demosaicing and white balance) is **device-dependent** — different cameras produce different RGB values for the same scene. **Color correction** transforms the camera's RGB to a standard color space (typically sRGB) so the image looks consistent across devices.

This is done via a **3×3 color matrix** calibrated for the specific camera:

$$\begin{pmatrix} R_{sRGB} \\ G_{sRGB} \\ B_{sRGB} \end{pmatrix} = M_{\text{camera} \to \text{sRGB}} \begin{pmatrix} R_{\text{cam}} \\ G_{\text{cam}} \\ B_{\text{cam}} \end{pmatrix}$$

The matrix is determined by photographing a color chart (e.g., the X-Rite ColorChecker) with known reference colors and solving for the matrix that maps the camera's measured values to the reference values.

---

## Step 4: Gamma encoding

The sensor measures light **linearly** — doubling the light doubles the pixel value. But human perception is **non-linear** — we perceive brightness roughly logarithmically (a doubling of light feels like a smaller, constant-step increase). To efficiently use the limited 8 bits per channel, we apply **gamma encoding**:

$$V_{\text{encoded}} = V_{\text{linear}}^{1/\gamma}$$

with $\gamma \approx 2.2$. This compresses the bright range (where the eye is less sensitive) and expands the dark range (where the eye is more sensitive), giving more perceptual precision per bit.

**sRGB** uses a slightly modified gamma curve (a linear portion near black, then a 2.2 power law), but the principle is the same: the stored pixel values are **non-linear** (gamma-encoded), not linear light measurements.

**Why this matters for deep learning:**
- Image augmentation that adds/subtracts pixel values assumes linearity, but gamma-encoded values are non-linear. Some augmentations should be done in linear space (convert to linear, augment, convert back).
- Mixing images from different sources (RAW vs JPEG vs HDR) requires understanding their gamma state.
- The "0.5" in a pixel value is **not** half the light — it is about 21.4% of the light (because $0.5^{2.2} \approx 0.218$). This surprises people who assume pixel values are linear.

---

## Step 5: Compression (JPEG)

The final step (for JPEG storage) is compression: convert to YCbCr, subsample the chrominance (4:2:0 — keep full luminance, downsample chroma by 2 in each direction), apply the DCT (Discrete Cosine Transform) in 8×8 blocks, quantize the DCT coefficients (discard high frequencies), and entropy-code the result.

This is why JPEG images have **block artifacts** at high compression — the 8×8 DCT blocks become visible. See [[1.5 Image File Formats]] and [[4.2 The Fourier Transform]] (DCT is a Fourier-related transform).

---

## The full pipeline, summarized

```
Light → Lens → Sensor (photodiodes + Bayer CFA) → RAW (single-channel mosaic)
  → Demosaicing → RGB (linear, device-dependent)
  → White balance → RGB (linear, illuminant-corrected)
  → Color correction → sRGB (linear, device-independent)
  → Gamma encoding → sRGB (non-linear, the "normal" image)
  → JPEG compression → .jpg file
```

Each step involves choices (demosaicing algorithm, white balance method, color matrix, gamma curve, compression quality) that affect the final image. Two cameras photographing the same scene produce different JPEGs because they make different choices at each step.

---

## Implications for deep learning

1. **JPEGs are heavily processed.** A CNN trained on JPEGs is training on the output of a 5-step pipeline, not on "raw" visual data. The demosaicing, white balance, color correction, gamma, and compression all introduce structure that the CNN may learn to rely on.

2. **Augmentation in linear vs gamma space.** Some augmentations (brightness changes, blending) are physically meaningful in linear space, not gamma space. Converting to linear, augmenting, and converting back is more correct but slower.

3. **Domain shift across cameras.** A model trained on images from one camera may not generalize to another, because the color matrices and demosaicing differ. This is a real problem for medical imaging and surveillance.

4. **RAW data exists.** Some deep learning work (notably in computational photography — see [[5.5 Deep Learning for Imaging]]) trains on RAW sensor data to avoid the pipeline's assumptions. This requires access to RAW files (DNG, CR2, NEF) and custom demosaicing/color pipelines.

---

## What you should walk away with

1. A camera sensor produces a **Bayer-pattern mosaic** (one color per pixel), not RGB.
2. **Demosaicing** interpolates the missing colors, introducing inter-pixel correlations.
3. **White balance** scales channels to neutralize the illuminant color (gray world, white patch, or learning-based).
4. **Color correction** maps device-dependent camera RGB to standard sRGB via a calibrated 3×3 matrix.
5. **Gamma encoding** ($V^{1/2.2}$) converts linear light to perceptual space, compressing bright range and expanding dark range. Stored pixel values are non-linear.
6. **JPEG compression** (YCbCr + chroma subsampling + DCT + quantization) introduces block artifacts.
7. A CNN trained on JPEGs is training on the output of this 5-step pipeline, not raw visual data — this affects augmentation, domain shift, and what the model actually "sees."
