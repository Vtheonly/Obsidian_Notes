# 14 — GPT-1 (Radford et al., 2018)

> [!info] TL;DR
> GPT-1 demonstrated that pretraining a decoder-only Transformer on unlabeled text with a causal language modeling objective, followed by minimal task-specific fine-tuning, achieves strong performance across diverse NLP tasks (classification, entailment, similarity, multiple choice). GPT-1 established the **pretrain-then-finetune** recipe for generative models, complementing BERT's encoder approach, and laid the architectural foundation for the entire GPT family.

## Citation

Radford, A., Narasimhan, K., Salimans, T., & Sutskever, I. (2018). *Improving Language Understanding by Generative Pre-Training*. OpenAI technical report (unpublished; circulated as a PDF).

## The Problem Being Solved

By 2018, NLP faced a data problem. Supervised learning required labeled datasets for every task — and most tasks had limited labeled data (a few thousand examples). Unsupervised pretraining had been explored for word embeddings (Word2Vec, GloVe) and for ELMo (which used bidirectional language model features), but no one had shown that a single pretrained Transformer could be fine-tuned to excel across many tasks with minimal task-specific architecture.

The key insight: generative pretraining (predicting the next token) on a large unlabeled corpus teaches the model syntax, semantics, world knowledge, and reasoning patterns. Then, a small amount of supervised fine-tuning adapts the model to specific tasks. This recipe — "generative pretraining + discriminative fine-tuning" — is the "G" and "P" in GPT.

The paper's contribution was not a new architecture (the Transformer was already a year old) but a demonstration that the pretrain-finetune recipe, applied to a decoder-only Transformer, worked across many tasks with minimal modification.

## The Architecture

GPT-1 is a 12-layer decoder-only Transformer:

| Property            | Value           |
|---------------------|-----------------|
| Parameters          | 117M            |
| Layers              | 12              |
| Hidden dimension    | 768             |
| Attention heads     | 12              |
| Context window      | 512 tokens      |
| Vocabulary          | ~40K BPE        |
| Positional encoding | Learned         |
| Activation          | GELU            |

The architecture is the standard Transformer decoder from [[02 - Vaswani Attention Is All You Need 2017|Vaswani 2017]], with causal masking (each token can only attend to itself and previous tokens).

## The Two-Stage Recipe

### Stage 1: Unsupervised Pretraining

Train on a large unlabeled corpus using the causal language modeling objective:

```
L1(θ) = Σ_{i} log P(u_i | u_{i-k}, ..., u_{i-1}; θ)
```

where `u_i` is the i-th token and `k` is the context window size.

**Training data**: BooksCorpus (~7,000 unique unpublished books, ~800M words). The choice of long-form continuous text (books, not web snippets) was important — it taught the model long-range dependencies and discourse structure.

**Training setup**: 1 month on 8 GPUs (P6000). The model learned to predict the next token with reasonable perplexity, demonstrating that the unsupervised objective provided useful signal.

### Stage 2: Supervised Fine-Tuning

For each downstream task, take the pretrained model and add a small task-specific head (usually a linear layer). Fine-tune end-to-end on the labeled dataset.

The key innovation: **input transformations, not architecture changes**. GPT-1 handles diverse tasks by formatting the input differently, not by changing the model:

- **Classification** (e.g., sentiment): `[START] text [EXTRACT]` → linear head.
- **Entailment** (e.g., SNLI): `[START] premise [DELIM] hypothesis [EXTRACT]` → linear head.
- **Similarity** (e.g., STS): `[START] text1 [DELIM] text2 [EXTRACT]` and `[START] text2 [DELIM] text1 [EXTRACT]` (both orderings, sum) → linear head.
- **Multiple choice** (e.g., RACE): `[START] context question [DELIM] answer [EXTRACT]` per option → softmax over options.

This **unified input format** meant the same pretrained model could be fine-tuned for any task with minimal architectural modification — just a linear output head. This was a significant departure from task-specific architectures (CNNs for classification, attention networks for entailment, siamese networks for similarity).

## Key Results

GPT-1 achieved state-of-the-art or near-SOTA on 9 of 12 tasks evaluated:

| Task                        | Previous SOTA | GPT-1   | Δ      |
|-----------------------------|---------------|---------|--------|
| SNLI (entailment)           | 89.0          | 89.9    | +0.9   |
| SST-2 (sentiment)           | 93.0          | 91.3    | -1.7   |
| MRPC (paraphrase)           | 86.0          | 86.2    | +0.2   |
| RACE (reading comprehension)| 51.3          | 58.8    | +7.5   |
| CoQA (conversational QA)    | 65.1          | 65.1    | 0.0    |

The most striking result was on RACE (reading comprehension): GPT-1 jumped 7.5 points, suggesting that pretraining on books gave the model genuine reading comprehension ability. The SST-2 regression showed that for very simple tasks (binary sentiment), task-specific architectures could still win — but only barely.

## Why It Worked

### Long-Form Pretraining Data
BooksCorpus provided continuous, coherent long-form text. This taught the model discourse-level patterns (narrative structure, character tracking, argument flow) that short-text corpora (Wikipedia, news) could not. The choice of pretraining data was as important as the architecture.

### Causal Modeling as Universal Pretraining
Causal language modeling is universal — every text sequence is a valid training example. There's no need for special masking (BERT's MLM) or paired data (translation). This makes it trivial to scale pretraining to arbitrary corpora, which would prove crucial as GPT-2 and GPT-3 scaled up.

### Minimal Task-Specific Architecture
By formatting inputs rather than redesigning the model, GPT-1 demonstrated that a single pretrained Transformer could handle diverse tasks. This unified the field — instead of building a different architecture per task, researchers could focus on pretraining and fine-tuning.

### Decoder-Only Architecture
The decoder-only architecture is simpler than encoder-decoder (no cross-attention) and supports generation natively. While BERT (released 6 months later) would show that bidirectional encoders are better for understanding tasks, GPT-1's decoder-only choice proved prescient — it's the architecture of all modern LLMs (GPT-3/4, Llama, Mistral, DeepSeek).

## Limitations

- **Small by modern standards**: 117M parameters is tiny. GPT-2 (1.5B) and GPT-3 (175B) would show what scale could unlock.
- **Short context**: 512 tokens. Modern LLMs handle 100K–1M tokens.
- **No alignment**: GPT-1 produced raw text completions, not helpful responses. It would take InstructGPT (2022) to add the alignment layer that made GPT-class models useful as assistants.
- **Limited evaluation**: the paper evaluated on standard NLP benchmarks, not on the generative tasks (writing, coding, reasoning) that would later define LLM evaluation.

## Impact and Legacy

GPT-1's contributions were conceptual and methodological, not architectural:

1. **Established the GPT recipe**: pretrain (causal LM) → fine-tune (task-specific head). Every subsequent GPT model follows this recipe, with RLHF added for alignment starting at InstructGPT.

2. **Validated decoder-only Transformers for NLP**: before GPT-1, the field was uncertain whether encoder (BERT-style) or decoder (GPT-style) would dominate. GPT-1 showed that decoders work; GPT-2 and GPT-3 would show they scale better.

3. **Unified input formatting**: the idea of formatting inputs to handle diverse tasks (rather than redesigning models) anticipated the text-to-text framing of T5 and the instruction tuning of modern LLMs.

4. **Pretrained models as a product**: GPT-1 was OpenAI's first major public model release. It established the pattern (release pretrained model, let researchers fine-tune) that would define the open-source LLM ecosystem.

For AI engineers, GPT-1 is mostly of historical interest — modern LLMs are 1000× larger and far more capable. But understanding GPT-1 clarifies *why* the field converged on decoder-only Transformers and pretrain-finetune: these choices were not inevitable, but the empirical evidence (starting with GPT-1) made them the default.

## GPT-1 vs. BERT: The 2018 Fork in the Road

GPT-1 (June 2018) and BERT (October 2018) were released within months of each other and established the two paths that would define NLP for years. Their key differences:

| Aspect                  | GPT-1                          | BERT                            |
|-------------------------|--------------------------------|---------------------------------|
| Architecture            | Decoder-only                   | Encoder-only                    |
| Attention               | Causal (unidirectional)        | Bidirectional                   |
| Pretraining objective   | Causal LM (next-token)         | Masked LM (fill-in-the-blank)   |
| Pretraining data        | BooksCorpus (~800M words)      | BooksCorpus + Wikipedia (~3.3B words) |
| Context window          | 512 tokens                     | 512 tokens                      |
| Parameters              | 117M                           | 110M (base), 340M (large)       |
| Fine-tuning             | Per-task head + end-to-end     | Per-task head + end-to-end      |
| Best at                 | Generation, long-form          | Classification, comprehension   |
| Worse at                | Classification (slight)        | Generation                      |
| Future direction        | GPT-2, GPT-3, LLMs             | RoBERTa, DeBERTa (encoder era)  |

**Why BERT initially won**:
- More pretraining data (4× more tokens).
- Bidirectional attention gave better representations for understanding tasks.
- MLM is harder than CLM, forcing the model to learn deeper representations.

**Why GPT-style ultimately won**:
- Decoder-only scales better (GPT-2 1.5B, GPT-3 175B showed this).
- Causal LM is universal — every text is a training example, no special masking.
- Generation is native; BERT can't generate efficiently.
- In-context learning emerges spontaneously in decoder-only at scale.
- The unified pretraining objective (next-token) simplifies scaling.

By 2020 (GPT-3), the industry had largely converged on decoder-only. BERT-style models remain dominant for specialized understanding tasks (embeddings, classification) but are no longer the architectural frontier.

## The Generative Pretraining Insight in Detail

The paper's central claim: generative pretraining (next-token prediction) on unlabeled text teaches the model enough about language that minimal task-specific fine-tuning suffices.

**Why this was non-obvious in 2018**:
- Pre-word2vec, NLP used hand-engineered features (TF-IDF, dependency parses).
- Word2Vec (2013) showed unsupervised pretraining of *embeddings* helped, but the rest of the model was still trained from scratch.
- ELMo (2018) extended this to contextual embeddings, but ELMo was a feature extractor — the downstream model was still task-specific.
- ULMFiT (Howard & Ruder 2018) was the closest precursor: pretrain an LSTM, fine-tune for classification. GPT-1 generalized this to Transformers and to multiple tasks.

**The key empirical finding**: a single pretrained model, with only a linear task-specific head and end-to-end fine-tuning, achieves SOTA on 9 of 12 NLP benchmarks. Before this, SOTA on each benchmark required a different architecture (CNN for sentiment, attention network for entailment, etc.).

This finding is now so accepted that it's hard to remember it was novel. Every modern LLM (Llama, GPT, Claude, Gemini) follows the GPT-1 recipe: pretrain on next-token prediction, then fine-tune (SFT, RLHF, DPO) for specific behaviors.

## The Unified Input Format (Detailed)

GPT-1's input formatting was a quiet but profound innovation. Instead of redesigning the model for each task, GPT-1 formats the input differently:

```
Classification:  [START] text [EXTRACT] → linear head → class
Entailment:      [START] premise [DELIM] hypothesis [EXTRACT] → linear head → entail/neutral/contradict
Similarity:      [START] text1 [DELIM] text2 [EXTRACT] + [START] text2 [DELIM] text1 [EXTRACT] → sum → linear head → score
Multiple choice: [START] context question [DELIM] answer_i [EXTRACT] per option → softmax over options
```

The `[START]`, `[DELIM]`, `[EXTRACT]` tokens delimit input structure for the model. The same pretrained Transformer processes all formats; only the linear head differs.

**Why this mattered**:
1. **Unified architecture**: one model, one architecture, all tasks. No more CNN-for-classification, siamese-for-similarity, etc.
2. **Pretraining transfers**: the pretrained model's understanding of language transfers to all tasks via the same backbone.
3. **Anticipated instruction tuning**: the format-driven approach prefigured T5's text-to-text framing (2019) and modern instruction tuning (FLAN, InstructGPT, 2022+). The idea that "the input format tells the model what to do" is the foundation of modern LLM prompting.

## The BooksCorpus Choice (Detailed)

GPT-1 was pretrained on BooksCorpus (~7,000 unpublished books, ~800M words). The choice was deliberate:

**Why BooksCorpus, not Wikipedia or CommonCrawl?**
- **Long-form continuous text**: books are coherent narratives, teaching long-range dependencies (character tracking, plot, argument flow).
- **Discourse structure**: books have chapters, scenes, arguments — teaching the model how language is structured at the document level.
- **No web noise**: CommonCrawl (used by later models) has machine-generated text, SEO spam, and boilerplate. BooksCorpus is curated (even if "unpublished").

**Why this was important**: a model pretrained on short snippets (Wikipedia articles) learns word-level and sentence-level patterns but not discourse. A model pretrained on books learns that text has long-range structure — character A mentioned in chapter 1 reappears in chapter 5; an argument set up in paragraph 1 is resolved in paragraph 10.

**Limitations**: BooksCorpus is small by modern standards (800M words vs. GPT-3's 500B tokens). GPT-1 was therefore limited in the world knowledge it could acquire. Later models (GPT-2, GPT-3) used much larger and more diverse corpora (WebText, CommonCrawl filtered).

## The 117M Parameter Choice

GPT-1's 117M parameters seem tiny by modern standards, but the choice was constrained:
- **Compute budget**: 8 P6000 GPUs for 1 month. Modern 70B models need 1000s of H100s for months.
- **BooksCorpus size**: with 800M words and 117M params, the model was near compute-optimal (Chinchilla would later suggest ~16B tokens for 117M params; BooksCorpus has ~1B tokens, so GPT-1 was undertrained by modern standards).
- **Memory**: 117M fits in 1 GPU for training; larger models would need model parallelism (immature in 2018).

The undertraining explains why GPT-1 wasn't yet impressive on generation — it could write coherent sentences but not sustained paragraphs. GPT-2 (1.5B params, 10× more data) was the first GPT model that could generate convincing long-form text.

## What GPT-1 Got Wrong (in Hindsight)

1. **Too small**: 117M was insufficient. GPT-2 (1.5B) showed what 13× more parameters unlocked.
2. **Too little data**: 800M words was 1000× less than Chinchilla-optimal. Modern small models (Llama 3 8B) train on 15T tokens.
3. **No alignment**: GPT-1 produced raw text completions, not helpful responses. It would take InstructGPT (2022) to add RLHF alignment.
4. **No in-context learning**: GPT-1 didn't demonstrate ICL — that emerged at GPT-3 scale (175B).
5. **Task-specific heads**: GPT-1 used linear heads for each task. Modern LLMs use the model itself (via prompting) for all tasks — no task-specific architecture.

These "mistakes" are unfair in hindsight — GPT-1 established the recipe that subsequent models scaled. But they show how far the field has come.

## The GPT Family Trajectory (Set by GPT-1)

GPT-1 set the trajectory for the entire GPT family:

| Model      | Params  | Training Data            | Key Innovation                      |
|------------|---------|--------------------------|-------------------------------------|
| GPT-1      | 117M    | BooksCorpus (1B tokens)  | Pretrain-then-finetune recipe       |
| GPT-2      | 1.5B    | WebText (40GB)           | Zero-shot task transfer             |
| GPT-3      | 175B    | CommonCrawl (500B tokens)| In-context learning, few-shot       |
| InstructGPT| 1.3B-175B| + RLHF data              | RLHF alignment                       |
| GPT-4      | ~1.7T (inferred) | Multimodal web     | MoE, multimodal, RLHF + PRMs        |
| GPT-4o     | Unknown | Multimodal (text+img+audio) | Native multimodal                |
| o1 / o3    | Unknown | + reasoning data         | Test-time compute scaling           |

Each step scales an axis: GPT-2 scaled parameters and data, GPT-3 scaled both further and discovered ICL, InstructGPT added alignment, GPT-4 added multimodal and MoE, o1 added test-time compute. GPT-1's recipe — pretrain + fine-tune — runs through all of them.

## Interview Questions

1. **Q: What was GPT-1's main contribution?**
   A: Established the pretrain-then-finetune recipe for decoder-only Transformers: (1) pretrain on large unlabeled text with causal LM, (2) fine-tune with a task-specific linear head on labeled data. Showed a single pretrained model could achieve SOTA on 9 of 12 NLP benchmarks with minimal task-specific architecture. This recipe runs through all modern LLMs.

2. **Q: How did GPT-1 differ from BERT?**
   A: GPT-1 was decoder-only with causal attention and next-token prediction; BERT was encoder-only with bidirectional attention and masked LM. BERT initially dominated understanding tasks (classification, NER); GPT-style ultimately won because (1) it scales better, (2) causal LM is universal training data, (3) generation is native, (4) ICL emerges at scale.

3. **Q: Why did GPT-1 use BooksCorpus instead of Wikipedia?**
   A: BooksCorpus provides long-form continuous text — coherent narratives that teach long-range dependencies and discourse structure. Wikipedia articles are shorter and more disconnected. BooksCorpus was the right choice for teaching the model how language is structured at the document level, even though it was small by modern standards (800M words).

4. **Q: What was GPT-1's "unified input format" innovation?**
   A: Instead of redesigning the model per task, GPT-1 used input formatting: `[START] text [DELIM] text2 [EXTRACT]` for similarity, `[START] premise [DELIM] hypothesis [EXTRACT]` for entailment, etc. The same pretrained model processed all formats; only a linear head differed. This anticipated T5's text-to-text framing and modern instruction tuning — the input format tells the model what to do.

5. **Q: Why wasn't GPT-1 impressive at generation?**
   A: Three reasons: (1) only 117M parameters — too small for sustained coherent generation, (2) trained on only 800M words (~1B tokens) — severely undertrained by modern Chinchilla standards (would need ~16B tokens for compute-optimality), (3) no alignment training — GPT-1 produced raw text completions, not helpful responses. GPT-2 (1.5B params, 10× more data) was the first GPT that could generate convincing long-form text.

6. **Q: How did GPT-1 set the trajectory for modern LLMs?**
   A: The recipe — pretrain on causal LM, then fine-tune for specific tasks — runs through GPT-2 (scaled params/data), GPT-3 (discovered ICL), InstructGPT (added RLHF alignment), GPT-4 (added multimodal + MoE), and o1 (added test-time compute). Each generation scales an axis, but the core recipe is unchanged from GPT-1. This is why GPT-1 is historically critical even though its capability is negligible by modern standards.
