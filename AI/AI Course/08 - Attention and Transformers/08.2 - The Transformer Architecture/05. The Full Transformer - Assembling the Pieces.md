## The full architecture

We now have all the pieces. The full Transformer (Vaswani et al. 2017) is:

```
INPUT (source)                    OUTPUT (target, shifted right)
   │                                      │
   ▼                                      ▼
[Token Embedding]                   [Token Embedding]
   + Positional Encoding                 + Positional Encoding
   │                                      │
   ▼                                      ▼
┌──────────────┐                  ┌──────────────────┐
│ Encoder      │                  │ Decoder Block 1  │
│ Block 1      │                  │ (masked SA,      │
│              │                  │  cross-attn, FFN)│
├──────────────┤                  ├──────────────────┤
│ Encoder      │◀─── cross-attn ──│ Decoder Block 2  │
│ Block 2      │                  ├──────────────────┤
├──────────────┤                  │ ...              │
│ ...          │                  ├──────────────────┤
├──────────────┤                  │ Decoder Block N  │
│ Encoder      │                  └──────────────────┘
│ Block N      │                          │
└──────────────┘                          ▼
       │                            Linear projection
       │                            to vocabulary
       │                                  │
       │                                  ▼
       │                              Softmax
       │                                  │
       │                                  ▼
       │                       Output probabilities
       │                       (over vocabulary)
```

### The encoder stack

- **Input:** source sequence (e.g., English sentence), tokenized and embedded, plus positional encoding.
- **Stack:** $N$ encoder blocks (each = self-attention + FFN, with residuals and LayerNorm).
- **Output:** a sequence of contextualized vectors $X_{enc} \in \mathbb{R}^{T_{src} \times d}$, one per source token.

### The decoder stack

- **Input:** target sequence shifted right (e.g., French sentence starting with `<BOS>`), tokenized and embedded, plus positional encoding.
- **Stack:** $N$ decoder blocks (each = masked self-attention + cross-attention to encoder output + FFN, with residuals and LayerNorm).
- **Output:** a sequence of contextualized vectors $Y_{dec} \in \mathbb{R}^{T_{tgt} \times d}$.
- **Final layer:** linear projection to vocabulary size, then softmax, producing a distribution over the vocabulary at each position.

### Training loss

Cross-entropy between the predicted distributions and the true target tokens, summed over all decoder positions. This is teacher forcing (see [[02. Teacher Forcing and Exposure Bias]]) — the decoder is fed the true previous tokens during training.

## The hyperparameters of the original Transformer

| Hyperparameter | Value |
| :--- | :--- |
| Model dimension $d$ | 512 |
| Number of heads $h$ | 8 |
| Head dimension $d_k = d/h$ | 64 |
| FFN hidden dimension $d_{ff}$ | 2048 (= 4d) |
| Number of encoder blocks $N_{enc}$ | 6 |
| Number of decoder blocks $N_{dec}$ | 6 |
| Positional encoding | Sinusoidal |
| LayerNorm placement | Post-LN (original); Pre-LN (modern) |
| Activation | ReLU (original); GELU (modern) |
| Dropout | 0.1 |
| Optimizer | Adam, with warmup + inverse-sqrt schedule |
| Batch size | ~25k tokens |

These are the "base" model hyperparameters. The "big" model scales to $d = 1024$, $h = 16$, $d_{ff} = 4096$, $N = 6$, achieving better translation at ~4× the compute.

## Why this architecture works — three perspectives

### Perspective 1: It is a fully parallelizable sequence model

Unlike the RNN, every position in the encoder can be computed simultaneously — there is no sequential dependency across time. This makes training on GPUs dramatically faster, which is what enabled training on web-scale datasets.

### Perspective 2: It has $O(1)$ path length between any two positions

Unlike the RNN, which requires $O(T)$ steps for information to flow from position 1 to position $T$, the Transformer connects every pair of positions in a single attention operation. This is why it handles long-range dependencies better than RNNs (see [[02. Long-Range Dependencies and Why RNNs Struggle]]).

### Perspective 3: It is a stack of contextualizers

Each encoder block takes a sequence of token representations and contextualizes them — each token's representation becomes a function of all other tokens. Stacking $N$ blocks deepens this contextualization: after 12 blocks, each token's representation encodes not just its local context but the global structure of the sequence. This is analogous to how stacked CNN layers expand the receptive field, except the Transformer's "receptive field" is global from the first block.

## What the Transformer does NOT do

Be honest about the limitations:

1. **$O(T^2)$ cost.** The self-attention matrix is $T \times T$, making the Transformer expensive for very long sequences. This is the subject of efficient-attention research (sparse, linear, flash attention).

2. **No memory.** The Transformer has no persistent state across sequences — each forward pass is independent. This is in contrast to RNNs, which can maintain a hidden state across a session. Memnet, Transformer-XL, and RNN-based retrieval-augmented models try to add memory, but vanilla Transformers are stateless.

3. **Exposure bias.** The decoder is trained with teacher forcing and suffers from exposure bias at inference (see [[02. Teacher Forcing and Exposure Bias]]). This is not unique to Transformers — it is a property of autoregressive training — but it remains a limitation.

4. **No built-in notion of hierarchy.** The Transformer treats all positions uniformly, with no explicit hierarchical structure. CNNs encode spatial hierarchy through pooling; TreeRNNs encode syntactic hierarchy through tree structure. The Transformer learns hierarchy implicitly through attention, which works but is less efficient than an explicit hierarchy would be.

## The three sub-families of Transformers

The full Encoder-Decoder Transformer is one design point in a broader space. Three sub-families have emerged, each suited to different tasks:

1. **Encoder-only (BERT, RoBERTa, ViT):** stacks of encoder blocks, bidirectional attention. Best for understanding tasks (classification, entity recognition, retrieval). Covered in [[01. The Encoder-Decoder Design Space - BERT vs GPT vs T5]].

2. **Decoder-only (GPT, LLaMA, PaLM):** stacks of decoder blocks (without cross-attention), causal attention. Best for generation tasks (text completion, chat, code). The dominant architecture for modern LLMs.

3. **Encoder-Decoder (T5, BART, original Transformer):** full encoder + decoder with cross-attention. Best for sequence-to-sequence tasks (translation, summarization) where input and output are distinct.

The choice between these is the subject of [[08.4 - Encoder, Decoder, and the Design Space]].

---

## What you should walk away with

1. The full Transformer = embedding + positional encoding → $N$ encoder blocks → $N$ decoder blocks (with cross-attention) → linear + softmax.
2. The encoder produces contextualized source representations; the decoder generates target tokens autoregressively, attending to the encoder via cross-attention.
3. The architecture is fully parallelizable (unlike RNNs), has $O(1)$ path length (unlike RNNs), and stacks contextualizers (analogous to stacked CNN layers).
4. Limitations: $O(T^2)$ cost, no memory, exposure bias, no built-in hierarchy.
5. Three sub-families: encoder-only (BERT), decoder-only (GPT), encoder-decoder (T5) — each suited to different tasks.

You now understand the Transformer. The rest of this chapter applies it: to vision (08.3, ViT) and to the design space of encoder/decoder choices (08.4).
