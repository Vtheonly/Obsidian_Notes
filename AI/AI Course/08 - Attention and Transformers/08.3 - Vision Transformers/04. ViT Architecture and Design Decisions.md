## The full ViT, assembled

Putting together everything from the previous three notes, here is the complete ViT architecture:

```
Image (224×224×3)
    │
    ▼
┌─────────────────────────────┐
│ Patch Extraction + Embed    │  Conv2d(3, 768, kernel=16, stride=16)
│ → (196, 768) patch tokens   │  + learned 1D positional embeddings
│ + CLS token prepended        │  + learned CLS token
│ → (197, 768) input sequence  │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ Transformer Encoder Block 1 │  Multi-Head Self-Attention (12 heads)
│                             │  + Residual + LayerNorm
│                             │  Feedforward (3072 hidden, GELU)
│                             │  + Residual + LayerNorm
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ Transformer Encoder Block 2 │  (same structure)
└─────────────────────────────┘
    │
   ...
    │
    ▼
┌─────────────────────────────┐
│ Transformer Encoder Block 12│  (ViT-Base has 12 blocks)
└─────────────────────────────┘
    │
    ▼
    Extract CLS token's final representation (768-dim)
    │
    ▼
┌─────────────────────────────┐
│ LayerNorm                   │
└─────────────────────────────┘
    │
    ▼
┌─────────────────────────────┐
│ Linear Head (768 → num_classes)│
└─────────────────────────────┘
    │
    ▼
Class logits
```

This is ViT-Base: 12 layers, $d = 768$, 12 heads, $d_k = 64$, FFN hidden = 3072 ($4d$), ~86M parameters. The architecture is *exactly* a BERT-base Transformer encoder, with the only vision-specific component being the patch embedding.

## The three standard ViT variants

| Model | Layers | $d$ | Heads | FFN | Params | Patches (224px) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| ViT-Tiny | 12 | 192 | 3 | 768 | 5.5M | 196 |
| ViT-Small | 12 | 384 | 6 | 1536 | 22M | 196 |
| ViT-Base | 12 | 768 | 12 | 3072 | 86M | 196 |
| ViT-Large | 24 | 1024 | 16 | 4096 | 307M | 196 |
| ViT-Huge | 32 | 1280 | 16 | 5120 | 632M | 196 |

Notice that the patch count (196) stays constant across model sizes — the model scales by deepening and widening, not by adding more patches. This is because the $O(N^2)$ attention cost makes adding patches expensive: going from 196 to 784 patches (16×16 to 8×8) quadruples the attention cost.

For higher-resolution variants (ViT-L/384, ViT-H/14), the patch size is reduced (14×14 instead of 16×16) or the image is larger (384px instead of 224px), increasing the patch count and the attention cost but providing finer spatial detail.

## Design decisions, justified

Each component of the ViT is a deliberate choice, often different from the original NLP Transformer. Let's justify the major ones:

### 1. Why GELU instead of ReLU in the FFN?

The original Transformer used ReLU in the FFN. BERT switched to GELU (Gaussian Error Linear Unit — see [[06. Activation Functions in Deep Learning]]), and ViT followed BERT. GELU is smoother than ReLU (no sharp kink at 0) and empirically performs slightly better in Transformers. The difference is small, but GELU has become the de facto standard for Transformer FFNs.

### 2. Why learned 1D positional embeddings?

The original NLP Transformer used fixed sinusoidal encodings. ViT uses **learned 1D** positional embeddings. Three reasons:

- **Learned > sinusoidal for vision.** Empirically, learned embeddings slightly outperform sinusoidal for ViTs, probably because the 2D structure of patches is not well-captured by the 1D sinusoid pattern.
- **1D is sufficient.** You might expect 2D positional embeddings (one for row, one for column) to be necessary for images, but experiments show 1D is enough — the model learns the 2D structure from the 1D ordering.
- **Fixed image size.** ViTs are typically trained at a fixed resolution (224px), so the maximum sequence length is known. Learned embeddings are fine for fixed-length inputs; sinusoidal's extrapolation advantage is irrelevant.

For models that need to handle variable resolution (DeiT, Swin), rotary or factorized 2D encodings are used instead.

### 3. Why Pre-LN instead of Post-LN?

The original Transformer used Post-LN (LayerNorm after the residual addition). ViT follows BERT and GPT in using **Pre-LN** (LayerNorm before the sublayer). Pre-LN is more stable for training deep stacks (12+ layers) because the residual path is purely additive, preserving gradient flow. Post-LN requires careful warmup and is prone to instability in deep models.

### 4. Why the CLS token instead of GAP?

Covered in [[02. The CLS Token and Why It Works]]. Short version: the CLS token is a learnable readout that adapts to the task, slightly more expressive than fixed averaging.

### 5. Why no dropout in the patch embedding?

The patch embedding is a single linear transformation; dropout here would corrupt the input before the Transformer can process it. Dropout is applied *inside* the Transformer blocks (on attention weights and FFN outputs) but not on the patch embeddings or positional embeddings.

### 6. Why 16×16 patches?

The patch size $P = 16$ is a compromise:

- $P = 32$: too coarse — each patch averages 1024 pixels, losing fine detail. Sequence length 49 (very cheap).
- $P = 16$: good balance — each patch covers 256 pixels, fine enough for most ImageNet classes. Sequence length 196 (manageable).
- $P = 8$: too fine — each patch covers 64 pixels, providing detail but making the sequence length 784 (expensive attention).

For higher-resolution tasks (medical imaging, satellite), smaller patches (8×8 or 14×14) are used with appropriate compute budgets.

## Training recipe

The ViT training recipe reveals a lot about the model's data hunger:

| Stage | Dataset | Detail |
| :--- | :--- | :--- |
| Pretraining | JFT-300M (300M images, 18K classes) | The original ViT was pretrained on Google's proprietary massive dataset. Without this, ViT underperforms ResNet. |
| Fine-tuning | ImageNet-1K (1.3M images, 1K classes) | Replace the classification head with a fresh one for the target classes, fine-tune the whole model. |
| Resolution bump | ImageNet-1K at 384px | After fine-tuning at 224px, fine-tune again at higher resolution for a final accuracy boost. |

The reliance on JFT-300M was the original ViT's biggest limitation. Subsequent work (DeiT, MAE, DINO) made ViTs competitive on ImageNet-1K alone through aggressive augmentation and self-supervised pretraining, but the original recipe needed the massive dataset.

## What ViT learns — attention visualizations

When you visualize the attention patterns of a trained ViT, you find:

- **Early layers** attend to local neighborhoods (patches near the query patch), even though there is no architectural constraint forcing this. The model *learns* locality from data.
- **Middle layers** attend to semantically related patches regardless of distance — e.g., a patch containing a dog's ear attends to other patches containing ears or fur.
- **Late layers** attend to the CLS token and to the most discriminative patches for the classification task.

This is striking: the ViT, with no built-in locality prior, *discovers* locality in its early layers. The CNN gets locality for free; the ViT learns it. This is the data-driven-learning advantage — but it only works because the ViT was trained on enough data (JFT-300M) to discover the prior.

## ViT's descendants and the modern landscape

The ViT spawned a large family of variants:

- **DeiT** (Touvron et al. 2021): ViT competitive on ImageNet-1K alone, via aggressive augmentation and CNN-teacher distillation.
- **Swin Transformer** (Liu et al. 2021): hierarchical architecture with shifted-window attention, reintroducing multi-scale priors. State-of-the-art on dense prediction tasks (detection, segmentation).
- **MAE** (He et al. 2022): masked autoencoder pretraining for ViTs — mask 75% of patches, reconstruct them. Provides a strong self-supervised pretraining objective that works on ImageNet-1K alone.
- **DINOv2** (Oquab et al. 2023): self-supervised ViT pretraining producing features that rival supervised ones across many tasks.
- **CLIP** (Radford et al. 2021): co-train an image encoder (ViT) and a text encoder (Transformer) on 400M image-text pairs, producing image features aligned with language. The backbone of modern multimodal AI.

The trend is clear: **ViTs have replaced CNNs as the default image encoder for large-scale vision tasks**, just as Transformers replaced RNNs for sequence tasks. CNNs remain relevant for small-data regimes and edge deployment, but the center of gravity has shifted to attention-based architectures.

---

## What you should walk away with

1. A ViT is a BERT-style Transformer encoder with a patch-embedding front-end and a CLS-token readout — the only vision-specific component is the patch embedding.
2. Standard variants scale from ViT-Tiny (5.5M params) to ViT-Huge (632M params) by deepening and widening, keeping the patch count fixed at 196 (for 224px images).
3. Key design choices: GELU activation, learned 1D positional embeddings, Pre-LN, CLS token, 16×16 patches.
4. The original ViT needed JFT-300M pretraining; modern variants (DeiT, MAE, Swin) are competitive on ImageNet-1K alone.
5. Trained ViTs *learn* locality in early layers — confirming that attention discovers CNN priors from data when given enough of it.
6. ViTs have replaced CNNs as the default for large-scale vision; CNNs remain relevant for small-data and edge cases.
