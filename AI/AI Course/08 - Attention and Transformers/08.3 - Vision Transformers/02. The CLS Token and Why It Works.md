# 02. The CLS Token and Why It Works

> **Prerequisites:** [[01. From Words to Patches - How ViT Tokenizes an Image]]
> **Connections:** [[11. Global Average Pooling (GAP)]] (the CNN alternative for image-level summaries)

---

## The classification problem

After the Transformer encoder processes the $N+1$ patch tokens (the $N$ patches plus the prepended CLS token), we have a sequence of $N+1$ contextualized vectors, each of dimension $d$. To classify the image (e.g., "is this a cat or a dog?"), we need to reduce this sequence to a single vector that can be fed to a linear classifier.

There are two natural ways to do this:

1. **Global Average Pooling (GAP):** average all $N$ patch vectors, producing one $d$-dimensional summary. This is what CNNs do (see [[11. Global Average Pooling (GAP)]]).

2. **CLS token:** use the final-layer representation of the special CLS token, prepended at the input, as the summary.

ViT uses the CLS token. Why?

---

## What the CLS token is

The CLS ("classification") token is a single learned vector, prepended to the sequence of patch embeddings before the first Transformer block:

$$Z_0 = [\mathbf{z_{cls}}; z_1 + PE(1); \ldots; z_N + PE(N)]$$

The CLS token has no fixed meaning — it is a *learned* parameter, just like the patch embedding matrix or the positional embeddings. At initialization, it is random. During training, it learns to be whatever the model needs it to be.

As the sequence passes through the Transformer blocks, the CLS token participates in self-attention like any other token. At each layer, it attends to the patch tokens (and to itself), accumulating information from across the image. By the final layer, the CLS token's representation is a **global summary of the image**, computed by attention rather than averaging.

At the end, only the CLS token's final-layer representation is used:

$$\text{logits} = \text{Linear}(z_{cls}^{(L)})$$

where $L$ is the number of layers. The patch tokens' final representations are discarded (for classification; they may be used for other tasks like segmentation).

---

## Why the CLS token instead of GAP?

Three reasons, in increasing order of importance:

### 1. Attention is smarter than averaging

GAP computes an unweighted average of all patch representations. Every patch contributes equally, regardless of whether it is relevant to the classification task. A patch containing the background sky contributes as much as a patch containing the cat's face.

The CLS token, by contrast, attends to patches with **learned weights**. If the task is "cat vs dog," the CLS token can learn to attend strongly to face patches and weakly to background patches, producing a summary that emphasizes discriminative regions. This is strictly more expressive than averaging — averaging is the special case where all attention weights are equal.

### 2. The CLS token can aggregate information across layers

In a deep Transformer, the CLS token's representation at layer $L$ is the result of $L$ rounds of attention. At each round, it can decide which patches to pull information from, and those patches' representations have themselves been contextualized by previous rounds. The CLS token thus aggregates not just the patches but the *refined, contextualized* patches — a richer summary than the raw average.

### 3. The CLS token is task-specific without architectural changes

GAP produces the same summary regardless of the task. If you switch from "cat vs dog" to "is there a person in this image?", the GAP summary is the same — only the final linear classifier changes.

The CLS token, by contrast, is a learned parameter that adapts to the task. For "cat vs dog," it learns to attend to animal-related patches; for "is there a person?", it learns to attend to person-related patches. The same Transformer backbone can be used for many tasks by simply re-training the CLS token (and the final classifier) — the patch representations do not need to change.

---

## Why does prepending a learned token work at all?

This is the deepest question, and the answer reveals something important about attention.

At first glance, prepending a meaningless learned vector to a sequence of meaningful patch embeddings seems arbitrary. Why should this token, which starts as random noise, become a useful image summary?

The answer: **attention is symmetric and learnable.** The CLS token's query at each layer is a learned projection of its current representation. At initialization, this query is random, so the CLS token attends to random patches and accumulates random information — useless. But the attention weights and the CLS token's representation are *trained by backpropagation*. The gradient signal from the classification loss flows back through the CLS token's representation, through its query projections, and adjusts them so that the CLS token learns to attend to whatever patches are most useful for the task.

In other words, the CLS token is a **learnable readout point**. The Transformer encoder builds rich contextualized representations of all patches; the CLS token learns to query those representations in a task-relevant way. The architecture provides the substrate (attention); training determines the readout.

This is the same principle as a `[CLS]` token in BERT — a learnable aggregation point that adapts to the downstream task. It is one of the more elegant design choices in modern deep learning: instead of designing a fixed aggregation rule (like GAP), let the model learn the aggregation.

---

## CLS token vs GAP — the empirical verdict

In practice, both work. The original ViT paper used the CLS token; follow-up work (notably "Early Convolutions Help Transformers See Further" and the Swin Transformer) showed that GAP works comparably, especially when the model is pretrained on large datasets.

The current consensus:

- **CLS token** is slightly better for small-to-medium datasets, where the learnable aggregation helps.
- **GAP** is slightly better for very large datasets, where the model has enough data to learn good patch representations and the CLS token's learnable aggregation is redundant.
- For most practical purposes, the difference is within noise.

The CLS token's main advantage is conceptual: it makes the "image summary" an explicit, learned, task-adaptive quantity, rather than an implicit byproduct of averaging.

---

## What you should walk away with

1. The CLS token is a learned vector prepended to the patch sequence; its final-layer representation is used as the image-level summary for classification.
2. It is a learnable alternative to Global Average Pooling — attention-based aggregation rather than fixed averaging.
3. Attention is smarter than averaging: the CLS token can learn to weight discriminative patches more than background patches.
4. The CLS token adapts to the task (cat-vs-dog vs person-detection) by learning different attention patterns, without architectural changes.
5. The reason prepending a "meaningless" token works is that attention is learnable: the CLS token's query projections are trained to retrieve task-relevant information from the patch representations.
