# 3.6 Canny and LoG — Advanced Edge Detection

> **Prerequisites:** [[3.5 Sharpening and Edge Detection]] (Sobel and Laplacian basics)
> **Connections:** [[3.4 Edge Preserving Filters]] (Gaussian smoothing), [[5.6 The Classical-to-Deep Bridge]]

The previous note covered the two basic edge detectors (Sobel and Laplacian). This note covers the **gold-standard** edge detectors that real systems use: **Canny** (the most widely used edge detector in classical CV) and **LoG / Marr-Hildreth** (the principled second-derivative approach). These are the detectors you should reach for when you need clean, reliable edges — not raw Sobel.

---

## The problem with basic edge detection

Raw Sobel and Laplacian have three problems that make them unsuitable for production use:

1. **Thick edges:** Sobel produces edges that are several pixels wide, not 1-pixel lines.
2. **Noisy:** both detectors respond to noise, producing spurious edges in textured or noisy regions.
3. **Disconnected:** the edges are broken into fragments, not continuous contours.

The **Canny edge detector** (John Canny, 1986) solves all three with a multi-step pipeline. It is still the default edge detector in OpenCV (`cv2.Canny`) and most classical CV pipelines, 40 years after its invention.

---

## The Canny Edge Detector — 5 steps

Canny framed edge detection as an **optimization problem** with three criteria:
- **Good detection:** real edges should be found, noise should not.
- **Good localization:** detected edges should be as close as possible to the true edge.
- **Single response:** one edge should produce one detector response (not a thick band).

His algorithm achieves these via five steps:

### Step 1: Gaussian smoothing

Apply a Gaussian blur to the image before computing gradients. This suppresses noise that would otherwise create spurious edges. The Gaussian's $\sigma$ controls the smoothing strength — larger $\sigma$ removes more noise but also blurs fine edges.

$$G(x,y) = \frac{1}{2\pi\sigma^2} \exp\left(-\frac{x^2 + y^2}{2\sigma^2}\right)$$

**Why Gaussian?** The Gaussian is the unique filter that is both smooth in the spatial domain and smooth in the frequency domain (it minimizes the time-frequency uncertainty product). This means it smooths without introducing ringing artifacts (which a box filter would).

### Step 2: Compute the gradient (Sobel)

Apply Sobel in $x$ and $y$ to get $G_x, G_y$. Compute:
- **Magnitude:** $|\nabla f| = \sqrt{G_x^2 + G_y^2}$
- **Direction:** $\theta = \arctan(G_y / G_x)$

At this point, we have a thick edge map (same as raw Sobel). The next steps thin and clean it.

### Step 3: Non-maximum suppression (NMS) — thinning

This is Canny's key innovation. The goal: reduce the thick edge band to a **1-pixel-wide line**.

For each pixel, the algorithm checks: *is this pixel the local maximum of gradient magnitude along the edge direction?*
- The edge direction $\theta$ tells us which way the edge runs.
- The gradient direction (perpendicular to the edge) tells us which way the edge transitions.
- We compare the pixel's magnitude to its two neighbors **along the gradient direction** (the direction of steepest change).
- If the pixel is **not** the maximum of the three, it is suppressed (set to 0).

**Quantization:** the gradient direction is continuous, but pixels are on a grid. Canny quantizes $\theta$ into 4 directions (0°, 45°, 90°, 135°) and compares along the corresponding neighbor pair.

**Result:** after NMS, edges are 1-pixel-wide lines. This is the "single response" criterion satisfied.

### Step 4: Double thresholding — separating strong, weak, and non-edges

Canny uses **two thresholds** ($T_{high}$ and $T_{low}$, typically with a 2:1 or 3:1 ratio):
- **Strong edges** (magnitude $> T_{high}$): definitely real edges. Keep.
- **Weak edges** ($T_{low} <$ magnitude $< T_{high}$): maybe edges. Keep for now, decide in step 5.
- **Non-edges** (magnitude $< T_{low}$): definitely noise. Discard.

The double threshold is smarter than a single threshold because it avoids the harsh cutoff: weak edges that are connected to strong edges are probably real (continuations of the strong edge), while weak edges in isolation are probably noise. Step 5 makes this decision.

### Step 5: Hysteresis / Edge tracking — connecting edges

**Hysteresis** links weak edges to strong edges:
- A weak edge pixel is kept **only if** it is connected (8-connectivity) to a strong edge pixel.
- This is done by tracing from each strong edge pixel, following the weak edges outward, and keeping the connected contour.
- Isolated weak edges (not connected to any strong edge) are discarded as noise.

**Result:** clean, thin, connected edge contours. This is the "good detection" and "good localization" criteria satisfied.

### Why Canny is still the default

Canny's pipeline is a masterclass in classical algorithm design. Each step addresses a specific failure mode of the previous step, and the combination produces edges that are:
- Thin (1 pixel wide) — from NMS
- Connected (continuous contours) — from hysteresis
- Low-noise (few spurious edges) — from Gaussian smoothing + double threshold
- Well-localized (close to true edges) — from the zero-crossing-like precision of NMS

Modern deep-learning edge detectors (HED, DexiNed) can outperform Canny on benchmarks, but Canny remains the default because it is fast, parameter-free (given $\sigma$ and the thresholds), interpretable, and good enough for most applications.

### Choosing Canny's parameters

- **$\sigma$ (Gaussian smoothing):** 1.0–2.0 is typical. Larger for noisy images, smaller for clean images.
- **$T_{low}$ and $T_{high}$:** often set automatically via Otsu's method on the gradient magnitude (see [[5.7 Thresholding and Otsu's Method]]). A common manual heuristic: $T_{high} = 0.4 \times \max(\text{magnitude})$, $T_{low} = 0.5 \times T_{high}$.

```python
import cv2
edges = cv2.Canny(image, threshold1=100, threshold2=200, apertureSize=3)
# apertureSize is the Sobel kernel size (3, 5, or 7)
```

## The LoG (Laplacian of Gaussian) / Marr-Hildreth Detector

An alternative approach based on the second derivative, motivated by biological vision.

### The motivation: Marr and Hildreth's theory

David Marr and Ellen Hildreth (1980) proposed that the human visual system detects edges using the **zero crossings of the Laplacian of a Gaussian-smoothed image**. Their argument:
1. The image must be smoothed (to handle noise) — use a Gaussian.
2. The edge location is where the intensity changes most rapidly — the second derivative's zero crossing.
3. The Laplacian (sum of second partials) is isotropic (detects edges in all directions, no orientation needed).

### The LoG operator

Combine Gaussian smoothing and the Laplacian into a single operator. Because differentiation and convolution commute:

$$\nabla^2(G_\sigma * f) = (\nabla^2 G_\sigma) * f = \text{LoG}_\sigma * f$$

So we can pre-compute the **Laplacian of the Gaussian** $\nabla^2 G_\sigma$ and convolve it with the image directly. The LoG kernel (the "Mexican hat" or "sombrero" function):

$$\text{LoG}(x,y) = -\frac{1}{\pi\sigma^4}\left(1 - \frac{x^2 + y^2}{2\sigma^2}\right) \exp\left(-\frac{x^2 + y^2}{2\sigma^2}\right)$$

This looks like an inverted sombrero: a negative central region surrounded by a positive ring. Convolving it with the image produces a response that is zero at edges (zero crossings) and non-zero elsewhere.

### The Marr-Hildreth algorithm

1. Convolve the image with the LoG kernel at a chosen $\sigma$.
2. Find the **zero crossings** of the result.
3. (Optionally) keep only zero crossings where the slope is steep enough (to filter weak responses).

**Advantages:**
- Biologically motivated — models the retina's center-surround receptive fields.
- Isotropic — no need to compute directions.
- Produces closed contours (zero crossings form closed curves), which is useful for segmentation.

**Disadvantages:**
- The zero-crossing contours can be noisy and produce many small closed loops.
- The $\sigma$ parameter trades off localization vs noise: large $\sigma$ gives good detection but poor localization; small $\sigma$ gives precise localization but more noise.
- Does not provide edge direction (only location).

### The DoG approximation

The LoG can be approximated by the **Difference of Gaussians (DoG)** — the difference of two Gaussian-blurred images at different $\sigma$ values:

$$\text{DoG}_{\sigma_1, \sigma_2}(x,y) = G_{\sigma_1}(x,y) - G_{\sigma_2}(x,y)$$

The DoG is cheaper to compute (two Gaussian convolutions vs one LoG convolution) and is close enough to LoG for practical purposes. The DoG is used as a building block in **SIFT** (see [[3.8 Feature Descriptors - SIFT, SURF, ORB, HOG]]) — the scale-space pyramid is built from DoG responses.

## Canny vs LoG vs Sobel — when to use which

| Detector | Output | Strength | Weakness | Best for |
| :--- | :--- | :--- | :--- | :--- |
| **Sobel** | Thick gradient magnitude | Simple, fast, gives direction | Thick, noisy edges | Quick gradient features, HOG |
| **Canny** | Thin, connected edges | Clean, parameter-tunable | Requires threshold tuning | General-purpose edge detection |
| **LoG / Marr-Hildreth** | Zero-crossing contours | Closed contours, biologically motivated | Noisy zero crossings, no direction | Segmentation via closed contours |

**Practical recommendation:** use **Canny** as the default. It is what `cv2.Canny` implements, it is what most tutorials use, and it produces the cleanest edges for most images. Use LoG when you specifically need closed contours (for segmentation) or when you want a biologically-motivated approach. Use raw Sobel when you need the gradient direction (for feature descriptors) or when you want maximum speed.

---

## What you should walk away with

1. **Canny** is the gold-standard classical edge detector, using a 5-step pipeline: Gaussian smoothing → Sobel gradient → non-maximum suppression (thinning) → double thresholding → hysteresis (edge linking).
2. **Non-maximum suppression** thins edges to 1 pixel by keeping only the local maxima along the gradient direction.
3. **Hysteresis** links weak edges to strong edges, producing connected contours while rejecting isolated noise.
4. **LoG (Laplacian of Gaussian)** finds edges as zero crossings of the second derivative after Gaussian smoothing — biologically motivated, produces closed contours.
5. **DoG (Difference of Gaussians)** approximates LoG cheaply and is used in SIFT's scale-space.
6. Use Canny as the default; use LoG for closed contours; use raw Sobel when you need gradient direction.
