# 3.10 The Hough Transform — Detecting Lines and Curves

> **Prerequisites:** [[3.5 Sharpening and Edge Detection]] (edges feed the Hough transform), [[3.6 Canny and LoG - Advanced Edge Detection]]
> **Connections:** [[3.8 Feature Descriptors - SIFT, SURF, ORB, HOG]] (feature extraction)

The **Hough Transform** is a classical technique for detecting **parametric shapes** — most commonly lines and circles — in edge images. It is powerful because it can find shapes even when they are broken, noisy, or partially occluded, by **voting** in a parameter space. This note explains the line Hough transform (the canonical example) and the circle Hough transform.

---

## The problem with edge linking

After running an edge detector (Sobel, Canny), you have an edge map — but the edges are individual pixels, not geometric shapes. To find a **line** in the image, you would need to group edge pixels into line segments. This is hard because:
- Edges may have gaps (the detector missed some pixels).
- Multiple lines may intersect.
- Noise creates spurious edge pixels.

**Edge linking** (connecting adjacent edge pixels into chains) handles simple cases but breaks on gaps and intersections. The Hough transform takes a different, more robust approach.

---

## The key idea: vote in parameter space

Instead of trying to connect edge pixels directly, the Hough transform lets each edge pixel **vote** for all the shapes it could be part of. Shapes that receive many votes are likely real shapes (because many edge pixels agree on them).

### The line parameterization

A line can be described by $y = mx + b$, where $m$ is the slope and $b$ is the intercept. Each line corresponds to a point $(m, b)$ in **parameter space**. The Hough idea:
- For each edge pixel $(x_0, y_0)$, all lines passing through it satisfy $y_0 = m x_0 + b$, i.e., $b = y_0 - m x_0$. This is a **line in $(m, b)$ parameter space**.
- So each edge pixel votes for a **line of possibilities** in parameter space.
- Multiple edge pixels on the same image line will vote for parameter-space lines that **all intersect at the same point** — the $(m, b)$ of the image line.

The algorithm:
1. Discretize the parameter space into bins (the **accumulator array**).
2. For each edge pixel, compute the parameter-space line and increment all bins it passes through.
3. Find the bins with the most votes — these correspond to detected lines.

### The $(\rho, \theta)$ parameterization

The $(m, b)$ parameterization has a problem: vertical lines have $m = \infty$, which cannot be represented. The standard fix uses the **normal form**:

$$\rho = x \cos\theta + y \sin\theta$$

where $\rho$ is the perpendicular distance from the origin to the line, and $\theta$ is the angle of the normal. Every line has a finite $(\rho, \theta)$ representation. Each edge pixel votes for a **sinusoidal curve** in $(\rho, \theta)$ space (not a line, but the same principle applies).

### The algorithm, concretely

1. Run edge detection → binary edge image.
2. Initialize the accumulator array $A[\rho, \theta]$ to zeros. $\rho$ ranges over $[-D, D]$ (where $D$ is the image diagonal); $\theta$ ranges over $[0, \pi)$ (or $[0, 2\pi)$).
3. For each edge pixel $(x, y)$:
   - For each $\theta$ in the discretized range:
     - Compute $\rho = x \cos\theta + y \sin\theta$.
     - Increment $A[\rho, \theta]$.
4. Find local maxima in $A$ above a threshold — these are the detected lines.
5. (Optional) For each detected $(\rho, \theta)$, find the edge pixels that contributed to it, and determine the line segment endpoints.

### Why this works

- A single noisy edge pixel contributes one sinusoid — it does not create a strong peak.
- Many edge pixels on the same line contribute sinusoids that all pass through the same $(\rho, \theta)$ point — this point gets many votes and is detected.
- Gaps in the edge do not matter — the pixels on either side of the gap still vote for the same $(\rho, \theta)$.
- Intersecting lines are fine — each line has its own peak in parameter space.

The Hough transform is a **global** method: it considers all edge pixels simultaneously, which makes it robust to noise and gaps but also computationally expensive ($O(\text{num\_edge\_pixels} \times \text{num\_}\theta\text{\_bins})$).

---

## The Circle Hough Transform

Circles are parameterized by center $(a, b)$ and radius $r$:

$$(x - a)^2 + (y - b)^2 = r^2$$

This has **3 parameters** (vs 2 for lines), so the accumulator is 3-dimensional. For each edge pixel and each possible radius $r$, the pixel votes for a circle of possibilities in $(a, b)$ space.

**Optimization:** the gradient direction at each edge pixel (from Sobel) tells you the direction toward the circle's center. So instead of voting for an entire circle of possible centers, each pixel votes only along the gradient direction — this reduces the votes per pixel from $O(\text{circumference})$ to $O(1)$ and dramatically speeds up the transform.

```python
import cv2
# Detect circles
circles = cv2.HoughCircles(
    image, cv2.HOUGH_GRADIENT, dp=1, minDist=50,
    param1=100, param2=30, minRadius=10, maxRadius=100
)
```

## The Generalized Hough Transform

The Hough idea generalizes to any shape that can be parameterized. For arbitrary (non-parametric) shapes, the **Generalized Hough Transform** uses a lookup table of edge orientations relative to a reference point, built from a template shape. It is powerful but computationally expensive and rarely used now that deep learning handles shape detection.

---

## Applications

- **Lane detection in autonomous driving:** detect lane markings (lines) on the road.
- **Document analysis:** detect text lines and table borders.
- **Medical imaging:** detect circular structures (cells, pupils, implants).
- **Industrial inspection:** detect manufactured parts with known shapes.
- **Particle counting:** count circular cells or droplets in microscopy images.

---

## Limitations

1. **Computationally expensive:** the line transform is $O(N \cdot \Theta)$ where $N$ is the number of edge pixels and $\Theta$ is the number of $\theta$ bins. For large images, this is slow. The **Probabilistic Hough Transform** (OpenCV's `HoughLinesP`) samples edge pixels randomly instead of using all of them, which is much faster with similar results.
2. **Parameter tuning:** the accumulator threshold, the $\rho/\theta$ bin sizes, and (for circles) the radius range all need tuning. Bad parameters produce missed detections or false positives.
3. **Only finds parametric shapes:** lines, circles, ellipses. For arbitrary shapes, use template matching or deep learning.
4. **Co-linear but separate segments are merged:** the basic Hough transform detects lines, not line segments. To get segments, you must post-process (find the edge pixels that voted for each line and group them into segments).

---

## What you should walk away with

1. The Hough transform detects parametric shapes (lines, circles) by **voting in parameter space**.
2. Each edge pixel votes for all shapes it could be part of; shapes receiving many votes are detected.
3. Lines use the $(\rho, \theta)$ parameterization (avoiding the infinite-slope problem); each edge pixel votes for a sinusoid in $(\rho, \theta)$ space.
4. Circles use a 3D accumulator $(a, b, r)$; the gradient direction optimization speeds it up.
5. The Hough transform is **robust to gaps and noise** (global voting) but **computationally expensive** (the probabilistic variant helps).
6. Applications: lane detection, document analysis, medical imaging, industrial inspection.
7. For arbitrary shapes, use deep learning; for parametric shapes, Hough remains useful.
