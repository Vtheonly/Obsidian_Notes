# 1.1 What is a Digital Image

> **Prerequisites:** None (this is the first note in the chapter)
> **Connections:** [[1.2 Image Representation Types]], [[1.3 Resolution and Bit Depth]], [[1.7 The Color Image Processing Pipeline]]

This note defines what a digital image **is**, mathematically and conceptually, and explains the two fundamental operations — **sampling** and **quantization** — that convert continuous reality into the discrete grid of numbers a computer can process. Understanding these foundations is essential because every subsequent operation in image processing operates on this discrete representation.

---

## The definition

A digital image is a **two-dimensional discrete function**:

$$f(x, y) \quad \text{where} \quad x \in \{0, 1, \ldots, M-1\}, \quad y \in \{0, 1, \ldots, N-1\}$$

- $x, y$ are **spatial coordinates** (column, row) — integers, because the image is sampled on a grid.
- $f(x, y)$ is the **intensity** (or color) at that coordinate — a discrete value, because the intensity is quantized.
- $M \times N$ is the image **resolution** (width × height in pixels).

For a grayscale image, $f(x, y)$ is a single number (the brightness, typically 0–255 for 8-bit images). For a color image, $f(x, y)$ is a vector — usually 3 values for RGB, but possibly more (RGBA, multispectral, hyperspectral).

**The key insight:** a digital image is a **discrete approximation** of continuous reality. The real world is continuous (light varies smoothly in space and intensity); the digital image samples it on a grid and quantizes the intensity to fixed levels. Everything in image processing — from blurring to edge detection to compression — operates on this discrete approximation.

---

## The two-step digitization: sampling and quantization

### Sampling (spatial discretization)

The continuous image (the light falling on the sensor) is **sampled** at discrete spatial positions — the pixel grid. Each sample is the average (or integral) of the continuous image over a small region (the pixel's area).

- **Sampling rate** = number of pixels per unit area (PPI — pixels per inch, for displays; DPI — dots per inch, for printing).
- **Higher sampling** = more pixels = finer spatial detail.
- **Lower sampling** = fewer pixels = coarser detail, **aliasing** (high-frequency patterns fold back as spurious low frequencies — see [[3.7 Geometric Transformations and Interpolation]]).

The **Nyquist-Shannon sampling theorem** states that to capture a signal with maximum frequency $f_{max}$, you must sample at least $2 f_{max}$ times. Below this rate, **aliasing** occurs — fine patterns (stripes, textures) appear as coarser, wrong patterns. This is why phone cameras have optical low-pass filters (to blur frequencies above the Nyquist rate before sampling).

### Quantization (intensity discretization)

The continuous intensity at each sample is **quantized** to a fixed number of levels — typically 256 levels (8 bits) for grayscale, 256 per channel for 8-bit RGB.

- **Bit depth** = number of bits per pixel = determines the number of intensity levels. 8 bits = 256 levels; 16 bits = 65,536 levels; 1 bit = 2 levels (binary).
- **Higher bit depth** = finer intensity gradation = smoother gradients.
- **Lower bit depth** = fewer levels = **banding** (visible steps in smooth gradients) and **posterization**.

**Quantization error** is the difference between the true continuous intensity and the quantized value. This error is bounded by $\pm 0.5$ LSB (least significant bit) and is usually modeled as uniform noise. For 8-bit images, this is at most $\pm 0.5/255 \approx 0.2\%$ — small but not zero, and visible in dark regions or smooth gradients.

## The coordinate system: where is the origin?

In **mathematics**, the origin $(0, 0)$ is at the bottom-left, with $y$ increasing upward. In **image processing**, the origin is at the **top-left**, with $y$ increasing downward.

```
(0,0) ──────── x (columns) ───────▶
  │
  │
y (rows)
  │
  ▼
```

This convention comes from how images are stored in memory (row-major order: the first row, then the second row, ...) and how displays scan (top to bottom). It is the opposite of mathematical convention and is a perennial source of confusion (e.g., when rotating images, the rotation direction appears reversed).

**Practical implication:** when you index an image as `image[y, x]` (in NumPy/OpenCV), the first index is the **row** (y) and the second is the **column** (x). This is the opposite of the mathematical $(x, y)$ convention.

## Image types by dimensionality

| Type | Dimensions | Example |
| :--- | :--- | :--- |
| Binary | $M \times N \times 1$ (1 bit) | Scanned documents, masks |
| Grayscale | $M \times N \times 1$ (8 or 16 bit) | X-rays, medical images |
| Color (RGB) | $M \times N \times 3$ | Photographs |
| Color (RGBA) | $M \times N \times 4$ | Photos with transparency |
| Multispectral | $M \times N \times k$ (k = 4–10) | Satellite imagery (red, green, blue, near-IR, ...) |
| Hyperspectral | $M \times N \times k$ (k = 100s) | Remote sensing, material identification |
| Volumetric (3D) | $M \times N \times P$ | CT/MRI scans, 3D microscopy |
| Video | $M \times N \times T$ | Time series of images |

Most of this chapter deals with 2D grayscale or RGB images, but the concepts extend to all types.

---

## How images are stored in memory

A grayscale image is a 2D array: `image[row, col]` = intensity at that pixel. A color image is a 3D array: `image[row, col, channel]` or `image[channel, row, col]` depending on the framework.

- **NumPy / OpenCV:** `(H, W, C)` — height, width, channels. BGR order (not RGB) for historical OpenCV reasons.
- **PyTorch:** `(C, H, W)` — channels first. RGB order.
- **TensorFlow:** `(H, W, C)` — channels last. RGB order.

The channel ordering (RGB vs BGR) and the dimension ordering (CHW vs HWC) are common sources of bugs when switching between frameworks. Always check the convention.

---

## What you should walk away with

1. A digital image is a **2D discrete function** $f(x, y)$ on an integer grid, with quantized intensity.
2. **Sampling** discretizes space (the pixel grid); **quantization** discretizes intensity (the bit depth).
3. Insufficient sampling causes **aliasing**; insufficient quantization causes **banding/posterization**.
4. The **Nyquist theorem** requires sampling at $2 \times$ the maximum frequency to avoid aliasing.
5. The image processing coordinate system has origin at **top-left**, $y$ increasing downward — the opposite of math convention.
6. Images are stored as arrays; the dimension order (HWC vs CHW) and channel order (RGB vs BGR) vary by framework.
