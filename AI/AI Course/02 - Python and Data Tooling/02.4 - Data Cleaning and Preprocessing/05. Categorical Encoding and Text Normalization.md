# 5. Categorical Encoding and Text Normalization

> **Prerequisites:** [[04. Feature Scaling and Normalization]]
> **Connections:** [[01. Handling Missing Data and Imputation Strategies]] (both are preprocessing steps)

Models require numbers, not strings. We must convert categories (e.g., "Red", "Blue") into numerical format. The choice of encoding depends on the cardinality of the feature and the type of model.

---

## 5.1 Text Normalization

Before encoding, clean the text to ensure consistency.

1. **Lowercasing:** "Apple" -> "apple".
2. **Stripping Whitespace:** " Apple " -> "apple".
3. **Removing Special Chars:** "Apple!" -> "apple".
4. **Replacing typos/synonyms:** "NYC", "N.Y.C.", "New York City" -> "new york".

```python
df['City'] = df['City'].str.lower().str.strip()
```

Without normalization, "Apple", "apple", and "Apple " would be encoded as three different categories — wasting dimensionality and splitting signal across spurious categories.

---

## 5.2 Label Encoding (Ordinal Encoding)

Assigns a unique integer to each category.

- "Low" -> 0, "Medium" -> 1, "High" -> 2.
- **Pros:** Compact (1 column).
- **Cons:** Implies **Order** (Ordinality). The model thinks $2 > 0$. Only use for Ordinal data (Rankings, levels, sizes).
- **Do NOT use for nominal data** (categories with no inherent order: colors, cities, names). The model will incorrectly infer an order.

```python
from sklearn.preprocessing import LabelEncoder, OrdinalEncoder
le = LabelEncoder()
df['Encoded_Rank'] = le.fit_transform(df['Rank'])

# OrdinalEncoder is better for features (LabelEncoder is for targets):
oe = OrdinalEncoder(categories=[['Low', 'Medium', 'High']])  # specify the order
df['Encoded_Level'] = oe.fit_transform(df[['Level']])
```

---

## 5.3 One-Hot Encoding (OHE)

Creates a new binary column (dummy variable) for *each* category.

- "Red" -> [1, 0, 0]
- "Green" -> [0, 1, 0]
- "Blue" -> [0, 0, 1]
- **Pros:** No implied order. Good for Nominal data.
- **Cons:** **Curse of Dimensionality.** If a category has 10,000 unique values (e.g., Zip Codes), you create 10,000 columns.

```python
# Using Pandas
df_ohe = pd.get_dummies(df, columns=['Color'], drop_first=True)
# drop_first=True removes one column to prevent multicollinearity (Dummy Variable Trap).

# Using sklearn (better for ML pipelines, handles unseen categories):
from sklearn.preprocessing import OneHotEncoder
ohe = OneHotEncoder(drop='first', sparse_output=False, handle_unknown='ignore')
encoded = ohe.fit_transform(df[['Color']])
```

**`handle_unknown='ignore'`** is critical: at test time, you may encounter a category not seen in training. Without this flag, the encoder crashes. With it, unknown categories produce all-zeros.

---

## 5.4 Target Encoding (Mean Encoding)

Replaces category with the **mean of the target variable** for that category.

- "Seattle" -> 0.65 (if 65% of Seattle samples in training are positive)
- **Use Case:** High cardinality categorical features (e.g., City names, Zip codes, User IDs) where OHE would create too many columns.
- **Risk:** Overfitting. Must be calculated on Training data only (use cross-validation within the training set to compute the means).

```python
# sklearn 1.3+ has a proper TargetEncoder (handles the leakage correctly):
from sklearn.preprocessing import TargetEncoder
te = TargetEncoder()
df['City_Encoded'] = te.fit_transform(df[['City']], df['Target'])

# Manual implementation (with K-fold to avoid leakage):
from sklearn.model_selection import KFold
import numpy as np

kf = KFold(n_splits=5, shuffle=True, random_state=42)
df['City_Encoded'] = 0.0
for train_idx, val_idx in kf.split(df):
    means = df.iloc[train_idx].groupby('City')['Target'].mean()
    df.loc[val_idx, 'City_Encoded'] = df.loc[val_idx, 'City'].map(means).fillna(df['Target'].mean())
```

**Why K-fold?** If you compute the target mean for each category on the full training set, then assign it to the same rows, you leak each row's target into its own feature. K-fold prevents this: each row's encoding is computed from the *other* folds' targets.

---

## 5.5 Other Encodings (Brief)

- **Frequency Encoding:** replace category with its frequency in the training set. Simple, works for high cardinality, but loses information about the target.
- **Binary Encoding:** convert the integer label to binary, then one-hot each bit. Compromise between Label and OHE — $O(\log_2 K)$ columns instead of $K$.
- **Hashing Trick (Feature Hashing):** hash category to a fixed-size array. No memory overhead, but collisions are possible. Used in large-scale systems (Vowpal Wabbit, online learning).
- **Embeddings:** map each category to a learned dense vector (as in NLP word embeddings). The most powerful approach for very high cardinality, but requires a neural network to learn the embeddings.

---

## Choosing the Right Encoding

| Situation | Recommended Encoding |
| :--- | :--- |
| Ordinal data (Low/Medium/High) | OrdinalEncoder (specify the order) |
| Nominal, low cardinality (< 15 categories) | One-Hot Encoding |
| Nominal, high cardinality (15-1000 categories) | Target Encoding (with K-fold) |
| Nominal, very high cardinality (> 1000 categories) | Target Encoding, Hashing, or Embeddings |
| Tree-based models | Label/Frequency encoding is often fine (trees can split on integers) |
| Linear models, NN, SVM | OHE or Target Encoding (trees handle raw integers; linear models cannot) |

---

## The Critical Practice: Fit on Train, Transform Both

Same as scaling — **never fit the encoder on the full dataset**. Fit on train, transform both. Or use a Pipeline with `ColumnTransformer`:

```python
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline

preprocessor = ColumnTransformer([
    ('num', StandardScaler(), ['Age', 'Salary']),
    ('cat', OneHotEncoder(handle_unknown='ignore'), ['City', 'Color'])
])

pipe = Pipeline([
    ('preprocess', preprocessor),
    ('model', LogisticRegression())
])
pipe.fit(X_train, y_train)
pipe.score(X_test, y_test)
```

The `ColumnTransformer` applies different transformations to different columns — scaling for numerical, OHE for categorical — and the Pipeline guarantees no leakage.

---

## What you should walk away with

1. **Label/Ordinal Encoding:** integers, only for ordinal data (implied order).
2. **One-Hot Encoding:** binary columns, for nominal data, but curse of dimensionality at high cardinality.
3. **Target Encoding:** mean of target per category, for high cardinality, but must use K-fold to avoid leakage.
4. **Other options:** Frequency, Binary, Hashing, Embeddings for special cases.
5. **Always fit on train, transform both** — or use `ColumnTransformer` + `Pipeline`.
6. Tree models can handle label encoding; linear models and NNs need OHE or target encoding.
