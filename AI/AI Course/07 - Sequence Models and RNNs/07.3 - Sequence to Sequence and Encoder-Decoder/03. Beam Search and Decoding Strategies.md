## The decoding question

At inference time, the decoder produces a probability distribution $p_t$ over the vocabulary at each step. How do we turn this sequence of distributions into a sequence of tokens?

This is the **decoding problem**, and the choice of strategy has a large effect on output quality. The strategies form a spectrum from cheap-and-greedy to expensive-and-careful.

---

## Strategy 1 — Greedy decoding

At each step, pick the most likely token:

$$y_t = \arg\max_{w} p_t(w)$$

This is the cheapest strategy — one forward pass per token, no search. It is also the worst, because it is **locally optimal but globally suboptimal**. A simple example: in translating "I am hungry" to French, the model might assign:

- Step 1: "je" (0.7), "j'" (0.25), "moi" (0.04), ...
- Step 2 (after "je"): "suis" (0.3), "ai" (0.3), "mange" (0.2), ...
- Step 3 (after "je suis"): "faim" (0.4), "fatigué" (0.3), ...

Greedy picks "je" (0.7) → "suis" (0.3, tied with "ai") → "faim" (0.4), giving "je suis faim" — grammatically wrong (should be "j'ai faim"). But the alternative path "j'" (0.25) → "ai" (0.6 after "j'") → "faim" (0.9 after "j'ai") has joint probability 0.25 × 0.6 × 0.9 = 0.135, while the greedy path has 0.7 × 0.3 × 0.4 = 0.084. The globally optimal path was not taken because the first step was locally greedy.

---

## Strategy 2 — Exhaustive search

The globally optimal sequence is the one that maximizes the joint probability:

$$y^* = \arg\max_{y_{1:T}} \prod_{t=1}^{T} p_t(y_t \mid y_{1:t-1})$$

For a vocabulary of size $V$ and sequence length $T$, this requires exploring $V^T$ paths. For $V = 30000$ and $T = 20$, that is $30000^{20} \approx 10^{88}$ — computationally impossible. We need a tractable approximation.

---

## Strategy 3 — Beam search (the practical default)

Beam search is a middle ground: at each step, keep the top-$B$ partial sequences (the "beam") rather than just the top-1 (greedy) or all (exhaustive). $B$ is the **beam width**, typically 4–10 in practice.

### The algorithm

1. **Initialize:** the beam contains one empty sequence with score 1.0.
2. **At each step $t$:** for each of the $B$ sequences in the beam, compute the top-$B$ next-token extensions. This gives $B \times B$ candidate sequences. Compute each candidate's cumulative log-probability.
3. **Prune:** keep the top-$B$ candidates by cumulative score; discard the rest.
4. **Terminate:** when a sequence emits `<EOS>`, move it to a "completed" list and remove it from the beam. Continue until the beam is empty or a max length is reached.
5. **Return:** the completed sequence with the highest score (often normalized by length to avoid bias toward short sequences).

### Why log-probabilities, not probabilities

Multiplying $T$ probabilities in $[0,1]$ underflows to zero for $T > 30$ or so. Summing $T$ log-probabilities is numerically stable. Always work in log space.

### Why length normalization helps

Raw log-probability is biased toward short sequences — fewer multiplications of numbers < 1 means a higher sum. The standard fix is to divide by length:

$$\text{score}(y) = \frac{1}{T^\alpha} \sum_{t=1}^{T} \log p_t(y_t \mid y_{<t})$$

with $\alpha \in [0.6, 0.7]$ typically. This makes the score per-token rather than total, removing the length bias. Without this, beam search produces unreasonably short outputs.

### Worked intuition

With beam width $B = 2$ on the "I am hungry" example:

- Step 1 candidates: "je" (0.7), "j'" (0.25), "moi" (0.04), ...
- Beam after step 1: [("je", 0.7), ("j'", 0.25)] (top 2)
- Step 2 candidates (extending each):
  - "je suis" (0.7 × 0.3 = 0.21)
  - "je ai" (0.7 × 0.3 = 0.21)
  - "j' ai" (0.25 × 0.6 = 0.15)
  - "j' suis" (0.25 × 0.1 = 0.025)
- Beam after step 2: [("je suis", 0.21), ("je ai", 0.21)] (top 2, ties broken arbitrarily)
- ...

In this tiny example beam search with $B=2$ still picks the wrong path (because "j' ai" at 0.15 is below the cutoff), but with $B=3$ it would keep "j' ai" alive and ultimately find "j'ai faim" (0.135) as the best path.

The lesson: **beam width controls the quality/runtime tradeoff.** Larger $B$ finds better sequences but is slower. For production translation, $B = 5$ is a common default.

## Strategy 4 — Sampling-based decoding (for creative generation)

Beam search produces **deterministic, low-diversity** outputs — it always picks the most probable sequence, which tends to be safe and generic. For tasks where diversity matters (story generation, dialogue, poetry), we want stochastic decoding.

### Pure sampling

Sample each token from the distribution $p_t$:

$$y_t \sim p_t$$

This is maximally diverse but can produce incoherent text — long-tail low-probability tokens derail the generation.

### Top-$k$ sampling (Fan et al. 2018)

Sample only from the top $k$ most probable tokens at each step, renormalized:

$$y_t \sim \text{RestrictedCategorical}(p_t, \text{top } k)$$

with $k$ typically 10–50. This truncates the long tail and prevents rare-token derailment while preserving diversity.

### Top-$p$ sampling / nucleus sampling (Holtzman et al. 2019)

Sample from the smallest set of tokens whose cumulative probability exceeds $p$:

$$y_t \sim \text{RestrictedCategorical}(p_t, \text{smallest set with cumulative prob} \geq p)$$

with $p$ typically 0.9–0.95. This adapts the truncation to the distribution shape — when the model is confident (one token at 0.99), the nucleus is tiny; when the model is uncertain (many tokens at 0.05), the nucleus is larger. Top-$p$ is generally preferred over top-$k$ for modern LLM generation.

### Temperature

Before sampling, divide the logits by a temperature $T$:

$$p_t = \text{softmax}(\text{logits} / T)$$

- $T \to 0$: distribution becomes peaked (approaches greedy).
- $T = 1$: original distribution.
- $T \to \infty$: distribution becomes uniform (pure randomness).

Temperature controls *how risky* each sample is. Top-$p$ with $T = 0.7$ is a common configuration for creative text generation.

---

## When to use which

| Task | Recommended strategy | Why |
| :--- | :--- | :--- |
| Machine translation | Beam search, $B = 5$, length-norm $\alpha = 0.6$ | Translation has a correct answer; diversity is not desired |
| Summarization | Beam search, $B = 4$ | Same — there is a "best" summary |
| Image captioning | Beam search, $B = 3$–$5$ | Same |
| Dialogue / story generation | Top-$p$ sampling, $p = 0.9$, $T = 0.7$ | Diversity and creativity matter; no single correct answer |
| Code generation | Greedy or beam with $B = 1$–$4$ | Code is brittle — a single wrong token breaks it; prefer determinism |
| Open-ended LLM chat | Top-$p$ sampling, $p = 0.9$–$0.95$ | The modern default for ChatGPT-class models |

---

## What you should walk away with

1. Greedy decoding is cheap but locally optimal — it misses globally better sequences.
2. Exhaustive search is intractable ($V^T$ paths).
3. Beam search keeps the top-$B$ partial sequences at each step; $B = 4$–$10$ is the practical sweet spot.
4. Always work in log-probabilities (numerical stability) and length-normalize (avoid short-sequence bias).
5. For creative generation, use top-$p$ (nucleus) sampling instead of beam search — it preserves diversity.
6. Temperature controls the sharpness of the sampling distribution.
