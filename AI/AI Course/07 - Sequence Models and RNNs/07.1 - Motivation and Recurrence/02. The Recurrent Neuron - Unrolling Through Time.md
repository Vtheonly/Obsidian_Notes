## The recurrence equation, in one line

A vanilla recurrent layer has a hidden state $h_t$ that gets updated at every time step:

$$h_t = \tanh \left( W_h \, h_{t-1} + W_x \, x_t + b \right)$$

That is the whole model. The names:

- $x_t \in \mathbb{R}^d$ is the input vector at time $t$ (e.g. an embedding of the $t$-th word).
- $h_t \in \mathbb{R}^h$ is the hidden state at time $t$ — the network's "memory" of everything it has seen up to and including step $t$.
- $W_x \in \mathbb{R}^{h \times d}$ is the input-to-hidden weight matrix.
- $W_h \in \mathbb{R}^{h \times h}$ is the hidden-to-hidden weight matrix (the "recurrent" matrix — this is what makes it recurrent).
- $b \in \mathbb{R}^h$ is a bias.
- $\tanh$ is the activation, chosen because it is bounded in $[-1, 1]$ and zero-centered (both helpful for training).

Crucially, $W_x$, $W_h$, and $b$ are **the same at every time step**. This is weight sharing across time — the parameter count is independent of the sequence length.

At every time step you can also emit an output:

$$y_t = W_y \, h_t + c$$

where $W_y \in \mathbb{R}^{o \times h}$ maps the hidden state to whatever output dimension you need (a class probability, a predicted next token, a regression value, etc.).

---

## Why this is "a neural network with a loop"

If you draw the recurrence equation as a circuit, you get a node $h$ that takes input from both $x_t$ and *itself* from the previous step. That self-loop is what makes the network "recurrent."

```
        x_t
         │
         ▼
   ┌───────────┐
   │   tanh    │◀──── h_{t-1}
   └───────────┘
         │
         ▼
        h_t ─────▶ y_t
         │
         ▼ (looped forward to the next step)
```

A computer cannot evaluate a loop directly — it needs a finite graph. So we **unroll** the loop across time, producing a copy of the same cell at every time step:

```
x_1     x_2     x_3         x_T
 │       │       │           │
 ▼       ▼       ▼           ▼
[C1]──▶[C2]──▶[C3]──▶ ... ──▶[CT]
 │       │       │           │
 ▼       ▼       ▼           ▼
y_1     y_2     y_3         y_T
```

Every `[Ci]` is the same cell with the same weights — we have just unrolled the loop. This unrolled picture is the one you will see in every textbook, because it makes the forward and backward computation visible.

> [!IMPORTANT] The unrolling is conceptual, not architectural.
> The network has only one set of weights. The "copies" in the unrolled diagram are not separate parameters; they are the same parameters evaluated at different time steps. When you train an RNN, you train one $W_h$, one $W_x$, one $W_y$ — never $T$ of them.

## Forward pass: a concrete example

Suppose the input sequence is `["the", "cat", "sat"]`, with 4-dimensional word embeddings and a hidden size of 3. The cell executes:

| Step | Input $x_t$ | Previous state $h_{t-1}$ | New state $h_t = \tanh(W_x x_t + W_h h_{t-1} + b)$ |
| :---: | :---: | :---: | :---: |
| 1 | embedding("the") | $h_0 = \mathbf{0}$ | $h_1 = \tanh(W_x x_1 + b)$ |
| 2 | embedding("cat") | $h_1$ | $h_2 = \tanh(W_x x_2 + W_h h_1 + b)$ |
| 3 | embedding("sat") | $h_2$ | $h_3 = \tanh(W_x x_3 + W_h h_2 + b)$ |

Two things to notice:

1. **The initial state $h_0$ is usually set to zero.** Some practitioners learn it as a parameter; for most tasks zero works fine.
2. **$h_3$ is a function of the entire input sequence.** If you change $x_1$, the change propagates through $h_1 \to h_2 \to h_3$. This is exactly the "memory" we wanted.

---

## What does $h_t$ actually represent?

This is the question that separates rote understanding from intuition. The honest answer is: $h_t$ is **whatever the network has learned to compress into a fixed-size vector that lets it predict future tokens**. It is not interpretable by design; it is an *information bottleneck* forced by the architecture.

A useful mental model: $h_t$ is a **lossy summary of the prefix** $x_1, \ldots, x_t$. The network is trained (via [[03. Backpropagation Through Time (BPTT)]]) to put into $h_t$ whatever information is needed to predict $x_{t+1}$ (or whatever downstream task you give it). If the task forces the network to remember the gender and number of the subject 20 words ago so that it can produce the right verb agreement, $h_t$ will learn to encode that. If the task does not require it, $h_t$ will not bother — which is the seed of the long-range-dependency problem we will meet in [[04. The Vanishing and Exploding Gradient Problem in RNNs]].

## Three common RNN configurations

The same cell supports several different tasks just by changing which $y_t$ you read out and what loss you apply.

| Configuration | Read out | Used for |
| :--- | :--- | :--- |
| **Many-to-one** | Only $y_T$ (final state) | Sentiment classification, sequence classification |
| **Many-to-many (synced)** | Every $y_t$ | Per-frame phoneme classification, POS tagging |
| **Many-to-many (encoder-decoder)** | All $y_t$ from a second RNN that reads the encoder's final state | Translation, summarization — see [[01. The Encoder-Decoder Pattern - Conditional Generation]] |

The cell is the same. The "RNN" is the same. What changes is which outputs you supervise and how.

## Weight sharing across time — the CNN analogy, made explicit

| | CNN | RNN |
| :--- | :--- | :--- |
| Weight sharing axis | Space (the kernel slides over the image) | Time (the cell slides over the sequence) |
| Sliding operation | Cross-correlation with a kernel | Linear transform + nonlinearity |
| "Receptive field" grows how? | Stacking layers (each layer sees a wider window) | Recurrence (each step incorporates one more input) |
| Parameter count vs. input size | Independent of image size | Independent of sequence length |
| Equivariant to | Translation | Time-shift (if you shift the input by $k$ steps, the output shifts by $k$ steps) |

This is why CNNs and RNNs feel like siblings in your mental library: both are the answer to "how do I share parameters across a structured input?" — one for space, one for time. The Transformer (next chapter) will be the answer to "how do I share parameters across positions *without* imposing a temporal order?" — and once you see that, the whole architecture tree snaps into place.

---

## What you should walk away with

1. An RNN is one cell, applied at every time step, with a hidden state that carries information forward.
2. The "unrolled" diagram is a bookkeeping trick — there is still only one set of weights.
3. $h_t$ is a lossy summary of the prefix $x_{1:t}$, trained to contain whatever the task needs.
4. The same cell supports many-to-one, synced many-to-many, and encoder-decoder setups — only the readout and loss change.
5. CNNs and RNNs are siblings: weight sharing across space vs. weight sharing across time.

The next note explains how to train this thing, which forces us to confront a subtle and dangerous fact: training an RNN is just backpropagation on the unrolled graph, but the unrolled graph can be **very deep** (as deep as the sequence is long), and that depth is what causes the vanishing and exploding gradient problem.
