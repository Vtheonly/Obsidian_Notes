## The hidden assumption of every network you have built so far

Every neural network we have studied so far — the perceptron, the MLP, the CNN — makes the same quiet assumption: **the input is a fixed-size, position-independent object**. A 28×28 image is a 28×28 image regardless of which class it belongs to. A 10-feature row in a tabular dataset has the same 10 features for every row.

This assumption is so natural that we never wrote it down. But it has a consequence that becomes obvious the moment you try to apply these networks to language, audio, or time series: **the network has no memory, and the network has no notion of order.**

To see why this matters, consider the difference between images and sentences.

- An image is mostly **translation-invariant**: a cat in the top-left corner is still a cat in the bottom-right corner. CNNs exploit this by sharing weights across spatial positions.
- A sentence is **order-dependent in an irreducible way**: "the dog bit the man" and "the man bit the dog" contain the same words but mean opposite things. No spatial pooling can recover that difference.

A feedforward network can only handle a sentence by **flattening** it into a fixed-length vector. That destroys two things at once: it forces you to choose a maximum length in advance, and it throws away the fact that the words form a *sequence* rather than a *set*.

---

## Three concrete tasks a feedforward network cannot do well

### 1. Language modeling: predict the next word

Given "the cat sat on the", predict the next word. A feedforward network can do this *if* you fix the context length — say, always look at the last 5 words. But then:

- It cannot use context from 20 words ago when the sentence calls for it ("I grew up in France. ... [many sentences later] ... I speak fluent ___").
- It needs a separate set of input weights for position 1, position 2, ... position 5. There is no parameter sharing across time, so the model has to relearn that "the" is "the" no matter where it appears.
- It cannot generate sequences of arbitrary length, because the input shape is fixed.

### 2. Translation: variable-length input, variable-length output

Translating "how are you?" to "comment ça va ?" maps 3 words to 3 words. But translating a 30-word sentence to a 25-word sentence is a different problem entirely: the input and output lengths differ, and there is no fixed alignment between input position $i$ and output position $j$. A feedforward network has no mechanism for this.

### 3. Time-series forecasting: long-range dependencies

Predicting tomorrow's electricity demand from the last 24 hours is fine for an MLP. But predicting next month's sales from a multi-year history, where seasonal patterns repeat every 365 days and trend changes slowly over years, requires the model to *remember* events from arbitrarily far back. A fixed window throws away most of that history.

---

## Why we cannot just "use a bigger window"

A natural reaction is: *just make the window larger*. Look at the last 1000 words, the last 10 years of data, the last 1000 audio frames.

This fails for three reasons.

**First, parameter explosion.** If the input dimension is 1000 and the first hidden layer has 1000 neurons, the first weight matrix has $10^6$ parameters — all of them dedicated to a single, position-specific mapping. There is no sharing, so the network has to independently learn that "the" at position 17 means the same thing as "the" at position 942.

**Second, statistical inefficiency.** Because each position has its own weights, the network never sees the regularity that "the" is "the" wherever it appears. It cannot pool evidence across positions. Generalization suffers.

**Third, fixed length is a lie.** No matter how big you make the window, there will always be a sequence longer than it. And for sequences shorter than the window, you waste input slots on padding tokens, which dilutes the signal.

---

## The key insight: share weights across time, just like CNNs share weights across space

A CNN works because the **same convolutional kernel** is applied at every spatial position. The network learns one pattern ("vertical edge") and reuses it everywhere. The number of parameters is independent of the image size.

The analogous idea for sequences is: **apply the same weights at every time step, and let the network's output at time $t$ depend on its own output at time $t-1$.** That way:

- The same "what does this word mean" function is applied to every position.
- The network's internal state at time $t$ is a function of the entire history up to $t$, so memory is built in.
- The number of parameters is independent of the sequence length.
- Variable-length sequences become first-class citizens.

This is the definition of a **recurrent neural network**. The next note makes it precise.

## A quick comparison table

| Property | Feedforward MLP | CNN | (Vanilla) RNN |
| :--- | :--- | :--- | :--- |
| Input shape | Fixed vector | Fixed image (or volume) | Variable-length sequence |
| Weight sharing | None | Across spatial positions | Across time steps |
| Memory of past | None | None (within one forward pass) | Yes (hidden state) |
| Handles order | No | Only spatial | Yes (explicitly) |
| Handles variable length | No | No | Yes |
| Gradient flow | One backward pass | One backward pass | Through time (BPTT) |

Notice that the RNN column is the first one that says "yes" to memory, order, and variable length simultaneously. That is the whole reason RNNs exist.

---

## What you should walk away with

1. A feedforward network treats every input as an unordered, fixed-size object. This is fine for images and tabular data, fatal for sequences.
2. Enlarging the input window does not solve the problem — it just makes the parameter explosion and statistical inefficiency worse.
3. The right move is to **share weights across time** and let the network carry state. This is what an RNN does.
4. CNNs and RNNs are conceptually siblings: CNNs share weights across space, RNNs share weights across time. Both reduce parameters by exploiting a symmetry in the data.
